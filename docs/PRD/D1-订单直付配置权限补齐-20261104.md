# D1 订单直付配置权限补齐

## 缺陷与权限合同

订单直付费用配置接口 `PATCH /api/admin/finance/purchase-payment-policy`、PC 调用及既有实施合同均要求 `finance_d1_fx_manage`，但正式权限种子没有注册该权限。结果是拥有既有 SUPER_ADMIN 角色的管理员读取正常，保存返回 403，通道仍为未配置，普通订单报价返回 `PURCHASE_PAYMENT_FEES_NOT_CONFIGURED`。

保留接口和 PC 的既有权限名，新增 API 权限定义，归属 D1 `/finance/recon`，高风险配置权限，默认仅绑定有效的 `SUPER_ADMIN`。`FINANCE_LEAD`、`FINANCE`、`RISK`、`AUDITOR` 等其他角色不新增默认授权，也不删除其既有明确授权；后续需要授权时使用既有 RBAC 流程。该权限不替代管理 D6 汇率牌价的 `finance_d6_manage`，不变更读取、CAS、幂等键和审计要求。

## 升级与新库

新增 `20261104_purchase_payment_policy_permission.sql`，通过受控迁移注册权限和 SUPER_ADMIN 绑定；重复执行不产生重复权限或绑定。经典 D 域种子同步定义，既有 D1 精确角色矩阵只为 SUPER_ADMIN 提供该新权限。启动迁移清单注册新增文件；Linux/macOS fresh bootstrap 从同一清单读取，无需独立复制 SQL。迁移不修改费用配置或支付、订单、钱包数据，不创建管理员或变更密码。

## 业务验收

应用正常迁移后读回实际管理员权限，正常调用带版本、理由和幂等键的费用 PATCH，确认成功及 App/Admin 权威读回一致，再对已创建普通订单重新报价并继续支付交付。无该权限的管理员仍应被拒绝，其他角色绑定保持原样；重放迁移及同一业务命令不得产生重复记录。此处列出验收要求，实际结果以本轮隔离业务证据为准。
