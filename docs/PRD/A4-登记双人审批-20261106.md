# A4 登记双人审批

BE-09（DEC-A-07）覆盖 A4 新事件登记、给已有事件新增字段和登记域扩展批次。具有 `platform_a4_write` 的后台账号通过 A2 提交。另一位处于启用状态且具备 `platform_a2_operation_approve` 的超级管理员审批，发起人不能审批自己的单。

- 三个登记 POST 对持有 A4 写权限的直接请求返回 `409 A2_CONFIRMATION_REQUIRED`。生命周期、留存、采样等现有操作仍按各自流程处理。
- A2 票据以规范化事件名标识对象，事件与字段登记共用事件对象锁。票据记录原登记字段、理由和事件目录版本。审批前事件、字段、扩展批次及目录版本均保持原状。
- 批准后通过现有登记服务执行。新事件和新增字段仍校验冻结的目录版本，版本已变更时拒绝执行并保留待批单。域扩展批准后按既有规则登记批次。
- 发起人可凭原幂等键只读查询自己的登记票据，当前 A4 查看权限可用，原写侧允许分支保留。响应丢失后的同键重试不会新增票据，也不会执行登记。

## A4-BE-08：手动留存清理的确认参数

- A2 审计清理和 A4 事件清理的新请求携带 `expectedRetentionMonths`，分别来自确认时的审计留存预览和事件留存配置，不由执行时的当前值代填。
- 新执行先读取对应留存月数；未传确认值返回 `422 RETENTION_EXPECTED_MONTHS_REQUIRED`，与当前值不同返回 `409 RETENTION_PARAMETERS_STALE`，均在清理锁、归档、删除和成功审计之前拒绝。A4 用这次读取的月数计算删除截止时间。
- 非空确认值纳入原命令摘要；旧无该字段的请求保留旧摘要，同键同体成功回执仍先恢复。后台定时清理、清理规则、锁和权限不变。
- 按用户 2026-11-16 代码验收口径复核并跳过测试编译；未执行清理、HTTP、数据库操作或 E2E。前端未改，旧客户端新执行需补确认字段后使用。
