# F1 等级月薪

V0、V1 固定为 0。V2 至 V8 首次配置的 USDT 月薪依次为 20、50、150、500、1500、4000、15000。迁移或首次九级初始化一次写入配置与审计。重跑迁移保留运营值。公开等级配置和后台 F1 返回十进制字符串 `monthlySalaryUsdt`。

F1 沿用 `PATCH /api/admin/teams/ranks/{rank}/thresholds/monthlySalaryUsdt` 和本级 `expectedRevision`。金额最多 12 位整数及 6 位小数。调低直接保存，调高用 A2 `f1_rank_policy_change` 的 `threshold` 动作和相同字段，由另一位有审批权的超管批准。提交和批准分别按 B1 原始精确覆盖率检查。

资格使用团队业务日历、真实晋升记录和当时的月薪。月初持有的等级按月初价格立即开放，当月新达到的更高等级次日开放。月底当天创新高的资格可在次月业务 1 日领取。已领月份不追加金额。上线当月只按当前持有等级和上线后的达级计算。上线当天刚达级的从次日开始，已隔夜持有的从上线时开始。

`GET /api/team/rank` 返回 `salary.businessDate`、当前可展示月份及开放时间、预告和下一次可领时间。月薪读取失败时返回 `salaryUnavailable: true`，仍返回等级和进度。`POST /api/team/rank/salary/claim` 接收 `month`、`amountUsdt` 及 `Idempotency-Key`，按本人和月份只入账一次。资格、确认金额和精确覆盖率校验通过后，同一事务写领取记录、已解锁奖励、钱包和 D4 RELEASE 流水。终态可从 `GET /api/team/rank/salary/claims/{key}` 按原键恢复。未领取成功的用户在窗口内可用新键重试。

`GET /api/admin/teams/ranks/salary/claims` 需要 F1 读权限，按用户编号、月份、等级过滤，每批最多 100 条。记录含 D4 流水号。F5 和团队奖励汇总识别 `vrank_salary`。F5 可用领取号核对并按原审批流程冲正、补发，原月仍为已领。月薪不在按用户暂停的类型中。

F5 月薪冲正按 OP-77 取本笔已入账月薪与当前非负可用 USDT 的较小值扣回。D4 和客服资金审计只记录实际扣款，扣回零元时没有扣款流水。未扣部分保留为 `recovery_pending`，可从 F5 详情和冲正回执读取 `recoveredAmount`、`pendingRecoveryAmount`。A2 批准单保留实际扣回和待追回金额。同键重试返回原结果，原月仍为已领。通用改状态命令不能代替带凭证的月薪冲正。全额冲正后按既有规则补发，待追回的奖励不进入补发。
