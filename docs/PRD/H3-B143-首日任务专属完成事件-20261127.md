# H3 B143 首日任务专属完成事件

以下首日任务各接受一项完成事件。有效绑定必须启用、未删除，且任务、事件、来源和用户字段全部符合约定。来源统一为 `SYSTEM`，用户字段统一为 `user_id`。

| 任务 | 完成事件 |
| --- | --- |
| `visit_earn` | `H3_DAY_ONE_EARN_PAGE_VIEWED` |
| `visit_store` | `H3_DAY_ONE_STORE_PAGE_VIEWED` |
| `view_product_roi` | `H3_DAY_ONE_S1_ROI_VIEWED` |
| `setup_profile` | `H3_DAY_ONE_PROFILE_SAVED` |
| `bind_bank_card` | `H3_DAY_ONE_CARD_BOUND` |

- H3 创建或修改启用绑定时，任一专属任务或专属事件错配按各自原有 422 业务码拒绝。页面观测用 `H3_DAY_ONE_PAGE_OBSERVATION_BINDING_INVALID`，业务事实用 `H3_DAY_ONE_BUSINESS_BINDING_INVALID`。启用任务缺少有效绑定返回 `H3_MISSION_ACTIVE_BINDING_REQUIRED`。对生效任务停用、删除或移走最后一条有效绑定返回 `H3_ACTIVE_DAY_ONE_BINDING_REQUIRED`。
- 管理接口的 `completionType`、`completionEvent` 只从有效绑定得出。空结果为 `unbound` 和空字符串。原始 `eventBindings` 继续提供历史错绑供运营编辑。
- 运营可把历史错绑原地改为正确事件，也可先加正确绑定，再停用、移走或删除错绑。若要移除生效任务仅剩的一条错绑，需先修正配置或暂停该任务。历史启动迁移要求每条生效首日任务保有至少一条完整的启用原始绑定，维护操作继续使用 `H3_ACTIVE_DAY_ONE_BINDING_REQUIRED` 保护该启动条件。
- 注册冻结原启用任务成员、路由和时窗，只复制有效事件绑定。旧配置只剩错绑的专属任务仍进入新注册快照。事件投影对新旧冻结绑定及旧账户的实时绑定都执行专属规则，普通事件照常完成正确绑定的普通任务。已冻结成员、路由、截止时间、进度和领用记录沿原记录处理。页面观测与真实资料保存、绑卡入口继续使用既有窗口及去重机制。

## S1 回本历史恢复依赖

B139 需要 App 和 H5 Lite 上报实际商品编号，并由后端核实该商品符合 S1 回本条件。已冻结且仅有错绑的回本任务，要在原窗口内以真实合格观测恢复完成，依赖 B139 的整条链路。本批保留已有 `s1-roi` 上报和有效绑定的正常处理，旧错绑的普通事件停止记完成。B139 发布后需独立验收上述历史恢复。

## 首日奖励领取事件

首日整组领奖仍按领取时的等级计算奖励，并通过 `quest.claimed` 上报 `reward_tier_basis=CLAIM_TIME`。启动迁移在该事件的当前生效版本登记非个人信息的可选枚举字段，避免新库因字段缺失而拒绝领奖并回滚奖励入账。其他任务可继续省略该字段。同一请求键重复提交时沿用原领奖回执。
