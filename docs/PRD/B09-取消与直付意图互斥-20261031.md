# B09：原单取消与直付意图互斥

订单取消统一由服务端判定。钱包命令查询返回 `NOT_SEEN / canResumeSameKey=true` 包含错误 PIN 后保留的 READY 命令，只表示当次查询未发现已提交效果或进行中的命令；它不撤销迟到请求，也不能证明其他标签页/支付键不存在直付意图。

同一原单存在 CREATING、SUBMIT_UNKNOWN、AWAITING_PAYMENT、FUNDS_CONFIRMED 或 MANUAL_REVIEW 的直付意图时，取消返回业务409 `ORDER_EXTERNAL_PAYMENT_IN_PROGRESS`。覆盖 HDPAY_BANK、CREGIS_USDT_BSC、CREGIS_USDT_ERC20，与当前前端所选方式或支付键无关。不释放库存、配额、券，也不生成取消审计。已取消原单仍返回原有幂等取消回执；EXPIRED 的迟到到款继续遵守原 D1 人工复核规则，本次不扩大到期条件。

该活跃意图拒绝通过业务异常回滚原取消事务，幂等命令记为 FAILED，可按原取消键重领；不缓存为已成功完成的409结果。外部意图此后确已终态未付、原单仍待付时，原取消键可重新核验后取消。异常或未决不得改取消键绕过。

取消与直付发起共用用户行锁。直付发起在该锁内对原单做 current read；取消入口使用 READ_COMMITTED，在等待用户锁后读取最新已提交的意图。若取消被加入已有、非显式 READ_COMMITTED 的事务，写入前返回业务码503 `ORDER_CANCEL_ISOLATION_UNAVAILABLE`，不伪造取消成功。既有 HTTP 两别名均无调用方事务，正常使用该入口创建的 READ_COMMITTED 事务。意图检查不加阻塞行锁，避免与交付的 intent→user 锁序相反。

取消先提交时，迟到钱包付款或直付发起从当前原单状态拒绝，不能扣本金或发起新收款；直付意图先提交时，取消拒绝。钱包付款先提交时，取消按已付订单拒绝。前端只能在同一账户/原单/原支付键的新鲜 NOT_SEEN+true 与原单仍待付时申请服务端取消；只有权威 CANCELLED 回执/读回才退出。409、超时、读失败和未知结果必须保留原支付键、原取消键、订单及 revision，继续恢复，不换号重付。已取消原单优先于仍可重试的 READY 命令，不能恢复付款。

验证采用隔离33348 MySQL、生产取消/直付业务服务及合成 HDPay；不调用真实供应商、短信或线上数据库。包含活跃状态×渠道、双方用户锁竞争、RR旧快照、外层RR拒绝、已取消回放和EXPIRED规则保留。具体结果以本批测试报告为准，源代码检查/隔离数据库不代替 TEST 或真机验收。
