# E6-BE-10：机型风控保存成功审计接入受控核查（候选 PRD）

基线：`nexion-backend` / `origin/test` = `dd5755ff3dbe602678b8dcc3a627420355d19b85`。本项只处理 B48 E6-BE-10，不混 A2-BE01、其它 scope 或前端。

## 规则

E6 机型风控设置保存（`PhoneModelRiskAdminService.update`）的直接写入有持久幂等回执和审计：

- scope：`E6_PHONE_RISK_SETTINGS`；
- 目标：`E.compute.phoneRisk.settings`；
- 成功审计：`ADMIN.PHONE_RISK_SETTINGS_UPDATED`，`resourceType=CONFIG`，`resourceId=E.compute.phoneRisk.settings`，`result=SUCCEEDED`；
- `_adminCommand` 由 `AuditLogService` 在幂等执行上下文中写入 recordId/scope/commandKey/requestHash。

未知结果的受控核查只有在**同一原命令**的真实成功审计可核时才可认定 `SUCCEEDED`；不能凭当前设置恰好相同、普通 GET、失败审计或他人审计推断。

## 当前缺口

`AdminCommandInvestigationService.allowedFact` 的可采信成功审计名单没有 E6 分支，且 `successEvidence` 查询只接受 `result='SUCCESS'`。E6 成功审计写成 `result='SUCCEEDED'`，因此即使 actor/method/path/recordId/scope/key/hash 全部匹配，也不会被采信；未知结果无法凭已有成功审计结案。

## 最小修复

1. `AdminCommandInvestigationMapper.successEvidence` 的审计结果条件改为接受 `SUCCESS` 或 `SUCCEEDED`；其它身份条件不变：
   - `id`、`is_deleted=0`、`actor_type=ADMIN`；
   - `actor_id=originAdminId`；
   - `method=originMethod`、`path=originPath`；
   - `created_at >= original.createdAt`；
   - `_adminCommand.recordId/scope/commandKey/requestHash` 与原始持久命令逐字相等。
2. `AdminCommandInvestigationService.allowedFact` 增加精确 E6 分支：
   - `scope` 必须是 `E6_PHONE_RISK_SETTINGS`；
   - `resourceType=CONFIG`；
   - `action=ADMIN.PHONE_RISK_SETTINGS_UPDATED`；
   - `resourceId=E.compute.phoneRisk.settings`。
3. 不修改 `PhoneModelRiskAdminService` 的写入、幂等键、审计、配置或返回；不修改 `PhoneModelRiskReceiptService` 的读取权限/状态判断。它已接受 `SUCCEEDED`/`CONFIRMED_SUCCEEDED` 的持久回执，核查后可按原号回读结案状态。
4. 不新增全局查键、审计读权、清键/换键、重发业务、A2 scope 或前端按钮。
