# BE-08 J1 业务开关恢复审批

J1 的单项关停、批量关停在授权人员确认后即时生效。J1 的恢复由具备 `emergency_j1_gate_resume` 与 A2 提案权限的管理员发起。直接向 `PUT /api/admin/emergency/kill-switches/{key}` 请求恢复时返回 `409 A2_CONFIRMATION_REQUIRED`。

恢复通过 `POST /api/admin/platform/audit/operations` 提案。业务来源为 `J1`，命令为 `J/j1_gate_resume`，参数为 `{ gateKey }`，锁定对象为 `{ domain: "J", type: "kill_switch", id: gateKey }`。后端确认当前关停、已补录自动关停结论并通过适用的覆盖率检查，保存当前关停标记。申请进入 A2 待办并以应急票置顶，业务保持关停。

另一位具备 A2 审批和 J1 恢复权限的有效超级管理员可以批准或驳回。批准时核对工单、对象锁和关停标记，并按原 J1 口径重新检查待补录状态与资金覆盖率。覆盖率可靠且达到红线才可恢复适用的资金业务。试用开关沿用免查覆盖率的规则。审批校验失败后工单保持待批，业务保持当时的开关状态。

提交结果未知时，发起人用原 `Idempotency-Key` 查询自己的工单。查不到时只在幂等有效期内提交原请求和原键。关停与其他既有应急入口继续采用原路径。
