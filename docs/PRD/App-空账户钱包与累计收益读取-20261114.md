# App 空账户钱包与累计收益读取

## 问题与口径

新 TEST 空账户没有设备或已结算收益。设备收益接口在读取设备前要求 E3 容量配置完整，返回 `E3_CAPACITY_CONFIG_INCOMPLETE`，使钱包真实余额无法读取；首页聚合查询明确返回计数 0，但周、月、累计收益投影将空集合转为 null，累计已付款也存在相同问题。

## 本批后端约定

- `GET /api/devices/earnings` 仅在设备查询明确返回空集合时不要求 E3 容量配置完整，钱包仍取当前认证账户的钱包事实。存在设备或设备集合缺失时仍要求完整配置；不初始化收益率、不造资产、不跳过身份、账户环境、用户资料、设备规格和已实现收益校验。
- `GET /api/app/home/overview` 的日、周、月、累计收益，在数据库明确返回任务数 0 时返回 `usdt=0,nex=0,jobCount=0`；摘要缺失或计数未知仍返回 null，存在记录的金额仍沿原校验。累计已付款仅在已付款订单数明确为 0 时返回 0，不改变全网统计。
- 不修改前端、收益结算、业务参数或钱包余额；仅恢复既有页面所依赖的读取合同。Sandbox 示例收益的 `period(null)` 仍为未知值。

## 验收

按本轮整体业务测试计划验证：空账户钱包读取成功、余额与真实钱包一致、累计收益及累计已付款为 0；有设备且配置不完整仍明确拒绝；未登录或跨环境用户仍被拒绝；已有收益账户保持真实金额。通过对应 App 钱包页面实际刷新验收。

当前仅完成源码及差异静态核对，尚未构建、部署或运行真实 E2E。构建及 TEST 实景验收由主 Agent 经 Jenkins 网页执行；本批不编写或运行单元测试或独立集成套件，不合并 main。
