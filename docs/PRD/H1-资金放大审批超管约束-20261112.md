## 规则

H1 资金放大类修改（本项为 `H1/h1_phase_dial` 的 A2 提案）只能由**另一位有效超级管理员**批准。判定“有效”以现有 `SuperAdminAuthorization` 的数据库事实为准：管理员未删除、`status=1`、`super_admin=1`；不读取前端隐藏按钮或显示角色。

- 发起人仍按其 `growth_h1_write` 和 A2 提案权限发起；不要求发起人本身是超管。
- 批准人必须同时具有 `platform_a2_operation_approve` 和当前 `growth_h1_write`，并通过现有 A2 的待审状态、可见范围、对象锁、非本人等校验。
- 本人批准仍在 H1 专属检查前返回原有 `A2_MAKER_CHECKER_REQUIRED`；驳回路径保持原样。
- 收紧方向、直接写入和其它 H1 操作不因本项扩大或改变；本次只补 H1 资金放大 **批准入口** 的身份硬约束。
- 不新增配置框架、角色授权、页面、文案或数据库表/列。

## 现版本缺口

当前 `AuditReplayBusinessPermissionGuard.validateDecisionPermission` 对 H1 `h1_phase_dial` 走通用分支：只要求 `platform_a2_operation_approve` 和 `growth_h1_write`，没有 SUPER_ADMIN 身份硬约束；`A2AccessPolicy.canDecide` 也只检查批准权和活跃管理员。因此，一个被授予批准权及 H1 业务写的非超管管理员可批准放大提案。现有 H1 没有类似 H3/H8 的 checker 类。

## 最小修复

1. 新增 `growth/application/H1GrowthApproval`：
   - `supports` 限定 `H` 域 `h1_phase_dial`；
   - `validateChecker` 要求当前认证检查人 ID 与调用人一致、`SuperAdminAuthorization.isSuperAdmin` 为真、具有 `platform_a2_operation_approve`；
   - 不复制 A2 的非本人、状态、锁、幂等或回执逻辑。
2. `AuditReplayBusinessPermissionGuard.validateDecisionPermission` 在 H1 进入普通业务权校验前调用该 checker；非超管批准返回 403 `H1_APPROVAL_FORBIDDEN`，不执行回放、不改配置、不写领域审计，票保持待审。
3. `validateOrdinaryProposalPermission` 继续校验 `growth_h1_write`；A2 `decisionQualification` 继续先校验非本人和待审状态；`OpsAuditCenterService` 的锁、幂等、回执和回放顺序不变。
4. 不把 H1 加入 `superAdminProposalCommand`（那会改变发起人身份/目标锁口径）；不加入 `AuditReplayDispatcher.specialized`（仍走原 H 域回放与企业目标校验）；不扩展 C5。

## 公共 TEST 最少整体业务场景（未来实现后执行）

固定三个不同角色，不能把发起人与尝试批准人混为一人：

- **M（maker）**：非超管，具有 `growth_h1_write` 和正常 A2 提案创建权；只负责提交放大方向的 `h1_phase_dial` 原票。
- **N（非超管批准人）**：与 M 不同，具有 `platform_a2_operation_approve` 和 `growth_h1_write`，并可见 H 域；用于验证 H1 专属超管约束。
- **S（有效超管）**：与 M、N 不同，实际 `SUPER_ADMIN` 且具有 A2 批准权和 `growth_h1_write`；用于验证合法批准。

若现有 TEST 没有合法的 N 账号，记录“前置缺失”，不得为其新授予角色、伪造超管身份或把 S 当 N；否则不能把 H1 拒绝分支记为已验。

1. M 从 H1 放大方向提交 `h1_phase_dial` 提案；确认票 pending、目标锁存在、当前配置/版本未变。
2. N 批准 M 的同一票：期望 HTTP 403 `H1_APPROVAL_FORBIDDEN`；票仍 pending，锁仍在，配置/版本/审计/事件不变。此步必须在 A2 非本人校验通过之后发生（N≠M），否则先得到 `A2_MAKER_CHECKER_REQUIRED`，测不到 H1 分支；不得以前端隐藏按钮代替。
3. S 批准 M 的原票：期望成功，目标月参数生效，领域审计/事件各一次；同批准键同体重放返回原回执，不重复回放。
4. 本人批准独立验证：若存在同时具备 A2 批准权的合法 M，M 批准自己的票仍返回 `A2_MAKER_CHECKER_REQUIRED`；若没有这样的合法账号，记录前置缺失，不授予权限，不把未执行描述为通过。驳回路径仍按原规则处理。
5. 数值型收紧/直接入口回归：不因本项新增 409 或改变原有 H1 直接写入和覆盖率检查；C5 和其它域不受影响。
6. 真实页面/HTTP/数据库由小6在公共 TEST 执行；本候选不声称通过。
