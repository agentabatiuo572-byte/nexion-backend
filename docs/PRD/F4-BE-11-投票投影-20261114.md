## 2. 当前事实（静态）

- F4 `GET /api/admin/teams/leadership-pool` 返回：
  - `currentWeekPoolUsd`：本周已结算时取实际 `weeklyInjectedUsd`，未结算时取 `weeklyGmvUsd × rate` 并以月剩余额度封顶（`LeadershipPoolProjection`）。
  - `participantCount`：当前 `leadershipRanks` 中 `v >= unlockRank && votes > 0` 的人数。
  - `topN/topSharePct`：头部集中度展示；`topSharePct` 用全部 ranks 票权（未按 unlock 过滤），不是派款金额。
  - `voteWeights`：仅 `v/votes/source`，来自正票等级；不含每级人数、总票、每票值。
- 正式 F4 结算 `LeadershipPoolService.settleTrusted`：
  - 用 `teamCommissionMapper.listLeadershipVoters(unlockRank)` 取当前自循环成员与票权；
  - 过滤 `votes>0`，`totalVotes` 为逐行票权之和；
  - 按 `poolAmountUsdt × votes / totalVotes`（6 位 DOWN，最后一人的 remainder）写 commission_event/ledger；
  - 审计 `F4_LEADERSHIP_POOL_SETTLED` 只记录 `poolAmountUsdt`、`totalVotes`、`settledUsers`、`week` 等**聚合**，没有每级人数/票数/每票值快照。
- 因此：
  - 当前未结算周的各等级人数/总票/每票值可由**当前正式资格**计算；
  - 已结算周只能用实际审计聚合得出总票/每票值；**每级已结算明细没有权威源**，不能拿当前 V 等级、当前票配置或最近分页反推。
- PC `assertF4Overview` 只检查原字段；未知字段不消费。页面不改；新投影不自动改变页面。

## 3. 实现（最小只读投影）

### 3.1 新管理 GET

`GET /api/admin/teams/leadership-pool/vote-projection`

- 权限：沿用原 `network_f4_read`；不新增权限、不扩大对象。
- 只读：不写配置/结算/派发/钱包/审计；不调用结算入口。
- 不进入原 F4 overview、不进入写回执；PC/App/H5/BI 不新增失败依赖。

### 3.2 当期估算（estimate）

仅当 `weeklySettledCount == 0`（本周尚未结算）且 `LeadershipPoolConfigGuard.requireValid()` 可读：

- 用与正式结算相同的 `leadershipVoterRanks(unlockRank)` 分组：
  - 同 `nx_team_member` 自循环行、`v_rank` V1–V8、`>= unlockRank`、`leadership_votes>0`、未删除；
  - 不做分页、不只取最近名单；按 rank/votes 全量分组。
- 返回：
  - `period:"CURRENT_WEEK"`、`currency:"USDT"`；
  - `poolUsd`：`LeadershipPoolProjection.amount`（本周估算，月剩余额度封顶）；
  - `eligibleCount`：各等级行数之和；
  - `totalVotes`：Σ `eligibleCount × votesPerMember`；
  - `perVoteUsd`：`poolUsd / totalVotes`，6 位 DOWN（指示性平均值；实际逐用户分配用同一 6 位 DOWN + 最后差额，可能有个别位差异）；
  - `ranks[]`：`rank`、`eligibleCount`、`votesPerMember`、`totalVotes`。
- 若本周已结算、配置不可读、无资格投票人、池为 0：`available:false` + `reason`（`CURRENT_WEEK_SETTLED`/`SETTLEMENT_CONFIG_UNAVAILABLE`/`NO_ELIGIBLE_VOTERS`/`NO_CURRENT_POOL`），不猜。

### 3.3 已结算（settled）

- 只读最新实际 `F4_LEADERSHIP_POOL_SETTLED` 审计（hot/archive）；
- 返回：
  - `available:true`、`period:"SETTLED_WEEK"`、`currency:"USDT"`；
  - `weekKey`：实际审计 resourceId；
  - `poolUsd`、`totalVotes`、`settledUsers`：审计聚合原值；
  - `perVoteUsd`：实际 `poolUsd / totalVotes`，6 位 DOWN（指示性平均）；
  - `ranks:null`、`ranksAvailability:"PER_RANK_NOT_RECORDED"`：**没有每级实际快照，不反推**。
- 无审计/审计不完整：`available:false`、`reason:"NO_SETTLEMENT_AUDIT"`。

不改 `currentWeekPoolUsd`/`participantCount`/`topSharePct`/`voteWeights` 原字段和值；不改 `LeadershipPoolService` 结算、状态、金额、头部限制、A2、权限、锁、幂等。

## 8. 2026-11-15 补充：`coverage` 段新增 `reliable`（F4-BE-15）

同一 `GET /api/admin/teams/leadership-pool`（权限 `network_f4_read`）的 `coverage` 段新增一个 additive 字段，取自本方法里**同一次** `coverageFacade.snapshot()`：

```json
"coverage": { "coverageRatio": 0, "redlinePct": 0, "reliable": false }
```

- 语义与 L3 的覆盖率可靠性一致（见 `docs/PRD/L3-BE-01-覆盖率估值可靠性-20261115.md`）：只有 `coverageRatio`、`redlinePct` 都解析成功且同一次 B1 快照 `valuationReliable=true` 时才为 `true`；快照缺失/不可解析或估值不可靠为 `false`。真实 0/0 且可靠时为 `true`，因此不能用数值是否为 0 判断未知。
- 不第二次读快照、不重算比率、不读价格/储备/负债；`coverageRatio`、`redlinePct` 原值与兜底行为不变，`coverageBelowRedline()` 与资金拦截口径不变。
- **既有写回执**：`leadershipPool()` 被六条写路径的成功响应复用，故这些路径在本次代码生效后产生的新成功回执，其 `coverage` 会多出 `reliable`：`F.pool.votes.V{n}`（`updateVRankVotes`）、`F.ambassador.{label}.status`（`updateAmbassadorStatus`）、`F.leaderboard.period.status`（`updateLeaderboardPeriodStatus`）、`F.quota.tier.{code}.monthlyQuota`（`updateQuotaTier`，其 `428`/`409` 的 data 也复用该读取）、`F.quota.usage.{id}.status`（`recycleQuotaUsage`）、`F.leaderboard.week.user.{userId}.status`（`updateLeaderboardMemberStatus`）。普通 UI 配置写走 `overview()`，不含该字段。
- 代码生效前已保存的旧成功回执没有该字段，按**未知**处理：不重写、不补读、不把缺失当 `false`；原键回放仍按原回执返回。
- 旧 PC 的 `normalizeF4` 只保留 `coverageRatio`/`redlinePct`，会忽略新字段，页面行为不变；`OperationConfirmModal` 仍只比较 raw 两值。本项不接页面、不改文案，页面接入需另改并验收。
