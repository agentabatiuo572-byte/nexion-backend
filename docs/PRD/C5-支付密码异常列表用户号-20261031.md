# C5 支付密码异常列表用户号查询修复

TEST 实景发现默认列表请求返回 500。原因是查询引用 `nx_user.user_no`，该物理列不存在；原 PIN 隔离测试曾虚构此列，未覆盖实际 schema。

列表和总数查询共同使用现有用户域规则 `U + LPAD(id, max(8, id位数), '0')` 派生展示编号，保留前导零及长编号。数字 id、完整 U 编号、昵称片段、完整手机号和原异常记录号仍可查询；不新增 user_no 数据列。查询显式关联异常外表用户 id，跨用户过滤不得匹配其他用户的昵称或手机号。

默认当前异常、全部/已解除/自然到期、业务日期首尾和分页应在实际 nx_user schema 下返回一致记录与总数。无截止时间的支付异常仍属当前异常；已到期锁定不混入当前列表。查询修复不解除锁定、不修改 PIN 或规则，不改变登录状态和外部免 PIN 范围。

真实 MySQL 回归直接读取仓库 `scripts/schema.sql` 的 nx_user DDL，明确断言不存在 user_no，覆盖默认空筛选 servlet 响应、数字/U编号/昵称/手机号/外人、状态、日期边界与分页。部署 TEST 后的页面复验由主任务另行记录。
