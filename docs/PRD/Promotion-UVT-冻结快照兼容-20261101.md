# 促销旧 UVT 资产快照的读取与执行

日期：2026-11-01。依据：本轮 BUG-010/旧NEX→UVT迁移独立复核的冻结促销快照缺口。

1. 旧已批准合同、政策、报价、订单预留及奖励的原始 JSON、hash、quoteID、业务单号、来源引用和金额保持不变。消费者必须先按原合同核实原hash，再把已验证的资产代码NEX投影为当前UVT语义。
2. 转换仅针对资产字段，以及促销规则buyerReward/inviterReward、award.reward内的奖励type。其他type、备注、来源引用、NEX前缀的业务ID不改；不扩大新建合同的可用枚举，新写入仍严格要求UVT。
3. 报价可用性、预留预算、新奖励入账、原账查询、历史奖励展示、reconcile和退款/追回均只查询或写入当前UVT资产行，不以SQL同时查NEX和UVT。旧冻结JSON不因执行而改写。
4. 历史奖励回读和reconcile先核snapshot_hash，不得因资产改名误判已发奖励“没有原账”；核对成功仍沿原状态规则，不补发或重复扣预算。旧订单回读保留原quoteID和支付金额，仅在核过原预留快照后投影奖励代码。
5. 新旧已批准纠正命令只允许原NEX到当前UVT的正向资产对应；篡改原快照、错误hash、未知资产或反向不一致保持拒绝。原权限、双人批准、原账及资金账务要求不变。

本轮候选、单元与隔离MySQL回归不代替TEST/原业务库副本实景。原复核者参与本修复后，不自签最终独立验收。
