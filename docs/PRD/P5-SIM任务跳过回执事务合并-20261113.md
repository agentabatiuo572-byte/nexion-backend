# P5 SIM 任务跳过回执事务合并

## 原行为与范围

`H3WeeklyParticipationEventConsumer` 只接收既有服务端可信的 `task.completed / COMPUTE_TASK` 事件。原实现先以独立事务 claim delivery，解析 payload 并要求正数 `user_id`，再将 `SIM-` 任务以独立写入标为 `SKIPPED / H3_RULE_CYCLE_INELIGIBLE`。所有 listener 正常返回后，dispatcher 另行写 outbox `PUBLISHED`；该分支至少经过三个写事务。

本批仅合并原已明确不合格的 SIM 分支中的 claim 与 SKIPPED，不扩展跳过范围。SIM 前缀仍按原 `aggregateId.trim().startsWith("SIM-")` 判断，payload 仍用原 ObjectMapper、Map 类型及 `positiveLong` 规则。预解析不合格或抛错时，继续原 claim 后的解析、FAILED/DEAD 与抛错路径；已有终态或未获 claim 的处理结果保留，不因预解析失败改变。

## 新行为与不变量

新增 `EventConsumerDeliveryService.claimSkipped`，沿用现有 `claimPendingBinding` 模式：外层 delivery 服务事务内执行原 claim，再且仅在 `claimed=true` 时，对同一 `consumerGroup/eventId` 调用原 markSkipped。claim 的 ensure、条件更新、行锁、attempt 增加规则、状态、超时与 reason 截断逻辑不改。未获 claim 时不写 SKIPPED，不覆盖其他持有者；原 SUCCESS/SKIPPED 幂等返回和其他未完成状态报错不改。

正常有效 SIM 首次处理仍保留一条 delivery，成功认领一次后为 `SKIPPED`，原原因、processed_at、next_retry_at/dead_at 清理等字段语义保留；重复终态事件不增加 attempt、不重写跳过回执。SIM 不生成 H3 资格事实或奖励，原金额、资格门槛、资金记录和幂等键不改。正向 NEX、其他任务和超出当前周的原处理保持原事务边界。

consumer 与 batch 不增加事务。dispatcher、outbox 发布、持久化、线程数、Hikari、单 JVM、600 秒任务及现有性能验收条件不改；outbox 仍须真实消费成功后才标 PUBLISHED。

## 异常与恢复边界

正常、重复和未获 claim 的业务结果保持不变。payload 无效仍按原 claimed 路径记录 FAILED/DEAD 并向外抛错；预解析的异常仅决定回到该路径，不吞掉最终处理异常。

claim+skip 的 SQL 或事务提交失败时，新外层事务将二者一起回滚，不会持久化本次 PROCESSING/attempt 增加；原实现此时可能已提交 claim 并再尝试 markFailure，故不宣称两者失败快照相同。这是事务合并的原子性目标。异常继续向 dispatcher 传播，仍由原 outbox 有界 retry/DEAD 承接；不会提前标 PUBLISHED。事务成功后、outbox 发布前中断，重投会看到原 SKIPPED 终态并按原幂等路径完成发布。
