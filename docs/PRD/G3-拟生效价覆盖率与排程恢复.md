# G3 拟生效价覆盖率与排程恢复

本节补充《Nexion 运营控制后台 PRD v3》G3 与 B1/D3 的服务端执行规则，对应 BUG-213、BUG-215 和 BUG-216。

- 周计划触发现有放大方向核验时，B1 以改后七帧的最高目标价重估。应急直写、钉帧、手动推进、自动推进会提高现价时，以实际拟发布的价格重估。
- B1 沿用 D3 储备和负债来源。对有效 UVT 锁仓，以本金与预计奖励的 UVT 合计乘拟生效价，其余负债按既有 USDT 口径计入。低于红线返回 `COVERAGE_BELOW_REDLINE`。估值不可用返回 `B1_COVERAGE_UNRELIABLE`。拒绝时保留原曲线、帧与价格。降低现价和原有非放大操作沿用既有规则。
- 服务启动时若没有排程配置，保持未配置。获授权的排程命令成功提交后，在当前进程按已保存的 cron 和时区安排后续推进。暂停、钉帧、循环／停末值和 UTC 执行日期幂等沿用既有规则。
- 缺少启用的非空排程时，`GET /curve` 返回空的排程 `value`、`rawValue` 和 `cronExpression`，读取不写入配置。BUG-286 起，首次合法排程须依照《G3-价格资金审批与首次排程-20261105》提交 A2，绑定未配置状态的 `scheduleRevision`，由另一位有权超管批准后启用；直接 `PATCH /curve/controls/schedule` 即使显式提交 `expectedValue: ""` 也返回 `G3_POLICY_APPROVAL_REQUIRED`。任一合法排程均可提案，包括「每日 00:00 UTC 自动推进」。缺失或 `null` 的 `expectedValue` 返回 `G3_EXPECTED_VALUE_REQUIRED`。排程已保存后的普通调整仍直接执行，旧空基准返回 `G3_STATE_CONFLICT`，基准匹配但同值仍返回 `G3_NO_CHANGES`，同一命令重试沿用现有幂等回执。
- 后台确认预览和缺排程时的页面可用性另行处理。涉及合规和已退役产品的既有限制继续适用。
