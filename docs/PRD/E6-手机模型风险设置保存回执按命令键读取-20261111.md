# E6 手机模型风险设置保存回执按命令键读取

## 问题

E6「手机模型风险设置」保存（`PUT /api/admin/config/phone-calibration/risk`，必须携带 `Idempotency-Key`）已按命令键幂等，但缺少按命令键读取原保存结果的只读接口：异常后无法在不重复写入、不依据当前配置推断的前提下核对原结果；且原有幂等记录未绑定发起管理员、原始路径与目标配置键，无法证明回执归属。

## 行为

- 风险保存改为服务端绑定命令来源：发起管理员（由认证身份派生）、原始方法与路径（由请求派生）、目标配置键 `phone_risk_settings`。回执持久保留，过期后仍可按命令键读取原结果。
- 新增只读接口 `GET /api/admin/config/phone-calibration/risk/receipts/by-key?commandKey=...`：
  - 要求登录且启用中的管理员，具备 `device_e6_read`。
  - 仅返回该命令键的持久原始保存结果与状态（命令标识：scope、命令键、原始方法/路径/目标、发起管理员、请求摘要、状态、原始响应中的 `settings`/`stats`），不执行写入、不读取当前设置、不据此推断结果。
  - 非发起管理员仅在符合既有恢复策略（超级管理员且具备 `platform_a2_unknown_investigate`）时可读取；其余一律 403。
  - 旧版未绑定来源的回执与不存在的命令键一律拒绝（409），不伪造来源。
  - 「成功」含 `SUCCEEDED` 与经通用调查确认的 `CONFIRMED_SUCCEEDED` 两种状态：两者均返回原始 `settings`/`stats`（原始响应未改写即返回），其它状态或响应不可读时原样返回空。
- 相同内容重复 `PUT`（同一命令键）仍返回原结果；同一命令键不同内容仍冲突，不重放。

## 整体业务验收

以具备 E6 读写权限的测试管理员保存一次风险设置，记录命令键；异常模拟/中断后按命令键读取回执，核对发起管理员、原始路径、目标配置键与状态为成功且结果与首次保存一致；再用相同内容重复 `PUT` 核对返回原结果、改内容重复 `PUT` 核对冲突；用另一无恢复权限的管理员读取核对 403。此处描述验收要求，实际结果以本轮业务证据为准。
