# B106 M3 客服圈选群发创建原号回执

创建回包丢失时，原操作人用原 `Idempotency-Key` 调用 `GET /api/admin/content/support-workbench/commands/{key}`。查询沿用批次读取权限，要求当前有客服对话读取权，或以主管身份拥有客服管理读取权。

- 找到原操作建成的批次时，返回 `data.status=SUCCEEDED` 和当前有权读取的 `data.result`。批次回执优先。批次内每位客户的发送结果仍以批次明细为准。
- 没有批次，且原操作已在领取命令后被明确拒绝时，返回 `data.status=FAILED`、原状态码 `data.businessCode` 和原原因码 `data.failureCode`。例如预览已过期返回 `409` 和 `SUPPORT_BULK_PREVIEW_EXPIRED`，空名单返回 `422` 和 `SUPPORT_BULK_SELECTION_EMPTY`。管理端沿用对 `FAILED` 的处理，解除冻结并保留输入。具体原因码可通过接口读取。
- 原命令在处理中，或只有技术故障、旧记录缺少可信拒绝回执等证据不足的情况，返回 `data.status=UNKNOWN`。当前操作人名下没有可查询的原命令或批次时，返回 `SUPPORT_COMMAND_NOT_FOUND`。

查询为只读操作。对已有可信拒绝的创建命令，同键同内容只返回原来的拒绝，重新确认后使用新命令号创建。同键异内容仍返回幂等冲突。取消、重试及其他客服命令回执沿用各自的规则。
