# G7 原成功命令回放优先于后发审批对象锁（B48 G7-BE-03）

- 来源：`uvel-docs/handoffs/2026-10-28/backend/20-backend-pending-20261031.md` G7-BE-03（34c02b0 新增）；与 G2/G3/G4 的幂等命中先返回约定对齐。
- 基线：`nexion-backend` `origin/test@dd5755ff`（公共 TEST #521）。
- 范围：只调整 `OpsRepurchaseAdminService.update` 的对象锁检查与幂等包装顺序。不改 G7 参数方向/单位/范围/回执/审计，不改 G7-BE-01/02、BUG425 列表保存、权限、前端。

## 1. 当前事实（基线静态核对）

- `OpsRepurchaseAdminService.update` 先做参数归一化、请求校验、业务权限检查，然后**在 `once(...)` 幂等包装之前**查询 `locks.countActiveByTarget("G", "repurchase_param", param)`；有活跃 A2 锁就 `409 OBJECT_LOCKED_BY_A2`。
- 原成功命令的幂等回执在 `once` 内部；如果同一幂等键已经成功，`once` 会直接返回原结果。但锁检查在它之前，后发待审票锁定同一参数后，原键重试会先撞锁，返回 409 而不是原回执。
- G2/G3/G4 的对应入口把锁检查放在幂等业务回调内（或由回放/业务服务在幂等命中之后执行），因此原成功键先返回。
- `once` 仍负责：同键同体 hash、原 actor/scope/目标/方法路径归属、失败/处理中/异体等既有幂等合同；`updateInternal` 负责参数方向/单位/范围、产品锁、A2 放大方向、覆盖率、落库、outbox、审计和回执。
- PUT `/api/admin/repurchase/config/{paramKey}` 与 PATCH `/api/admin/market/nex/repurchase/params/{paramKey}` 都调用同一个 `update`，本次修复对两条原键合同同时生效。

## 2. 修复口径

把对象锁检查从 `once` 之前移到 `once` 的现有业务回调内，紧跟幂等命中判断、在 `updateInternal` 之前：

- 原成功键同体：`once` 直接返回已保存的回执，不进入回调，因此不查后发锁；响应、原票号/键、审计、业务事实保持原样。
- 新键在活跃锁下：进入回调，先查锁，仍 `409 OBJECT_LOCKED_BY_A2`，不执行 `updateInternal`，不再次保存。
- 同键异体、不同 actor/scope/目标、方法/路径不符、失败/处理中：沿用 `once` 既有合同拒绝或隔离，不因顺序调整放行。
- A2 回放：`A2ReplayContext.isReplaying()` 为真时跳过本参数锁检查，和原实现一致；`G2G7ParamApproval.replay` 仍先校验自己的操作 ID、单对象锁归属、旧值和系数/单位，不把回放变成第二次保存。
- 不新增幂等框架、操作码/锁表、权限或页面字段；不改变 `updateInternal` 的参数方向、范围、覆盖率、outbox、审计和回执。

一次新键被锁拒绝会在现有幂等层留下失败记录；锁解除后同键同体可按现有失败重试机制恢复，同键异体按幂等冲突处理。这是既有幂等键语义，不新增行为。

## 3. 保持不变的合同

- 身份/原调用权限/业务权限：`requirePermission(PERMISSIONS.get(param))` 和控制器原权限不变；不放宽。
- 幂等：actor/scope/原目标/同键同体 hash/方法路径/原回执归属沿用现有 `once` 和 `AdminCommandOrigin` 合同。
- A2：另一超管批准、自批拒绝、对象锁/typed 旧值、方向/单位/范围/覆盖率/回执/审计不变。
- G7 两条入口（PUT/PATCH）使用同一个 `update`，都保留各自原键合同。
- 不混 G7-BE-01 锁详情字段、G7-BE-02 APY0/schema、BUG425 已验列表保存；不碰 F4/OpsTeamService/前端/TEST。

## 4. 前端接入影响

- 页面/文案不变。新键在活跃锁下仍收到原 `409 OBJECT_LOCKED_BY_A2`；原成功键的恢复会返回原回执而不是锁错误。页面不需要新增字段或改提示。
- 若页面同时保留原幂等键和原请求体，可直接恢复；换体/换人继续按原合同处理。

## 5. 公共 TEST 业务验收（未执行）

前置：合法 G7 管理员与 A2 提案/审批角色；不修改真实奖励率、不批准资金参数。没有合法样本/角色则记未验。

1. **原保存成功**：选一个可安全保存的 G7 参数（例如 APY 的**同值**保存，不改实际奖励率），带合法理由和幂等键 K1 提交成功，记录原回执、票号/键、原参数和审计。
2. **同对象后发待审**：用正常 A2 提案在同一参数上提交一个放大方向提案（例如 APY 提高），**不批准**，只让待审对象锁存在；核对锁为 `G/repurchase_param/{param}`。
3. **原键同体回放**：用 K1 和完全相同的 body 重试 → 应返回原成功回执，而不是 `409 OBJECT_LOCKED_BY_A2`；不新建票、不再次落库/发事件。
4. **新键仍拒锁**：用新幂等键提交一个合法新请求 → `409 OBJECT_LOCKED_BY_A2`，参数/审计不变。
5. **异体/换人**：同键换 body 或换操作者 → 按原幂等/权限合同拒绝或隔离，不泄露原回执、不再次保存。
6. **A2 回放**：如需，验证另一超管批准该待审提案时，A2 自有锁/旧值/系数/单位/覆盖率/回执/审计按原合同执行（本单不改回放）。
7. **收尾**：撤回自己创建的待审测试票，释放锁；原参数、审计和未批准的提案保持不生效。没有合法样本/角色时记录未验，不伪造丢响应、锁、票或审计。
