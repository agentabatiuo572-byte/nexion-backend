# G4 创世节点参数放大方向审批（A01、A02、A04～A08）

2026-11-11 · BUG-286 · 后端 · 口径依据产品 T11 补充（`uvel-docs/admin-console/decisions.md` T11-4）

## 生效规则

`PATCH /api/admin/market/nex/genesis/params/{paramKey}` 的写入按参数分别判定「放大资金流出」的方向，放大方向必须先取得 A2 双人审批票；收紧方向仍直接写入。A2 复用通用 `G/g4_genesis_param` 命令，不新增专用 op。

| 参数 | 编号 | 必须先审批 | 仍直接写 | 应付 Δ |
| --- | --- | --- | --- | --- |
| `supply` 节点总量 | A01 | 提高 ACTIVE 系列真实总量 | 降低或等额（仍受已售下限、100,000 上限与末档起点校验） | 0，只查当前覆盖率 |
| `price` 一级购买单价 | A02 | 提高系列单价 | 降低、等额 | 现存合格同系列持仓逐笔「新日分红 − 旧日分红」求和 |
| `royalty` 内部转售手续费 | A04 | 按生效的整数基点比较，降低 | 提高、等额、亚基点级变化 | 0，只查当前覆盖率 |
| `airdropPct` 释放分配占比 | A05 | 任何改动 | 无（等价改动被 `G4_GENESIS_PARAM_VALUE_INVALID`/无变化拦截） | 0 |
| `emissionCurve` 释放曲线 | A06 | 任何改动 | 无 | 0 |
| `airdropLockDays` OG 倍率锁仓期 | A07 | 任何改动 | 无 | 0 |
| `divBase` 每日收益基数公式 | A08 | 任何改动 | 无 | 0 |
| `showcaseEnabled` App 商城入口 | A09 | 不审批 | 展示开关保持直接写 | 不适用 |
| `dividend` 每日收益比例 | A03 | 见 `G4-分红审批与真实补发.md` | — | 见该文件 |

- 放大直写返回 `409 G4_GENESIS_PARAM_APPROVAL_REQUIRED`，不落库、不写审计、不产生业务事件。
- `royalty` 落库列为 `nx_genesis_series.royalty_bps`（INT），因此方向判定按 `pct × 100` `HALF_UP` 后的整数基点比较；`2.5% → 2.4999%` 这类亚基点改动不算放大。
- A05～A08 按产品口径视为说明性配置：修改走审批、不计应付，本次不为它们新增释放或公式执行功能；分红仍按 S01 固定公式（系列价 × 持有量 × 日比例）。
- 无 ACTIVE 系列的纯目录维护沿用原行为：不查覆盖率，开售那一刻再由独立闸门检查。

## 拟值覆盖率 Δ

不预测未来的量。审批时只把这次改动确定能算出的新增应付 Δ 加进应付款，检查「储备 ÷（应付 + Δ）」不破红线；算不出确定新增的，Δ 取 0，只查当前覆盖率。提案时算一次，批准回放时按当时的数据重算。

- `price` 的 Δ 与 G4-A03 同一算法：对现存合格同系列持仓逐笔计算新日分红减旧日分红，逐笔按 `HALF_UP` 保留六位后求和，负差计 0。
- A01 总量提高、A04 手续费降低、A05～A08 说明性配置的 Δ 均为 0。
- 覆盖率不可靠（`ratioReserveUsd`/`ratioLiabilitiesUsd` 缺失或 `redlinePct` 非正）返回 `503 B1_COVERAGE_UNRELIABLE`；Δ 计入后破线返回 `422 COVERAGE_BELOW_REDLINE`。

## A2 合同

- 复用既有通用命令：`command.domain=G`、`command.op=g4_genesis_param`，`sourceDomain=G4`，`obj` 与 `target.id` 为该参数键，客户端 `params` 只提供 `paramKey`、`value`（A05 airdropPct、A06 emissionCurve、A08 divBase 另提供 `decisionRef`）。发起与批准的业务权限按各参数原有直写权限校验（`finprod_g4_write`、`finprod_g4_price_write`、`finprod_g4_royalty_write`、`finprod_g4_airdrop_pct_write`、`finprod_g4_emission_curve_write`、`finprod_g4_airdrop_lock_days_write`）。
- 服务端专用 `G4ParamApproval` 在提案时绑定：发起人、规范拟值、旧值 `expectedValue`、现行系列 `expectedSeries`（`seriesId:seriesCode`）、可选 `decisionRef`。客户端不能提供旧值或系列。
- 提案预览与批准各按拟改值复核方向、当前旧值和现行系列，并按 T11 重算覆盖率；提案阶段破线或旧值/系列已变化即拒绝，不会把一次批准应用到另一条系列或另一个旧值上。
- 批准回放经 `G4AdminCommandService.updateParam`，保留原幂等键、`G4_GENESIS_PARAM_CHANGED` 领域审计、业务事件和 `decisionRef`；A05、A06、A08 的回放同样要求原直写入口的 `decisionRef`。
- 锁目标统一为 `{domain:"G",type:"genesis_param",id:paramKey}`；同一参数待审时再次提案返回 `409 OBJECT_ALREADY_PENDING`。

## 2026-11-12 真实业务复核（隔离完整 schema 候选库）

- A02 price：直写 `100→200` 返回 `409 G4_GENESIS_PARAM_APPROVAL_REQUIRED`；发起 A2 提案，另一位超管批准后落库 `200`，领域审计 1 条、`admin.genesis_param_changed` 事件 1 条；提案摘要显示「确定新增应付 Δ 0.100000 USDT」。
- A02 陈旧快照：待审期间把系列价改为 `110`，原批准键返回 `409 G4_GENESIS_PARAM_STALE`；恢复 `100` 后同一批准键、同一 body 成功。
- A02 覆盖率：把 B1 红线临时调到 1000% 后发起 `200→300` 提案，返回 `422 COVERAGE_BELOW_REDLINE`，未生成工单。
- A01 supply：直写 `1000→1100` 返回 409；另一超管批准后总量 `1100`，领域审计与事件各 1 条。发起人自批返回 `403 A2_MAKER_CHECKER_REQUIRED`。
- A04 royalty：`3%→2%` 直写 409、A2 批准后落库 `200 bps`；`3%` 提高方向直接生效。
- A05 airdropPct：直写 `8→9` 返回 409；A2 提案（带 `decisionRef`）批准后配置为 `9`。
- 对象锁：royalty 待审时再次对同一参数提案返回 `409 OBJECT_ALREADY_PENDING`。
- 非超管/无业务权限审批人被拒绝由 `G2G7_PARAM_APPROVAL_FORBIDDEN`/`A2_MAKER_CHECKER_REQUIRED` 共用路径覆盖；G4 自批已实测。
- 未逐项实测：A06 emissionCurve、A07 airdropLockDays、A08 divBase 的批准回放；A03 dividend 仍走原 `G4DividendApproval`，不在本批重验。PC 未接入新合同、公共 TEST 未部署。
