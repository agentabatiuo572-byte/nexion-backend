## 2026-11-17 L5-BE-03：当前状态生产与历史兼容

当前导出在请求内同步准备并保存创建时快照。`OpsBiService.createReportOnce` 对允许的高敏财务明细写入 `PENDING_CONFIRM`，其它允许的聚合导出写入 `READY`；现有团队树与监管报告的独立创建链也写入 `READY`。本条仅说明现行状态来源，不改变各入口的权限、范围或放行政策。

| 状态 | 当前合同 |
| --- | --- |
| `READY` | 当前创建或合法放行后的可下载状态；签发和使用下载令牌仍要求真实快照及原访问权限 |
| `PENDING_CONFIRM` | 当前高敏财务明细创建后的待放行状态；创建时快照已同步保存，另一管理员批准后转为 `READY` |
| `PENDING_SPLIT_CONFIRM` | 历史兼容状态，现行创建和状态切换不生产它；已有记录仍按原双人批准规则处理，合法批准后转为 `READY`，不表示当前有拆分生成流程 |
| `GENERATING` | 历史兼容状态，当前无将任务置为该状态的生产链或随后自动生成文件的 worker，不承诺等待后自行变为可下载 |
| `EXPIRED` | 历史兼容状态，当前没有报告到期置为该状态的转换；下载令牌到期与此报告状态无关 |
| `FAILED` | 历史兼容状态；当前同步生成、存储或必需审计的异常向上传播并沿原事务回滚，不另落一条 `FAILED` 报告 |

四个历史状态继续保留在原枚举、列表筛选和排序中，不删除或改写存量记录；当前正常业务未生产这四个状态，历史记录仍可能被读取。原 `GENERATE` / `RERUN` 动作要求已存在快照，只按敏感性切到 `PENDING_CONFIRM` 或 `READY`，不重新生成快照或启动异步任务；历史记录能否操作仍取决于原类型、快照、权限和批准身份检查。

## 保留时点与下载令牌的区别

- 报告记录及快照元数据没有按上述状态或创建时间配置的自动到期、定时删除路径。当前应用层不按天数清除这些历史状态，也不在 24 小时后将报告改成 `EXPIRED`；列表只按原类型、`is_deleted` 和显式筛选读取，没有年龄淘汰条件。查询可见性不代表物理删除或保留保证。
- `downloadToken` 从签发时起有效 24 小时；校验要求 `expires_at > now`，到期即不能使用。到期 grant 的物理删除由后续签发时的 `deleteExpiredGrants` 触发，不保证恰在到期时执行；不删除报告、快照元数据或文件，满足原条件的 `READY` 报告仍可重新签发令牌。
- 对象存储只沿原失败事务清理回调移除本次未提交对象，没有为已提交快照设置年龄清理。独立旧 mock 数据清理脚本按特定标记软删除匹配报告，不是报告保留定时器；本条不执行该脚本，也不将它用于正常报告。
- 当前源码没有提供已提交报告和文件的固定物理保留天数或外部存储清理时点。本合同明确应用层无自动淘汰的现状，不新定保留期限，不承诺永久保存，也不追认未核实的数据库运维或对象存储生命周期政策。

本次仅补既有后端合同，无 Java、SQL、状态枚举、文件生成或保留政策改动；不修改下发说明和客户端，未执行实际启动、E2E、HTTP、数据库、导出或部署验证。

### B80 PC 复核后的 Java 导出规则

- B80 迁移为 `SUPPORT` 角色补发 S、D 基础码，实际资格和范围仍逐次核对。普通在任客服仅可导出自己的汇总，在任主管按当前负责组导出，无组主管不可导出，额外审批权 A 仍须显式授予。本人列表、详情、原键回执使用同一摘要权限。撤回待审任务仍按本人当前写权单独判定。
- 一次预检只使用一份发布代。事实代超过两分钟或刷新增量失败会阻止新申请，可以保留有证的旧代行数。整源无法读时返回 `503 EXPORT_SOURCE_UNAVAILABLE`。单个有权所选类型读取失败时整包仍可读，该类型标 `READ_FAILED`，行数为空。重复类型、非法范围或重复组 ID 返回 422。创建、决定和撤回统一按公共 NFC 可见字符规则核理由，原输入留痕。
- 按原键查回使用 `GET E/command-receipt`（创建）或 `GET E/{taskId}/command-receipt?command=DECISION|WITHDRAW`，通过 `Idempotency-Key` 请求头传原键，区分大小写，并限定原操作者和原动作。它可返回已受理结果、处理中、已持久化失败或 `UNKNOWN`。缺回执或回执过期须待确认。普通命令记录期限为 24 小时，成功冻结回执可在任务业务记录仍可见时继续核对。单次下载凭证保留 24 小时，文件保留 7 天，缺少令牌返回 `403 EXPORT_TOKEN_REQUIRED`。
- 异人批准后先返回已批准版本，后台再复核与生成。原因、决定和原键记录持久化，生成失败保留批准痕迹。下载继续复核本人任职、当前权限及文件中可识别客户的读取范围。
