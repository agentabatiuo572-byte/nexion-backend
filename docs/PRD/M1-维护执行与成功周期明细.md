# M1 维护执行与成功周期明细

客服从工作台的「维护进展」核对整个统计期间，从「维护趋势」核对选中业务日。每次成功提交的维护按执行时间计一次。同一周期内两次执行产生两条执行明细。周期只有进入 `SUCCEEDED` 才按关闭时间计一次，跨日完成计在关闭日。成功客户数仍按客户去重，暂停主动维护仍按当前绑定客户计数。

## 维护发送到期校验（BUG-164，2026-11-04）

依据客服中心决定 M-C23，HTTP 与 WebSocket 的人工 `MAINTENANCE` 消息均在同一后端执行入口校验到期。客户必须仍归发送客服、维护开启且已配置维护天数。当前绑定尚无维护执行时允许首次维护；已有执行时，下次到期为当前绑定最后执行时间与最后成功周期时间的较晚者，加现行维护天数。到期时刻可发送，未到期或规则未配置返回 409 `SUPPORT_MAINTENANCE_NOT_DUE`；暂停维护仍返回 `SUPPORT_MAINTENANCE_STOPPED`。发送与工作台下次维护时间共用计算表达式。

校验失败会回滚本次消息、附件关联、维护执行和周期写入。成功消息的同键回执继续幂等返回，不因首次发送后尚未再次到期而拒绝重放。普通 `SERVICE` 消息不受维护到期限制；权限及当前绑定校验仍适用于重放。

工作台客户列表现有 `GET /api/admin/content/support-workbench/customers` 支持 `pageNum`、`pageSize`（1–100）及 `customers.total`，每页同回执更新卡片和客户列表。`snapshotId` 只是本次回执标识，不是可复用查询版本；翻页须按现有实时分页合同处理，不能伪造稳定 `queryVersion`。BUG-164 登记的 PC 无版本列表完整性、可接待客服卡无名单入口、个人资金下钻口径及 M3 深链问题继续按现版本跟踪，本次不改页面。

## 期间净贡献和首充来源明细（BUG-164，2026-11-04）

`GET /api/admin/content/support-workbench/analytics` 增加以下只读 `view`，保留 `FINANCE` 原有充值、购机、退款等支付流水语义。原始支付流水不得相加冒充新增净贡献，也不得作为唯一首充明细。

| `view` | 金额与计数口径 |
|---|---|
| `NET_CONTRIBUTIONS` | 现有资金贡献引擎已验证的期间带符号变动，按贡献形成时的客服与组归属。充值后余额消费不重复贡献，跨期退款或本金提现的负数按真实成功期间计入。合计对应 `scopeSummary.financial.currencies[].net.confirmed`。 |
| `FIRST_DEPOSITS` | 客户终身唯一且历史已证明的首笔充值事实，在所查期间、币种和事件时归属内。金额对应 `firstSources[].deposits.confirmed`，每条对应一名客户。 |
| `FIRST_PURCHASES` | 同上，但只取唯一首事件为实付购机的客户。金额对应 `firstSources[].purchases.confirmed`，每条对应一名客户。 |

三个视图均要求 `basis=PERIOD_EVENT`、UTC `from`/`to` 和单一 `currency`。沿用获准的 `groupId`/`agentId`；`category`、`firstState`、`filter` 须为 `ALL`，不接收关键词，以保证与原期间汇总对账。错误组合返回 422 `SUPPORT_ANALYTICS_DETAIL_QUERY_INVALID`。默认按成功时间倒序，允许 `SUCCEEDED_AT`、`AMOUNT` 排序。沿用 `pageNum`、1–100 的 `pageSize` 与现有 `queryVersion`；后页传同视图第一页的 `expectedVersion`，不能拿其他视图版本继续。未完成的来源版本仍标 `UNKNOWN`，不提供稳定续页。

`records` 仅返回当前客户读取范围内的事实：稳定不透明 `id`、客户编号与名称、`kind`、币种、精确十进制 `amount`、`succeededAt`、原 `agentId`/`groupId`。净贡献金额保留负号。同一贡献来源、同一资金事件消耗多个内部资金份额时，先精确合并金额再形成一条记录，例如两笔收益 10 和 20 共同支付一次 30 的消费，返回一条金额 30 的贡献事件。`totalCount`、`visibleCount`、`restrictedCount` 均按合并后的贡献资金事件计数，不按内部份额计数。合并后的金额参与金额排序；同时间或同金额继续按客户编号和稳定记录 ID 排序，再分页。内部来源证明、账本证据和原始引用不暴露为记录 ID。

`detailSummary` 返回 `status`、`observedAmount`、已确认 `totalAmount`、当前可见 `visibleAmount`、转出受限 `restrictedAmount`，满足可见金额加受限金额等于已确认金额；另返回 `totalCount`、`visibleCount`、`restrictedCount` 以及对应去重 `customerCount`、`visibleCustomerCount`、`restrictedCustomerCount`。金额和计数都统计完整查询全集，不从当前页求和。首充明细的条数等于客户数；同币种两类首充客户数之和对应原期间首充已确认客户数。`PARTIAL` 仍只对账已确认部分，`observedAmount` 与已确认金额分列，不把未知历史计为零。

原期间仍计入、但客户已转出当前读取范围的事实只给上述合并计数与金额，不返回客户、事实、原客服/组、时间或来源标识。净贡献证据不足或无法与已确认汇总对账时返回 503 `SUPPORT_ANALYTICS_SOURCE_UNAVAILABLE`；首充未证明的候选不列入已确认明细。每次读取和续页继续重校当前权限与范围。

PC 后续应将个人净贡献、充值首充金额、购机首充金额分别接到对应新视图，展示受限部分并按返回版本翻页。本次仅补后端读取能力，PC 的现有点击行为仍属于 BUG-164 待修范围。

统计缓存编译与直接读取一样，仅按净贡献来源的付款事实 ID 读取归属证明。退款事实仍参与原资金重放与负数贡献，不作为新的贡献来源证明混入；不得因多余退款证明将已完整核实的净贡献误判为未知。

## 查询

`GET /api/admin/content/support-workbench/performance/details`。调用方沿用工作台的 `mode`、`groupId`、`agentId`。从同一回执取 `performance.from`、`performance.to`、`performance.scopeVersion` 和顶层 `evaluatedAt`，原样传入。

| 参数 | 业务含义 |
|---|---|
| `metric` | `EXECUTION` 查执行记录，`SUCCESSFUL_CYCLE` 查成功周期。 |
| `from`、`to`、`evaluatedAt` | UTC 时刻。期间含起点、不含终点，事实时间不晚于工作台统计截止点。 |
| `scopeVersion`、`expectedTotal` | 必填。传工作台返回的范围版本及点选数字。期间数字取自 `performance`，某天的数字取自 `performance.days` 对应日期的 `executionCount` 或 `successfulCycleCount`。 |
| `day` | 可选业务日期，格式为 `YYYY-MM-DD`。未传时查整个期间。传入时按工作台的业务日历取该日与原期间的交集。 |
| `pageNum`、`pageSize`、`expectedQueryVersion` | 默认第 1 页、每页 20 条，允许 1–100 条。后页回传第一页的 `queryVersion`，保持页大小。记录先按事实时间倒序，同一时刻按事实 ID 倒序。 |

响应的 `windowFrom` 和 `windowTo` 是所查期间或日期的实际 UTC 边界，相邻业务日共享同一边界。选中日期时，`timeZone` 为该业务日生效的时区。查询整个期间时，它与工作台一致，表示期间起点的时区。可见记录包含事实 ID、客户 ID、原执行客服、绑定和周期 ID。执行行返回 `executedAt` 与 `messageId`，成功周期行返回 `closedAt` 与 `successEventId`。

期间可传含纳秒的 UTC 时间。数据库事实精确到微秒。若某条执行恰在 `T`，则 `[T, T+1ns)` 含该条，`[T+1ns, T+1µs)` 不含该条，工作台与明细遵循同一规则。

## 权限与对账

两个指标都以原工作台的客服当前成员范围选历史事实。专属客服查本人，主管查当前负责组，总管理员按获准范围查询。明细还要核对当前客户权限。客户转出查询范围后，归属原客服的历史记录仍计入 `total`，仅在 `restrictedCount` 中体现。响应不返回这些记录的客户、事实 ID 或逐笔时间。

每次查询的 `visibleCount` 是可逐笔查看的总条数，`records` 只包含当前页，满足 `visibleCount + restrictedCount = total`。按日查询时，`total` 对应趋势图当天的同一指标。不传日期时，`total` 对应期间总数。真实零返回空列表。读取或权限失败须向调用方报告，不能用空列表代替失败。若原数字或版本失效，接口返回 409 `SUPPORT_PERFORMANCE_VERSION_CHANGED`，客户端重新取工作台和第一页。后页未传查询版本返回 422 `SUPPORT_PERFORMANCE_VERSION_REQUIRED`。

缺少 `metric`、`from`、`to`、`evaluatedAt`、`scopeVersion` 或 `expectedTotal` 均返回 400 `REQUEST_PARAMETER_REQUIRED`。无权使用的模式返回 403，指定当前范围外的组或客服返回 404。
