# F3-BE-05:分组分配时间的存储区带偏移投影

## 1. 问题与范围

F3 管理端成员分组读取 `GET /api/admin/teams/binary/assignments` 返回 `assignedAt`(`LocalDateTime`),序列化为 `yyyy-MM-dd HH:mm:ss`,没有偏移。`nx_binary_leg_assignment.assigned_at` 是 `DATETIME`;页面按“北京时间”解释,但 A3 业务时区可改,页面写法不能跟随。

本候选:

- 保留旧 `assignedAt` 原样;
- 在管理专属 `AssignmentMemberRow` 增加可空 `assignedAtIso`(ISO-8601 带 `+08:00` 偏移);
- 不改写入、表、历史值、权限、对象范围、App/BI/写回执或页面。

## 2. 时基与来源

### 2.1 字段与写入

- 表:`scripts/migrations/20260722_f3_binary_settlement.sql:4-22`,`assigned_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`。
- 全部生产写入:
  - 手动 `BinaryCommissionSettlementService.assignLeg` → `insertAssignment`(`:93-102`);
  - 自动补位 `autoPlaceMissing` → 同一 `insertAssignment`(`:475-487`);
  - SQL `assigned_at=NOW()`,不是应用 `LocalDateTime.now()`。
- 没有生产 seed/更新 assigned_at;列只有本表 F3 写入。
- 读取:`BinaryCommissionSettlementMapper.listAssignmentMembers` 返回 `assigned_at assignedAt`(`:38-55`);接口 `OpsBinarySettlementController.assignments`(`:31-43`)只要求 `network_f3_read` + 已认证 ADMIN,按 `ownerUserId` 范围。

### 2.2 存储区

- `BusinessCalendar.STORAGE_ZONE = Asia/Shanghai`(`shared/config/BusinessCalendar.java:27-28`),注释明确 storage 保持北京时间固定 +08,业务日历只切日/周/月。
- `DateTimeFormatConfig.BUSINESS_ZONE = Asia/Shanghai`(`:16`),全局 LocalDateTime 序列化格式 `yyyy-MM-dd HH:mm:ss`(`:18-26`)。
- Hikari 默认每个池连接 `SET time_zone='+08:00'`(`application.yml:37`),JDBC 默认 `serverTimezone=Asia/Shanghai`(`:29`);prod 只覆盖 URL/账号/密码,不覆盖 Hikari init(`application-prod.yml:4-10`)。
- 因此源码合同下,`assigned_at` 的 `NOW()` 值按 Asia/Shanghai 墙钟写入;`assignedAtIso` 用 `atZone(STORAGE_ZONE).toOffsetDateTime()` 生成同一存储区偏移。

**未证**:当前部署池的连接 `time_zone`/`assigned_at` 历史值没有在本单独立采样;root 的新诊断会话 UTC 不能反推应用池,不能据此改合同。若部署覆盖 Hikari init、存在手工 SQL 写入或旧数据来自其它会话,`assignedAtIso` 仍可能按 code contract 解释而实际不同。当前先用源码合同;公共 TEST 需只读核对自然行。A3 业务时区变更不改变 storage instant,只影响业务日/展示;本字段保持存储区偏移。

## 3. 实现

`BinaryCommissionSettlementMapper.AssignmentMemberRow` 增加:

```java
@JsonProperty("assignedAtIso")
public String assignedAtIso() {
    return assignedAt == null ? null
            : assignedAt.atZone(BusinessCalendar.STORAGE_ZONE).toOffsetDateTime().toString();
}
```

- 旧 `assignedAt` record component及序列化不变;
- `null`/UNASSIGNED 行保持 null;
- 不补 00:00/当前时间/0;
- 不新增列、query、SQL 或写侧快照;
- `AssignmentMemberRow` 仅管理端 F3 `AssignmentPage` 使用;App `AppTeamNetworkMapper.MemberRow`/BI/写回执不引用该 record,新字段不会带给 App/写回执;
- 权限/HTTP/方法/服务读权不变;PC 仍使用旧字段并保持冻结文案。

## 4. 兼容性/边界

- API 只增加 `assignedAtIso`(string|null),旧字段、顺序和其他字段不变。
- `assignmentSource`、leg、owner/member userId、分页、count、status 过滤、owner 范围不变。
- 旧 `assignedAt` 无偏移仍存在;新字段不替代,不静默改变共享格式。
- 历史值不重写;没有新历史快照/DDL。
- 不改 F3 分组执行、归零/周期、奖励、账本、权限、A3 时区配置;BUG-198 归零周期文字与本项独立。
- A3 改业务时区:新字段仍是存储 instant;若 PC 需按新业务时区显示,应消费新字段后自行格式化,不能把 storage 偏移当业务时区。
