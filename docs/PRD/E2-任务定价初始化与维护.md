# E2 任务定价初始化与维护

## 启动初始化

任务奖励下限或上限为 0 是已保存的有效配置。应用重启与整库安装保留已有奖励、模型、最低显存和停派状态。Java 只对旧表刚扩列时模型与显存均为空的规范任务补默认值，沿用该行原来的任务状态和停派值。

Bash 与 PowerShell 都在任务目录建好后执行 E2 初始数据脚本。只有某类从未配置正式任务时才补该类的规范默认任务。已有正式任务优先保留，包括由非规范 ID 提供的定价。历史软删除记录保留。手机档位继续从 `nx_onboarding_phone_tier_config` 读取。

## 通用任务维护

通用任务新增、更新和删除在写入前比较 App 生效定价及真实派发配置。比较覆盖规范任务、替换后的后备任务、不同显存门槛实际选中的任务和已配置的 TEST Cloud V1 绑定。提高实际奖励、降低有效门槛、恢复可派发资格或提高派发奖励速率时，直写返回 `409 A2_CONFIRMATION_REQUIRED`。收紧及等价的通用维护仍按各入口原有授权执行。

有 E2 写权限的运营可用现有 A2 任务提案请求，也可提交 `E/e2_task_lifecycle_change`。专用请求用 `sourceDomain=E2`，`target` 为 `E/e2_task_lifecycle`，目标 ID 为现有任务 ID 或 `new-<任务类>`。`params.values` 提供 `action` 和原目录字段，更新和删除提供 `taskId`。服务端计算并绑定实际影响。另一位有 A2 审批权限的超管批准时复核当前配置和 B1 红线。待审期间 App 继续读当前配置，已领取任务保留发放时的奖励快照。配置改变导致审核快照失效时返回 `409 E2_TASK_PRICING_STALE`，需重提。升级前的通用票若按现值判断为放宽，须按新审核范围重提。

原 E2 停止与恢复派发、模拟任务审批和启动默认数据继续使用各自入口。
