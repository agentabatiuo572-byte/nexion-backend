## K1-A09 收益审核规则

- 直接入口：`PATCH /api/admin/risk/multi-account/release-params/{key}`，权限 `risk_k1_cluster_release`。
- 保留 `duplicateAccountPendingFrom` 2–50、`duplicateAccountFreezeFrom` 1–50、`pending≤freeze`、manual_only 与退役 key 的 410；收紧和同值仍直接保存。提高两个阈值属于放宽，新直写返回 `409 K1_RELEASE_PARAM_APPROVAL_REQUIRED`，值和 version 不变。
- A2 提案：`domain=K`、`op=k1_release_param`、`sourceDomain=K1`、`type=fund`，target 为 `{domain:"K",type:"release_param",id:key}`，values 为 `key/value/expectedVersion`。服务端 before 包含 `key/value/version/values` 完整快照；待审不写业务值。
- 另一名有 `platform_a2_operation_approve` 的有效超管批准时，重读 version 和完整 before；不符返回 `409 K1_RELEASE_PARAM_STALE`。复核范围、阈值关系、放宽方向及现有精确 B1，再复用正式写入；值、version 和业务审计只写一次。
- 待审同目标的重复提案继续受 A2 对象锁保护；待审期间原直接入口仍允许合法收紧/同值保存，不为待审新增直写锁。保存使版本/快照变化后，旧提案按陈旧保护拒绝，需按现行流程结束旧票并重新提案。
- 新 409 门位于原幂等回读之后；历史直写成功键以原 body 恢复原成功，不重复改值/version，新提案/批准键重放也不重复生效。

## K1-A11 人工放行收益

- 直接入口：`POST /api/admin/risk/multi-account/releases/{entryNo}/manual`，权限 `risk_k1_cluster_release`。新直放返回 `409 K1_EARNINGS_RELEASE_APPROVAL_REQUIRED`，无紧急直放旁路；原成功键仍按已有幂等记录恢复。
- A2 提案：`domain=K`、`op=k1_earnings_release`、`sourceDomain=K1`、`type=fund`，target 为 `{domain:"K",type:"earnings_release",id:entryNo}`，values 为 `entryNo`。
- before 使用完整 `RecoveryEntry` 投影，包含 `entryNo/userId/sourceType/sourceRef/sourceEnvironment/asset/grossAmount/recoveredAmount/netAmount/bucket/status`；不能用只带净额且缺少来源的 `lockProtectedEntry` 代替。部分追回、来源/环境、保护状态或净额改变，旧票按陈旧/保护状态拒绝，不以新净额覆盖原提案。
- 批准保持用户→钱包→source 锁顺序，同一事务锁 entry 比较完整 before，再复用正式 `manualReleaseOnce` 的保护校验、精确 B1 和资金投影。仅将原 entry 的 bucket 改为 `withdrawable`，保留一条 `K1_EARNINGS_MANUALLY_RELEASED` 业务审计；不新入账、不新发奖、不生成提现单。
- 不新增原服务没有的 frozen-account/cluster 放行拒绝；bucket 改变不表示已可提交提现，账户、簇和钱包限制继续由后续提现链执行。

## A2 权限、原键与恢复

- 发起人须具当前 `risk_k1_cluster_release` 及 `platform_a2_proposal_create` / `platform_a2_write` 之一；批准人须为另一名有效超管且具当前批准权限，自批拒绝。
- K1 纳入专用提案绑定、服务端 proposalReason、source/target、roleGate、对象锁、回放和 decisionDetail。绑定 before 由服务端读取，不信任客户端 before 或 maker。
- 本人原键 GET 与业务原票恢复仅允许原 maker 且当前仍具上述精确权限组合；他人、错域/错目标、失去业务权或提案资格均不得借其他域写权恢复。无需给发起人额外全局 A2 读权。
- 合并时保留后发 H4 的 `authorityGranted` / `growth_h4_read` 恢复分支，并在当前 H1/H4/G4 原键 GET 权限组合上追加 K1 精确组合，避免整段旧实现覆盖。
