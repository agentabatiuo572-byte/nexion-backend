# BE27 H5 Lite 独立 TEST 入口

2026-11-08，用户已批准已有 `h5-lite` 分支独立发布至
`https://18.142.169.24/h5-lite/`。本条记录发布能力约定；代码、构建、部署、
静态入口与真实业务验收分别记录，未完成的步骤不记通过。

H5 Lite 的 TEST 来源固定为 `nexion-frontend-uniapp` 的 `h5-lite`；独立任务为
`nexgrid-h5lite-test`，制品为 `h5lite-h5-build.tgz`。现有后端、PC、App H5
继续只取各自 `test`。不合产品 main，不构建 APK，不新增 App 导航，不修改
预览关闭按钮／safe-top 样式、登录、MFA、CORS、账号等级、权限或业务数据。

公开入口只增加 `/h5-lite` 到 `/h5-lite/` 的规范跳转及该前缀的静态代理；
Lite 构建资源均使用 `/h5-lite/` 基址，业务仍访问原根 `/api`、`/auth`、
`/ws`。不得占用 App `/app/` 或根 assets/static。两端同源，会共用同源存储和
刷新 cookie，验收使用独立浏览器身份或串行同一获准用户，不清其他会话。

Lite 复用受信 owner 发布路径、制品摘要及安全解包、非 root 只读静态容器、
当前分支头校验、锁／事务日志／保留与回退。使用独立 8084/8085 回环槽、
`/srv/nexgrid/cd/h5lite` 发布目录及自己的 state/promotion；现场必须重新核实
端口。Jenkins SUCCESS 只代表制品就绪，不代表已公开发布。

构建必须先经现有官方 `admit-build h5lite 实际构建号` 独立预约；不得借用
App／uniapp 额度。永久退休主机的原三项封存预算与 retirement 回执保持原字节，
仅已批准 `CI_10_GIB` 有效运行配置增加 Lite 的10GiB请求，共用单一10GiB构建
总额和20%主机保留门禁。发布／回退仍经官方 drain 与成功后的 resume-release。
旧 compute-v2-ci-maintenance 入口保持永久退休，不重新启用、不要求 Lite main job。

首发前状态必须如实表示无旧 Lite 发布，不能拿 App 充当旧 Lite。首次
rollback-check 实际切换并恢复原 nginx／404，无需伪造旧健康服务；首发失败
同样恢复无入口状态并停止、移除该 Lite 候选。首发 deploy 必须匹配同 SHA、
build 的真实回退证明。成功后才能形成自己的旧健康容器；后续失败只回退
Lite，不触碰已有 App／PC／后端服务。中断或恢复不确定保留日志并停止切换。

已有主机升级需先核实安装的完整受信 closure，按已审核不可变 commit 和外部
独立摘要，只替换明确改动的文件／pin；其他已安装文件不得被仓库旧示例覆盖。
具体安装、初始空状态和现场依赖见
[部署说明](../../deploy/public-test/README-h5lite-test.md)。当前候选尚未安装、
构建或发布；正常 TLS 入口、真实登录、材料上传／取消／补交／刷新、终态只读
与私有文件回读仍须由本轮正式 TEST 实景验收，不以 App H5 或本地预览代签。
