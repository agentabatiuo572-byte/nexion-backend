# G7 快捷金额列表保存修复（候选 PRD）

基线：backend/test `99d808bd`。只修 BUG-425 后端候选；不改前端、页面文案、权限或 TEST。

## 现象与根因

- PC 通过 `PATCH /api/admin/market/nex/repurchase/params/presets` 保存多个快捷金额（如 `100 / 200 / 500`）。
- `OpsRepurchaseAdminService.updateInternal` 先 `normalizeValue("presets", ...)` 得到列表，随后无条件 `amplifies(key, decimal(before), decimal(after))`；`decimal` 把整个列表串当单个数字，返回 `422 G7_NUMBER_INVALID`，正式存储 `updatePresets` 走不到。

## 最小修复

- 仅 `presets` 不进入数值方向比较：`boolean amplifies = !"presets".equals(key) && amplifies(key, decimal(before), decimal(after));`
- `normalizeValue` 的列表拆分、去重、排序、最多 12 项、正数、两位小数、`G7_PRESETS_INVALID` 保持。
- 直接走既有 `mapper.updatePresets(after)`，不改存储列、审计、事件、权限、A2 待审锁、幂等或原命令回执。
- 其他数值参数（apy/nurture/penalty/lockDays/lottery）仍按原解析和方向判断；不收窄/扩大其他输入。
