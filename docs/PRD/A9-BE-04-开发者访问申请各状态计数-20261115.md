# A9-BE-04 开发者访问申请各状态计数（管理端最小后端候选）

日期：2026-11-15
范围：后端管理端 `GET /api/admin/developer/access-requests` 只读响应追加 `statusCounts`；不含 PC/App/H5 页面改动。

## 1. 背景

当前接口返回 `PageResult`（`total/pageNum/pageSize/records`），`total` 受当前 `status` 筛选影响。运营在「待审批」页签看不到已批准、已驳回、已撤销、已过期的数量；本候选只补五项状态计数，不改变原列表/分页/筛选。

## 2. 接口合同

`GET /api/admin/developer/access-requests?pageNum&pageSize&status&keyword&sourceEnvironment`

- 读权保持：`developer_access_read` 或 `ROLE_SUPER_ADMIN`；不扩权、不改申请人和 App 范围。
- `status` 仍只接受 `PENDING`、`APPROVED`、`REJECTED`、`REVOKED`、`EXPIRED`；非法值仍 422 `DEVELOPER_ACCESS_STATUS_INVALID`。
- `sourceEnvironment` 仍只接受 `PRODUCTION`、`SANDBOX`；非法值仍 422 `DEVELOPER_ACCESS_ENVIRONMENT_INVALID`。
- `pageNum/pageSize/keyword` 原校验、排序和软删过滤不变。

新增响应字段（与原字段平级）：

```json
{
  "total": 3,
  "pageNum": 1,
  "pageSize": 20,
  "records": [],
  "statusCounts": {
    "PENDING": 3,
    "APPROVED": 3,
    "REJECTED": 0,
    "REVOKED": 0,
    "EXPIRED": 0
  }
}
```

- 五个键固定、顺序固定；某状态无行时为合法 `0`。
- `statusCounts` 与列表使用同一 `keyword`、`sourceEnvironment`、`is_deleted=0` 过滤，**不使用当前 `status` 筛选，不应用分页**。
- `total`、`pageNum`、`pageSize`、`records` 的旧语义和 JSON 值保持不变；`records` 仍受当前 `status`/分页影响。
- 一条 `GROUP BY status` 读取；不逐状态、不逐行查询，无新增框架/表/缓存。
- 计数来源是数据库 `nx_developer_access_request.status` 的真实存储值；不按当前时间推导 `EXPIRED`，不触发生命周期写入，不把未知状态合成五项之一。查询失败正常报错，不把异常吞成 0。
- 不修改共用 `PageResult`；新增 A9 专属薄 DTO `OpsDeveloperAccessPage`，仅保留旧四个字段并追加 `statusCounts`。

## 3. 影响范围

- 管理端读取：只追加字段，旧客户端忽略即可；PC 当前类型在 `lib/admin/developer-access-client.ts:25`，本候选不改 PC。
- App 开发者申请提交/最新状态：`AppDeveloperAccessService`、`AppDeveloperAccessController`、写链、鉴权、申请人范围均不变。
- A9-BE-01（时区）、A9-BE-02（userNo/隐私）、A9-BE-03（排序）不在本候选；原列表排序仍为 `created_at DESC, id DESC`。
- 不新增 `platform_a9_read` 或其它权限。

## 4. 状态语义

- `PENDING`：提交后初始状态。
- `APPROVED`/`REJECTED`：管理端审批写链的终态。
- `REVOKED`：管理端撤销写链的终态。
- `EXPIRED`：只统计数据库已有该状态的行；当前代码没有按时间自动写入该状态的路径，因此可能为 0，不能据当前时间自行推导。
- 计数只映射五个合法状态；若数据库出现其它未知 status，不伪造为五项，五键和可能小于 `total`，需以真实数据核对，不在本候选扩字段。

## 5. 验证计划（本候选未执行环境验证）

1. 静态：`mvn -Dmaven.test.skip=true -DskipTests package` Java 17 编译打包通过。
2. 公共 TEST 只读对照（由小6在授权环境执行，不造数据）：
   - 请求不带 `status`，核对 `statusCounts` 与 `total`（`total` 应为五键计数加任何未知状态的总和；若历史无未知状态应相等）。
   - 请求 `status=PENDING`，确认 `total/records` 收窄而 `statusCounts` 不变；切换页签只影响列表。
   - 带 `keyword`/`sourceEnvironment`，确认计数与列表同过滤，且不随分页变化。
   - 无某状态行时该键为 0；非法 status/env 仍 422；无读权仍 403。
