## 实际权益和资金方向

方向由 `nx_streak_milestone.reward_type/reward_amount` 决定。奖励名称只用于输入与说明，旧名称首数字不代表实际支出。分别比较 UVT 数量、USDT 数量、SPIN 票数三个分量，任一新增或增加即须 A2，另一分量减少不能抵消。现行规范没有跨资产净额抵销、汇率或票估值政策；此归类落实 T02 和三个独立消费者，不引入兑换或定价。

| 当前真实类型 → 拟类型 | UVT | USDT | SPIN | BADGE |
| --- | --- | --- | --- | --- |
| UVT | 数量增加审批；降低或不变直接 | 正金额审批 | 正票数审批 | 固定原 code 可兑现时直接 |
| USDT | 正金额审批 | 数量增加审批；降低或不变直接 | 正票数审批 | 固定原 code 可兑现时直接 |
| SPIN | 正金额审批 | 正金额审批 | 票数增加审批；降低或不变直接 | 固定原 code 可兑现时直接 |
| BADGE | 正金额审批 | 正金额审批 | 正票数审批 | 普通文字直接，不读取名称数字 |

例如实际 UVT 100 → USDT 1、USDT 10 → SPIN 1、SPIN 1 → UVT 0.1 均须审批；实际 UVT 10、旧名称 `+5 UVT` → `+7 UVT` 是实际 10→7 的收紧。BADGE 不构成资金或票分量；原 BADGE 文案修改保留原 amount，其数值不表示徽章数量。其他类型转 BADGE 时 amount 为 0，仍使用该行原 code。

## 输入与旧入口

原入口 `PATCH /api/admin/growth/check-in/streak-milestones/{milestoneId}`、权限 `growth_h5_write`、`Idempotency-Key`、原 `GrowthConfigUpdateRequest` 与命令 `STREAK_MILESTONE_UPDATE` 保持。原 DTO 的 `value` 为奖励文本，`expectedValue` 为原奖励文本，可按旧合同省略后由服务端读取当下值。放大返回 `409 H5_APPROVAL_REQUIRED`，不自动创建票、不修改目录；收紧和普通说明按理由直接保存。待审期间仍允许原 H5 收紧/普通说明直写；若该直写改变 typed 旧态，旧票在批准时返回 `409 H5_CONFIG_STALE`，不覆盖新值。本候选不把 G2/G7 的全冻结规则外推到 H5。

A02 仅支持明确的一种 UVT/USDT/SPIN/BADGE。金额文本支持 `+5 UVT`、`UVT ×5`、`+1 USDT`、`$1`，票支持 `Lucky Spin 票 ×2`、`转盘票 ×2`、`2 SPIN` 等同形格式。资金与票数必须是无符号十进制，最多六位有效小数且精确落在 `DECIMAL(18,6)`；SPIN 还须为不超过 Java int 的整数。不接受负号、多权益、多数量、千分逗号、科学计数或隐式舍入。仅本入口解析收紧，其他域的 `rewardFlow` 不变。NEX、POINTS、积分与未知类型不兼容、不自动迁移；真实旧类型不可解释时返回 `422 STREAK_REWARD_STATE_UNSUPPORTED`。

徽章文本必须包含 BADGE 或“徽章”且不混合其他权益；文字数字不参与方向。只使用原 `badge_achievement_code`，且对应成就须 active、未删除，否则返回 `422 STREAK_BADGE_NOT_CONFIGURED`。本次没有徽章选择器，也不按名称创建或更换 code。

零金额或零票沿用既有可保存边界；这不定义“零即关闭”或“零也完成领取”。旧 App 仍拒绝资金/票的非正数，相关写入与领取不一致另行查重；本次没有修复该消费者，也不得声称零领取通过。

## A2 提案、旧态和批准

提案入口 `POST /api/admin/platform/audit/operations`，`sourceDomain=H5`、`obj=<milestoneId>`，单一 target `{domain:"H",type:"h5_streak_milestone",id:"<milestoneId>"}`。命令：

```json
{"domain":"H","op":"h5_streak_milestone","params":{"values":{"milestoneId":1,"reward":"+6 UVT","expectedReward":"+5 UVT"}}}
```

`milestoneId` 必须是 JSON 正整数；两个 reward 字段必须是字符串。服务端固定 maker、真实方向和摘要，并在锁定目标行后保存 `before={id,day,rewardType,amount,reward,badgeCode,status,deleted}`；amount 是规范化精确十进制字符串。客户端伪造 before、maker 或 amplifies 不改变判定。原 expectedReward 与真实名称不符返回 `409 H5_CONFIG_STALE`。

有 H5 写权限即可提本类并按本人原键恢复，不授予泛 A2、他人或其他域读取权限。批准仍要求另一名有效超管和 `platform_a2_operation_approve`。批准前重新核对来源域、对象与唯一活动锁；回放重新绑定完整 before、重新解析新奖励、重算方向，并重新查可靠 B1 和精确红线。只改 type/amount/name，CAS 同时约束 name/type/amount/code/day/status/deleted。仅 typed amount/type/code、天数或状态改变，即使名称未变也使旧票返回 `409 H5_CONFIG_STALE`。

不需审批的提案返回 `422 H5_APPROVAL_NOT_REQUIRED`；不可靠 B1 返回 `422 B1_COVERAGE_DATA_UNAVAILABLE`，低于红线返回 `422 B1_COVERAGE_BELOW_REDLINE`。正常收紧、徽章文字不查 B1。成功继续生成原命令回执、领域审计和 outbox；成功的提案键、批准键和直接写入键按原边界恢复，不另建幂等业务编号。
