# G4 档位与系列总量

创建首档、追加档位或修改末档截止时，已有唯一 ACTIVE 系列的总供应量随末档截止一同更新。档位、系列总量、档位版本和审计共用同一事务。总量变更沿用 `finprod_g4_write` 与供给字段的既有操作锁，审计记载总量调整前后的值。首档保存后市场保持关闭。

联动写入的总量不得低于已售，也不得超过既有上限 100,000。修改非末档时只调整相邻边界，末档和总量保持原值。没有在售系列时可以准备档位，由既有初始化命令以末档截止创建系列。目录保留连续性、已售和末档与总量相等的读取检查。

## A15～A17 档位审批

- A15 提高任一实际未售起售位置的单价，或 A15～A17 增加 ACTIVE 系列真实总量，须经 A2 双人审批。调节相邻档位边界时按未售位置的新旧报价比较，沿用真实购买按当前系列持仓数定位起售位置的口径。合法降价、未售报价等价变化、仅影响已售区间和没有提高未售报价的合法缩容仍可直接保存。
- 原档位 POST、PATCH 对放大返回 `409 G4_CATALOG_APPROVAL_REQUIRED`。A2 原提交入口使用 `command.domain=G`、`command.op=g4_genesis_tier_change`、`sourceDomain=G4`、`obj=tiers`、`target={domain:"G",type:"genesis_catalog",id:"tiers"}`。参数为整数 `to`、整数 `priceUSDT`（可用十进制字符串）、整数 `expectedTiersVersion`，编辑时另带原档位 `tierId`。发起时记录服务端系列身份、总量和整表版本及内容摘要。审批详情显示实际受影响的档位、总量和版本。
- 发起和执行需要 `finprod_g4_price_write`，实际同步总量另需 `finprod_g4_write`。批准人须是另一名有效超管，并具备 A2 审批权和对应业务权限。批准时重校发起人的业务权限、目录源状态和放大方向。合法直接收紧可以保存，目录版本变化后原提案不能批准。
- 提案和决定的幂等指纹、发起人身份校验均使用认证管理员 ID。发起人保有对应业务权限时，可以按原幂等键恢复该提案及当前状态。批准人在 A2 幂等有效期内同键重试返回原回执。
- 按 OP-57，A15～A17 目录维护免 B1 覆盖率检查。若市场当前已开，批准后扩大后的总量即时生效。独立总量命令和从关闭到开放的原 B1 门槛仍适用。无 ACTIVE 系列时沿用纯目录维护行为，首档和追加的新条款审批分类待产品明确。

## 独立总量

独立的「节点总量」命令同样一次更新系列总量和末档截止，保留档位起点、价格与历史订单及持仓。目标总量必须大于末档起点，避免覆盖其他档位。越过该边界时，命令拒绝变更并返回 `GENESIS_SUPPLY_REQUIRES_TIER_UPDATE`，由档位命令处理区间调整。

独立调整沿用同一权限、操作锁、已售下限、100,000 上限和扩容覆盖率检查。末档截止变化时递增档位版本。审计记载末档、总量与版本的前后值。以同一幂等键重放成功请求时返回既有结果。

A2 审批 G4 参数提案时，审批人须具备 A2 审批权、工单访问范围及该参数直写所需的业务权限，并与发起人不同。节点总量、展示开关和每日收益基数公式使用 `finprod_g4_write`，其余参数按各自的直写权限校验。缺少参数权限时返回 403，工单维持待审，操作锁、总量、档位和版本保持原值。
