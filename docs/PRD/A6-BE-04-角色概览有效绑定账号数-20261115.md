# A6-BE-04 角色概览补「已启用绑定账号数」（最小后端候选）

日期：2026-11-15
范围：A6 管理端角色概览 `GET /api/admin/platform/roles/overview` 只读响应末尾追加 `enabledAdminCount`；不改 PC/App/H5。

## 1. 背景与口径

旧 `adminCount` 直接数 `nx_admin_role_relation` 的有效关系行（`rr.is_deleted=0`），因此包含已停用、已软删的账号。本候选保留旧字段及旧语义不变，另加一个**精确、可解释**的启用账号数：

`enabledAdminCount = 该角色未删绑定中，账号记录 `nx_admin.is_deleted=0` 且 `nx_admin.status=1` 的 DISTINCT 账号 ID 数。`

- 必须 `COUNT(DISTINCT a.id)`；同一账号重复关系不多计。
- 不按角色 `status` 过滤；角色停用是另一维。
- 不把 MFA、临时锁定、在线状态、实际权限生效推断为“启用”。
- 账号启用/删除只取 `nx_admin` 权威字段；绑定只取 `nx_admin_role_relation.is_deleted=0`。
- 无绑定是合法 `0`；查询失败正常报错，不吞异常成 0。

## 2. 接口合同

`GET /api/admin/platform/roles/overview`，权限保持 `platform_a6_read`。

`RoleSummary` 原字段保持：

```json
{
  "id": 1,
  "roleCode": "SUPER_ADMIN",
  "roleName": "Super Administrator",
  "remark": "...",
  "status": 1,
  "builtin": true,
  "adminCount": 2,
  "permissionCount": 10,
  "menuGrantCount": 8,
  "enabledAdminCount": 2
}
```

- `adminCount` 仍是旧的关系行计数口径，不重定义。
- `permissionCount`、`menuGrantCount`、detail、角色范围、鉴权、写链、导航均不变。
- `enabledAdminCount` 追加在 `RoleSummary` 末尾；旧客户端可忽略。
- 一条 JOIN `nx_admin` 的 `GROUP BY rr.role_id` 查询，与现有 overview 角色循环合并；不新增每角色 SQL、HTTP、缓存、表、索引或框架。
- 不顺手重构旧 `countAdminsByRole` 的 N+1。

## 3. 数据与边界

- 绑定唯一键为 `(admin_id, role_id)`，但查询仍用 DISTINCT，按产品口径防重复。
- 软删账号（`nx_admin.is_deleted=1`）和停用账号（`nx_admin.status=0`）不计。
- 角色本身停用不排除该角色的计数；角色是否可授权/导航是 A6 既有其它口径。
- 不修改 A1 账号启停、A6-BE-01 停用角色授权、A6-BE-02 审计只读策略、A6-BE-03 权限/菜单计数。
- PC 现有 `lib/admin/a6-client.ts:14` 的 `A6RoleSummary` 及 `rbac-contracts.ts:45-56` 不读取新字段，旧页面显示不变；后续展示位置为 A6 角色卡 `a6-roles.tsx:166`，本候选不改。

## 2026-11-16 补充：内置 AUDITOR 角色保持只读

角色授权入口 `PUT /api/admin/platform/roles/{roleId}/grants`（`OpsPlatformRoleService.updateRoleGrants`）此前只拒绝改动 `SUPER_ADMIN`，内置的 `AUDITOR`（`nx_admin_role.role_code='AUDITOR'`，迁移 `20260712_rbac_classic.sql` 种子即「只读审计」）可以被授予写或高敏权限，违背它自己的只读定义。

现按**既有**数据分类在最少的共用边界拒绝，不新增角色模型或命名规则：

- 判定身份用不可变角色码 `AUDITOR`（`BUILTIN_ROLE_CODES` 之一），不看角色中文名、不按自定义角色名匹配。
- 权限是否只读沿用权限目录已经在用的同一套 `perm_type` 归一：显式 `READ` 才算只读；`CRITICAL` 与其它非空未知值按 `HIGH`；未填 `perm_type` 时回退 `_read` / `_write` 后缀判定，其余一律 `HIGH`（见 `AdminPermissionMapper` 目录查询里的同一 `CASE`）。
- 校验位置在 `updateRoleGrantsOnce` 解析出 `roleCode` 之后、快照与提案之前，因此**专用入口的提案创建与 A2 回放共用**同一门；命中返回稳定业务码 `403 AUDIT_ROLE_WRITE_FORBIDDEN`（沿用仓库既有码），不落提案、不改授权。
- 只读权限（`READ`）仍可正常授予；其它角色的合法授权、`SUPER_ADMIN` 不可变、actor/期望集合/事务与对象锁、幂等与回执全部不变。
- 不主动改或撤销任何存量授权（含历史上已授予 AUDITOR 的写权限）；不新增权限表、角色或迁移。
