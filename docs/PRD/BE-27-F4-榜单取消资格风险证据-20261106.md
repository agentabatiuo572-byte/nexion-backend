# BE-27 F4 榜单取消资格的风险证据

依据 B30 第 27 项、S06 与 F-PD06。

取消成员本周榜单资格需要该成员有本业务周内由 K2 服务产生的有效刷榜信号，且信号关联的有效榜单行必须以该成员为检测对象。同簇成员随该行收到的信号和通用风控接口录入的同名信号不能作为 K2 依据。K1 依据要求该成员实际属于达到检测阈值的待处理簇，或属于已标记或已冻结的簇。已解除、已清除或已删除的簇不作为依据。K2 信号按 GROWTH_TEAM 业务周计算，包含周初，截止于下一周周初之前。

A2 发起和实际处置时都核验证据。无证据返回 HTTP 422 `NO_RISK_EVIDENCE`，不会取消资格。审批前证据已失效时，原申请保持待审。直接通过原 F4 配置接口发起的同一成员处置也受证据检查。成功处置的审计包含实际使用的 K1 簇编号或 K2 信号编号。

区域大使审批的材料核验门槛待明确权威数据来源和操作入口。申请单目前只记录 App 提交内容、审批状态和开通预算。需明确线下签到真实性与人数、KOL 发票及流量的独立核验结果，以及物料和 SDK 配额如何映射到现行预算类别与申请号。材料核验应是独立于大使批准和 A2 决策的持久状态，本次维持现有批准与拒绝流程。

## 2026-11-16 补充：派奖只读预览与取消资格可读判据

总榜派奖在批准前看不到后果，取消资格只能提交后才知道会不会被拒。现补两个只读读取，均沿 `network_f4_read`，**不写任何东西**：不结算、不建事件、不动榜单/额度/审计、不认领幂等键、不加锁。

- `GET /api/admin/teams/leadership-pool/payout-preview?period=week&periodKey=YYYY-MM-DD`：按已批准派奖同一周期解析（`today`/`week`/`month`/`allTime`，周期未结束返回 `422 F4_CLOSED_PERIOD_REQUIRED`）返回每名次的真实用户（`userId` 与榜单同格式 `userNo`）、名次、`computePoints`、未受限金额 `amountBeforeCaps`、头部上限后实际金额 `amount`、削减依据 `limitedBy`（`top1MaxPct` / `top5MaxPct`），以及本期奖池、`topN`、`minComputePoints`、两名头部占比、合计与削减差额。
- 预览与结算调用**同一分配计算**（权重 share、top1 上限、top5 上限与累计），因此预览金额即实际发放金额；只读路径不取得结算互斥锁，也不写 `lastSettled` 检查点。
- 读不到真实依据时返回 `available=false` 与原因，不填猜测值：`F4_LEADERBOARD_POOL_NOT_CONFIGURED`（奖池未配置或为 0）、`F4_LEADERBOARD_PAUSED`、`F4_LEADERBOARD_ALREADY_SETTLED`（本期已有结算键）、`F4_LEADERBOARD_NO_CANDIDATES`（门槛以上无人）。
- `GET /api/admin/teams/leadership-pool/disqualification-readiness?limit=50`：返回本业务周榜单候选行，逐行给 `disqualificationAvailable` 与该行实际依据 `riskEvidenceRef`（K2 信号编号或 K1 簇编号），无依据时 `reason=NO_RISK_EVIDENCE`。判据复用 A2 发起与实际处置同一查询，不新增风险定义，不放宽也不收紧。
- 榜单展示快照（暂停冻结信封）与 `leaderboardPeriods` 结构不变；本补充只新增独立读取，页面是否展示另议。
