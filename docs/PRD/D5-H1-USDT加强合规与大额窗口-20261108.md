# D5 / H1：USDT 加强合规审查与大额窗口

本轮范围为已确认的两项规则，适用于 USDT-BEP20、USDT-ERC20。D5 的固定网络费、UVT 抵扣、每日次数、余额比例、到账 SLA 和独立网络权限继续使用既有配置。BANK-VND 保留原银行契约；TRC20 不纳入本轮合规执行变更。

## 业务规则

| H1 加强合规 | 本笔本金 | 新单与自动处理 | H1 附加等待 |
|---|---|---|---|
| 关闭 | 任意金额 | 沿用普通小额免审、强审金额、K3/K4 规则 | 无 |
| 开启 | 不超过 1,000 USDT | 必须人工复核，小额免审不能放行 | 无 |
| 开启 | 严格大于 1,000 USDT | 必须人工复核，小额免审不能放行 | 从提交时刻起 N 天 |

1,000 USDT 恰好等于门槛，不附加 N 天。N=0 仍须人工审核。等待到期只表示可以继续审核，不表示审核通过、发给支付商或到账。K3 `freeze` / `delay` 优先，不能被合规或强审的普通人工路线覆盖；既有风险延期、冻结及人工截止不因关闭 H1 合规而解除。

开启时，大额且有正天数窗口的新单以 `EXTENDED_HOLD`、`H1_COMPLIANCE_HOLD`、`previousStatus=REVIEW_PENDING` 保存；到期返回 `REVIEW_PENDING`，不会自动通过。小额、门槛等额及零天窗口直接进入人工队列。关闭时的合格小额继续复用既有 H1 自动复核任务，截止即提交时刻，不再附加 N 天；任务仍重查 K3/K4、强审、关停、覆盖率与每日次数。

## 旧单、切换与恢复

- 所有尚未首次出款的两网订单，在领取出款任务时重新读取当前 H1 规则。开启后，既有 `REVIEW_PASSED` 若没有当前合规人工审批证明，返回可操作的人工队列；当前大额窗口尚未结束时进入上述等待子状态。保留原钱包预留、费用、提现号、支付商幂等键和原提交审核路线；记录 `D2_WITHDRAWAL_COMPLIANCE_REVIEW_REQUIRED` 审计及原因，不重新扣款。
- 只有通过既有权限、强审、K3/K4、关停、地域、披露、资金覆盖及次数门槛的真实 D2 `APPROVE` 才写 `H1_COMPLIANCE_APPROVED:M{month}:{phase}:D{days}`。共享出款入口核对当前证明和大额截止。规则变化后证明不匹配时可重新人工审批；`DELAY`、`FREEZE`、解除及到期回人工不继承审批证明。
- 旧已审核单回人工后，再审批保留相同提现号的既有 D3 预留凭证。先核实原凭证号、方向、金额、有效状态一致，再复用；不重复写出金预留。冲突仍报错并保留资金。
- 明确属于 H1 的旧 `H1_PHASE_COOLDOWN` / `H1_ZERO_DAY_AUTO_REVIEW` 单，必须同时有 `previousStatus=REVIEW_PASSED`；新 `H1_COMPLIANCE_HOLD` 则须有 `previousStatus=REVIEW_PENDING`。既有任务按当前开关及本金计算有效截止，关闭或不满足大额条件时可以结束 H1 专属等待；旧自动审核资格仍重查风险。仅这些两网 H1 生命周期可提前处理，其他 K3 / 人工延期、冻结沿用其原截止。
- 每轮仍限 500 笔，数据库先筛选实际生效的到期单并按有效截止排序，不让未到期 H1 单占满处理配额。当前 H1 信息缺失或不可靠时，明确 H1 两网单沿用原截止：未到期保留等待，到期只回人工队列并记录 H1 不可用原因，不默认关闭或自动放行；其他 D2 / K3 及 BANK-VND 单继续按原截止与既有路径恢复，不因这类 H1 策略缺值阻断整批。数据库、审计或出账失败仍向上传播，不伪造处理成功。
- 已持久化支付商意图、已发送、结果未知订单继续原 CID / 原幂等键查询及恢复路径，本轮不退回重新发起。5 分钟重试对账周期及 15 分钟安全门槛不变。

## API 契约

`GET /api/withdrawals/policy` 与 D5 `withdrawalLimitsData` 新增只读 `complianceReviewThresholdUsdt=1000`；D5 `sourceByField.complianceReviewThresholdUsdt="compliance-rule"`。`complianceHoldEnabled`、`cooldownDays` 保留既有名称。门槛不能通过 D5 编辑接口修改。

App 的 `policyVersion` 纳入当前 H1 月份、阶段、合规开关、窗口与本规则版本。取得旧版本后 H1 发生变化，再提交返回 `WITHDRAWAL_POLICY_VERSION_CONFLICT`，需重读策略。已成功请求按原键回放原单和费用，不再次扣款。D7 的银行报价保留既有 D5-only 版本摘要，不因 USDT 合规规则单独变化失效。

`POST /api/withdrawals/eligibility` 和新提交响应增加：

| 字段 | 类型 | 含义 |
|---|---|---|
| `complianceReviewRequired` | boolean | 本笔受加强合规人工审查 |
| `complianceHoldApplies` | boolean | 合规开启且两网本笔本金严格大于 1,000；N=0 时仍可为 true |
| `complianceHoldDays` | integer | applies 时取 N，否则为 0 |

开启时 `fastLaneApplied=false`，普通 `route=manual`，`riskReasons` 包含 `H1_COMPLIANCE_REVIEW_REQUIRED`；K3 freeze / delay 保留优先路线。合规关并不表示本笔必然免审，仍以服务端风险与权限结果为准。

提交时将上述三字段写入既有必写提交审计。列表、详情和放弃请求后的已提交恢复，一次按返回页提现号批量读取原提交快照，兼容热审计与冷归档；不按当前 H1 重算历史。原单缺快照则省略该组字段，表示未知。原 `riskRoute` 保留提交快照，当前 `REVIEW_PENDING` 等状态优先表明待人工处理。生命周期到期回人工可能清空 `holdUntil`，消费者不能据此编造截止或到账时间。

列表、详情及原键恢复返回原单既有 `d5_payout_due_at` 为 `payoutDueAt`，与提交响应使用同一持久值。普通提现的预计到账读取该 SLA 截止；`holdUntil` 仅表示审查或风险等待截止，不能当作预计到账。历史 `payoutDueAt` 缺失时保持未知，不重算或覆盖旧单。

上述读取同时返回原单 `completed_at` 为 `confirmedAt`，实际到账时间只读取该已完成记录。缺少完成时间时显示未知，不用审查截止或预计到账代替真实到账，也不回填历史单。

## 银行与发布

BANK-VND 保留正天数等待、仅零天符合小额条件才自动审核、D7 报价、受益人、风险指纹及独立支付商恢复行为。本轮不将两网合规人工证明或 1,000 USDT 门槛扩展到银行。

不新增数据库表、列或迁移。仅使用现有生命周期、提交审计及资金凭证。候选只进入测试分支；正式合并与发布另循既有批准要求。代码编译和完整业务 E2E 的实际结果由本轮验收回执记录，本文不将计划场景视为已通过。
