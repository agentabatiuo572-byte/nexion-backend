# D1 / D5：USDT 分网络资金控制

按用户 2026-11-07 确认的图中方案实施。本文描述目标契约；构建、TEST 发布和实景验收分别记录，不能据此认定真实链上资金已验收。

## 运营入口与权威状态

- D1「充值与地址设置 → 收款与出款开关」保存 BEP20、ERC20 两个独立充值开关。数据库仅新增充值权限，不另建分网络出款权限。
- 充值实际开放同时要求：选定网络的运营充值开关、服务启动及 RPC 配置、全局分配地址与充值入账总闸开放。库存不足属于地址准备中，不等同网络关闭。
- D5 保留既有 TRC20 / BEP20 / ERC20 配置与审批，返回 `networkStatus`（network、configured、enabled、disabledReason）及 `effectiveNetworks`。App 提现 policy、申请和地址换绑复用同一实际可用网络判断；PROVIDER 模式不开放 TRC20。
- D5 配置开启不等于可用。实际状态还受全局出款总闸、服务商币种、链节点和现有风控／对账条件限制。

## 无副作用的充值读取

登录用户调用 `GET /api/deposits/policy`，返回恰好 BEP20、ERC20 两行 `networks`：`network`、`enabled`、`disabledReason`、`confirmations`、`feeUsdt`、`minDepositUsdt`、`feeUsdtExact`、`minDepositUsdtExact`。关闭网络仍返回真实费用和最低额。

该接口只读，不分配地址、不创建供应商地址、不补池、不触发风控写入。App / H5 Lite 先读 policy，初始仅显示开放网络；选中后才请求该网地址。读取失败或全部关闭不默认请求 BEP20。地址接口仍再次校验网络，额度／库存不足时返回准备中，不能借用另一网络地址。

## 写入、审批与恢复

- D1 网络提案包含共享闸版本和该网版本；每网充值单独提案、另一管理员复核，自审、失权、陈旧版本及混合全局／网络载荷均拒绝。提交、复核和紧急关闭沿用持久幂等回执与审计。
- 新充值建址、地址分配、自动／人工入账，以及外部 USDT 下单报价、建单和履约均检查选定网络的充值权限。钱包余额购买不受链上充值开关影响。
- 关闭网络后，App 原付款单隐藏可付款地址并返回不可付款状态；历史查询、回调核实、扫描和对账继续运行，不因关闭丢失到账事实。未发出出款被阻断，已发出原单继续查询恢复。
- 恢复共享充值闸必须按选定网络审批、通过现有恢复条件，另一网络充值保持关闭，出款不随充值恢复打开。全局出款审批不恢复充值；紧急关闭同时关共享闸和两个充值开关，旧提案失效。
- 新提现及换绑按共享闸在用户锁之前的顺序锁定，重新检查 D5 与链上能力。关闭通道的换绑在消耗 OTP 之前拒绝；成功幂等回放仍返回原成功结果。

## 迁移和验收边界

迁移新增 `nx_cregis_network_switch` 两行与既有审批单的网络版本字段，按既有共享充值闸种子化，服务启动/RPC 的独立批准仍保留。重复迁移不覆盖运营值。PROVIDER 启动检查结构及两行齐全；非 PROVIDER 不要求新增网络表。

验收最少覆盖只读 policy 不建址、BEP20/ERC20 独立关闭、D1 双人审批及陈旧回放、D5 实际网络与 App 一致、关闭网络下单／提现／换绑拒绝、已发原单可查询、紧急关闭与分别恢复。只做 E2E 和整体业务验证，不使用单元测试或独立集成套件。真实链上充值、提现、归集和短信发送另需具体资金验收安排。
