# D1 / D5：USDT 分网络资金控制

按用户 2026-11-07 确认的图中方案实施。本文描述目标契约；构建、TEST 发布和实景验收分别记录，不能据此认定真实链上资金已验收。

2026-11-09 文档纠错：按已获准接入并进入 test 的 [TRC20 三网契约](TRC20完整网络接入-20261108.md)对齐下述网络范围。B40 完整 TEST 业务验收仍待完成，已有换绑、恢复开关或 B42 的局部证据不代表 B40 全项通过。

## 运营入口与权威状态

- D1「充值与地址设置 → 收款与出款开关」保存 BEP20、ERC20、TRC20 三个独立充值开关。分网络运营开关只保存充值许可，出款仍沿用 D5 配置和既有总闸。
- 充值实际开放同时要求：选定网络的运营充值开关、服务启动及 RPC 配置、全局分配地址与充值入账总闸开放。库存不足属于地址准备中，不等同网络关闭。
- D5 保留既有 TRC20 / BEP20 / ERC20 配置与审批，返回 `networkStatus`（network、configured、enabled、disabledReason）及 `effectiveNetworks`。App 提现 policy、申请和地址换绑复用同一实际可用网络判断；PROVIDER 模式按各网实际许可与能力开放，TRC20 还须其独立部署许可、TRON 节点证明和项目币种能力就绪，不能只按配置开启认定可用。
- D5 配置开启不等于可用。实际状态还受全局出款总闸、服务商币种、链节点和现有风控／对账条件限制。

## 自动完整对账时效

TEST 的 `NEXION_CREGIS_FULL_RECONCILE_MS` 固定为 `300000`（5 分钟，上一轮结束后计时），与代码默认值一致。BEP20、ERC20、TRC20 按链分别对账，每轮只推进至约 5 分钟前的闭合窗口；从未配置且没有历史活动的 TRC20 不要求产生对账结果，不因此使原两网失效，原 BSC 全局安全门槛保持不变。

15 分钟安全门槛保持不变：最近完整对账成功不得超过 15 分钟，对账覆盖进度落后不得超过 900 秒，且该次成功后不能出现新的失败（`INCOMPLETE`）对账记录。网络开关、全局资金闸、风险及支付商能力仍须满足原条件；对账异常时继续暂停，不能为了展示可用而放宽门槛。

周期调整只修改 TEST 环境变量并重启原后端版本，不改业务代码、运营开关或数据库安全条件。验收应覆盖多轮自然定时对账及原 10–15 分钟空档，按三网实际配置与历史活动核对真实可用状态，不靠手动对账维持通过。

## 无副作用的充值读取

登录用户调用 `GET /api/deposits/policy`，返回 BEP20、ERC20、TRC20 三行 `networks`：`network`、`enabled`、`disabledReason`、`confirmations`、`feeUsdt`、`minDepositUsdt`、`feeUsdtExact`、`minDepositUsdtExact`。关闭或尚未具备开放条件的网络仍返回该行及真实费用、最低额和关闭原因，不据三行目录推导三网均已开放。

该接口只读，不分配地址、不创建供应商地址、不补池、不触发风控写入。App / H5 Lite 先读 policy，初始仅显示开放网络；选中后才请求该网地址。读取失败或全部关闭不默认请求 BEP20。地址接口仍再次校验网络，额度／库存不足时返回准备中，不能借用另一网络地址。

## 写入、审批与恢复

- D1 网络提案包含共享闸版本和该网版本；每网充值单独提案、另一管理员复核，自审、失权、陈旧版本及混合全局／网络载荷均拒绝。提交、复核和紧急关闭沿用持久幂等回执与审计。
- 新充值建址、地址分配、自动／人工入账，以及外部 USDT 下单报价、建单和履约均检查选定网络的充值权限。钱包余额购买不受链上充值开关影响。
- 关闭网络后，App 原付款单隐藏可付款地址并返回不可付款状态；历史查询、回调核实、扫描和对账继续运行，不因关闭丢失到账事实。未发出出款被阻断，已发出原单继续查询恢复。
- 恢复共享充值闸必须按选定网络审批、通过现有恢复条件，其他网络充值保持关闭，出款不随充值恢复打开。全局出款审批不恢复充值；紧急关闭同时关共享闸和三个充值开关，旧提案失效。
- 新提现及换绑按共享闸在用户锁之前的顺序锁定，重新检查 D5 与链上能力。关闭通道的换绑在消耗 OTP 之前拒绝；成功幂等回放仍返回原成功结果。

## 迁移和验收边界

原迁移新增 `nx_cregis_network_switch` 的 BEP20、ERC20 行与既有审批单的网络版本字段，按既有共享充值闸种子化；TRC20 前向迁移补独立行且默认关闭，不继承旧开关，不更新既有 D5 配置。重复迁移不覆盖运营值。PROVIDER 启动检查结构及三行齐全；非 PROVIDER 不要求新增网络表。TRC20 的充值／出款部署许可默认关闭，服务启动、RPC 和资金许可的既有批准仍保留。

验收最少覆盖只读 policy 不建址、BEP20/ERC20/TRC20 独立关闭、D1 双人审批及陈旧回放、D5 实际网络与 App 一致、关闭网络下单／提现／换绑拒绝、已发原单可查询、紧急关闭与分别恢复。B40 完整 TEST 验收尚未核销，各子项仅按实际业务证据记录。只做 E2E 和整体业务验证，不使用单元测试或独立集成套件。真实链上充值、提现、归集和短信发送另需具体资金验收安排。
