# M4-BE-01：FAQ 检索统一长短语言码（候选 PRD）

基线：`nexion-backend` / `origin/test` = `63a4f669281753e6c5511faa268f935291dbb352`（当前 #522 公共 TEST 候选）。本项只修 Nova 检索边界的长短语言码比较，不改维护 API、存储、App/PC、FAQ 内容或其它语言能力。

## 现行合同

- 维护端 `OpsSupportKnowledgeService` 接受 `zh-CN`、`en-US`、`vi-VN`、`id`、`ms`、`fil`、`ru`、`kk`、`uz`；空语言默认 `zh-CN`，不支持的值返回 `SUPPORT_FAQ_LANGUAGE_UNSUPPORTED`。
- App Nova 请求只接受 `zh`、`en`、`vi`（`AppNovaAiService.validate`）。
- FAQ 存储为维护端长码；读取 SQL 会把历史短码转换为对应长码，未知历史值按 `zh-CN` 映射；维护端不允许未知码。
- `RagNovaAiGateway.publishedDeviceEarningsAnswer` 已把 `zh/en/vi` 映射为 `zh-CN/en-US/vi-VN`，该路径本身可达；本次不改它。
- `RagNovaAiGateway.novaQuestion` 却直接用请求短码与 FAQ 长码 `equalsIgnoreCase` 比较，导致 `surface=Nova` 的已发布 `zh-CN/en-US/vi-VN` FAQ 在 Nova 对话中无法进入知识上下文。这是本次确认的可达错配。

## 最小修复

1 个 Java 文件 `+20/-1`，只改 `RagNovaAiGateway` 的比较边界：

```java
String faqLanguage = canonicalFaqLanguage(normalizedLanguage);
...
.filter(faq -> faqLanguage.isBlank()
    || faqLanguage.equalsIgnoreCase(canonicalFaqLanguage(faq.language())))
```

新增私有 `canonicalFaqLanguage`：

- `zh` / `zh-CN`（大小写等价）→ `zh-CN`
- `en` / `en-US` → `en-US`
- `vi` / `vi-VN` → `vi-VN`
- `id` / `ms` / `fil` / `ru` / `kk` / `uz` 原样精确比较
- 未知/其它标签（如 `en-GB`、`xx`）原样保留，不猜测、不回退英语
- 两侧都规范化，使历史短码/长码等价；不迁移历史行
- 空白语言保持原行为：不按语言过滤

`publishedDeviceEarningsAnswer`、维护端语言校验/默认值、存储格式、SQL、App 请求校验、回答文本、发布/有效性/租户/权限过滤、排序/条数/截断均不改。未新增语种、翻译或迁移历史 FAQ。

## 2026-11-16 补充：FAQ 直接写入并入原命令回执与受控核查

M4 支持知识库（FAQ）的四个直接写此前不在受控核查范围内：`M4_SUPPORT_FAQ_CREATE`、`M4_SUPPORT_FAQ_UPDATE:{faqId}`、`M4_SUPPORT_FAQ_STATUS:{faqId}`、`M4_SUPPORT_FAQ_DELETE:{faqId}`。它们走共享幂等入口，但没有原命令身份，也没有保留成功回执，出问题只能看当前知识库内容——那不能证明当时那条命令做了什么。

现按既有机制接这四个 scope：读权用该页既有精确读权 `service_m4_read`（写权仍是 `service_m4_write`，未改）；成功证据按 writer 实际资源与动作成对——资源固定 `SUPPORT_KNOWLEDGE`，动作分别为 `M4_SUPPORT_FAQ_CREATED`、`M4_SUPPORT_FAQ_UPDATED`、`M4_SUPPORT_FAQ_STATUS_CHANGED`、`M4_SUPPORT_FAQ_DELETED`，别 scope 的动作不能顶替。

`localConfiguration` 只收新建与更新：状态变更会在公开客服知识面上发布或下架答案、删除会移除条目，因此这两种不作为「未执行」证据，未知保持 `STILL_UNKNOWN`。目标（faqId）来自路由，原请求哈希、幂等键、TTL、认证 actor、请求校验与现有写入语义均不变。

M4-BE-03 的 Nova 退役/迁移政策与页面入口不在本次范围，未改动；本补充也不改变其它已合域的元数据。

## 2026-11-25 FAQ 删除理由按可见字符计数

- BUG-729 的 FAQ 删除走 `DELETE /api/admin/content/knowledge/faqs/{faqId}`。理由与 PC 删除确认框用同一口径，按 NFC 规范化后的 Unicode 码点计数，空白、控制字符、零宽格式字符和组合标记不计入。可见字符上限 200，下限为 A2 当前规则（默认 8）。低于下限或高于上限返回原有的 HTTP 422 REASON_REQUIRED。实际执行删除时读取当前规则，原幂等键的成功重放返回原回执。
- 计数只使用理由的副本。审计记录 `M4_SUPPORT_FAQ_DELETED` 按原规则保存实际理由，保留内部空白和用户输入的字符。删除仍要求 `service_m4_write`、原幂等键和请求体中的状态与版本，成功后软删除并递增版本。
