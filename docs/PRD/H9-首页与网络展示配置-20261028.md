# H9 首页与网络展示配置（2026-10-28）

## 模块与入口

H9 按「首页数字增长、首页网络实况、赚取页任务中心、全球网络、设备预估排名、历史估算」集中配置。每个模块只展示相关输入、说明与保存按钮；切换模块保留未保存草稿。刷新及保存不清空其他模块的草稿。

介绍页在线设备/累计已发放继续读取首页数字增长；首页网络实况的注册人数读取注册基数与增长规则，在线设备与介绍页共用当前批次；设备预估排名仍按独立排名配置计算。真实设备、余额和任务不受这些展示设置影响。

设备预估排名的表格、开关、输入、帮助和底部操作统一使用 H 域样式。

## 首页真实收益汇总

生产账号首页汇总成功读取且确认今日结算笔数为 0 时，`earnings.today` 的 `usdt`、`nex`、`jobCount` 均返回 0，App 今日收益显示 `$0.00`。汇总或今日笔数未知时保持缺值，读取异常仍返回失败；周、月、累计与同比规则不变，不从历史流水推算今日金额，也不使用 H9 展示配置补值。

`earnings.todayVsYesterdayUsdt` 返回今日已结算 USDT 减昨日相同时间段已结算 USDT，复用现有 `earningsSummary` 的同次查询与业务日历窗口，不修改百分比 `todayVsYesterdayPct`。两侧金额沿用主金额的非负归一规则；成功确认结算笔数为 0 的窗口按 0 计算，汇总或笔数未知、非空窗口金额缺失或无效时返回 `null`。差额允许正、负、零；Sandbox 不提供真实对比金额，明确返回 `null`。读取异常继续返回失败，不改账务、激活和其他周期。

## 赚取页任务中心

H9 管理接口 `values.activeJobsBase` 和 App 平台配置的 `publicStats.activeJobsBase` 是同一个值，可发布 0 至 100,000,000 的整数。显式提交 null 清空基座；旧客户端省略该字段时沿用上次发布值。

赚取页与全球网络共用首页展示批次的作业数。App 首页通过 `onGrid.activeJobs` 返回当前展示值。作业展示从 H9 发布基数起算，随在线设备增长，暂停时保持当前值。展示作业数不参与派单、结算和账本。

## 全球网络

全球网络继续明确标识「模拟数据」。固定的8个城市、坐标与翻译属于静态内容；节点基数、基础延迟和变化参数由 H9 配置，经公开配置接口读取。App/H5 不内置数值回退。无有效配置时数值显示占位，地图和城市入口仍保留；读取新配置后更新指标。动画计时器不重复请求接口，隐藏页面暂停采样，恢复按当前时间与最新配置显示。

| 配置 | 合法范围 |
|---|---|
| 数据变化间隔 | 1–86400秒，最多3位小数；存储为整数毫秒 |
| 每任务小时处理量上下限 | 0–10000，下限≤上限，最多6位小数 |
| 延迟浮动上限 | 0–60000整数毫秒 |
| 每中心分布比例 | 0–100%，最多两位小数，八城合计 100% |
| 每中心基础延迟 | 0–60000整数毫秒 |

8 个中心须完整且无重复：新加坡、东京、胡志明市、伦敦、巴黎、法兰克福、纽约、圣何塞。在线节点总数取首页网络脉搏的在线设备数，作业总数取同一首页展示批次。客户端将两项实时总数分别按各中心的 `sharePct` 作最高平均数整数分配，中心之和与总数一致。

启动迁移按原节点数换算比例，剩余的 0.01% 按余数从大到小分配。原八城全零时各分 12.50%。迁移再次运行保留已发布的比例；旧客户端更新延迟也会保留这些比例。

## 保存、权限与兼容

每次保存只合并当前模块草稿和最新已保存值；仍通过 H9 原有权限、版本校验、理由确认、幂等与审计。设备排名沿用其独立接口与版本。其他模块若有未保存修改且服务端同字段发生变化，保留草稿并提示刷新，不覆盖他人设置。保存失败不宣称生效，刷新失败保留已有内容。

全球网络配置使用现有 H9 聚合内的 `globeDisplay` 字段，不新增资金配置或通用缓存。旧记录由后端补足原展示基线；旧客户端省略此字段时保留已保存配置。旧客户端重试使用原 H9 指纹，避免升级后误判同一幂等请求。

## 2026-11-17 H9-BE-01：作业与中心在线节点显示投影

本轮仅补原管理 GET 尚缺的作业与中心投影。已交付的注册人数、首页在线设备和 `paidCents` 读取公式及原公开接口保持；`source` 仍描述原首页/H9 来源，新增字段分别标明自身来源。

- `activeJobsActual` 用于诊断，生产环境复用 `AppHomeOverviewMapper.onGrid("PRODUCTION", false)` 的在途作业条件。启用模拟任务且作业数已知时，计入有效运行规则槽，优先读取 `HomeSharedSnapshotCache` 的有效五秒快照，否则使用 `activeRuleSlots` SQL。来源标为 `APP_HOME_ON_GRID`。查询不可用时，诊断值为空并列出 `APP_HOME_ON_GRID_UNAVAILABLE`。

- `centerNodes` 仅返回原八中心的 `id`、`onlineNodes`，来源 `centerNodesSource=APP_DISPLAY_SIMULATION`，表示 App 显示推算，不是权威节点台账。按 `src/lib/globe-simulation.ts` 的 `splitByWeights(total, weights, true)` 分配本次 `homeDisplay.onlineDevices`。以固定顺序 `sg/jp/vn/uk/fr/de/us-ny/us-sj` 对 binary64 权重求和（`sharePct`，旧配置用 `nodes`），先取 `总数 × 权重 / 权重之和` 的下整值，再将剩余节点逐一分给 `权重 / (当前分配数 + 1)` 最大的中心，同值取固定顺序靠前的中心。中心之和等于在线总数。旧八权重全零与 App 解析器一致不可用；在线总数缺失时仍按八中心返回各自 `null`，不捏造 0，不复制城市名/坐标/说明。

## 2026-11-20 BUG-531：首页与全球网络共用的作业展示数

- `GET /api/config/home-display` 的 `data.activeJobs[]` 与 `online[]`、`paidCents[]` 使用同一个展示批次和每秒样本索引。平台配置 `publicStats.networkPulse.activeJobs`、App 首页 `onGrid.activeJobs` 和 H9 管理预览 `activeJobsDisplay` 均读取该批次的当前样本。

- App 和 H5 Lite 按 H9 权重将同一作业展示总数以最高平均数法拆到八中心，中心合计等于总数。总数或权重不可用时保留缺值。
