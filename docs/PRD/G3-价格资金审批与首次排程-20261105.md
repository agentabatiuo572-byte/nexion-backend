## 业务规则

1. G3-A01、A02：任意一天目标价或上涨概率提高，提交 A2，由另一位有 A2 批准权的超管批准。批准前七日计划保持原值；批准后只更新计划，当前价格不因保存计划立即变化。后续按日推进沿用生效计划。
2. 周计划中某天上调不能用别的日期下降抵消。包括未超过整周峰值的日期涨价。全无目标价和概率上调的收紧仍可直接保存，波动幅度等原有普通配置维持原流程与权限。
3. G3-A07：手工提高现价经 A2，待审期间全站读旧价，批准后写入当前价并发布行情点。降低现价仍可直接执行。下次计划推进继续使用对应帧，不改成永久钉价。
4. G3-A04：未配置到首次合法自动推进排程经 A2，类型为参数审批，不标记为资金放大。批准前不启用这份排程，批准后同进程重建调度。已有排程的普通调整继续直接保存。未配置用明确空值表达，不能视为 0 或自动补默认。
5. 周计划放大按改后整周最高目标价重估现有 UVT 本息应付款；现价放大按实际拟发布价重估。提案和批准都重新检查 B1 的原始精确判定。上涨概率不换算成臆测的未来兑换人数或应付款。初次排程不新增专门的覆盖率预测，实际推进涨价时保留既有拟发布价检查。
6. 收紧可在待审期间执行，并使旧修订的提案失效。批准不能覆盖后来的业务值。普通采样同一价格不改变语义修订号。
7. 原有业务写账号只获得本类提案和本人原回执查询能力，不授予 A2 全域读取或新菜单。本人不能自批，非超管不能仅凭批准码批准。

## 接口合同

沿用现有 A2 创建、批准、驳回及按幂等键查询接口。新窄命令为 `domain=G`、`op=g3_market_policy_change`，`params.values` 只接受以下之一：

| action | values |
| --- | --- |
| curve-cell | action、dayIndex（JSON整数0～6）、field（targetPrice或pumpProbability）、value（十进制字符串）、expectedRevision |
| current-price | action、value（十进制字符串）、expectedRevision |
| initial-schedule | action、value（合法排程文本）、expectedRevision |

`GET /api/admin/market/nex/curve` 增加 `curveRevision`、`priceRevision`、`scheduleRevision`，为当前规范化业务内容的确定性摘要。请求必须使用对应修订号，不接受多余字段、数值型 value 或非整数日期。

- 目标价和现价：大于 0、不超过 1,000,000 USDT/UVT，最多八位小数；不把超精度输入静默舍入。
- 上涨概率：0～1，最多六位小数，沿用后端数据精度；PC 当前输入步长仍按现有页面合同处理。
- 精确业务权分别为 `finprod_g3_curve_target_price_write`、`finprod_g3_curve_pump_prob_write`、`finprod_g3_override_price_write`、`finprod_g3_write`。
- 对象锁分别为 G/nex_market_curve/weekly、G/nex_market_override/currentPrice、G/nex_market_control/schedule。一次业务审批只有一个对应对象。
- 初次排程工单固定 `param`、`amplifies=false`，其他三类固定 `fund`、`amplifies=true`；服务端核对类型、对象和本票锁，不能由调用者伪造。
- 原 PUT 全周计划与 PATCH 现价入口仍可执行合法收紧；放大返回 409 `G3_POLICY_APPROVAL_REQUIRED`。旧通用 G3 A2 回放也没有放大特权，仍核对 expectedFrames/expectedValue，不能绕过新命令。

主要拒绝：409 `G3_POLICY_REVISION_CONFLICT`；422 `G3_POLICY_PROPOSAL_INVALID`、`G3_POLICY_VALUE_INVALID`、`G3_POLICY_APPROVAL_NOT_REQUIRED`；403 `G3_POLICY_APPROVAL_FORBIDDEN`。原有状态、权限及 B1 错误继续使用既有合同。
