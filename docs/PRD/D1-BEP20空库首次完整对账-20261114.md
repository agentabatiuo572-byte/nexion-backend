# D1 BEP20 空库首次完整对账（2026-11-14）

## 问题与适用范围

首次部署时，BEP20 没有本地地址，D1 原完整对账入口返回 `NO_ADDRESSES`；开启收款要求最近完整对账，补充地址又要求已开收款，形成初始化闭环。本次仅增加后端 BEP20 空库存取证路径，沿用原接口和页面；已有地址、ERC20 和 TRC20 的对账路径保持原行为。

## 首次取证条件

- 必须为实际 `PROVIDER` 模式，已配置本链只读 RPC，确认数至少为 15，当前项目真实返回 BEP20 USDT 收款币种能力。
- 全局 assign、credit、payout 和 BEP20 收款数据库开关全部关闭；门禁存在且不处于地址提交 BUSY 状态。部署运输参数不等同于数据库资金开关。
- 本项目本链没有任何本地地址、入金事件、链观察、回调、异常来源、认领、退款、自动归集任务或购买直付意向/到账记录；BEP20 资金准备计划和入金策略快照也必须为空。回调及充值/提现订单没有独立项目字段，沿用本链全表历史的保守阻断，含已终结和软删除记录。
- 复用正常恢复的风险检查，任何未决外部敞口、未知地址、缺失供应商记录、失败/争议回调及严重告警继续拒绝。仅首次生成对账证据时不递归要求已有 COMPLETE；正常开通仍完整执行原风险检查、最近 BEP20 完整对账及目标链完整对账要求。

## 真实证据与原子提交

通过现有完整对账入口及原定时任务，在原闭合、重叠时间窗口内调用供应商两遍入金历史分页查询。每遍必须为 total=0 且 rows 为空，同窗结果哈希一致；任一非空结果立即失败，发生在发现/物化历史入金之前。分页、供应商读取或 RPC 失败均按原流程记录 INCOMPLETE，不能推进成功水位。

真实 RPC 校验 BSC 链身份，读取链头高度/哈希及满足确认数的高度/规范区块哈希，并复查链头哈希一致。由于本地追踪集合为空，此路径不扫描或物化充值，不调用钱包、订单、地址创建、归集或出款动作。

成功提交前在同一事务锁定全局门禁和 BEP20 开关，重新检查开关、全部空库存及风险条件，再写空集合游标、正式 COMPLETE 和成功水位。仅 BEP20 空库存路径的最终提交事务使用 SERIALIZABLE，使空库存查询的原生范围锁保持至提交，覆盖不共享门禁的资金准备计划等并发插入；已有地址和 TRC20 等普通路径隔离级别不变。游标不得倒退；审计写入失败时同一事务回滚。本次审计 action 为 `CREGIS_BEP20_EMPTY_POOL_RECONCILED`，关联原 runId，source 为 `EMPTY_POOL_BOOTSTRAP`，包含窗口、零供应商行数、链头和确认高度哈希、游标及 `WINDOW_AND_EMPTY_LOCAL_TRACKED_SET_ONLY` 证据范围。

供应商两遍窗口为空只证明该窗口无入金；空本地追踪集合的链证明不代表 Cregis 项目全部历史、外部地址余额或既有资金归零。当前 Cregis 项目 `1466552794661984` 客户端存在既有外部可归集 1 USDT，网络、归属、时间及处置范围必须继续单独核验，不得通过本次 COMPLETE 隐去或认作已对平。
