# P5 Cregis 网关连接复用

## 问题与范围

`CregisGatewayRouter.provider()` 原先每次调用都创建 `HttpCregisGateway`，其构造方法又创建新的 Java `HttpClient`。充值地址校验、对账、提现能力查询、付款与回调查询等正常并发请求因此无法复用同一客户端的连接池。

2026-11-11T21:01:40Z 的隔离验收记录 N243 确认：512MiB 私有 Mock Provider 被 OOM 杀死，App 仍运行且未 OOM。连接和客户端反复创建是已确认的源码问题；它与该次 Mock OOM 的具体因果及修复后的资源效果仍需真实业务复验，不能仅凭构建通过宣称已解决。

本次只修改 Router 中 Provider 网关的选择与生命周期。不修改金额、签名、付款幂等键、风险开关、UNKNOWN 恢复、RPC 校验、任务周期、读写超时、接口响应或任何前端页面。

## 目标行为

- 同一 Router 首次处于 `PROVIDER` 模式并访问 Provider 时创建网关，后续访问复用该网关及其 `HttpClient`。同步范围仅为选择/初始化，网络请求在返回后执行。
- 每次调用仍先检查当前模式；`DISABLED` 和 `LOCAL_SANDBOX` 调用 `provider()` 仍返回原错误。切回 `PROVIDER` 时可复用已有实例。原 `isolatedLocalSandbox()` 行为不变。
- `connectTimeoutMs` 等客户端构造配置在首次创建时读取。当前源码没有运行时修改 Cregis 应用配置的入口，不新增热更新或多版本客户端缓存；应用配置变更沿用现有重启流程。
- 网关继续引用同一 `CregisProperties`。URL、项目、API key、读取超时及各业务开关仍按原位置读取；不缓存能力、对账、风控或资金结果。每次请求仍独立生成 nonce、时间戳、签名、请求体及响应订阅器。
