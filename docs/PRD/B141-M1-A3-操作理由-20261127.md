# B141 新建客服组和保存开发者接口文档草稿的操作理由

- 新建客服组（`POST /api/admin/content/support-agents/groups`）和保存开发者接口文档草稿（`PUT /api/admin/developer/docs`，状态为 `DRAFT`）在业务层执行 A2 理由规则。先进行 NFC 规范化，再按 Unicode 字符计数，空白、控制字符、格式字符和未合成的组合标记不计入。
- 下限取当前生效的 `admin.a2.reason_min_chars`，上限为 200 个可见字符。下限为 10 时，9 个可见字符或用空格、全角空格、不换行空格和零宽字符补足均返回 `422 REASON_TOO_SHORT_MIN_10`。超过 200 个可见字符返回 `422 REASON_TOO_LONG_MAX_200`。101 个和 200 个普通单字符表情可提交。缺少 A2 理由配置时，新请求返回 `503 A2_REASON_POLICY_UNAVAILABLE`。
- 请求指纹继续使用原请求。有效期内，相同请求用原号重放可返回已有回执，业务数据及审计只写一次。HTTP 请求仍先经过原有权限检查与当前 A2 理由规则。直接调用客服组服务时，具备当前权限的操作者仍可按原请求取回有效期内的同一成功回执。客服组继续核对主管资格，草稿继续核对修订号并保留上一版公开内容。
- 客服组主管历史与草稿配置备注分别按各自数据库字段容量保存理由。超出容量时先压缩连续的不可见填充，再按现有规则生成 Unicode 摘要。审计保留理由、操作和前后状态。

## B144 客服组其余操作与开发者接口文档发布

- 客服组改名、启停或归档、移交负责人、调成员、改资格、改客户路由，以及开发者接口文档发布，使用同一 A2 理由规则、上下限和错误码。文档发布与草稿继续校验原修订号，草稿继续保留上一公开版本。
- 客服组负责人、成员、资格与路由历史按 200 个数据库字符保存理由，客服权限范围刷新通知也使用同一长度的理由。开发者文档配置备注按 255 个数据库字符保存。长理由使用已有的压缩和摘要规则，审计保持原有操作、请求字段和前后状态。请求原文仍用于同键重试比对。
