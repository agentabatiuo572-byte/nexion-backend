# B135 M1 客服维护与 K2 风险处置的操作理由

客服个人工作台暂停或恢复维护，以及 K2 对命中执行标记账户、拦截新人礼、标记刷榜或冻结账户簇时，后端按 A2 理由规则校验。字符计数先做 NFC 规范化，再排除空白、控制字符、格式字符和未合成的组合标记。下限取当前生效的 `admin.a2.reason_min_chars`，上限为 200 个可见字符。

- 101 和 200 个单字符表情均可提交。达到 201 个可见字符时返回 `422 REASON_TOO_LONG_MAX_200`。下限为 10 时，9 个可见字符加空格、全角空格、不换行空格或零宽字符仍返回 `422 REASON_TOO_SHORT_MIN_10`。
- 校验在新命令占用幂等键之前完成。维护仍核对当前客户归属、绑定和维护版本。风险处置仍检查相应权限、版本和审批锁，冻结沿用现有授权及关联状态变更。原请求指纹继续使用原来的字段和理由正文。
- 与旧版已成功请求完全匹配时，授权操作者仍可用原号获取维护的保留回执或 K2 有效期内的回执。回查不会重新执行操作，无法找到匹配回执时按现行理由规则返回错误。
- 数据库的理由摘要字段按各自容量保存。超长时先去掉两端的不可见填充，仍超长时按 Unicode 字符截取并标记省略。普通理由保留原内容，审计仍包含操作人、对象、前后状态和命令号。
