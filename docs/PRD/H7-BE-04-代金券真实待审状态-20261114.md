## 4. 读接口增量

在原 `GET /api/admin/growth/vouchers` 的每个 `vouchers[]` 行增加：

```json
{
  "pendingApproval": null
}
```

或：

```json
{
  "pendingApproval": {
    "action": "删除代金券",
    "ticketId": "A2-...",
    "submittedBy": "显示名",
    "submittedAt": "2026-11-14T01:23:45"
  }
}
```

规则：

- `pendingApproval=null`：该券当前没有活跃 H7 锁；明确空，不补对象。
- 有效对象：锁为 active、票为 `status=pending` 且未删除、票 `operation_id` 非空、`operator_name` 非空、`created_at` 非空；命令满足第 3 节全部约束；`params.voucherId` 与锁 `target_id` 完全一致。
- `action` 只取两种 H7 中文动作；不把其他操作伪装成删除/作废。
- `ticketId` 取票的 `operation_id`，是读取接口可公开的审批单号；不返回 `ticket_id` 以外的内部标识。`submittedBy` 只取 `operator_name`；`submittedAt` 取票 `created_at`，按现有 projection 的 `ISO_LOCAL_DATE_TIME` 原样格式化，不新增 Z/时区推断。
- 有活跃锁但票/命令不完整、类型/目标不一致、JSON 无法解析：返回**非空** `pendingApproval` 且四个字段均为 `null`，表示“有锁但不可验证的待审/未知”；不返回虚构动作、提交人、时间或票号，也不退化成 `null`（无锁）。
- 查询 source/DB 失败：异常向原接口传播为失败，不把失败伪装成空列表或无锁；不新增吞错。
- 只对本次 `vouchers[]` 中已有的券 ID 查询；不扩展行范围、不读其他对象。
- 原有 `vouchers`、`skus`、`stats`、`sources`、字段类型/顺序和原读权限不变；`pendingApproval` 是向后兼容的 add-only 字段。

- 唯一投影入口是 `vouchersForRead()` → `withVoucherPendingApprovals`；不新增通用框架、缓存或写链依赖。
- 不改 `H7VoucherDisposition`、`OpsAuditCenterService` 的建单/批准/锁/回放、`OpsGrowthController` 权限或任何写方法。

## 7. 失败模式/边界

- 锁与票并发变化：读取以当前 active 锁 + 当前 pending 票为准；查询后状态变化不缓存，下一次读取重新取。本候选不新增事务/锁语义。
- 锁存在、票已 approved/rejected 但锁未释放（异常残留）：join 不到 pending，返回未知对象而非无锁；不释放/修改锁。
- 票存在、锁不存在：列表不返回待审（锁是对象待审范围的权威），不凭票推断。
- 票命令历史版本多/字段不完整：未知对象；不猜。
- 列表为空：不查询、不返回待审。
- 查询异常：接口失败；不是空待审。
- 未改数据库结构；无迁移/回滚数据。
- 本候选只读；不会创建锁/票，不会执行删除/作废/核销。
