# P5 后台长查询租约心跳

## 实际问题与目标

PROD build31（main 3e841523）隔离运行的 P14LEASEGAP 已观察到 analytics 与 leaderboard 在 `SupportPaymentFactService.readWithCapturedHistory:75` 等待 MySQL；约第 8 分钟 analytics 锁已过期，leaderboard 同 token 的 PTTL 约 478 秒，后续另有约 39 秒的 `nx_compute_task` 查询。原分页回调只能在查询完成后续租，无法覆盖一段连续长 SQL / 验证 / 编码期间的租约。本批解决该实际缺口；不将锁续租成功等同于完整代际或容量通过。

## 后台行为

- analytics 与 leaderboard 只有在成功取得原 owned token 后才登记心跳。共享一个由 Spring 管理的 daemon 单线程执行器，每 30 秒固定延迟调用现有 owned-token Redis 续租；原 analytics 120 秒、leaderboard 600 秒租期、刷新时点和任务频率不变。
- 心跳只执行原 Redis 续租，不访问数据库、不传递事务、连接、认证或线程上下文。数据库和验证继续使用调用线程原物理只读 RR。
- 心跳或前景续租首次抛出的 RuntimeException 永久保存在本次 handle。后续前景页回调、排行榜逐流发布前校验以及最终缓存发布前重新抛出原错误；不转换为财务 UNKNOWN，也不忽略后继续成功发布。
- 心跳覆盖源读取、完整验证与 JSON 编码。编码完成后，同步取消本次心跳并等待已在执行的续租退出，检查首个失败，再执行现有最终 owned renew 与 Redis Lua publish。Lua 仍核对原 token，失去所有权不能覆盖完整缓存；owned release 仍不能删除新 owner。
- 正常、异常和提前返回均在 finally 取消本次 handle；Spring 销毁唯一执行器。原构造签名供手工构造调用者兼容，不新建未托管线程；正式 Spring 构造器显式注入共享组件。

## 边界与保持项

心跳失败不会主动中断正在执行的 JDBC 查询；查询返回后在下一前景检查或最终发布边界失败。首次失败以后不恢复该旧 handle 的续租，下一次任务仍按原调度重新竞争 token。单线程 Redis 调用若阻塞可能影响另一心跳的时效，最终 owned-token 检查仍负责拒绝过期 owner；本批不修改 Redis 超时和租期。

排行榜现有逐流 SQL publication 保留原事务与逐流 owned 检查，不引入跨 Redis/数据库的新事务或 fencing 协议。心跳续租错误在下一次原逐流前景检查及最终缓存边界阻止后续发布，已经提交的合法 publication 不回写或删除。

不改金额、财务计算、来源覆盖、UNKNOWN、授权范围、客户批量、SQL/索引、刷新时点、页面、runtime 资源预算、固定业务样本、PLAN/SAMPLES、20 份冻结工具 hash 或原 raw 门槛。
