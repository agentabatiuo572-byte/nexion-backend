# TRC20 网络接入（2026-11-08）

本增量基于用户本轮确认的 PC D1/D2/D5 与 App/H5 Lite 方案。BEP20/ERC20 继续执行《D5-H1-USDT加强合规与大额窗口-20261108》，TRC20 不加入这两网的强制人工复核范围。银行、固定网络费和 UVT 抵扣规则不变。

## 本次交付支持范围

本次支持已接入 TRC20 的新版 App、H5 Lite、PC 管理端及配套后端。用户已明确取消旧版本客户端兼容要求；旧版兼容候选仅保留为本地未发布草稿，不纳入本次交付或验收。

服务端沿用本次三网接口合同，不引入 `includeTrc20` 等旧版能力协商参数。资金开关、原单状态、费用、幂等键及原 CID 恢复规则继续按下文执行。

时间字段依据真实订单数据返回：不为旧版解析要求补造 holdUntil、等待窗口或 ETA，不以当前 H1 回填不存在的历史 N，也不将窗口到期表述为到账；实际到账仍以 confirmedAt 为准，无真实值时保持未知。

## 网络身份与资金许可

- Cregis 链 ID `195`，唯一接入币种为 USDT，主网合约 `TR7NHqjeKQxGTCi8q8ZY4pL8otSzgjLj6t`、6 位精度。公开支持清单不代替当前项目的 address/payout 币种能力。
- `NEXION_CREGIS_TRON_RPC_URL` 是独立 TRON 原生 HTTP API 基址，不回退到 BSC/Ethereum。可选服务端 `NEXION_CREGIS_TRON_API_KEY` 仅用于 TRON-PRO-API-KEY 请求头，绝不返回前端。
- TRON 资金可用状态还需实际节点主网/精度读取成功；失败返回 CHAIN_PROOF_UNAVAILABLE，缺收款币种能力返回 ADDRESS_ASSET_UNAVAILABLE。新部署许可 `NEXION_CREGIS_TRC20_DEPOSIT_ENABLED` 和 `NEXION_CREGIS_TRC20_PAYOUT_ENABLED` 默认 false；充值还需原全局 assign/credit 闸、独立 TRC20 maker/checker 开关，提现还需原 payout 闸、D5 网络配置、J1 总闸、实际项目权限及对账就绪。
- 前向迁移新增独立 TRC20 充值开关（默认关闭）与地址池状态 3，不继承旧开关，不更新已有 D5 配置。游标、水位和对账批次均按链独立。全局安全对账仍维持原 BSC 约束，各网额外检查自己的水位；从未配置且没有存量活动的 TRC20 不使原两网失效。已配置节点且当前项目收款权限可靠的新 TRC20 空库存，在不存在已知地址/观察/回调/未知资金活动或未决风险时，可以通过供应商两遍空历史查询、原生固化扫描和独立水位闭合产生明确 bootstrap COMPLETE，以打破“开网需要对账、补池需要先开网”的初始化闭环；任一 provider 查询非空或读取失败即不能按空库存成功完成；提交水位前复用既有 gate 锁再次核实空状态，写 CREGIS_TRC20_EMPTY_POOL_RECONCILED 审计。仅证明所记录对账窗口为空，不声称项目历史从未有地址或交易。过程不建址、不入账，也不改变开闸权限。
- BSC 自动归集、甲方付款和 BSC 资金准备钱包保持 BEP20 专用。TRC20 不使用这些地址或资金动作。

## 地址、充值和购买支付

地址边界校验完整 Base58Check；地址统一保存为保留大小写的 Base58，节点 41 前缀十六进制只作为等价编码转换。交易 ID/区块 ID 是无 0x 的 64 位十六进制，不把 EVM 地址、交易回执或大小写折叠用于 TRON 身份。地址库存、购买专用地址、异常认领和退款的数据库地址比较保留大小写。

`network=TRC20`，购买支付 `paymentMethod=CREGIS_USDT_TRC20`。D1 状态、网络能力、地址池 `addressPools.TRC20` 以及共同 min/fee/confirmations 沿用既有 DTO；购买渠道费用初始未配置，不擅造费率。确认数最低 15，购买确认宽限沿用非 BSC 的 5 分钟，响应继续提供 deadlineAt/confirmationGraceEndsAt。

正常地址分配和下单只能使用本链、已独立验证为零余额的库存。读状态不建址。池不足返回原准备中/不可用状态，重复操作沿用原幂等键。TRC20 回调需原签名、来源 IP、时间窗、项目/链/合约/CID/收款人和金额全部一致，供应商二次查询与原生链证明均成立才入账或确认购买；重复、乱序和未知结果保留原恢复路径。

## 原生链证明与对账

TRON 原生读取校验主网 genesis `00000000000000001ebf88508a03865c71d452e25f4d51194196a1d22b6653dc` 和 USDT 6 位精度。只使用 walletsolidity 的规范块、交易体和执行回执认定最终成功，要求 receipt.result=SUCCESS、交易体成功、正确 USDT Transfer/收款人/精确金额/日志序号，且同时满足 full head 至少既有确认数与固化高度。仅 FullNode 深度、供应商成功、空 JSON 或缺回执都不等于到账。已入账原单查询遇空固化回执仅等待重试，不因此制造重组冻结；确实冲突的规范证据仍进入原事件流程。分配前原生 USDT 余额要求 full 与 solidified 两种视图均为零。

按固化块顺序读取原生批量交易回执，并与规范块交易集合核对后推进游标；链扫描仍有原单批上限和 100 块重叠，不改变自动全量对账 5 分钟和资金安全 15 分钟门槛。缺节点但有历史活动时保留观察失败和不可用状态，其他网络继续处理，不静默当成功。

已有充值的规范性检查、重组事件及双人恢复继续走现有流程。TRC20 找到可验证规范成功交易时支持恢复/解除原冻结；空交易体或空回执本身不构成缺席证明，因此不以此冲销已入账资金、收债或创建替代出款。无法证明时保留原事件、原 CID 与资金等待核实。本轮未引入能证明任意历史区间缺席的独立归档索引，不宣称空节点结果已经证明资金消失。

异常认领保留实际 Transfer 发送方的单次授权；TRC20 使用 TIP-191 的 TRON Signed Message 文本签名与 Base58 发送方核对，BSC 原 EIP-191 授权和既有签名消息保持兼容。异常退款持久化本链，按原 CID 查询；首次退款仍需既有双人批准和本链运输许可，链证明成立才完成，未知状态不新发。

## 提现阶段窗口与恢复

- TRC20 每笔金额均使用本单阶段 N 天窗口：50、1000、1000.000001 都从创建/提交时刻加 N，独立于加强合规开关与 1000 阈值。N=0 没有额外阶段等待。K3/K4、普通小额免审、强审阈值、披露确认、权限和已有资金预留继续生效。
- TRC20 eligibility 与新原单快照：`complianceReviewRequired=false`，`complianceHoldApplies=(N>0)`，`complianceHoldDays=N`。这些字段只描述阶段等待；不以 required=false 推导已审核，不以到期推导到账。原 `holdUntil`、`payoutDueAt` 与真实 `confirmedAt` 继续返回。
- `policyVersion` 纳入 TRC20 阶段规则版本，旧报价仍须 409 刷新。新单将原 N 记录到现有提交审计，不新增支付意图来冒充提交。
- D2 审批和首次出款复用同一截止计算：必须使用原提交审计 `cooldown_days + createdAt`，审计损坏/非法返回 TRC20_WINDOW_SNAPSHOT_INVALID；无原审计返回 TRC20_WINDOW_SNAPSHOT_UNAVAILABLE，不能取今天 N 或 0 改变旧期限。资料不足的原单保留资金，并进入现有待人工队列核实；不能恢复不存在的历史 N，也不新造人工凭证绕过。仍存在的独立 holdUntil 更晚时取较晚截止。
- 尚未发送的历史 REVIEW_PASSED 单若窗口未满，首发闸退回既有 EXTENDED_HOLD 并记审计，钱包及原预留不动；独立风险 owner 保留。正常到期任务再按小额/K3/K4和权限处理，人工单到期只变为可复核，不自动到账。TRC20 不要求 BEP/ERC 的合规人工批准 proof。
- 已有 provider 意图、CID 或未知结果继续原恢复/回调/查询，不二次创建支付；失败退款及重复审核复用原 D3 凭证和钱包分录，不重复预留或返还。
- 换绑写入也在服务端最终锁读 J1 提现总闸与分网许可，前端可用状态不代替服务端许可。

## 验证与上线前置

本候选仅进行 main compile/package 与差异检查，不编写或运行单元/独立集成套件。系统验收按本轮 trc20-test-plan，通过真实业务入口和必要只读数据核对开展，记录新建单、历史起点和只读外部查询的区别。没有真实 TRC20 入账历史、库存、受控资金交易或安全隔离系统时，不能宣称正向充值/实付 E2E 已通过。

正式启动先执行已登记的幂等前向迁移；新增网络默认关闭。当前供应商项目权限、节点读取可达只证明读取能力，不自动授权建址、消耗配额、发送资金或修改公共环境。部署/开启资金闸及正式分支合并仍由本轮负责 Agent 按用户授权独立处理。
