# ERC20 无充值地址时的提现开通前对账

ERC20 出款能力要求近期完成本网络对账。此前没有充值地址时，首次对账直接返回 `NO_ADDRESSES`，即使只开提现也无法满足条件；TRC20 已有同类空池首次对账入口。

本次将同一入口应用于 ERC20，复用现有 TRC20 校验和真实证据：对应 RPC 已配置、确认数至少15、该网络没有地址/事件/观察/入账/异常来源/服务商提现活动、全局风险及近期 BEP20 对账合格、未解决敞口为零、项目支持该网 USDT 地址权限、两遍服务商闭合窗口一致且为零、真实链最终区块及完整游标。完成前和事务提交时都核验确认数底线、空池与风险条件。

所有空池首次对账在服务商窗口非零时，先拒绝，再结束本次对账；不会先登记该窗口中的资金策略快照。失败对账记录保留，不伪造完成水位。

不创建充值地址或订单，不入账，不伪造历史，不降低对账或风险条件。保留 D5 和出款的双人审批。审计事件及失败码按实际网络命名，TRC20 和 BEP20 既有标识不变。

无充值地址不再阻挡提现配置；使用提现时仍需要用户收款地址，服务商项目的对应币种出款权限，以及真实可用资金/手续费资源。本次新 TEST 的账面储备是用户授权测试值，不能作为真实资金证明。

验收通过实际管理端、服务商及链上只读查询、正常双人审批和 App 网络/参数读取进行；不创建真实订单、不验证真实付款、不改前端代码。
