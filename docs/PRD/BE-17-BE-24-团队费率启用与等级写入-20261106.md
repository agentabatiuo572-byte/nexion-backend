# BE-17 和 BE-24 团队费率启用与等级写入

首次启用 F2 七层结算时，A2 发起申请和批准执行均检查 L1 至 L7 的有效 USDT 比例与 UVT 系数。合法的零费率计为已配置。费率不齐时不能进入首次启用，原结算模式与版本维持。暂停和恢复沿用现有状态与版本规则。

新配置和等级写入使用 V0 至 V8。F4 解锁门槛与票权保留其 V1 下限。旧的高等级解锁门槛原值可读，修正前结算继续显示配置阻断。历史 V9 至 V12 用户等级、筛选和既有记录继续可读。

验收在隔离库进行。F2 用缺少单层、补齐且有合法零费率、申请后费率缺失三个状态验证 A2 提交、批准和结算模式回读。F4 对解锁门槛及票权分别验证 V9 拒绝、V8 可写，保留旧配置阻断。F1 对有活跃历史等级配置的用户验证拒绝写入 V12，再按 V12 筛选核对原记录。

## 2026-11-17 F3-BE-02：批量配置的逐项业务权限

`F/f_config_batch` 的 1–32 个有序 `changes` 项按现 writer 的 key/value 解析，只用于权限和票据对象推导，不创建或执行单项提案。原 ACTIVE 七键沿 `f_config` 的现权限，其余可映射 UI 键沿 `f_ui_config` 的现权限；未知映射明确拒绝，不设批量万能权限。`F.binary.paused` 仍需引擎暂停权，其余 `F.binary.*` 需匹配费率权，`F3.dailyCap.*` 需 F3 写权；普通字段原 F2 权限不因 F3 页面来源被替换。

发起和实际批准路径共用逐项权限校验，首个失败保持原拒绝码；比例精度、榜单证据及其它原检查保持。组合 descriptor 与整票目标集使用这些同源单项定义：obj 为原序 key 逗号串，before/after 为各项服务器当前值与拟改值，目标按实际普通 `team_config` 或 UI `ui_config` 保持原序；同来源沿该原域，混合来源标记 F。审批 action 沿现页面已有整批动作，仍 fund 类型，放大标志按原单项判断合并。

仍只保存一条完整 command、一张审批票，原整批事务及任一失败回滚全部不变。不更改单项权限、业务 writer、值/请求指纹、对象锁规范、A2 原键恢复、F4 政策或页面/说明，不拆多票。本轮未 E2E/HTTP/DB/业务/部署。

## 2026-11-17 F4-BE-13：周结算定时的保存边界

采用原二选一的“保存时只接受每周一次”分支。`F.pool.settleCron` 的现保存校验与持久化均调用 `normalizeWeeklyCron`，先复用原 Spring 合法 5/6 段解析及数值范围检查，再要求秒/分/时各为一个整数、日号为 `*` 或 `?`、月份为 `*`、星期为单个 0–7 或 MON–SUN。5 段按原规则补秒 0；例如 `0 2 * * MON` 规范为 `0 0 2 * * MON`。每日、每月、一天多次、每周多日或限定月份的配置返回 `F4_SETTLE_CRON_WEEKLY_REQUIRED`，原语法非法仍为 `F4_SETTLE_CRON_INVALID`。

新校验仅接入 F4 这两处保存边界，不改共用 `normalizeCron` 的既有读取语义、`LeadershipPoolConfigGuard`、调度器执行、最近结束周选择、检查点/暂停或补发政策；不为保存限制静默停用旧配置。不自动重写、迁移或代填各环境现值；本轮各环境配置未读取/修改，尚不能据此声称各环境已每周触发。角色权限、审批、请求指纹、原成功键和业务结算保持。仅代码/编译口径，未 E2E/HTTP/DB/业务/部署。
