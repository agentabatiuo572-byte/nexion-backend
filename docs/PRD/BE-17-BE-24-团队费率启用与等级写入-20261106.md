# BE-17 和 BE-24 团队费率启用与等级写入

首次启用 F2 七层结算时，A2 发起申请和批准执行均检查 L1 至 L7 的有效 USDT 比例与 UVT 系数。合法的零费率计为已配置。费率不齐时不能进入首次启用，原结算模式与版本维持。暂停和恢复沿用现有状态与版本规则。

新配置和等级写入使用 V0 至 V8。F4 解锁门槛与票权保留其 V1 下限。旧的高等级解锁门槛原值可读，修正前结算继续显示配置阻断。历史 V9 至 V12 用户等级、筛选和既有记录继续可读。

验收在隔离库进行。F2 用缺少单层、补齐且有合法零费率、申请后费率缺失三个状态验证 A2 提交、批准和结算模式回读。F4 对解锁门槛及票权分别验证 V9 拒绝、V8 可写，保留旧配置阻断。F1 对有活跃历史等级配置的用户验证拒绝写入 V12，再按 V12 筛选核对原记录。

## 2026-11-17 F4-BE-02：月上限与独立周池的金额保存边界

`F.pool.monthlyCap`、`F.leaderboard.poolUsd` 的同一实际 writer 在写入前复用 `parseConfiguredMoney`，沿原消费者格式：去 `$`/逗号，支持 K/M 倍数，BigDecimal 数值必须非负；原来合法的零、格式和精度保持，不从结算 SCALE6 推导新的输入小数门，不新增最大额度。非法值经原异常链返回 422 / `F4_POOL_MONEY_INVALID`，不先落坏值；持久化仍保原输入格式，不新增金额 canonicalization。

原 ConfigGuard 读取继续把非法金额转为原 `ConfigUnavailable(INVALID_THRESHOLD)` 和同一 fingerprint，历史坏值不迁移或重写。月上限 0 是合法零额度，剩余额度为原 `max(cap-monthPaid,0)`。榜单独立周池只有 week 且值严格大于 0 才覆盖 `periodPrize.week`；填 0 表示沿现 periodPrize.week 回退，不表示停发。缺失/旧非法独立池仍沿原回退，回退本身不正时原 settle 返回 0；today/month/allTime 的原期间奖池不改。

单项 PATCH、A2 `f_config`/`f_ui_config`/`f_config_batch` 均经同一 writer 的保存门；原幂等成功键恢复、权限、对象锁、请求 hash、审批、批量事务、USDT 结算和既有四周期 JSON 非负校验保持。不新增政策、schema、页面或下发说明。本轮未 E2E/HTTP/DB/业务/部署。

## 2026-11-17 F4-BE-19：金额键的同结算放大方向

`F.pool.monthlyCap` 使用结算配置守卫原 `parseConfiguredMoney` 比较新旧金额，沿 `$`/逗号/K/M 格式和原精度，额度调高才放大。0 是零额度；旧缺失或非法上限原来使结算配置不可用，修复为正额度会恢复潜在付款，按放大处理，修复为 0 不增加付款容量。

`F.leaderboard.poolUsd` 使用结算原金额解析和同一个 `configuredPeriodPrize(week)` 读取，比较实际生效奖池：正数覆盖周奖金，0、缺失或旧非法独立池沿原周奖金回退。两边都为正数时不增加回退读取；需要回退时同一次方向判断只取一个基准。例如周奖金 1000 时，0 改 200 是减少，200 改 0 是增加，0 改 0 不放大。结算的数值解析、回退语义与实际派奖算法均不变。

原单项、批量回放的同 writer 红线检查和 `delegatedFDescriptor` 共用方向判断；调高沿现资金覆盖率保护，提案标记 `amplifies=true`。只补两键及必要同源取值，复用原金额保存格式门，不改其它比例/奖池、审批/锁/hash/成功回执优先或实际结算；不触及人工解锁函数。无 mapper/动态 SQL 改动，XML 检查不适用；仅必要 Java17 跳测编译，未实际启动、E2E、HTTP、DB、资金、业务或部署，不改客户端/下发说明或 uvel-docs。

## 2026-11-17 F2-BE-02：空规则表的受控首次配置

维护端原有 `F.unilevel.L{n}` / `F.unilevel.nex.L{n}` 只支持已有行的单字段 UPDATE；空表时没有 INSERT，且 L1 USDT 被固定 10% 的校验拒绝。这里只补首次配置的受控 A2 命令 `f_unilevel_bootstrap`，不改原单字段 UPDATE、L1 固定费率、结算或页面。

请求沿用既有 A2 提案/批准入口，一次提交 L1-L7 七层，每层显式提供 `layerNo`、`usdtPct`、`nexPerUsd`；另带 `expectedVersion=0`。缺层、缺字段、空值、顺序/层号不合法、重复层、USDT 不在 0-100、UVT 为负或精度不能落入真实列均拒绝。L1 USDT 必须为 10%，由现有 `CompleteLayerRates` 检查；不采用旧备份值、不自动补 0、不复制其他层费率、不执行 seed 或直接 DB 写。

执行仅允许在 A2 已批准回放中进行：锁定 `commission_type='unilevel'` 的全部历史行（含停用/软删，不扫描其他 commission_type）；只有不存在任何 UNILEVEL 行时才继续；`expectedVersion=0` 表示本次首次配置的前置状态，不假设全局 F 版本。七行在同一事务内全部插入，任一失败全部回滚；写入 `nx_commission_rule` 的 `commission_type`、`layer_no`、`usdt_rate`、`nex_per_usd`、`status=1`、`is_deleted=0`，其余真实 schema 默认列按原定义，不新增 schema/迁移。

业务权沿用 `network_f2_royalty_rate`，A2 maker/checker、对象锁 `F:unilevel_rule:bootstrap`、幂等/24 小时契约和原审批链均不旁路；金额/百分比转换复用现有 F2 helper 与真实 DECIMAL 精度，不另造上下限。成功后写既有 `F_TEAM_UNILEVEL_RULE_CHANGED` 审计，detail 保存显式 layers、理由、幂等键和 operationId；非空表、非法初值或写入冲突均保持原记录不变。
