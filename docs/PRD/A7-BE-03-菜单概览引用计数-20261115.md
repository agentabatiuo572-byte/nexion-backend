## 2. 最小实现

### 2.1 Overview 树节点

`PlatformMenuTreeOverview.MenuTreeNode` 末尾新增：

```java
long roleBindingCount,      // 当前守卫的 role_menu 绑定行数
long activePermissionCount  // 当前守卫的启用权限行数
```

- 字段放在 `MenuTreeNode` wrapper（overview 树），**不改 `MenuNodeView`**；create/update 成功回执仍只有原节点字段，不新增写链查询/字段/失败依赖。
- 原 `node`/`children` 顺序、树范围/排序、所有原字段不变；旧 PC `normalizeA7Node` 只取 `node/children`，额外 wrapper 字段可忽略。

### 2.2 两条批量查询

overview 各执行一次，按 `menu_id` 分组，后续内存合并；不逐节点 SQL/HTTP、无表/索引/缓存/框架：

- `AdminRoleMenuMapper.countActiveMenuBindingsByMenu`：

```sql
SELECT menu_id AS menuId, COUNT(*) AS count
  FROM nx_admin_role_menu
 WHERE is_deleted=0
 GROUP BY menu_id
```

- `AdminPermissionMapper.countActivePermissionsByMenu`：

```sql
SELECT menu_id AS menuId, COUNT(*) AS count
  FROM nx_admin_permission
 WHERE status=1 AND is_deleted=0
 GROUP BY menu_id
```

- `OpsPlatformMenuService.overview` 构造 `Map<Long,Long>`，`buildChildren` 递归时按节点 id 填两字段；空绑定合法为 0，查询失败正常抛错，不 catch 成 0。
- 不新增每节点查询，不改 `countActiveByMenuId` 原方法/守卫 SQL。

## 3. 语义边界

- `roleBindingCount` 是**当前守卫的 `role_menu` 绑定行数**，不等于不同角色数；表中若同一角色/菜单存在多行，行数会大于角色数。原表“几个角色”应按实际唯一关系另行核对，本候选不静默改成 `COUNT(DISTINCT role_id)`。
- 不过滤停用角色，也不判断角色是否启用；只要绑定行 active，守卫就会阻止删除/停用。
- `activePermissionCount` 是**当前守卫的启用权限行数**（status=1, is_deleted=0）；不是 API-only，不加 resource_type 过滤；未新定“有效权限”。
- 不过滤菜单可见性；树本身含 status=0 节点（`selectAllActive` 只排软删），计数对所有树节点计算。
- 父子节点各自独立计数，不向上汇总；不引入父闭包。
- 空绑定 0 是合法值；查询失败不得伪装 0。
