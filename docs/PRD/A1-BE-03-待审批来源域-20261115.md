## 1. 事实与问题

当前 `OpsAdminAccountService.overview:133-145` 的 `pendingAcctTickets` 来自 `pendingA1OperationTickets:829-830` → `OpsAuditCenterService.pendingOperationCountByActionMarker:214-225`:

- 取 `is_deleted=0`、`status='pending'` 的票，再在 Java 中按 `action.contains("(A1)")` 过滤。
- 现在 PC 的 A1 提案 action 是「编辑账号资料/变更角色/重置两步验证/启用禁用账号」等，不带 `(A1)`；新 A1 待审批会漏计。
- 反过来，其它域若 action 自带 `(A1)` 也会被算进来；动作文字不是授权/来源事实。

A1 的实际建票来源:

- 四项常规 A1 A2 命令：`a1_account_update_profile`、`a1_account_change_role`、`a1_account_reset_2fa`、`a1_account_status_update`（Guard `:78-82`、`:1200-1234`）。
- 治理恢复创建：`a1_account_create`；`sourceDomain` 请求为 A1，command 经 A2 头像/创建上下文。
- 全登出/历史安全基线等命令：`a1_account_force_logout`、`a1_security_baseline_update`（Dispatcher A 域命令）。
- A1 直接写（正常创建、密码重置、单会话撤销、资格、权限登记）不走 A2 pending 票；不应由本计数相加。
- A1 `linkA2Proposal` 的密码重置/RBAC 事后留痕走 `recordExecuted`，票状态是 `approved`，不是 pending；不能由 action 文字计入待审。

## 2. sourceDomain 持久化事实

- `OpsAuditCenterService.createProposalOnce:283,304,364-365` 把 `sourceDomain` 写入票；但 `normalizeDomain`（`:2192-2196`）只保留首字母：
  - `"A1"` 持久化为 `"A"`；`"A6"` 也是 `"A"`。票表的 `source_domain` 不能区分 A1/A6。
- 旧票可能 `A`/`A1`/null；不能仅凭 `source_domain='A'` 统计 A1，否则把 A6 算入；也不能仅凭 `source_domain='A1'`，新票实际是 A。
- `command_json` 是 pending 票的权威命令快照（`:425-512` 写入 `{domain,op,params,...}`）；A1 的 7 个 canonical op 及 A6 的 op 都在 Dispatcher `OPERATIONS`（A 域）中，必须用 command 的 `domain+op` 区分。
- 头像命令 `A2ReplayContext.isAvatarCommand` 使 `a1_account_create`/`a1_account_update_profile` 的 sourceDomain 变成 `"A"`（`OpsAuditCenterService:324-334`）；只按 sourceDomain= A1 会漏掉这类 A1 票。
- `command_json` 为 null/不可解析的旧票没有可靠 A1/A6 证据；本单不猜、不迁移、不回填；旧票在文档中标 unknown 边界，API 仍返回 int，无 unknown 状态字段。

## 3. 最小实现

只改 A1 的待审批计数，不动票据写入/审核/来源/动作/迁移:

1. `AuditOperationTicketMapper` 新增只读 SQL `countPendingA1Commands()`:
   - `is_deleted=0 AND status='pending'`
   - `command_json IS NOT NULL AND JSON_VALID(command_json)`
   - `UPPER(JSON_UNQUOTE(JSON_EXTRACT(command_json,'$.domain')))='A'`
   - `LOWER(JSON_UNQUOTE(JSON_EXTRACT(command_json,'$.op')))` 属于 A1 canonical op:
     `a1_account_create`、`a1_account_update_profile`、`a1_account_change_role`、`a1_account_status_update`、`a1_account_reset_2fa`、`a1_account_force_logout`、`a1_security_baseline_update`。
   - 不用 `action` 字符串，不用 `source_domain` 单字母，不扩 A6/A7。
2. `OpsAuditCenterService.pendingA1OperationCount()` 复用现有 `ensureSeedData()` 后调用该 SQL；返回值仍为 int。
3. `OpsAdminAccountService.pendingA1OperationTickets()` 改为调用新方法。
4. `pendingOperationCountByActionMarker` 原样保留，其它调用/全局 A2 计数/审核/权限/对象范围/错误行为不变。
5. 无新表/列/索引/迁移/seed/历史补写；无新权限；无前端/页面/文案。

## 4. 计数边界

| 票 | 是否计入 | 原因 |
|---|---|---|
| pending, command domain A + `a1_account_update_profile` 等 A1 op | 是 | canonical A1 command |
| pending, avatar `a1_account_create`/`a1_account_update_profile` sourceDomain A | 是 | command op 仍 A1 |
| pending, A1 command sourceDomain A/A1/null | 是（有 command） | command 权威，不依赖 source 字母 |
| pending, action 带 `(A1)` 但 command 为 A6/non-A1 | 否 | 防动作文字误计 |
| pending, A6 `a6_*` sourceDomain A | 否 | op 白名单 |
| approved/rejected/withdrawn/expired/软删 | 否 | 只 pending 未删 |
| pending, command_json null/坏 JSON | 不计（文档 unknown） | legacy 无可靠来源；不是 API 状态，不猜、不迁移 |
| A1 直接写无 A2 票 | 不适用 | 不是待审批票 |

旧 pending 票若只有 action `(A1)` 而无 command，本单不恢复计数；字段可能低估旧票。这里的 **unknown 只是文档边界**：API 仍返回 int，不新增 unknown 状态字段，也不声称旧票已完整计数；不把旧票猜成 A1，不回填、不迁移。

## 5. 读时初始化/副作用

- `OpsAdminAccountService.overview:133-145` 先 `seedSecurityBaselines()`，再调 `pendingA1OperationTickets()`。A1 overview **不是纯 GET**。
- `seedSecurityBaselines` 同时处理 session/lock 两行，行为不同：
  - **session** `seedBaselineIfAbsent("session", ...)`：先 `selectActiveByKey("session")`，只有不存在时才插入；已有 session 行不更新。
  - **lock** `seedDerivedLockBaseline:852-862`：不存在时插入；**已存在且 `baseline_value` 或 `description` 与 C6 `auth.risk.*` 派生值不同**时，调用 `upsertBaseline("lock",...)` **覆盖该行**，不仅新增。实际表 `nx_admin_security_baseline` 字段：`baseline_key,label,description,baseline_value,locked,sort_order,status,created_at,updated_at,is_deleted`；`ON DUPLICATE KEY UPDATE` 还会把 label/description/value/locked/sort_order/status/is_deleted 写为当前派生值（唯一键 `baseline_key`）。
  - 派生源: `auth.risk.login_lock_threshold`、`lock_duration_minutes`、`login_long_lock_threshold`、`long_lock_duration_hours`；lock 行 label「登录锁定基线」、locked=1、sort=20，value 形如「5次 / 15min + 10次 / 24h」。
- 该同步只更新 A1 的**派生展示 baseline 行**；不修改 `auth.risk.*` 配置、C6 登录风控本体、MFA 绑定/策略或账号会话。但它是持久写，不能因“已有基线”就保证纯读/只申请新增。
- 新 `pendingA1OperationCount()` 与旧方法一样调用 `ensureSeedData()`；当前 `readTimeBusinessSeedsDisabled()` 硬编码 true（`OpsAuditCenterService:1955-1969`），seed 分支立即返回；不能承诺未来仍不 seed。
- A2 `overview` 也调用 `ensureSeedData()`；`AuditOperationTicketMapper.createTicketTable` 是 DDL 方法但 overview 不调用；不新增 DDL。
- 计数 SQL 只读；`seedSecurityBaselines`/`ensureSeedData` 的既有行为不改；不删除/关闭既有 lock 同步。
- 真实 GET 验收须先列明：当前 session/lock 是否存在、lock 旧 baseline_value/description、GET 后预期 label/value/status 和是否覆盖、C6 `auth.risk.*` 不变、对运营展示/审计的影响，并取得具体数据批准；不能把 A1 overview 说成纯 GET 而绕过每菜单加数审批。
