## 旧状态只读库存

在目标环境先查询，不迁移或伪造历史单：

```sql
SELECT UPPER(status) AS status, COUNT(*) AS rows_count,
       COALESCE(SUM(amount_usd),0) AS amount_usd,
       COALESCE(SUM(ledger_id IS NOT NULL),0) AS posted_rows
FROM nx_wallet_asset_adjustment
WHERE is_deleted=0 AND UPPER(status) IN ('PENDING','PENDING_REVIEW','SUSPENDED')
GROUP BY UPPER(status);

SELECT UPPER(status) AS status, is_deleted, COUNT(*) AS rows_count
FROM nx_wallet_asset_adjustment
GROUP BY UPPER(status), is_deleted
ORDER BY status, is_deleted;
```

`PENDING`、`PENDING_REVIEW` 为旧待复核，`SUSPENDED` 为旧红线挂起；现有后端仍可审批、驳回、由发起人撤回，`historyOnly=true` 会排除这些状态。`ledger_id` 非空只表示已有关联账本，不能假定尚未入账。有效库存为零时该历史处理场景记为不适用，不造历史假单；非零时先核对单号、人员、金额、账本与锁，再与 PC 确认可读可处理方案。本次不擅改旧状态或前端列表。
