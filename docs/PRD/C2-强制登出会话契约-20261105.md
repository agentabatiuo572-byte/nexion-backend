# C2 强制登出会话契约

`POST /api/admin/users/profiles/{userId}/sessions/revoke-all` 要求 `user_c2_session_revoke_all`、`Idempotency-Key` 和操作理由。C5 的全设备登出接口要求其对应的 `user_c5_session_revoke_all`。两条直接接口均拒绝 `A2_PROPOSAL_REQUIRED`，包括超级管理员，不允许绕过另一人审批。没有活跃会话时，审批执行返回 `409 NO_ACTIVE_SESSION`。

两处入口共用 A2 命令 `C/c2_session_revoke_all`，目标为 `C/user/用户ID`。提案和批准分别要求当前 A2 资格及 C2 或 C5 全设备登出业务能力，发起人不得批准自己的提案。提案本身不撤销会话。本人可按原幂等键核对原提案或重试，无需泛 A2 读取权限；仍须保有 A2 提案资格及上述业务能力，不能据此读取他人工单。冻结、禁入和改密的既有撤销副作用不受这两条直接接口的审批守卫影响。

成功返回 `userId`、`status=REVOKED` 和 `revokedCount`。计数取操作前满足有效期和闲置期限的活跃会话数，会话撤销覆盖该用户全部会话。`C2_USER_SESSIONS_REVOKED` 成功审计记录同一计数。相同命令按原幂等规则回放结果。

C2 与 C5 共享 A4 事件 `admin.session_revoked`，业务字段为 `target_user_id`、`operator`、`role`、`reason`、`scope` 和 `occurred_at`。`operator`、`role` 取自认证运营账号。C2 全部登出使用 `scope=all`，C5 单会话撤销使用 `scope=current`。C2 的 `revokedCount` 仅用于接口回包和审计。

## 用户数据只读视图的有效期

时长仅允许 5、10、15、30 分钟，自批准创建时刻起算，不支持续期。会话记录、JWT 和返回的截止时间使用同一签发时刻；数据库时间按 Asia/Shanghai 存储。5 分钟对应 `expires_at-created_at=300秒` 及 JWT `exp-iat=300秒`，不因 JVM 时区与应用数据库连接池时区不同而改变。列表、读取鉴权、主动结束及过期审计沿用同一业务时钟；普通 App 和管理员登录的签发方式保持原合同。

升级迁移只把未删除、`ACTIVE`、合法时长且截止超过创建时刻加 TTL 的行归正到原 TTL；不整体平移时间，不更改已结束行或原审计。执行前保留旧行及应用池实际时区证据。S32 名称统一的剩余服务端显示文案另行登记，不以有效期修复代替页面确认。
