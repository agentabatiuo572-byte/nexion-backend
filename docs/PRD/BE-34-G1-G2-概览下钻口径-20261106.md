# BE-34 G1、G2 概览下钻口径

依据 B30 第 34 项、S22 与 G-DEC15。

- G1 `GET /api/admin/market/staking` 的持仓状态计数与清单只取四档历史 USDT 质押，排除已删除记录。提前解锁按 `early_withdrawn_at` 取 LEGACY 业务月，包含月初，截止于下月月初之前。其他状态保持不限月份。
- G2 `GET /api/admin/market/exchange` 的个人额度、平台额度及地区拦截总数与清单按各自状态和 `created_at` 取当前 LEGACY 业务日，包含日初，截止于下一业务日之前。排队清单仍可跨业务日。
- 分组总数按符合范围的全部记录计算。G1、G2 各组明细保持既有排序并最多返回 50 条。

## 2026-11-16 补充：G1 概览按正式到期条件投影持仓状态

`GET /api/admin/market/staking` 是只读投影，不推进 `nx_staking_position`、不生成账本、不改领取与收益：

- 生效状态：持久 `status` 为 `ACTIVE` 且 `unlock_at <= 本次now` 时投影为 `MATURE_UNCLAIMED`（与 App 读取时 `matureDuePositions` 的到期条件、以及领取入口允许已到期 `ACTIVE` 直接领取的规则一致）；`ACTIVE` 分组只保留 `unlock_at > 本次now` 的记录；其余状态按持久值。
- 持久值单独以 `storedStatus` 返回，`status`、`statusLabel`、`statusTone` 用投影后的状态；未到期 `ACTIVE` 仍是「计息中」，已到期未领显示「到期未领」。
- 同一次请求内计数与清单共用同一个 `now`（同一 `Clock`），不出现「计数已到期、清单未到期」的错位；`count` 与 `rows` 仍按同一 scope（四档 USDT、排除已删除、提前解锁按 LEGACY 业务月）。
- 七组顺序、每组最多 50 条、四档范围、排序与权限不变；App 质押读取、领取、D1/资金账本、写入口一律不动。
- `REFUNDED`（已退款）在现行代码中仍没有产生该状态的路径，本投影只如实显示持久值，不新增退款状态、不回填历史。

## 2026-11-16 补充：历史质押奖励汇总与持仓同范围

G1 概览的 `stats.interestUsd`（`nx_staking_position.estimated_interest_usdt` 汇总）此前不过滤产品，与本文件「持仓计数与清单只取四档历史 USDT」的范围不一致。现该汇总也按同一四档 `USDT_30D`、`USDT_90D`、`USDT_180D`、`USDT_365D` 过滤：

- 仍只统计 `ACTIVE`、`MATURE_UNCLAIMED` 且 `is_deleted=0`；`COALESCE(...,0)` 的真 0 语义不变，不改为 null。
- 奖励列仍为 USDT，时间范围与其他状态口径不变；不改资金、产品、利息生成或历史数据。
- 该值不只在 GET `/api/admin/market/staking` 出现：改池参数、开售、熔断处置与 J1 恢复四个写方法成功回执复用同一 overview，因此这些**新**回执里的 `stats.interestUsd` 也按四档计算；已存的旧成功回执保留原值，不回填、不重算。

## 2026-11-16 补充：G1 概览的最小起投金额保留原精度、缺源为 null

`GET /api/admin/market/staking` 的档位行里，`minStake` 直接取 `nx_staking_product.min_amount`（`DECIMAL(18,6)`，`NOT NULL` 且 `CHECK (min_amount > 0)`）：

- 此前实现先 `setScale(2, HALF_UP)` 再输出，等于把 6 位小数的库值改成 2 位，`0.000125` 这类值会被舍成 `0`；现按库值原精度输出（仅去掉末尾无意义的 0，例如 `100.000000` → `100`），不再做任何舍入。
- 若某行确实取不到最小金额（`null`），`minStake` 与 `minDisplayValue` 都返回 `null`，不再用 `safeBig` 把缺源改写成 `"0"`，也不显示成 `"0 USDT"`；真实配置的 0 与本字段无关（库上有 `min_amount > 0` 约束）。
- `lockedUsd` / `lockedDisplay` 保持原样：它来自 `COALESCE(SUM(...), 0)`，为 0 表示该档确实没有锁仓，属于真实 0，不改成 null；`stats.interestUsd` 仍直接取仓储聚合值。
- 其余不变：只读投影，不推进持仓状态、不生成账本、不改质押结算/准入/收益/本金或 G1 退役政策；不引入价格、汇率或默认兜底；读权限与查询范围、其余字段与排序均未改。
