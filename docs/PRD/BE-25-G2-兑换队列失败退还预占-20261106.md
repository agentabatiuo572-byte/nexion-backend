# BE-25 G2 兑换队列失败退还预占

G2 批处理执行兑换时，钱包更新拒绝本次交易的订单终止为 `FAILED`，批次回执在失败项中返回 `WALLET_BALANCE_CONFLICT`。若订单已有成功的来源币预占，则原币原额退还到用户可用余额，并写入一条 `<exchangeNo>-REFUND` 兑换流水。历史无预占单在失败时没有资金变动。

订单终止、余额回退、退款流水和资金凭证在同一个事务内提交。回退不能完成时，批处理事务回滚，待处理订单仍为 `QUEUED`。退款不发放目标币，不扣手续费。重复读取原批次回执或处理下一批不会再次退款。

资金凭证沿用 `CANCEL` 阶段表达预占释放，记录的原单终态仍为 `FAILED`。对账须核对原预占与退款的金额、币种及钱包变动。现有 G2 批次事件和审计记录保留失败统计和结果，事件注册补齐已发送的 `failed_count` 和 `outcome` 字段。

## 原批次回执核对

G2 批次成功后保留幂等回执和发起管理员的稳定编号。本人具备 G2 批处理权限时，可带原 `Idempotency-Key` 调用 `GET /api/admin/market/exchange/queue/process`，返回原批次统计及各订单结果。查回执不执行兑换或更新队列。

缺少本人归属、历史未绑定归属或暂不可读取的原命令返回 404。历史 POST 的原请求指纹和原成功回执继续可重放；服务端仅向新批次发起人提供该批次回执。页面先查回执，再读当前队列。
