# B15 主管接待与 B16 注册欢迎语

## 对客发送与接待

专属客服、主管和总管理员从原首次联系或回复接口发消息，正文、商品、图片仍走原命令。必须拥有 `service_m3_write` 并在当前绑定范围内。客服给自己绑定的客户发消息时记录 `ADVISOR`，即使兼任主管。主管在本组给其他客服的客户发消息时记录 `SUPERVISOR`，总管理员在获准范围内记录 `ADMIN`。会话仍归客户绑定的专属客服，消息作者显示实际发送人。主管、总管理员不能发 `MAINTENANCE`。维护、业绩、客户活跃和首次联系沿用原事实口径，主管与管理员仍可处理客户的待回复。

单个客户同时只有一个接待人。后台个人发言取得接待，之后每条个人发言重新计时。客户发言、已读和圈选群发不计时。圈选群发遇到其他人接待时，批次结果为 `SKIPPED`，`failureCode` 为 `SUPPORT_SESSION_BUSY`。接待人失去资格或客户转绑时原发送路径重新核验，接待到时释放。持有人主动结束只让出接待，保留会话、绑定及待回复；专属客服成功标记已解决也释放接待。

| 后台入口 | 行为 |
|---|---|
| `GET /api/admin/content/support-workbench/customers/{id}/session-hold` | 从当前客户范围读取 `FREE`、`MINE` 或 `OTHER`，含 `holder`、`lastSentAt`、`autoEndAt` 和 `endMinutes`。未绑定、越组为 404。 |
| `POST /api/admin/content/conversations`、`POST /api/admin/content/conversations/{no}/replies` | 同一客户写入串行。其他人正在接待时返回 409 `SUPPORT_SESSION_BUSY`，带持有人及预计结束时间。主管维护返回 422 `SUPPORT_SESSION_MAINTENANCE_NOT_ALLOWED`。 |
| `POST /api/admin/content/support-workbench/customers/{id}/session-hold/end` | 带 `Idempotency-Key`，仅当前接待人可结束。其他人调用返回 409 `SUPPORT_SESSION_NOT_HOLDER`。 |
| `GET/PUT /api/admin/content/conversations/timeout-policy` | `sessionEndMinutes` 默认 10，接受 2–120 的整数。和提醒策略共用版本、理由、总管理员及原配置权；新值立即决定尚未结束的接待何时到时。 |

后台收件箱各行返回当前 `holder`。接待开始及结束经现有会话事件通知可读该客户的后台端，输入状态按当前接待人和权限检查。每条人工后台消息记录 `senderRole`。客户上一次个人客服消息来自其他人时，先插入一条 `system/AGENT_SWITCH`。App 返回新接待人名字，管理端同时返回身份。切换提示不增加未读，不替换列表预览，不修改最后消息时间。发起、回复、接待结束及拒绝均记录审计，在忙碌拒绝记录中保留接待人。

## 注册欢迎语

手机号和第三方注册在同一事务完成客服绑定和欢迎消息写入。已有绑定时，欢迎语显示绑定客服的真实名字与头像。无绑定时创建无归属的专属会话，欢迎语无作者，客户仍可先留言。后续首次绑定沿用该会话。每个新账号只有一条欢迎语，发出的正文使用注册时账号语言和已发布版本。中文用 `zh`、越南文用 `vi`、其余使用英文。

App 收到普通 `agent/TEXT` 客服消息，未读为 1，沿用原已读接口清除。后台分页和详情为该消息返回 `origin=WELCOME`。这条消息不占接待、不算上一次人工客服发言、不触发随机分配，不产生待回复、首次联系、主动维护和业绩事实。

`GET /api/admin/content/support-agents/welcome-message` 返回 `version`、`texts.zh/en/vi`、`updatedAt`、`updatedBy` 和 `reason`，读取权限同客服规则。总管理员持原规则写权可用 `PUT` 和 `Idempotency-Key` 更新，提交 `expectedVersion`、三语文本和理由。每段去掉首尾空白后为 1–500 个字符并允许换行，理由 8–200 个字符。版本不符返回 409，同键同内容在 24 小时内恢复原结果。命令回查沿用 `GET /api/admin/content/support-workbench/commands/{key}`。迁移只在配置缺失时插入默认文案，重启保留运营保存的内容；已发消息保留原文。
