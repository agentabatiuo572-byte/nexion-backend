# D2 提现冻结与原审核原因

对应 BUG-292。

- 冻结期间，提现列表和详情继续提供当次冻结理由、责任人、期限及复查时间。服务端随冻结保存原审核原因。手动解冻或冻结到期回到待审核时，恢复原有原因。原因为空的普通单，手动解冻后仍为空。普通冻结到期沿用原有的到期复查提示。
- 大额加强审核原因来自提交时的强审判定。历史冻结单和曾解冻、仍待审核的历史单，凭同一用户和提现单的成功提交审计恢复强审标记。已经解冻的历史单还须有成功解冻审计且原因为空。未保留证据的原因保持现状。
- 解冻只回到待审核。后续放行仍走原有鉴权、角色、地址确认、实时风控和兑付覆盖率校验。

## ERC20 失去链上确认

ERC20 的 `TX_ORPHANED`（含历史 `DEAD`）继续冻结并占用提现额度，不允许手动退款。直接调用 D2 `REFUND` 时，在状态、钱包、待提现、预留、账本和事件改变前明确拒绝 `409 ERC20_ORPHANED_REFUND_FORBIDDEN`，不能把出款结果未知当作未出款。既有服务商标记保护、银行轨核对及其他链退款条件保持。合法审核拒绝仍按原预留返还合同入账；底层预留状态不合法时返回明确的 409 业务拒绝。
