## 1. 背景与既有事实

- 原始待办：`uvel-docs` `origin/main` `handoffs/2026-10-28/backend/20-backend-pending-20261031.md:1562` A6-BE-03。
- `GET /api/admin/platform/roles/overview`（`platform_a6_read`）当前 `RoleSummary` 只有 `adminCount`；权限/菜单数量只能逐个读 `GET /{roleId}`。
- 详情两个集合的现行口径：
  - `permissionCodes`：`role_permission.is_deleted=0` + `nx_admin_permission.status=1/is_deleted=0/resource_type='API'`，`SELECT DISTINCT permission_code`；**不按角色 status 过滤**，不排除 `PERM_*`；
  - `menuIds`：`SELECT menu_id FROM nx_admin_role_menu WHERE role_id=? AND is_deleted=0`；**没有 DISTINCT、没有 menu 表 JOIN**，可能含停用/软删菜单 id。
- 本候选只恢复这两个既有 detail 绑定统计，不定义“实际生效/可见”指标。

## 2. 最小实现

### 2.1 DTO

`PlatformRoleOverview.RoleSummary` 末尾新增：

```java
long permissionCount,   // 项：active API 权限去重码数，等于 detail.permissionCodes.size()
long menuGrantCount     // 个：active 角色-菜单绑定行数，等于 detail.menuIds.size()
```

原有字段/顺序不变；旧 PC 只读已知字段，额外 JSON 可忽略。

### 2.2 批量查询

不逐角色发 HTTP，不新增缓存/表/索引/框架。overview 一次读取两条 `GROUP BY role_id`：

- `AdminRolePermissionMapper.countActivePermissionCodesByRole`：

```sql
SELECT rp.role_id AS roleId, COUNT(DISTINCT p.permission_code) AS count
  FROM nx_admin_role_permission rp
  JOIN nx_admin_permission p
    ON p.id=rp.permission_id
   AND p.status=1 AND p.is_deleted=0 AND p.resource_type='API'
 WHERE rp.is_deleted=0
 GROUP BY rp.role_id
```

  必须按 `permission_code` DISTINCT，与 detail 的 `SELECT DISTINCT permission_code` 一致；不用 p.id。

- `AdminRoleMenuMapper.countActiveMenuGrantsByRole`：

```sql
SELECT role_id AS roleId, COUNT(*) AS count
  FROM nx_admin_role_menu
 WHERE is_deleted=0
 GROUP BY role_id
```

  用绑定行 `COUNT(*)`，与 detail 的 `menu_id` 列表长度一致；不加 DISTINCT、不 JOIN menu、不过滤角色状态、不补父子闭包/超管全导航。

### 2.3 overview 合并

- 两条查询各执行一次，结果按 `roleId` 放入 Map；现有角色循环用 `getOrDefault(roleId,0L)`。
- 空绑定合法返回 0；查询失败正常抛错，不 catch 成 0。
- overview 继续包含 status=0 停用角色，不包含软删角色；计数不按角色 status 过滤，保证与 detail 的绑定集合一致。
- 不改 `countAdminsByRole` 的既有 N+1（A6-BE-04 独立），不新增每角色查询。

## 3. 语义边界

- `permissionCount` 是“详情当前返回的启用 API 权限码数量”，不是原始关系行数；停用角色仍可能 >0，但不是该角色账号的实际生效权限。
- `menuGrantCount` 是“详情当前返回的菜单绑定数量”，不是实际可见菜单数：detail 不 JOIN menu，可能含停用/软删节点；实际导航另有限制，超管导航还独立于 role_menu。
- 无角色父子继承；`SUPER_ADMIN`/`admin.super_admin` 的生效导航不在本计数内。
- 若后续要真正“有效权限/可见菜单”，是另一未实施合同，需同步 detail/页面/停用/超管规则；本候选不实现、不声明。
