# A2 工单身份与原键恢复

## 工单归属和决定

A2 队列和工单回执的 `mine` 表示当前已认证管理员是原发起人。使用实际账号 ID 判定。登录名、显示名和脱敏操作人用于展示。同一个账号改名后仍拥有其原工单，其他账号即使显示同一脱敏名也按自己的身份与权限处理。只允许查看本人工单的角色也按实际账号 ID 限定可见范围。

发起人不能批准或驳回自己的工单，可以按原权限撤回。其他管理员仍须通过原 A2 决定权限和目标域授权。历史工单使用可信发起审计或原有服务端绑定的发起人身份，已归档的原审计可用于恢复。身份缺少可信证据或相互冲突时，拒绝依赖归属的决定，保留原记录。

## 共享命令的原键

提案、即时操作留痕和工单决定用已认证的管理员 ID、操作和业务载荷生成请求摘要。相同键按原命令恢复。其他账号重用该键不能读到先前操作者的回执。不同业务请求用新键。

提案处理租约届满后，成功创建的工单仍按原发起人、键及原请求恢复，包括已驳回和已撤回的工单。已有成功回执用原命令摘要和可信审计验证。存在原提案但缺少可信回执时保留原键恢复入口，待处理或结果未知的记录仍受原门禁保护。

原键查询入口为 `GET /api/admin/platform/audit/operations/proposals/by-idempotency-key?idempotencyKey=...`。漏传 `idempotencyKey` 返回 HTTP 400 并指出缺失参数。已传的空值及不合法键按原校验返回。合法查询仍需当前可读权限及原发起人身份。

## 确认摘要的资金效果

A2 队列及工单回执提供可空的 `operationCode`、`fundEffect` 和 `refundOrderNo`，供确认摘要和退款奖励影响面板使用。服务端依据有权查看的工单中保存的结构化命令及其所属域填充。缺少匹配命令或必要参数的历史工单仍可查看，相关字段为空。

| 操作 | `operationCode` | `fundEffect` | `refundOrderNo` |
| --- | --- | --- | --- |
| F5 暂停奖励 | `f5_commission_suspension` | `REWARD_SUSPENSION` | 空 |
| F5 恢复奖励 | `f5_commission_suspension` | `REWARD_RESUMPTION` | 空 |
| E4 订单退款 | `e4_order_refund` | `ORDER_REFUND` | 已保存退款命令的原订单号 |

`fundEffect` 表示拟审批的资金效果。F5 暂停及恢复仍使用原 `acct` 类型，审批和资金红线按原契约判断。摘要接入以结构化字段为准。旧原键回执保留操作快照并补充该元数据，当前状态仍可从 A2 原键查询。

## A6 角色写入回执

角色创建、编辑、状态修改、删除和授权使用同一写入回执约束。服务端按认证管理员 ID、操作、目标、原键和业务内容识别同一请求。审批回放还绑定实际工单编号。通过当前入口权限检查后，原操作者可按同一键恢复已成功回执。另一账号在同一操作和目标重用该键时返回 `409 IDEMPOTENCY_KEY_PAYLOAD_MISMATCH`，不返回原单据或角色快照。未成功的领域操作可按原键重试。

升级前的回执须匹配原请求。角色直接变更从热审计或归档审计核对原操作、目标、键和唯一的操作者 ID。待审回执还核对实际工单命令、目标与原发起审计。归属或结果缺少可信证据时返回 409。回读当前审批状态继续使用 A2 原键查询。
