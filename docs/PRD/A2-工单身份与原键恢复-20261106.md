# A2 工单身份与原键恢复

## 工单归属和决定

A2 队列和工单回执的 `mine` 表示当前已认证管理员是原发起人。使用实际账号 ID 判定。登录名、显示名和脱敏操作人用于展示。同一个账号改名后仍拥有其原工单，其他账号即使显示同一脱敏名也按自己的身份与权限处理。只允许查看本人工单的角色也按实际账号 ID 限定可见范围。

发起人不能批准或驳回自己的工单，可以按原权限撤回。其他管理员仍须通过原 A2 决定权限和目标域授权。历史工单使用可信发起审计或原有服务端绑定的发起人身份，已归档的原审计可用于恢复。身份缺少可信证据或相互冲突时，拒绝依赖归属的决定，保留原记录。

批准和驳回按认证会话中的管理员 ID 核对账号的当前启用状态。已停用、已删除或不存在的账号即使持有仍可认证的旧会话，提交决策或按原键重试也返回 HTTP 403。新决定在取得工单行锁后再次读取当前状态，覆盖等锁期间提交的停用。该拒绝保留工单原状态、对象锁及目标业务数据。当前仍具备审批和目标访问权限的原操作者可按原键恢复成功回执。

## 当前账号的批准与驳回资格（B44）

`AuditOperationTicket` 在 overview 队列及其单票详情、本人原键查询、提案／即时留痕／决定响应和原成功回执中统一增加以下字段，不新增详情接口，不改变已有读取范围：

| 字段 | 类型及含义 |
| --- | --- |
| `canApprove` | 布尔；当前账号是否具备对当前原单发起新批准的资格 |
| `canReject` | 布尔；当前账号是否具备对当前原单发起新驳回的资格 |
| `approveDeniedCode` | 可空整数；批准资格被拒时原检查的 `ApiResult.code` |
| `approveDeniedMessage` | 可空字符串；批准资格被拒时原检查的 `ApiResult.message`，保留机器原因及冒号后的细分内容 |
| `rejectDeniedCode` | 可空整数；驳回资格被拒时原检查的 `ApiResult.code` |
| `rejectDeniedMessage` | 可空字符串；驳回资格被拒时原检查的 `ApiResult.message` |

对应资格为 true 时，其两项拒绝信息均为 null；为 false 时保留真实检查的 code 和 message。新决定及能力读取共用当前账号、全局批准权、原单域范围、pending 状态、可信原发起人、异人审批和原命令必要身份／对象／分类／锁绑定检查。本人、终态、发起人无法核验或原命令不可识别时不默认可批准；普通历史单缺命令不因此新增驳回限制。两个实际决定入口的身份、全局权和域范围拒绝统一由本规则返回 `403 FORBIDDEN`，其他业务接口的错误协议保持原契约。

业务资格复用后端实际决定的规则，分别判断批准和驳回。保留退款、A4、J1、课程、G4、D5／D6／D7、设备、券、增长和资金专项的原角色／动作权限及原拒绝原因；不以读权、发起权或“超管”标签代替实际授权。G4 按原单是否变供应量区分所需权限；D7 强制倒挂专项权仅用于批准；G4 目录、课程激活和 D6 批准时核原发起人当前资格，驳回沿用原较小条件。增长的 E5 强制激活／解绑委托仍必须具备全局 A2 批准权，不扩大到其他设备动作。A1 当前角色和登出对象、E1 强制开关转换、L5 报告自己的发起人及大使当前材料核验人与最终执行人分离约束，同样采用实际业务的共享资格检查。

D2 解冻沿原 SUPER_ADMIN／FINANCE_LEAD／RISK_LEAD 角色资格；提现通过只读取当前原提现金额和有效强审门槛，金额达到（含等于）门槛时沿原 SUPER_ADMIN／FINANCE_LEAD 资格。角色不足保留 `403 WITHDRAWAL_ROLE_NOT_ALLOWED`；不新增财务读写动作权限，普通 A2 驳回不叠加这些批准条件。原单或门槛缺失，以及风险、披露等业务执行前置，不转换为资格拒绝，仍由实际业务入口检查。

这些角色条件不覆盖既有普通 A2 准入。当前账号具备 `platform_a2_proposal_create` 而没有 `platform_a2_write` 时，原委托路径对未映射的 D2 命令仍返回 `403 A2_BUSINESS_PERMISSION_UNMAPPED`；符合主管角色也不绕过该拒绝。页面使用返回的当前资格和原因，不另行推导这组权限组合。

J4 以原提案保存的授权快照核验当前 SOP 定义，变更时批准资格返回原 `J4_PLAYBOOK_SNAPSHOT_CHANGED` 等原因；驳回保持普通资格。checker 仅按原规则要求 A2 批准权和 J4 执行权，不新增 maker 提案时各目标直写权限。能力计算只读取当前事实，不初始化表、取得执行写锁、认领命令或运行目标业务。

资格为 true 不表示全部业务执行前置已通过。理由／原键输入校验、资金与 B1 覆盖率、参数合法性、业务快照和版本、供应商、库存、材料、文件及实际任务条件仍由提交时的原业务链检查。实际新决定在原锁内重核资格，退款维持先订单参与对象、再工单的锁顺序。读取能力不执行预演，不修改工单、锁、原成功回执、目标业务或资金。

普通成功回执的业务快照及 status 保持原样；原有专项提案恢复回读当前工单的语义保持不变。六个资格字段每次按当前 DB 工单和当前查看者重新计算。因而普通旧回执 status 仍为 pending、但当前工单已终态时，两项新决定资格为 false。合法同键恢复已成功决定仍要求当前启用身份、全局批准权和原单域访问权，不以终态或新决定的 maker 检查阻断恢复，也不重放决定。

本轮只交付后端和本契约。PC 后续按这六个字段显示入口及原因并删除重复授权规则；本轮未修改 PC、App 或 H5 Lite 页面。

## 共享命令的原键

提案、即时操作留痕和工单决定用已认证的管理员 ID、操作和业务载荷生成请求摘要。相同键按原命令恢复。其他账号重用该键不能读到先前操作者的回执。不同业务请求用新键。

同一待审工单并发提交决定时，业务只生效一次。同键同请求在原决定执行中返回 `409 IDEMPOTENCY_REQUEST_IN_PROGRESS`，完成后按原键返回原成功回执；不同键的决定仍按工单串行核验，已完成的工单返回 `409 A2_OPERATION_ALREADY_TERMINAL`；带调查绑定的命令（如 E4 退款）在原决定仍处理中时，可能先由原键门禁返回 `409 IDEMPOTENCY_ORIGINAL_OPERATION_REQUIRES_INVESTIGATION`。批准与驳回并发也只允许一个终态决定，发起人／审批人资格及原审批业务规则保持不变。

提案处理租约届满后，成功创建的工单仍按原发起人、键及原请求恢复，包括已驳回和已撤回的工单。已有成功回执用原命令摘要和可信审计验证。存在原提案但缺少可信回执时保留原键恢复入口，待处理或结果未知的记录仍受原门禁保护。

原键查询入口为 `GET /api/admin/platform/audit/operations/proposals/by-idempotency-key?idempotencyKey=...`。漏传 `idempotencyKey` 返回 HTTP 400 并指出缺失参数。已传的空值及不合法键按原校验返回。

已认证的有效管理员可凭 `platform_a2_proposal_create` 原键找回本人发起的普通提案（无业务回放指令）。服务端按管理员 ID 和原幂等键定位发起记录，再核验工单的原发起人。其他人的键与未知键均返回 `404 OPERATION_RESULT_UNKNOWN`。A2 列表、操作日志及按追踪号查日志继续要求 A2 读权限。G4 创世商品档位等专项提案继续执行各自的业务权限校验。

无 A2 读权限的发起人也可凭提案权限和当前业务权限恢复本人发起的三种财务提案。D1 Cregis 充值策略要求渠道配置权限。D5 提现限额逐项核对原提案涉及字段的写权限。D7 法币提现参数要求配置权限，涉及强制倒挂时还要求倒挂专项权限。恢复只读原工单及其当前状态，无需重验业务配置版本。

C2 用户冻结和恢复提案的原发起人，即使其 A2 列表范围不含 C 域，也可按原键读取本人原单。此恢复例外要求账号当前启用，且仍有 `platform_a2_proposal_create` 及原动作对应的业务权限：`c2_account_freeze` 要求 `user_c2_account_freeze`，`c2_account_unfreeze` 要求 `user_c2_account_unfreeze`；另一动作的权限不能替代。原键查询返回原单当前状态，同键、同对象和同请求的 POST 恢复已成功回执，不重新创建或执行提案。账号停用或上述权限撤销后，不再允许通过此例外恢复。此规则只补齐本人原对象、原动作的回执，不扩大财务的 A2 跨域列表、他人工单或批准权限。

## 确认摘要的资金效果

A2 队列及工单回执提供可空的 `operationCode`、`fundEffect` 和 `refundOrderNo`，供确认摘要和退款奖励影响面板使用。服务端依据有权查看的工单中保存的结构化命令及其所属域填充。缺少匹配命令或必要参数的历史工单仍可查看，相关字段为空。

| 操作 | `operationCode` | `fundEffect` | `refundOrderNo` |
| --- | --- | --- | --- |
| F5 暂停奖励 | `f5_commission_suspension` | `REWARD_SUSPENSION` | 空 |
| F5 恢复奖励 | `f5_commission_suspension` | `REWARD_RESUMPTION` | 空 |
| E4 订单退款 | `e4_order_refund` | `ORDER_REFUND` | 已保存退款命令的原订单号 |
| 其它有已保存结构化命令的工单 | `command.op()`（完整、稳定的操作码） | 空 | 空 |

`operationCode` 只在工单确实保存了可解析的结构化命令时填充，取原命令的 `op`，不从动作名称、前后文案或页面状态推测；没有命令的旧票保持空。A4、H7、H2、J1、F5、E4 的既有值继续按原分支返回，不改变已下发值。E4 退款命令缺少订单号时继续保持空，不回退成通用代码。

同一原工单在创建回执、本人按原键、队列、详情和历史中使用同一份 `ticketMetadata`，由已保存命令推导，不因入口不同而改变代码。`operationCode` 只是确认摘要/页面展示元数据，不是批准或读取授权；权限、本人归属、目标、版本、对象锁、业务回放和决策规则不变，未知命令也不会因填码获得任何放行。

处理历史另有精简摘要 DTO，同样从已获权查看的原工单元数据带出可空的 `operationCode`。无法关联原工单或原命令无法解析的旧记录继续为空，不从历史动作、结果或说明推测。历史的既有字段、排序、执行链和读取权限保持原规则。

PC 现有消费者只按具体代码判断：J1 恢复、A4 注册类、H7 券处置和 K1 找回分别匹配各自的 `command.op`；本次补齐让 K1 找回的代码从“空即跳过”变为与预期代码一致，其他特定代码判断不受影响。页面接入/文案属于 PC 后续任务，本次只补后端字段。

`fundEffect` 表示拟审批的资金效果。F5 暂停及恢复仍使用原 `acct` 类型，审批和资金红线按原契约判断。摘要接入以结构化字段为准。旧原键回执保留操作快照并补充该元数据，当前状态仍可从 A2 原键查询。

## A6 角色写入回执

角色创建、编辑、状态修改、删除和授权使用同一写入回执约束。服务端按认证管理员 ID、操作、目标、原键和业务内容识别同一请求。审批回放还绑定实际工单编号。通过当前入口权限检查后，原操作者可按同一键恢复已成功回执。另一账号在同一操作和目标重用该键时返回 `409 IDEMPOTENCY_KEY_PAYLOAD_MISMATCH`，不返回原单据或角色快照。未成功的领域操作可按原键重试。

升级前的回执须匹配原请求。角色直接变更从热审计或归档审计核对原操作、目标、键和唯一的操作者 ID。待审回执还核对实际工单命令、目标与原发起审计。归属或结果缺少可信证据时返回 409。回读当前审批状态继续使用 A2 原键查询。

角色写入和成功回执在同一外层业务事务中提交或回滚。执行前按原记录编号核对当前持久认领状态；不能因外层事务保留了认领提交前的旧快照，而误报命令认领失效。只有当前记录未删除且仍为 `PROCESSING` 才继续业务处理。此核对保留原隔离级别、原键归属校验、权限和双人审批要求，不重放结果未知或已受控结案的命令。
