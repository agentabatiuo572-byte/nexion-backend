# H3 任务奖励的资金放大审批

2026-11-06。对应 BUG-286 的 H3-A02、A03、A10、A11 阶段倍率、A20、A22 后端范围；不包含页面修改，也不代表整单关闭或公共 TEST 已部署。

## 生效规则

| 业务动作 | 须等待另一人批准 | 原入口立即执行 |
| --- | --- | --- |
| 首日三档奖励 | 完整奖励或宽限奖励任一提高，即使另一档降低 | 两档均未提高的有效收紧；过期档仍必须为 0 |
| 首日、WEEKLY_T1、WEEKLY_T2 新任务 | 创建正奖励任务 | 创建零奖励任务 |
| 周任务、月主题奖励 | 奖励提高 | 奖励降低 |
| H3 的 P1～P6 阶段倍率 | 倍率提高，或原未配置后首次给出有效正倍率 | 倍率降低 |
| 商城备用卡 | 基础奖励提高、倍率提高、paused 改 active | 奖励/倍率降低、active 改 paused |

正奖励任务在批准前不存在，批准后仍为 paused，审批不会替任务绑定事件或启用。原始整数、金额精度在方向比较前校验：周任务奖励与备用卡基础奖励为整数；月奖励、首日两档和文本倍率最多 6 位有效小数，不通过四舍五入或截断改变方向。原有上下界、任务类型、路由和分类校验继续执行。

直写放大返回 `409 H3_APPROVAL_REQUIRED`。提案和批准均要求 B1 数据可靠、UVT 估值为正，并用 B1 的精确红线判定；显示为 100.00% 不能覆盖实际低于线的结果。缺可靠数据返回 `B1_COVERAGE_DATA_UNAVAILABLE`，实际低于线返回 `B1_COVERAGE_BELOW_REDLINE`。收紧不受这项放大检查阻断。

## A2 合同

- 保留原普通写入口：`POST /api/admin/growth/quest-events/missions` 和 `PATCH /api/admin/growth/quest-events/config/{key}`；放大改用 `POST /api/admin/platform/audit/operations`，`sourceDomain=H3`、`type=fund`、`amplifies=true`。
- 配置指令为 `domain=H, op=h3_quest_config`，`params.values` 只含 `configKey, value, expectedValue` 三个字符串。白名单为 `dayOne.triReward`、`mission.{code}.reward`、`monthly.{code}.reward`、`weekly.mult.P1`～`P6`、`promoBanner.baseReward/multiplier/status`。目标为 `{domain:H,type:h3_quest_config,id:configKey}`，`obj=configKey`。
- 创建指令为 `domain=H, op=h3_mission_create`，`params.values` 只含 `missionCode, missionName, missionType, rewardPoints, category, actionRoute`；`rewardPoints` 为非负 JSON 整数，其余为字符串。目标为 `{domain:H,type:h3_mission,id:missionCode}`，`obj=missionCode`。
- 有 `growth_h3_write` 的管理员可发起本类提案，且可按 `GET /api/admin/platform/audit/operations/proposals/by-idempotency-key?idempotencyKey=原键` 恢复本人原结果；这不授予泛 A2 读取、跨域提案或审批权。不新增角色、grant 或菜单配置。
- 批准/驳回仍要求有效超管和 `platform_a2_operation_approve`，发起人与审批人必须不同。服务端绑定真实 maker，以及任务/月主题的对象 ID、类型、状态，备用卡的原整卡状态和配置原值；批准重新核对，陈旧票不得覆盖新状态。
- 批准回放经过原 `OpsGrowthCommandBoundary` 与原业务方法，保留奖励 CAS、领域审计、命令事件和幂等。客户端提供的 maker/状态不能取代服务端绑定。旧形状或其他回放指令不能获得批准执行的放行标志。

## 快照和未交付边界

方向、CAS 和 B1 校验通过后、实际变更前，才冻结旧周定义。直写被拒绝或仅提案预检不发布周 header/items/bindings。已开始首日实例的任务、奖励、资格时长及已有周定义不回写；今后真实新周期仍由原发布流程读取当时任务定义。审批不改变 H1 的 `questBonusMultiplier`。

`weekly.champBonus` 仍为最多 160 字自由文本。现有规格没有确定币种、金额、阶段与冠军范围的结构化经济合同，后端也没有接通冠军派奖消费者；本批不将首个数字当奖励、不新增派奖，冠军文本部分仍待产品决定。

BUG-315 将 H3 `weekly.mult.P1`～`P6` 接入正式周任务。发布时从可靠的 H1 节奏取得阶段和 H1 倍率，以该阶段读取 H3 倍率，连同任务定义一起冻结。地区新模板同样冻结两套倍率，由模板复制的周期继承原快照。旧已发布行的 H3 倍率为 1，原阶段留空，沿用原 H1 数值和历史领取。

App 现有周任务状态的 `questBonusMultiplier` 返回冻结的 H1 × H3。实际周任务奖励为任务基础奖励 × H1 × H3，按原规则最后向下保留六位小数。已发布周期继续使用自己的快照，随后批准的配置影响之后发布的周期。迁移仅为从未配置的阶段补原有默认值，保留已有值。选中阶段无有效倍率时，发布入口返回 `H3_WEEKLY_PHASE_MULTIPLIER_UNAVAILABLE`，可走既有配置审批修复。

月主题目前也没有接通 App 月任务入口。本批备用卡只治理现有配置与 App 投影，未新增发币消费者。

PC 仍需按页面确认门禁完成具体方案确认后接入本合同；未接入的页面直接放大将收到 409。后端 API/数据库验收不替代 PC、App 页面实景与公共 TEST 部署验收。
