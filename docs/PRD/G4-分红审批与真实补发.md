# G4 每日比例与真实补发审批

BUG-286 本阶段仅治理 G4-A03（含 EX-15 首次）与 G4-A19。其他参数、目录和 PC 改造仍未交付，不以此关闭 G4 全组。Genesis 正式开放、市场状态、熔断与 H1 收益门维持独立准入。

每日收益比例 0 表示未配置，首次正值及已有比例提高需提交 A2，批准前原比例不变。已配置后的降低和等效值仍直接写入；待审不阻止原入口收紧，旧提案因真实旧值/系列身份失效而不能覆盖后来的配置。保持原 0～5%、六位 HALF_UP 归一规则。每次变更的产品/财务决策编号和理由必填，批准执行原提案理由及编号，经同一领域审计与 `admin.genesis_param_changed` 事件链落地。

补发待审期间不生成批次、明细或钱包入账。批准走原真实逐持仓发放链：新批次逐持仓以系列当前单价×每日比例/100，逐笔保留六位金额；已有批次只补原 PENDING/FAILED 明细的原用户及金额，不重算快照、不改原 decision_ref，不重复支付 PAID。完成批次回原结果。原 `g4_genesis_rerun_dividend` 审批命令必须走真实链，旧用户0聚合 PENDING 台账支路停止执行。

比例提案绑定真实 ACTIVE 系列 ID/code、原有效比例。每次批准均核对原操作和快照，即使拟值相对现值已变为降低或等效。新补发绑定系列、原单价、原比例及真实持仓身份集合。已有补发绑定原批次快照及待付明细身份和金额。未完成批次的待付集合清空或金额归零时，批准仍校验快照。冲突返回 409 并保留待审，已完成批次回读原结果。批准人必须是另一有效超管，具备 A2 批准权及本操作的原业务写权限。

比例发起仅需 `finprod_g4_dividend_rate_write`，补发仅需 `finprod_g4_write`；不新增角色授权。对应写者仅可创建本类命令及按本人原幂等键查回执，不因此读取整个 A2 队列或他人票。服务器判定操作对象与资金方向，不信任客户端标签。

拟值覆盖率使用 canonical B1 的未舍入 R/L 交叉相乘：比例只替换同系列现行 `Σ(acquired_price×rate/100)` 项；补发仅新增实际本次待付金额 S，计算 L+S，不把储备当作已经外付、不用包含已付的批次总额。提案和批准均重新核对，不可靠估值拒绝。金额恢复后原命令可重试，失败保持待审且事务内资金事实不部分生效。

新增只读 `GET /api/admin/market/nex/genesis/dividend-approval-state` 取得比例 revision；补发带 `?batchNo=...` 取得批次 revision 和实际本次金额。原 A2 op 名保持，params 增加 `expectedRevision` 与必填 `decisionRef`；旧票缺这些快照合同必须撤回重提。PC 页面本阶段未改，接口细节见本轮 PC 接入合同。

本阶段不改变已完成订单/持仓价格、B1 acquiredPrice 与实发 current series price 的旧差异（BUG-316）、新批次原跨系列选择（BUG-317）、旧批次事件 rateApplied 的旧口径（BUG-318）。正向验收以单系列初始数据为前提，不冒称这三项已修。目录 A15～17 的已批准免 B1 规则及其它参数留后续实施，本阶段不改这些入口。
