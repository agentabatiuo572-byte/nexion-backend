# B28 D1 旧人工银行与国际卡退役

App 钱包的银行卡充值由 HDPay 收银台受理，商城银行卡付款使用 `HDPAY_BANK`。D1 停止接收旧人工银行转账和国际卡的业务写入。历史流水、回单、配置和对账表继续保留。

| 入口 | 后端规则 |
| --- | --- |
| 人工银行 | 管理端登记回单、新建或修改收款账户、匹配、入账、核销及退回旧回单，均返回 HTTP 410 和 `VIETQR_MANUAL_TOPUP_RETIRED`。本人用旧人工转账的创建键重试或取消旧单同样拒绝。已有回单仍按原口径进入 D1 和 D3。 |
| 国际卡 | PSP 主备、卡风控参数、BIN 锁、拒付追回，以及 Card 渠道的启停、费率和金额上下限均返回 HTTP 410 和 `CARD_TOPUP_CHANNEL_RETIRED`。通过验签的卡授权、结算、失败和拒付通知同样拒绝，包括重复请求。旧卡锁同步任务退出调度。 |
| 共享对账 | `POST /openapi/v1/topups/provider-statements` 继续验签。Card 来源返回国际卡退役错误。BTC、ETH、USDT-TRC20 和 USDT-ERC20 按各自的供应商、金额和业务日期写入对账单，同一事件重复提交只保留一笔。保留 D1 流水与差异核销。 |
| 共享银行配置 | HDPay 沿用 `vietqr` 渠道开关及单笔上限。完整配置请求可以随限额提交原有人工字段。使用当前版本变更人工容差、宽限或账户轮换时拒绝，并发更新仍按既有版本规则处理。 |
| 现用资金链路 | 钱包和商城各自建单、保存商户单号与金额。钱包在途投影、凭证上传和人工确认仍按原流程。D3 继续按锁定汇率计入已收到但待核实的金额，未收到款的在途单不增加该项。B1、B2 沿用同一资金来源。 |

管理端沿用原权限，外部请求沿用原签名和时效检查。接口退役不执行数据迁移、表删除或历史资金调整。

2026-11-08 历史回填读取口径：`GET /api/admin/finance/topup/overview` 的既有 `historicalBackfillComplete` 仅在 `nx_topup_cumulative_backfill_run` 存在准确的 `20260720_d1_verified_v1` 执行记录、且当前未删除的 OPEN 异常为零时返回 `true`。未找到执行记录时返回 `false`，表示执行情况未证实，不据此认定从未执行；`historicalBackfillAnomalyCount` 仍返回当前真实 OPEN 数量，可以为零。历史执行记录中的旧异常数量不代替当前数量。该标记仅说明旧历史回填有执行记录且当前无已登记的未结案异常，不证明现代银行、链上充值、退款及重组后的累计金额准确。本次仅修改读取投影，不执行旧迁移，不修改钱包、执行记录或异常，也不恢复退役入口。
