# G3-BE-04 最近一次排程执行业务回读

## 背景
PC 的 G3 页面只能看到排程配置，看不到排程最近一次是否真的执行。`nx_g3_schedule_execution` 已有 claim/mark 写入，但没有读取出口。

## 最小实现
新增只读接口 `GET /api/admin/market/nex/curve/schedule-execution`，权限 `finprod_g3_read`。返回该表按 `run_date DESC, id DESC` 的最新一条：

- `runDate`、`status`、`claimedAt`（`created_at`）、`updatedAt`（`updated_at`）。
- `runDateBasis=UTC_DAY`、`runDateMeaning=CLAIM_DATE`：`advanceIfDue` 以 UTC 日期 claim，同一 UTC 日期至多一条；cron 的 `zone` 只决定触发时刻，不改变记录日的 UTC 基准。`claimedAt`／`updatedAt` 原样返回数据库会话时间（`timestampBasis=DB_SESSION_TIME`），不冒充 UTC 或页面时区。
- `SUCCEEDED` 只表示 claim 和 mark 事务提交；暂停、固定、末帧无循环、无帧等无价格变化的分支也写 `SUCCEEDED`，不能当作改价成功。
- 异常回滚会使 claim/mark 一并回滚，表中没有失败行；`failureObservable=false`、`lastAttemptKnown=false`，不得把“最近一条”解读为“没有失败”或“最后尝试”。
- `PROCESSING` 表示已有 claim 但未 mark，结果未知；不推断失败。
- 表不记录 before/after 价格，`priceChangeKnown=false`、`executionOutcomeKnown=false`；`SUCCEEDED` 只表示 claim/mark 提交，不表示价格实际变化。实际推进时同一事务另发 `market.curve_advanced`（仅 activeDayIndex 变化时），无失败事件，不能从本表反推。
- 无记录时返回 `available=false`、`reason=NO_PERSISTED_SCHEDULE_EXECUTION`，不伪造成功或失败。


## 接口合同

`GET /api/admin/market/nex/curve/schedule-execution`，权限 `finprod_g3_read`（与现有 `GET /curve` 相同）。只读，不改 overview、写链、A2、幂等或调度器。

```json
{
  "available": false,
  "source": "nx_g3_schedule_execution",
  "runDateBasis": "UTC_DAY",
  "runDateMeaning": "CLAIM_DATE",
  "timestampBasis": "DB_SESSION_TIME",
  "oneClaimPerUtcDate": true,
  "failureObservable": false,
  "priceChangeKnown": false,
  "lastAttemptKnown": false,
  "reason": "NO_PERSISTED_SCHEDULE_EXECUTION",
  "execution": null
}
```

有记录时 `available=true`，`execution` 为 `{runDate,status,claimedAt,updatedAt}`；`status=PROCESSING` 返回 `reason=EXECUTION_NOT_TERMINAL`，`status=SUCCEEDED` 返回 `reason=SUCCEEDED_MARK_ONLY`，均保持 `executionOutcomeKnown=false`。服务端按 `run_date DESC,id DESC` 取一条；不合并 outbox、不推断失败原因、不把时间字段命名为“最后尝试”或“改价时间”。

## 前端位置
G3「运行方式 / 自动按日推进」附近（`g3-market.tsx` 运行方式摘要区），另加“最近一次排程执行”行。只读展示服务端原始状态、记录日基准和结果未知提示；不改现有接口、按钮、权限、展示文案。页面接线待前端确认。

## 验收边界
数据库只证明 claim/mark 的持久状态，不证明价格变动、失败原因或调度器健康。PC 页面未接此接口前，不能宣称页面已显示最近执行。
