# E2 任务池

依据 PLAN-v3/v3.1、三轮评审和 2026-11-09 产品负责人最终澄清。后台配置只影响后续逻辑任务；已经冻结的单、历史补算和凭证保持原规则。

## 任务等级与隔离

商城固定四个 DEVICE 池：L1 初级、L2 中级、L3 高级、L4 旗舰，编号 1–4。后台不能增加、改名或删除等级。PHONE 是独立手机池，不能随机生成任务。等级决定跑什么，月收益目标决定金额；等级不提供单价。

`nx_sim_task_pool` 保存 code、kind、level、name、sort_order。code/kind 由迁移确定，运行时授权只读取不可变 `nx_sim_task_type_version.pool_code` 与商品版本 `allowed_pool_codes`，不读取池表的显示字段。池代码参与版本缓存序列化及历史载荷计费。三张历史表继续由原 INSERT 触发器递增 epoch；钱包仍恰好四个触发器。

旧大类/具体 ID 历史只用于切换前的合法补算，缓存和 SQL 的 policyAt/nextPolicyAfter 均排除 DEVICE 新类型。新 DEVICE 类型使用 DT- 新 ID，不写入旧目录 `nx_admin_device_task`。所有任务类型/商品/E3 版本只追加。

## 一次性切换

部署顺序为停应用、执行 `20261109_task_pools.sql`、启动新代码。单行切换标记保证重启不重复清池。历史迁移保持 origin/test 原始字节。启动链以 `20261109_task_class_pool_compat.sql` 替代旧大类授权迁移，跳过已有 allowed_pool_codes 的版本，重启不会把池策略重新发布成空旧范围或丢弃目标。TEST 仅按文件名顺序执行新增文件：机房退役、手机菜单、兼容授权、任务池；本地兼容授权在任务池之前，手机菜单和机房退役在其后，fresh post 再重申菜单和退役。`20261109_phone_menu_visibility.sql` 内联菜单 SQL，不依赖 SOURCE。同一个业务时区微秒生效时刻完成：

1. 手机当前发布策略实际解析到的具体候选追加 PHONE 版本，保持 ID、时长、金额、币种和启停；未入选的旧类型不入池。追加手机 `["PHONE"]` 策略；没有旧手机策略时初始化空 PHONE 策略。
2. 每个有发布历史的非手机 key（包括删除/下架商品）追加空等级版本，保留当时已发布 T/b。未发布草稿不创建历史，只清旧范围字段。
3. 旧格式 E1 范围、手机策略、E2 新增/修改/状态待审票据置 rejected，原因 `TASK_POOL_FORMAT_RETIRED`，删除相应对象锁。新请求、A2 预览和回放拒绝旧格式。机房退役票据由独立机房迁移处理。

切换后不再按旧范围开始新的逻辑任务；既有冻结单和切换前合法补算可以照常付款。

## 随机添加与批量启停

DEVICE 操作直接生效，理由 8–200 字，写必需审计及注册 outbox 事件，不走 A2、不查 B1。每批一个事务、一个生效时刻；epoch 增量等于插入版本行数，提交后只暴露完整批次。D3 对最终集合检查一次，不逐项调用 publishType。

随机数量 1–50，可选 EM/SP/IG/LL/FT/VG 过滤。名称为英文类型基础名和具体内容，同池不重名；权重是合法金额域内正 USDT、六位小数，接口不显示 DEVICE 权重。时长为 5 分钟倍数：EM 30–60、SP 45–90、IG/LL 60–120、FT/VG 90–120。只约束随机入口，不收紧手机和旧历史的数据库全局时长 CHECK。

每池最多 200 启用、300 总任务。随机添加和批量状态使用保留的幂等回执；相同 key/内容返回原结果，不产生新版本，不同内容拒绝。启停追加版本，不改变在途任务。列表以全部启用任务的算术平均时长计算 `1440 / 均值`，不是平均各类的单量；无启用任务时两个估算均为 null。停用影响按已发布的完整多池候选集合计算商品和设备数，草稿引用单独展示；统计和引用按批读取，不逐池或逐商品计 SQL。

PHONE 启停以发布版本的 enabled 为前态、以本次 status=active 为启用目标；不读取旧目录 kill_init 作为 SIM 开关，审批预览与回放一致。PHONE 创建、修改、启停继续使用原 `/tasks` 和 A2/覆盖率检查；请求及回放 params 必须带 `poolCode:"PHONE"`，更新必须命中 PHONE 版本。手机策略固定 `["PHONE"]`，移除大类选择。手机原按单价格、1 小时有效期保留。

PHONE 参数更新省略 `status` 时保留目录当前状态，包括经状态接口停用后的 `inactive`；A2 预览和回放使用相同规则。更新接口显式改变目录状态时在预览即拒绝，启停继续使用原状态接口。启用或提高奖励的资金放大比较及覆盖率检查不变。

E6 承载 PHONE 池。经典 RBAC 种子、启动迁移及 fresh post 为持有有效 E2/E5 菜单或 `device_e2_*` / `device_e5_*` 权限的角色补 E 域和 E6 菜单可见性，只补菜单，不新增任何 authority；各模块读取和动作继续按原 E2/E5/E6 权限判断。

## E1 资金规则

`allowedPoolCodes` 多选替代旧 class/ID 字段。商城只接受 L1–L4，上架至少选一个等级，托管机房文字上架必填且不超过 128 字。已交付设备的托管文字继续按原快照复制；订单履约不再用 `UVEL DC` 兜底。建议列表来源为 SKU 里去重的非空托管文字。

选择 DEVICE 等级必须有月收益目标，拒绝在仍选择等级时清空目标。统一覆盖草稿保存、首次发布、同票范围+目标、仅目标修改、上下架、预览/回放和下架存量商品。D6 仅目标修改复用已发布范围；从未发布的 off/pending 商品继续只存草稿。目标放大仍经 A2，并在批准执行时查 B1；覆盖率不足时业务回滚、票据与锁保留待审。商品目标的 D3、金额域和建单 200 字节快照保护保留。

SIM 按逻辑 started_at 的已发布策略决定目标分支；DEVICE 权重不能作为无目标商品或手机的单价。D4 等概率可复现选择、建单冻结、取消无部分付款、Cloud Share UTC 日 UVT、F5、试用冻结和用户/设备暂停沿用。

## API 与错误

统一前缀 `/api/admin/devices`，ApiResult、既有权限与理由规则不变。

| API | 内容 |
|---|---|
| GET /task-pools?kind=DEVICE\|PHONE | 池、总/启用数、均值、每日估算、商品引用 |
| GET /task-pools/{code}/tasks | 类别/启停过滤及分页；PHONE 含 baseReward/asset，DEVICE 不含 |
| POST /task-pools/{code}/random-tasks | count、taskClasses?、idempotencyKey、reason |
| POST /task-pools/{code}/tasks/status | taskTypeIds、enabled、idempotencyKey、reason |
| GET /task-pools/{code}/disable-impact | productsLosingAllTasks、devicesAffected |
| GET /sku-datacenter-labels | 非空 SKU 托管机房文字建议 |

池读取/写入沿用 device_e2_read/write，托管建议为 device_e1_read。没有等级创建、改名、删除 API。PHONE 的旧 `/tasks` 权限和 A2 流程不变。

| 错误 | 含义 |
|---|---|
| TASK_POOL_COUNT_INVALID / TASK_CLASS_INVALID | 数量或类别非法 |
| TASK_POOL_ENABLED_LIMIT / TASK_POOL_TOTAL_LIMIT | 409，data 含 limit、enabled/total、requested |
| TASK_TYPE_NOT_IN_POOL | 请求中存在其他池或未知类型 |
| TASK_POOL_KIND_FORBIDDEN | DEVICE 批量入口不能写 PHONE，旧任务入口不能写 DEVICE |
| TASK_POOL_IDEMPOTENCY_CONFLICT | 同 key 不同内容 |
| TASK_POOL_FORMAT_RETIRED | 旧 class/ID 或无 PHONE 标记的旧任务格式 |
| SKU_POOL_REQUIRED / SKU_POOL_TARGET_REQUIRED | 上架无等级、选择等级但无目标 |
| SKU_POOL_KIND_INVALID | 商品混入 PHONE 或未知等级 |
| MONTHLY_TARGET_CLEAR_FORBIDDEN_WITH_POOLS | DEVICE 等级仍被选中时拒绝清目标 |
| SKU_DATACENTER_REQUIRED / SKU_DATACENTER_INVALID | 上架缺托管文字，或文字超长 |

审计/outbox 只新增 `E2_TASK_POOL_RANDOM_ADDED` 和 `E2_TASK_POOL_STATUS_CHANGED`；均注册为 record-only 事件。不存在等级增删改事件。

## 负载与恢复

尚无逻辑时刻适用发布版本的非手机商品，按空池等待处理，不构造发布历史、不改种子或目录。缓存和 SQL 的 nextPolicyAfter 从首个商品版本继续；在首版之前忽略不能恢复该商品的 E3 事件。首版生效且可运行时按 L2 恢复，不补激活到发布之间的收入。手机缺历史的原错误规则不变。

L1：真正空闲的 WAITING_CONFIG 最多 30 分钟检查一次，取安全网、已知未来版本、phoneValidUntil、stopAt、finishAfter 的最早值。十二步历史补算上限保留短间隔续跑，ERROR/CLOSING/生命周期不降频。发布提交后沿 `(product_code,state)` 找等待行，每批至多 500、每批独立短事务、按设备主键排序；不持有配置或 epoch 锁。漏唤醒由安全网接手。按用户暂停在原命令事务记录 SIM 截止并唤醒，恢复也唤醒；单台取消激活沿既有同事务 requestStop 路径，不等安全网。

L2：只有非手机 DEVICE 从逻辑空池变为可运行时加一次偏移，也覆盖补算尚未持久化 WAITING_CONFIG 的路径。固定输入为 UTF-8 `SIM-WAKE-1|deviceId|yyyy-MM-dd'T'HH:mm:ss.SSSSSS`（Asia/Shanghai 本地业务时刻），SHA-256 全部 32 字节按无符号整数 mod 300 得到 0–299 秒。偏移后开始时间先存入 next_start_at，未来开始前不预留、不冻结；实际开始时重新 policyAt 并重查截止/停用。游标防止重试重复叠加。持续运行和未经历空池的新激活、所有手机均不加偏移。原月锚点、S、权重保持，空档不积预算，不补发；金额差不能解释为精确少五分钟收入。

L3/L4：随机时长约束和批量一次提交如上，不增加调度线程、队列或重载同步锁。

L5 暂缓：保留 20,000 行/8 MiB 全历史缓存与原 SQL 回退，guard 超限记一条 WARN。

L6：App/Lite 目录仅新增 `taskLevels:number[]`，取请求时已发布池中的 1–4 编号，升序，缺省 []；即使所选池暂时空也保留等级。一次响应一个逻辑 now、一次 caller epoch 校验、同一份只读快照；旧 RR/未提交/guard 回退时用一条批量商品版本 SQL，不逐 SKU 查询。不公开任务内容或权重。只在批量投影加 readOnly 边界，不改变含 sandbox 写入的整个 catalog 类。`/api/store/catalog`、`/api/goals/recommendation`、`/api/app/team/quota` 共用此目录。E2 聚合与所有新/变更 SQL 用隔离副本做 EXPLAIN；小样本时延不作生产容量承诺。
