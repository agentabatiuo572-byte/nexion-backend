# E1 设备月收益目标

批准基线：PLAN-v3（R1–R10、D1–D6）、任务交接 22 §3.2/§3.3。后台改变目标型号的金额计算，不改变具体任务等概率选择。普通用户展示保持「预估，以实际到账为准」。

## 规则

| 规则 | 后端行为 |
|---|---|
| R1 | Cloud Share、S1、Pro、Pro v2、Rack P1/P2 按 SKU 配置月 USDT 目标。手机排除。目标为空保持原单价链；Cloud Share UTC 日 UVT、dailyEarnNEX 不变。 |
| R2 | 原始 L=purchased_at，缺省 activated_at；设备月为 [L+k 月,L+(k+1) 月)，每个端点从 L 起算，业务日 Asia/Shanghai。月末和闰年不滚动锚点。 |
| R3 | 无效运行/WAITING_CONFIG 不累计；停机不补发；取消不付部分奖励并撤销本单预留。 |
| R4 | Q=T×该归属设备月的 E3 产能比例；E3 配置版本取逻辑 started_at。无目标任务保留原 started_at 产能投影。 |
| R5 | 日目标权重在 [.7,1.3] 内，按设备月覆盖秒数配平。实际日到账还受任务组合、完成归属与纠偏影响，不承诺实际日值也在此带内。 |
| R6 | 合格具体类型等概率、每设备一单、建单冻结。补算使用 policyAt(nextStartAt)，每批最多 12 步；重试不重抽。 |
| R7 | 精确月估值=T；日估值=T/30。Share 日区间=T(1∓b)/30；参考年率=T(1∓b)×365/30÷价格×100，单位为百分数点。设备当前日产再乘当前 E3；先投影再筛选、排序和计算。 |
| R8 | 目标开启、清空或 T×(1+b) 上升为资金放大；服务端按类型化前后值判断，A2 批准执行时先查 B1，不可靠或低于红线拒绝，业务写入回滚且票据待审。 |
| R9 | E5 批量只读当前设备月进度；GET 不生成权重/周期行，不结算。 |
| R10 | 新领取试用的日 USDT=T/30，即使为零也不走旧正数兜底；已领取试用、订单和购入设备快照保留。 |

D1：整单按 due_at 所在设备月和业务日归属；实际入账时间 posted_at 独立。E5 C 只包含该周期实际入账的目标任务 USDT。

D2：只撤回当前 RUNNING 单的 p/lo/hi/reward，C 不变；普通停止和赠机退款 SQL 都遵循相同规则。generation 不分割设备月账。

D3：开启目标的候选池仅允许正额 USDT 且时长≤3600 秒。E1 范围/目标写入、E2 类型新增/启用/金额/币种/时长/类别变更及 A2 回放均校验；包括下架及归档后仍有设备的已发布型号。空池允许 WAITING_CONFIG。配置共用现有 E3 配置锁，不在运行时过滤不兼容类型来改变概率。

D4：无新部署密钥。`SIM-TYPE-SHA256-1|deviceId|generation|logicalStart|nonce` 的 SHA-256 前 32 位采用拒绝采样；池按具体 taskTypeId 排序。周期 u、日权重使用 `DMT-V3-SHA256-1|deviceId|cycleStart|purpose`，输入 UTF-8、时间为业务时区 ISO LocalDateTime。事务回滚后可复现。

D5：T∈[1,1000000]，最多两位小数；b∈[1,50] 百分数点，最多一位小数。Q<.01 时本段预算和目标 USDT 奖励为零。正 Q 最小 .01，最短月 28 天，统一 D_cap=3600，使内带 b′>0.5%。

D6：目标和带宽缺省/null 保留；只用 clearMonthlyTarget=true 清空。同票必须有手填 dailyEarn（Share 为 shareYieldMin/Max）。仅目标变更且已有发布历史，复制已发布范围追加目标版本，即使型号下架；本票同时批准范围变化/首次上架，发布本票范围；从未发布的 off/pending SKU 只存草稿。清空追加 target=NULL 版本。售价变化重算 Share 派生年率。

## API

E1 SKU 请求及 A2 params 新字段：

```json
{"monthlyTargetUsdt":"50.00","monthlyTargetBandPct":"10.0"}
```

金额接受十进制字符串或数值。开启时目标、带宽必须能解析成完整一对；局部修改保留另一项。字段省略和 JSON null 均保留；清空示例：

```json
{"clearMonthlyTarget":true,"dailyEarn":"1.000000"}
```

SKU 响应新增 monthlyTargetUsdt、monthlyTargetBandPct、derivedDailyEarnUsdt、derivedShareYieldMinPct、derivedShareYieldMaxPct。无目标均为 null；Share 派生年率仅 Share 有值。dailyEarn/baseRate、estimated_daily_usdt 和 Share 年率镜像同步写入。日货币值 HALF_UP 六位，年率 HALF_UP 四位；T 是权威源，不能从日镜像反算月额。

App catalog 新增 monthlyEstimateUsdt（精确 T）、dailyEstimateLowUsdt/dailyEstimateHighUsdt（仅 Share，有目标时六位日区间）。无目标这三项为 null。有目标 Share 的 dailyEarn 也为 T/30。数量由消费端只乘一次。

E5 的 monthlyTarget 为 null，或：

```json
{
  "cycleIndex":1,
  "cycleStartAt":"2026-11-01T13:37:11.123456",
  "cycleEndAt":"2026-12-01T13:37:11.123456",
  "creditedUsdt":10.123456,
  "rangeLowUsdt":45.00,
  "rangeHighUsdt":55.00,
  "capacityPct":100.000000,
  "targetActive":true,
  "configChangedInCycle":false
}
```

cycleIndex 为展示用一基月序号。range 是当前配置满月持续运行的 Q(1∓b) 预估，不重算历史 C。无周期行但有目标时只读返回 C=0 及区间；已清空但当前周期有历史时保留 C/周期，targetActive=false，rangeLowUsdt/rangeHighUsdt 均为 null。无目标且无当前周期历史时 monthlyTarget=null。未来周期提前建行不会替代当前周期。

## 错误和审批

| 错误 | 状态/数据 |
|---|---|
| MONTHLY_TARGET_POOL_INELIGIBLE | HTTP 422；ApiResult.message 同名，data={code:"MONTHLY_TARGET_POOL_INELIGIBLE",affectedSkuIds:[...]}。E1/E2/A2 提案和审批回放均保留受影响 SKU 列表。 |
| MONTHLY_TARGET_USDT_INVALID / MONTHLY_TARGET_BAND_INVALID | 422，支持域/精度不合法。 |
| MONTHLY_TARGET_PAIR_REQUIRED | 422，目标和带宽不能解析为一对。 |
| MONTHLY_TARGET_CLEAR_CONFLICT | 422，清空同时传非空目标/带宽。 |
| MONTHLY_TARGET_MANUAL_EARNING_REQUIRED | 422，清空未提供有效手填基线。 |
| MONTHLY_TARGET_DEVICE_INELIGIBLE | 422，手机/不支持的设备身份；phone SKU 原有保留键拒绝也继续适用。 |
| COVERAGE_BELOW_REDLINE | 409，放大批准时 B1 不可靠或低于红线；票据保持 pending，可原票重试。 |
| A2_CONFIRMATION_REQUIRED | 409，目标变化直接写入未走审批。 |

沿用已有权限、双人审批、版本冲突与幂等边界。客户端 amplifies 不决定资金分类。D3 结构化异常穿过 A2 序列化、回放和幂等包装，到 HTTP 错误边界输出，不压成仅有 message 的错误。

## 金额、证据和不变量

周期表键为 (user_device_id,cycle_start)，与 generation 无关。累计 P/Lo/Hi 使用 DECIMAL(50,24)，A/C 使用六位。任务归属周期按 due_at；跨度积分按业务日拆分，目的周期外权重取 1。

m=3×3600/S+q/Q，q=.000001，b′=b−m；g=1+b′u。三条积分增量为 Q×{g,1−b′,1+b′}×∫w/S。池速率 r̄=sum(base)/sum(duration)，不是单秒速率的算术平均。c=clamp(1+(P−A)/(Qg/30),.5,1.5)。名义额 base×p/duration/r̄ 乘 c 后 HALF_UP 六位，再夹入本笔累计沿可用的六位格点；空格点取非负上沿 floor6。Q=0 独立输出零，不为旧舍入余量产生新付款。

每笔保持 Lo−q < A ≤ Hi。统一时长上限覆盖头尾偏差；加上 q/Q 货币余量，固定配置、持续运行周期的最终 C 落在 Q(1∓b)。分段配置只累计新段速率，不用最后配置改写历史；停机/取消不留应得债。没有额外尾期补发或未来时段预付。

目标任务使用 SUPPORT_DEVICE_EARNING_V3，任务行保存不可变 target_snapshot_json：算法、周期、建单前 P/Lo/Hi/A、p/lo/hi、r̄、c、Q/g/b′、加权秒数、基础额/时长、T/b/产能和最终金额。小数、日权重在 JSON 中用十进制字符串保存，避免 MySQL JSON DOUBLE 丢失 24 位精度；时间保存六位微秒。reward_amount 是唯一付款真源，V3 读取从快照复算第 4 步。

V1/V2 使用显式旧字段投影：键集合、null 形状、时间表示和哈希输入不变。V3 正额/零额均进入资金证据覆盖；零额不创建零金额钱包流水。钱包差额=凭证=流水=earning=C 增量，同一事务成功或回滚。Share UTC UVT 日奖和 F5 按实际入账金额的既有异步事件链不变。

锁沿用用户→设备/runtime→任务/钱包的既有顺序；新增周期写入在用户/设备/runtime/钱包锁之后。E5 无行锁。取消仅当前运行单，不引入历史账重放。

## 迁移与验收

20261109_device_monthly_target.sql 增量增加 SKU（正式商品与 E1 扩展）、策略版本、任务快照和周期表，并扩大日镜像/Share 年率精度。历史目标列默认 NULL，不回填策略历史或改写旧任务。schema.sql、新建库 fresh_db/post.txt 与 PowerShell startup 链同步。无新依赖、必填环境配置或 nx_user_wallet 触发器。

升级先执行 startup 链，再部署代码；迁移可重复。新周期 lookup/E5 元组批量查询均使用 PRIMARY(user_device_id,cycle_start)。不向真实源库导入副本数据，不补造过去版本。

验收分为支持域不变量、固定种子整周期模拟、隔离真实应用链。模拟结果和 C11 触点逐项记录在本地交付报告；不能用编译或 SQL EXPLAIN 代替真实 A2/B1、钱包证据/F5 和并发流程签收。服务由协调者在 8140、隔离 DB/Redis 上启动。
