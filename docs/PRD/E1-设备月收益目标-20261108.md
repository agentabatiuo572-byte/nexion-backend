# E1 设备月收益目标

批准基线：PLAN-v3（R1–R10、D1–D6）、任务交接 22 §3.2/§3.3。后台改变目标型号的金额计算，不改变具体任务等概率选择。普通用户展示保持「预估，以实际到账为准」。

## 规则

| 规则 | 后端行为 |
|---|---|
| R1 | Cloud Share、S1、Pro、Pro v2、Rack P1/P2 按 SKU 配置月 USDT 目标。手机排除。目标为空保持原单价链；Cloud Share UTC 日 UVT、dailyEarnNEX 不变。 |
| R2 | 原始 L=purchased_at，缺省 activated_at；设备月为 [L+k 月,L+(k+1) 月)，每个端点从 L 起算，业务日 Asia/Shanghai。月末和闰年不滚动锚点。 |
| R3 | 无效运行/WAITING_CONFIG 不累计；停机不补发；取消不付部分奖励并撤销本单预留。 |
| R4 | Q=T×该归属设备月的 E3 产能比例；E3 配置版本取逻辑 started_at。无目标任务保留原 started_at 产能投影。 |
| R5 | 日目标权重在 [.7,1.3] 内，按设备月覆盖秒数配平。实际日到账还受任务组合、完成归属与纠偏影响，不承诺实际日值也在此带内。 |
| R6 | 合格具体类型等概率、每设备一单、建单冻结。补算使用 policyAt(nextStartAt)，每批最多 12 步；重试不重抽。 |
| R7 | 精确月估值=T；日估值=T/30。Share 日区间=T(1∓b)/30；参考年率=T(1∓b)×365/30÷价格×100，单位为百分数点。设备当前日产再乘当前 E3；先投影再筛选、排序和计算。 |
| R8 | 目标开启、清空或 T×(1+b) 上升为资金放大；服务端按类型化前后值判断，A2 批准执行时先查 B1，不可靠或低于红线拒绝，业务写入回滚且票据待审。 |
| R9 | E5 批量只读当前设备月进度；GET 不生成权重/周期行，不结算。 |
| R10 | 新领取试用的日 USDT=T/30，即使为零也不走旧正数兜底；已领取试用、订单和购入设备快照保留。 |

D1：整单按 due_at 所在设备月和业务日归属；实际入账时间 posted_at 独立。E5 C 只包含该周期实际入账的目标任务 USDT。

D2：只撤回当前 RUNNING 单的 p/lo/hi/reward，C 不变；普通停止和赠机退款 SQL 都遵循相同规则。generation 不分割设备月账。

D3：开启目标的候选池仅允许正额 USDT 且时长≤7200 秒（120 分钟）。E1 范围/目标写入、E2 类型新增/启用/金额/币种/时长/类别变更及 A2 回放均校验；包括下架及归档后仍有设备的已发布型号。空池允许 WAITING_CONFIG。配置共用现有 E3 配置锁，不在运行时过滤不兼容类型来改变概率。

D4：无新部署密钥。`SIM-TYPE-SHA256-1|deviceId|generation|logicalStart|nonce` 的 SHA-256 前 32 位采用拒绝采样；池按具体 taskTypeId 排序。周期 u、日权重使用 `DMT-V3-SHA256-1|deviceId|cycleStart|purpose`，输入 UTF-8、时间为业务时区 ISO LocalDateTime。事务回滚后可复现。

D5：T∈[1,1000000]，最多两位小数；b∈[1,50] 百分数点，最多一位小数。Q<.01 时本段预算和目标 USDT 奖励为零。正 Q 最小 .01，最短月 28 天，统一 D_cap=7200 秒；最坏 b′≥0.000971428571（约 0.09714%），仍为正。D3 的获批新时长为 EM 10、SP 60、IG 90、LL 90、FT 120、VG 120 分钟，基础奖励仍须为正 USDT，发布版本后仅影响新任务。

金额域准入：E1 开启/修改目标及发布、E3 单项/批量批准影响目标 SKU 时，用 `E3CapacityCurve` 放大检查已有的 future probe months（同时取 age=0 的 100%）求候选配置的最高产能 C_max；E3 变更使用前后配置共同的探测点，不参与 E3 的 SKU 取 100%。不把增长曲线截到 100%。单任务保守界为 `ceil6(T×C_max/100×7200/(28×86400)×1.3×(1+b/100)×1.5)`；超过任务、凭证、流水、earning 和资金记录共同的 DECIMAL(18,6) 上限 `999999999999.999999` 时拒绝，返回受影响 SKU。T≤1000000、产能≤100%、b≤50 时该界≤8705.357143。探测期沿用既有 E3 放大检查，不据此承诺无穷月龄的复利支持域。

建单另核对实际夹紧后的 reward；超出上述金额域、首周期产能列容量或紧凑快照 200 字节限制时抛 `MONTHLY_TARGET_REWARD_OUT_OF_RANGE`。整笔预留/任务事务回滚，不留下周期、任务或资金写入；现有设备重试事务保留 ERROR/last_error 和 30 秒重试时刻。E3 历史或探测期外增长也由此保护，不扩列、不重定价历史任务。

D_cap 的取舍：m=3D_cap/S+q/Q，扩大上限会压缩可随机波动的内带；必须满足 b_min>3D_cap/S_min+q/Q_min。现有 1% 下限支持 7200 秒，不能在保持 1% 的同时任意提高时长上限；进一步提高 D_cap 必须重新计算并增大最小带宽。

D6：目标和带宽缺省/null 保留；只用 clearMonthlyTarget=true 清空。同票必须有手填 dailyEarn（Share 为 shareYieldMin/Max）。仅目标变更且已有发布历史，复制已发布范围追加目标版本，即使型号下架；本票同时批准范围变化/首次上架，发布本票范围；从未发布的 off/pending SKU 只存草稿。清空追加 target=NULL 版本。售价变化重算 Share 派生年率。

## 2026-11-09 任务池替换规则（覆盖上文对应条款）

商城改为固定 L1 初级、L2 中级、L3 高级、L4 旗舰的 DEVICE 等级多选。凡草稿或已发布范围选择 DEVICE 等级，月目标必须存在，不能清空；因此 R1「目标为空保持原单价链」和 D6「清空追加 NULL 目标」仅对未选择 DEVICE 等级的范围适用。上架至少选择一个等级。D6 仅目标修改仍复用已发布范围，下架存量也校验；从未发布 off/pending 仍只存草稿。A2 预览、回放和所有 E1 写入分支使用同一约束，目标放大照旧执行 B1。

D5 已批准的 EM10/SP60/IG·LL90/FT·VG120 时长方案只继续适用于 PHONE；DEVICE 随机生成改为 EM30–60、SP45–90、IG/LL60–120、FT/VG90–120 分钟，均为 5 分钟倍数。D3 仍要求正 USDT、≤7200 秒，金额域和 200 字节冻结快照检查保留。DEVICE 池内容编辑直接生效，不走 A2/B1；PHONE 编辑和 E1 目标放大保持原审批及覆盖率保护。

商品和类型版本分别增加 allowed_pool_codes/pool_code。旧大类/ID 历史永远排除 DEVICE 类型。单次切换仅给有发布历史的非手机 key 追加空等级版本，保留 T/b；手机只承接切换前实际候选，旧草稿不变成已发布。新 `taskLevels:number[]` 目录字段取已发布等级编号，后台池显示名不影响运行授权。新任务池规则、API、一次性迁移及 L1–L6 详见 [E2 任务池](E2-任务池-20261109.md)。其余 R1–R10、D1–D6 不变，月中配置按新段速率累计，停跑不补发。

## API

E1 SKU 的 A2 预览、提案与批准回放共用库存校验，在规范化前检查提交值。`UNLIMITED` 仅允许 Share，stock 必须为空；带 stock 值时返回 422 `SKU_UNLIMITED_STOCK_MUST_BE_EMPTY`，不将其静默改成 null 或创建待审票。`UNLIMITED + stock:null` 保持有效；`FINITE` 继续要求 0–2147483647 的十进制整数字符串，否则返回 `SKU_STOCK_INVALID`。

E1 SKU 请求及 A2 params 新字段：

```json
{"monthlyTargetUsdt":"50.00","monthlyTargetBandPct":"10.0"}
```

金额接受十进制字符串或数值。开启时目标、带宽必须能解析成完整一对；局部修改保留另一项。字段省略和 JSON null 均保留；清空示例：

```json
{"clearMonthlyTarget":true,"dailyEarn":"1.000000"}
```

SKU 响应新增 monthlyTargetUsdt、monthlyTargetBandPct、derivedDailyEarnUsdt、derivedShareYieldMinPct、derivedShareYieldMaxPct。无目标均为 null；Share 派生年率仅 Share 有值。dailyEarn/baseRate、estimated_daily_usdt 和 Share 年率镜像同步写入。日货币值 HALF_UP 六位，年率 HALF_UP 四位；T 是权威源，不能从日镜像反算月额。

App catalog 新增 monthlyEstimateUsdt（精确 T）、dailyEstimateLowUsdt/dailyEstimateHighUsdt（仅 Share，有目标时六位日区间）。无目标这三项为 null。有目标 Share 的 dailyEarn 也为 T/30。数量由消费端只乘一次。

`/api/devices/earnings` 的每个 devices 项新增 boolean `monthlyTargetActive`，当前设备 SKU 的 monthly_target_usdt 非 NULL 即 true；不受目录可见性、上架状态影响。无目标为 false；旧服务未提供时 App/Lite 按 false。E5 monthlyTarget.targetActive 的既有进度含义不变。

E5 的 monthlyTarget 为 null，或：

```json
{
  "cycleIndex":1,
  "cycleStartAt":"2026-11-01T13:37:11.123456",
  "cycleEndAt":"2026-12-01T13:37:11.123456",
  "creditedUsdt":10.123456,
  "rangeLowUsdt":45.00,
  "rangeHighUsdt":55.00,
  "capacityPct":100.000000,
  "targetActive":true,
  "configChangedInCycle":false
}
```

cycleIndex 为展示用一基月序号。range 是当前配置满月持续运行的 Q(1∓b) 预估，不重算历史 C。无周期行但有目标时只读返回 C=0 及区间；已清空但当前周期有历史时保留 C/周期，targetActive=false，rangeLowUsdt/rangeHighUsdt 均为 null。无目标且无当前周期历史时 monthlyTarget=null。未来周期提前建行不会替代当前周期。

## 金额、证据和不变量

周期表键为 (user_device_id,cycle_start)，与 generation 无关。累计 P/Lo/Hi 仍使用 DECIMAL(50,24)，每笔 p/lo/hi 在加入周期前先 HALF_UP 到 12 位；A/C 使用六位。任务归属周期按 due_at；跨度积分按业务日拆分，目的周期外权重取 1。

m=3×7200/S+q/Q，q=.000001，b′=b−m；g=1+b′u。三条积分增量为 Q×{g,1−b′,1+b′}×∫w/S。池速率 r̄=sum(base)/sum(duration)，不是单秒速率的算术平均。c=clamp(1+(P−A)/(Qg/30),.5,1.5)。名义额 base×p/duration/r̄ 乘 c 后 HALF_UP 六位，再夹入本笔累计沿可用的六位格点；空格点取非负上沿 floor6。Q=0 独立输出零，不为旧舍入余量产生新付款。

每笔保持 Lo−q < A ≤ Hi。统一时长上限覆盖头尾偏差；加上 q/Q 货币余量，固定配置、持续运行周期的最终 C 落在 Q(1∓b)。分段配置只累计新段速率，不用最后配置改写历史；停机/取消不留应得债。没有额外尾期补发或未来时段预付。

目标任务使用 SUPPORT_DEVICE_EARNING_V3。target_snapshot_json 仅存一个 JSON 字符串：`"1|p|lo|hi|P-A|Lo-A|Hi-A|poolRate|Qg|cycleSeconds"`，各项为有符号 base36 定点整数；前六项 scale=12，poolRate/Qg 的 scale=24，cycleSeconds 为设备月秒数（scale=0，用于 V3 核对 due 的周期归属），前缀 1 为紧凑格式版本。Qg 在计算 c 前先 HALF_UP 到 24 位。回撤使用前三项和任务 reward_amount；V3 从后三项差额、poolRate/Qg 与任务原有 base_reward/duration_seconds 复算 c、名义额及第 4 步夹紧。Q=0 时 Qg=0，直接复算为零。任务已有的周期起点、基础额、时长、产能倍率和最终金额不重复保存，完整中间 Snapshot 仅在建单内存中短暂存在。

支持域内单月最多 44,640 个一分钟任务，积分单项舍入误差总计不超过 2.232×10⁻⁸ USDT，远小于头尾时长裕量中保留的余量；仍以 Lo−q<A≤Hi 和外带验收。贡献先舍入再记账，取消逐项精确减回，不从未舍入积分倒推。资金 journal 的 source snapshot 只在 simulation 中复制这一个紧凑字符串，不再存第二份完整快照；V1/V2 键和形状不变。目标是每笔 JSON_STORAGE_SIZE≤200 bytes。产品未上线，不迁移早期验收 V3 形状；运行中的旧验收进程保留，切换前协调其旧验收历史处置。

V1/V2 使用显式旧字段投影：键集合、null 形状、时间表示和哈希输入不变。V3 正额/零额均进入资金证据覆盖；零额不创建零金额钱包流水。钱包差额=凭证=流水=earning=C 增量，同一事务成功或回滚。Share UTC UVT 日奖和 F5 按实际入账金额的既有异步事件链不变。

锁沿用用户→设备/runtime→任务/钱包的既有顺序；新增周期写入在用户/设备/runtime/钱包锁之后。首次周期先 INSERT ... ON DUPLICATE KEY UPDATE 主键不变，再对已存在的完整主键 SELECT FOR UPDATE；不得锁不存在的周期键。后继任务若其已结前单的 target_cycle_start 等于归属周期起点，则直接锁已知存在行，常规路径仍为一次锁定读+一次累计 UPDATE，不增加语句。跨周期、首次、重开无存在证明时走 insert-first。RR 下避免 missing-key gap lock 与相邻设备的插入意向锁冲突；资金 settlement 原有去除 FOR SHARE 的优化保持。E5 无行锁。取消仅当前运行单，不引入历史账重放。

## 版本任务池缓存与唯一结算入口

nx_sim_task_type_version / nx_sim_product_task_policy_version / nx_sim_e3_version 保持只追加。三表各有 AFTER INSERT trigger，在同一发布事务内递增单行 nx_sim_policy_epoch(id=1,epoch)，包括首次 E3 初始化和每个类型/商品的第一版本。回滚同时撤销 epoch。没有新增钱包 trigger（仍恰好四个）。

每次 policyAt/nextPolicyAfter 在调用方事务内按 epoch 主键做普通一致性读：等于本实例缓存 epoch 则用不可变内存历史；较高则加载；较低说明 RR 事务快照较旧，按原 SQL 从该事务的数据库视图解析。加载器使用独立 REQUIRES_NEW、REPEATABLE_READ、readOnly 事务，先读 epoch，再在同一一致性读视图内读完整已提交历史（包含未来生效版本）；不缓存调用方未提交发布。加载后 epoch 与调用方不一致时也回退 SQL。原子引用只允许向更高 epoch 交换；不同实例各自刷新，热路径无 JVM 锁和 SQL 锁。

内存只保留最新一个 epoch，不按设备/任务/时刻扩展。单份历史上限 20,000 版本及 8 MiB 估计原始载荷（含字符串和固定字段计费），超出时该 epoch 直接用原 SQL；统计和加载在同一快照内，查询本身另有 LIMIT 20001。旧快照随正在解析的调用释放后由 GC 回收。未来版本只在 effective_at 到达时生效，无需等 epoch 再变。类授权仍先选每个类型的最新适用版本再按类别过滤；旧 ID 授权与 nextPolicyAfter 的既有语义保留。

DEV home worker 在 SIM 开启时不派新单；即使 SIM 关闭，也排除已有 SIM runtime 或当前 SKU 有目标的设备。发现和设备锁内重查均识别目标/runtime。已有冻结 DEV 单照旧到期排空；若设备 pending_deactivate 且尚无 SIM runtime，先走原 finalizePendingDevice 完成取消激活、runtime OFFLINE 标记及事件/审计，释放槽位，再拒绝新派单。discovery 持续保留无 SIM runtime 的待收尾设备，直到其完成停用，即使旧 DEV 单已不再 RUNNING。已有 SIM runtime 的设备继续归 SIM lifecycle 收尾。SIM 仍等待旧单排空后接管。DEV 奖励不计入 C。该排空例外不允许同设备并行 DEV/SIM 新单。

## 迁移与验收

20261109_device_monthly_target.sql 增量增加 SKU（正式商品与 E1 扩展）、策略版本、任务快照和周期表，并扩大日镜像/Share 年率精度。历史目标列默认 NULL，不回填策略历史或改写旧任务。schema.sql、新建库 fresh_db/post.txt 与 PowerShell startup 链同步。无新依赖、必填环境配置或 nx_user_wallet 触发器。

升级先执行 startup 链，再部署代码；迁移可重复。可选 nx_commerce_sandbox_catalog 两次 ALTER 均先判断表存在再判断列缺失；表已退役则跳过，绝不重建。20261109_sim_policy_epoch.sql 在完整 schema、startup 和 fresh post 中同步登记。新周期 lookup/E5 元组批量查询均使用 PRIMARY(user_device_id,cycle_start)。不向真实源库导入副本数据，不补造过去版本。

验收分为支持域不变量、固定种子整周期模拟、隔离真实应用链。模拟结果和 C11 触点逐项记录在本地交付报告；不能用编译或 SQL EXPLAIN 代替真实 A2/B1、钱包证据/F5 和并发流程签收。服务由协调者在 8140、隔离 DB/Redis 上启动。
