# M3 结束接待：命令绑定接待实例（BUG-416）

2026-11-12 · 后端合同 · PC 接入待后续页面任务

## 问题

原 `POST /api/admin/content/support-workbench/customers/{customer}/session-hold/end` 的幂等键只按「管理员 + 客户」保存。原结束命令没到后端、接待因空闲结束、超过 24 小时后同一管理员再接待同一客户时，旧命令号查不到回执又不能重试，占住新接待的手动结束入口。

## 后端合同

- `GET .../session-hold` 的 `State` 新增 `sessionRef`，标识一次接待实例（`assignmentId:startedAt`）。同一客户重新接待后该值改变。
- `POST .../session-hold/end` 可选 body：
  ```json
  { "sessionRef": "15:2026-11-11T16:55:23.237313" }
  ```
- 带 `sessionRef` 时：
  - 实例一致性只在**首次执行**时校验；请求的实例必须与当前接待实例一致，否则 `409 SUPPORT_SESSION_CHANGED`，不会结束当前另一个接待。
  - 幂等请求哈希绑定 `customer | sessionRef`；同一键在新接待上使用会因哈希不同返回 `409 IDEMPOTENCY_KEY_PAYLOAD_MISMATCH`，PC 应在新接待生成新命令号。
  - 原命令成功后再用同一键、同一 body 重试，先返回原回执，不读取也不改变当前新接待 R2；实例校验不会把成功回放变成 409。
- 不带 `sessionRef` 时保留旧行为（`admin + customer` 哈希），仅用于尚未升级的 PC；该旧路径仍有原缺陷，PC 必须按 `sessionRef` 保存命令号后才完成整单修复。

## PC 接入要求（未完成）

- 读取 `State.sessionRef`。
- 结束命令的持久化 fingerprint 改为 `session-end:{adminId}:{customerId}:{sessionRef}`。
- 旧命令号在新 `sessionRef` 下收到 `409 SUPPORT_SESSION_CHANGED` 时，才允许清除旧记录并生成新命令；不得删除原号、超时解锁或换号冒充原命令重试。
- 若旧命令确实到过后端，仍先用原命令号查回执；只有明确失败或确认未执行才进入新接待的新命令。

## 边界

- 不改变接待超时、转绑、分配和消息发送逻辑。
- 不用 B38 通用核查替代实例绑定：原命令从未到后端时不存在可核查记录。
- 本单后端局部通过不代表整单关闭，PC 未接入前保持开放。
