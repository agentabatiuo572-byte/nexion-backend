# F5 奖励动作复核门禁

冻结、解冻、提前解锁、结算发放及驳回状态转换须经 A2 审批。持有相应 F5 动作权限的管理员直接调用奖励状态接口时，返回 `409 A2_CONFIRMATION_REQUIRED`；缺少对应动作权限时返回 403。审批回放仍核对当前版本和合法状态，再写入奖励、账本和审计。

现有 F5 动作权限允许发起相应的 F5 提案，并按原键找回本人的工单及当前状态。其他账号的键返回 404。发起者仍须通过准确的动作、对象和锁目标校验；A2 总览、日志和批准权限沿用原规则。

新建 F5 状态处置、冲正、补发及暂停／恢复提案的发起角色由服务端认证身份确定：财务主管、风控主管及超管分别显示对应实际角色，不采用客户端自报角色，也不统一归为风控。新票响应与本人原键回执沿用该创建时角色，供 A2 角色筛选和详情展示；历史票保持原记录，权限、两人审批、资金和审计业务规则不变。

奖励状态使用专用 A2 指令和奖励记录锁。通用团队界面配置指令不能变更奖励状态。此前通过通用指令发起的待审工单可驳回。

审批处置按目标 `CM-{id}` 精确读取未删除奖励的当前状态、版本和所属用户，不受概览最近 100 条记录的范围限制。历史奖励仍按相同的专用对象锁、合法状态机和版本 CAS 校验执行；资金入账、冲正、任务事件和审计规则不变。

异常预警与近期审计动态继续使用全局最近 200 笔奖励样本，异常列表沿用相同的游标范围；样本读取复用不含账本编号关联计算的投影。主列表仍返回完整奖励、结算组、版本和真实账本编号，统计、样本量、状态及权限口径不变。

奖励列表的 `coolingDaysLeft` 始终返回非负整数。暂停等合法处置清空冷却截止后，冻结或终态记录明确返回 0；仍有冷却截止的记录继续按截止日期计算非负剩余天数，不因状态变为终态而清零。此读取修正不改变奖励状态、版本、冷却截止、钱包、账本或审计，也不放宽页面数据校验。
