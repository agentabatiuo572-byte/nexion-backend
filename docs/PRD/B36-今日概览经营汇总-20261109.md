## 接口与时间

`GET /api/admin/overview/business-summary?period=today|week|month|all&registrationGranularity=day|week|month`。
默认 `today` / `day`，无效参数返回 400。返回 `period`、`timezone`、`statisticsStart`、`asOf`、`generatedAt`、`rollupAsOf`、`range`、`comparison`、`blocks`。

日界、周一及月首使用 `BusinessCalendar.legacy()`；数据库仍保存北京时间。`range` / `comparison` 均为左闭右开，返回绝对时间。今日比较昨日同一经过时间，本周比较上周同期，本月比较上月同一经过天数和时分秒，上月较短时截止上月月末。总计没有比较期。注册搜索 `joinedFrom` / `joinedTo` 使用同一业务日界，不再直接拼数据库本地零点。

## 六块事实口径

金额均为 USDT 本金。所有金额、交易笔数和人数排除 `nx_user.sandbox=1`；完成/在途提现同时排除 `d5_payout_source=mock/dev-simulator`。用户注册、首次转化和活跃另排除已删除用户。历史资金不会因为用户注销而抹除。

| 块 | 本期值 / 分项 | 事实与排除 |
| --- | --- | --- |
| `deposits` | `amountUsdt`、`previousAmountUsdt`；BEP20、ERC20、TRC20、银行、外部直付、历史国际卡、其他及笔数 | 已成功入账的 USDT 钱包账本，精确匹配链上订单/国际卡付款；HDPay 复用 D1 的到账校验；历史 VietQR 精确匹配已入账回执，已有同意图 HDPay 到账时不重复计算。外部直付须已确认且已交付，取冻结报价 `subtotalUsdt` 本金，渠道/网络费用不算本金。钱包购机、注资、调账、孤立账本、待确认/失败均不算。以钱包账本创建时间或直付确认时间归属。 |
| `withdrawals` | USDT 本金、越南盾订单的 USDT 本金、手续费及完成笔数；`inTransit` 带当前金额/笔数/时点 | 仅 `CONFIRMED/SUCCESS` 且有完成时间的 USDT 订单，以完成时间归属；`BANK-VND` 的 `amount` 本来就是 USDT 本金。费用优先实际费用 `d2_actual_fee`，旧记录回退 `fee`，单列且不另从本金扣减。在途为此刻审核/处理中及冻结/待恢复的未完成存量，不跟随历史期间累加。 |
| `netDeposits` | 入金减完成提现 | 不计储备/财务注资；需要同时具有入金和提现读权。 |
| `sales` | 设备销售净额；财务统计权限可读原销售额、退款额、有效订单数、客单价 | 仅已付款完成设备订单及其终态退款单。退款归原付款日期，从原销售额减去 B37 实退字段，旧单回退精确 E4 退款账本/账单；全额退款有效订单数为 0，少退后保留正净额的订单数为 1；客单价为净额除有效订单数，分母为 0 返回空。团队奖励、创世节点和优惠券面额不计。 |
| `registrations` | 新增人数、累计人数、首充/首购及各自比较值、日/周/月走势 | 注册完成且未删除的正式用户；首充为一生第一笔有效外部入金，首购为一生第一笔有正净额的有效设备购买，并非当期第一次重复充值/购买。走势空日/周/月补 0，周一归桶。 |
| `activeUsers` | 周期去重活跃人数及比较值，另按设备权限返回在线/异常设备当前存量 | 读取实际 `nx_user_daily_active` 逐用户去重，用 `first_seen_at` 限制同时段，跨日不可相加。`all` 明确 `available=false`、原因为 `ALL_TIME_ACTIVE_NOT_PROVIDED`，不构造历史活跃数。设备仅正式环境、正式归属的已激活设备，在线/异常复用 E5 心跳和状态定义。 |

旧 L3 `daily-flows` 与 revenue 的原口径保持，只补上测试用户排除；提现流再补模拟来源排除。旧 D1 `aggregateToday` 对历史卡采用本金加渠道费且不包含全部历史银行/外部直付，不能将该旧总额冒充 B36 本金总额；共享链上/HDPay 本金队列可逐笔对账，完整对账须按上述差异桥接。

历史终态退款单若既无实退字段又无精确退款账本/账单，该付款期的销售块返回 `available=false` / `SALES_REFUND_FACT_UNAVAILABLE`，不把未知退款猜成零或全额；比较期同类问题以 `previousUnavailableReason` 单独标明。
