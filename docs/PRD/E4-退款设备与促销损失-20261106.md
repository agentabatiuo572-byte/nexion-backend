# E4 整单退款设备与促销损失

适用 BUG-271、B38-BE-06 与促销 D06。A2 退款经第二位有权管理员批准后，购买设备归属转为 `REFUNDED`，设备停用。已经持久化的普通未完成计算任务在同一退款事务取消，清空原派发和重试指针；已完成、已入账及退役留档事实保留。赠品按原义务和设备发放凭证收回，已到账的赠品收益按原币种保留。历史已确认退款且已撤销归属的购买设备补齐相同的停止状态。

普通模拟任务以退款时点为收益截止。退款事务保留当前任务的冻结报价与身份；有当前任务时运行态进入 `CLOSING`，由正常结算调度继续处理：`due_at` 不晚于截止时点的任务按原规则入账一次；晚于截止时点的任务取消，原因保留 `ORDER_REFUND`。无当前任务时直接停止。处理后运行态为 `STOPPED`，当前任务和后续调度指针清空，不补派下一项。已经验证完成、尚未入账的 ComputeV2 任务继续使用原冻结凭据和批次幂等结算，不因设备随后退款停用而漏付；已到账普通设备收益不冲回。试用转购及促销奖励继续按各自整单关闭规则处理。

B38-BE-06 的验收须核到真实退款前后的钱包、唯一收益账本、收据、任务及设备终态。仅保留已完成任务行不等于已支付，促销奖励发放与追回也不替代普通计算收益的结算证据；截至 2026-11-09 本次只读核查，正式 TEST 的完整普通退款收益链仍待执行，不据源码核查标记通过。

赠机存在月目标模拟任务时，退款与后续赠品冲正共用既有月目标取消入口：锁定同一用户、设备的 `RUNNING` 且未退役任务，按任务原有紧凑字符串快照撤销该单 P/Lo/Hi 与金额预留，并校验周期用户、实例和算法身份；解码或身份不匹配则整笔事务回滚。已完成任务与周期已到账 C 不回撤，退款重试不重复撤销已取消任务的预留。

`GET /api/admin/devices/orders/{orderNo}` 增加 `devices` 数组，包含该订单全部未软删除的设备实例。每项包含 `deviceId`、`deviceInstanceNo`、`kind`、`sourceChannel`、`status`、`ownershipStatus`。`kind=PURCHASE` 对应订单设备，`kind=PROMOTION_GIFT` 对应促销赠品。购买设备排在赠品之前，各组按设备 ID 升序。无关联时返回空数组。原 `deviceId`、`deviceInstanceNo`、`deviceActivatedAt` 继续返回旧版单实例投影。A2 通过 BUG-309 已交付的 `operationCode=e4_order_refund`、`fundEffect=ORDER_REFUND` 和 `refundOrderNo` 回读保存的命令，退款标题仅供展示。

普通订单尚未付款或尚无关联设备时，仍可按原付款状态读取详情。退款影响统计兼容正式设备与模拟任务标识的既有字符规则差异，同时保留用户、设备、实例、代次、当前任务、来源环境和状态的关联约束；不能把其他设备的任务计入本订单。统计查询失败不能当作可信的零收益，也不能据钱包入账推定订单已付款。

活动效果的 `assets[].unrecoverable` 按原币种累加两类事实。资金奖励取最终未追回余额，赠品收益取 D06 冲正凭证 `platformLoss` 中实际保留的 USDT、UVT。资金奖励的 `platformLoss` 与未追回余额对应，只计一次。分组 `DEVICE` 的 `reversed`、`unrecoverable` 仍按设备台数核对。每次新查询生成新快照，已保存的查询和导出快照保留原时点结果。

效果报表 `giftCostUsdt` 使用发生赠品发放的原订单在建单时锁定的应付额 `nx_order.amount_usdt`。在活动、版本和奖励义务时间窗口内，同一订单发放多台或向多名受益人发放时只计一次，退款不改变原下单金额。无已发赠品返回 `0.000000`，已发赠品关联的原下单事实不完整时返回 `null`。试算的同名字段是确定匹配赠品时本次报价的 `pricing.amountUsdt`，试算无匹配赠品或资料未齐时返回 `null`。销售金额、实收净额、平台损失和成本分别核算。
