# A3 内容读取与 B3 阶段筛选

## A3 内容读取

拥有 `platform_a3_read` 的运营账号可通过 `GET /api/admin/developer/docs` 和 `GET /api/admin/content/how-it-works` 读取开发者文档和产品说明。对应的 `HEAD` 沿用同一读权限。两个接口分别返回现有发布版本或草稿及其发布状态。写入沿用各接口现有的权限校验，开发者和内容域其他路径继续按各自的权限校验。

### A3-BE-02 保存原命令（2026-11-16）

两个内容保存 PUT 复用原持久幂等机制，按当前管理员、内容种类和请求体哈希隔离命令。显式 `Idempotency-Key` 优先；旧调用未发送时使用同请求体派生的 `auto:` 键，原样重试仍恢复原结果。新执行才调用原内容、理由和 revision 校验，同键异体拒绝；保存结果仍返回原内容视图，不扩大读写权限，不改变内容发布规则或 PC 请求。该项仅代码复核及编译通过，未 E2E。

### A3-BE-01 发布规则引用（2026-11-17）

发布为 `PUBLISHED` 前，检查各语言内容块的 `title`、`body` 与 `items`；仍含客户端无法解析的 `{value}` 时，沿用 `422 HOW_CONTENT_INVALID` 拒绝发布。草稿继续使用原引用模型，已有发布内容不回填，不引入新引用语法或解析模板。该项按代码复核和跳过测试的编译口径交付，未执行真实发布或 E2E。

### B101 原操作核查与结案

开发者文档和业务说明的保存可通过 `GET /api/admin/commands/investigations/by-command-key`，按原 `commandKey`、`PUT` 及确切原路径查询。回执区分成功、明确拒绝、处理中、未知和查无。原操作人或具调查权的超级管理员可查，并需拥有 `platform_a3_read`。

两类内容分别按固定配置对象保留未决锁。同一对象由不同管理员保存时使用共同的锁。原号超过 24 小时仍未决时须结案。由具调查权和 A3 读权的超级管理员沿用调查接口，核对原回执、确切匹配的成功审计或已确认的本地回滚。结案后释放对象锁；证据不足时维持未知。历史记录可凭原命令身份和可核证结果回读，继续保留证据不足的原号。保存的版本校验、权限和旧客户端派生原号继续适用。

## B3 运营阶段

B3 按注册事件的 `phase` 归属筛选。`SYSTEM` 对应「系统默认」，与 `P1` 至 `P6` 一样可用于漏斗总览、辅助指标、趋势、CSV 和保存视图。后续事件仍按同一注册用户的实际发生顺序纳入漏斗。空值与 `ALL` 表示全部阶段，其他阶段值返回 `422 B3_PHASE_INVALID`。

阶段选项来自已有注册事实，使用与请求相同的合法值范围。合法组合没有匹配注册时保留可用筛选选项和「暂无法计算」状态，便于切换回有数据的筛选。
