# K4 评分同步、调度与锁范围优化（2026-11-05）

本次优化减少无变化评分的重复写入、共享调度线程阻塞及无关用户的锁等待。用户范围保持 `is_deleted=0 AND COALESCE(sandbox,0)=0`，不增加 `status` 过滤；评分算法、注册／提现入口、全局隔离级别、数据库连接池和资金锁不变。

成员同步仅补齐缺失或已软删除的评分行。缺失行按原规则建立为 0 分、`pending` 模型、行版本 0，等待首次真实投影；软删除行通过原重复键分支恢复，保留原评分、模型版本、行版本和 `as_of`，人工覆盖及贡献继续按原流程处理。唯一键及重复键竞争处理保留，不把恢复行重置为初始评分。正常已有行不再仅因同步更新 `updated_at`。

评分新鲜度仍由 `as_of`、模型版本及来源变化判断，pending 不作为有效评分，提现继续执行原新鲜度校验。已确认的读取影响是：legacy `as_of IS NULL` 的时间回退不再随同步前移；PC 评分搜索仍按原匹配优先级、`updated_at DESC,id DESC` 排序，但次排序时间反映实际记录修改。接口、前端及排序规则本身不改。

整轮调度保留配置键 `nexion.risk.k4.sync-delay-ms`，默认 fixedDelay 为 5000 毫秒，启动时立即执行，每批最多处理 200 人。K4 使用单线程专用调度器，并保留同一实例的 synchronized 串行边界；其他模块仍使用原调度器，不增加评分并发。关闭时最多等待 10 秒，不保证强制终止超时 SQL。fixedDelay 从上一轮结束后计时，五秒不是完成 SLA；新注册／恢复及来源变化可能多等一个周期，数据库耗时、事件积压和超过 200 人的队列另计。

成员同步仍在一个 READ COMMITTED 事务内依次执行孤立评分退役、缺失／软删除补齐、孤立人工覆盖停用和孤立贡献退役，任一步失败整组回滚。该事务先提交，再用另一事务读取活动模型及待投影用户，实际评分继续使用原逐用户事务。模型或候选读取失败会停止本轮并抛出异常，已提交的成员同步不回滚，下轮重试；版本竞争、人工覆盖保留及事件发布规则不变。

逐用户修改先以原评分行与用户行的 canonical 等式和资格条件只读解析真实用户 ID，再以 `nx_user` 主键缩小锁定及 UPDATE 范围。四个共享修改入口保留原 `FOR UPDATE`、canonical、删除／sandbox 和 CAS 条件，不把缺失 ID 当作 0，也不新增提前返回。U 前缀至少八位补零及原 collation 匹配逻辑保留，不新增字符串转数字校验。

启动及运行同步先只读检查三类孤儿：未删除评分、活动且未删除人工覆盖、未删除贡献。三类均为空时跳过三条清理 UPDATE，补齐照常执行；任一类非空时仍按原顺序及锁定资格复核清理。预查不授权删除，预查后才出现的孤儿可能留待下一轮处理，用户恢复或退出范围仍由原当前读与后续调度收尾。
