# 702 通知收件箱保留与并发读取

## I3-BE-02/05：后台保存与实际投递边界（2026-11-16）

通知活动新建、草稿保存及新调度/发送按实际语言、标题回退和换行拆分后的投递内容检查，标题最多 128、正文最多 512 个 Unicode 码点，超过时拒绝新执行，不在用户收到时截断。预算新写按 `DECIMAL(18,2)` 拒绝两位以外的非零小数，尾随零不改变金额。检查放在原幂等新执行回调内，原有效成功回执先恢复；技术失败/拒绝回执沿用现有机制。历史数据、前端、投递 SQL 和权限不变；本轮代码复核和编译，未 E2E。

App 按当前登录账户读取通知。分页按通知 ID 降序，分类、优先级及游标只限制本页。返回的未读数涵盖同一快照中该账户全部可见的未读通知。投递状态和用户偏好继续决定可见性，关键通知必收。

| 优先级 | 每账户保留规则 |
| --- | --- |
| critical | 永久保留，标记已读后也不能通过清理已读删除。 |
| high、normal | 按各自启用的后台上限保留最新记录。按创建时间排序，时间相同取较大的通知 ID。 |
| low | 同样按该档上限保留，创建时间早于当前时间 48 小时的记录同时淘汰。 |

打开列表时先完成该账户既有的提现通知补投，再处理确实超限或过期的记录。没有待淘汰记录的轮询只读取保留数据。需要淘汰时逐条按主键软删除，只处理优先级和创建时间仍符合本次判定的记录，在处理下一条前释放上一条的锁。已淘汰记录不因清理其他已读通知或调高上限重新出现。

后台派发及调整上限仍在各自写事务内按账户排名、淘汰超限记录并清理过期低优先级通知。单条或批量标读仍校验账户、投递状态和偏好，原有通知读取事件与写入一同提交。

## I3-BE-01：真实活动统计和发送窗口（2026-11-17）

仅 I3 管理概览读取在同一个只读 REPEATABLE_READ 快照、同一 `asOf` 内查询；不修改任何发送、标读、事件或保留策略的 writer。月份及周界使用 `BusinessCalendar.legacy` 当前有效时区，周一开始，上下界转为 Asia/Shanghai 持久时钟，采用左闭右开窗口；响应 `stats.basis` 给出实际界限、时区及来源。

- `monthCampaigns` 统计本月创建的未删除活动；`monthSent` / `monthScheduled` / `monthDraft` 是同一个创建 cohort 中当前对应状态的数量，不是全量，也不是通知消息条数。`criticalInflight` 仍为当前全部 critical 在途活动数；`monthBasis` 明示创建时间与当前状态口径。
- 立即发送与定时发送的业务编号格式不同，统一关联取同事务 `notification.delivered` 的 `campaign_id`、`notification_id` / `NOTIFICATION` aggregate ID；只接服务器权威、注册事件，按活动+通知 ID 去重，再读 `nx_notification`。不以通知文案、受众、当前用户、计划排期或审计阅读猜关联。保留物理通知/投递事实（包括收件箱已淘汰的软删行）仍是已经发生的事实，不因偏好或活动当前状态倒改历史。
- 每行新增 `deliveryFacts`：发送数量、真实已读标志数量、同活动通知 `pushed_at` 的 `firstSentAt` / `lastSentAt` 窗口及来源/时区。它表示已进入用户通知流的持久时点，不宣称外部推送供应商或终端已送达。多用户只返回真实最早/最晚时间，不伪造单一活动发送时间；原排期文字保持。
- 原 `sent` / `read` 字符串类型保持；当真实投递数与活动原记录的精确发送数一致、关联通知均有发送时点时，以动态真实数量投影，否则 `complete=false`，`read` 不返回，原 `sent` 仅保留旧记录值。实际时间窗口也仅描述保留且已关联的通知，缺源不拿 `updated_at`、创建时间或排期补值，未确认完整时不冒充完整活动历史。
- 平均已读率沿原当前 SENT 活动集合，仅用真实发送分母及已读数量；投递覆盖未确认或分母为零时不返回 `avgReadRate`，以 `deliveryFactsComplete` 和已知原始计数区分，不造 0%。本周已读沿同一个活动集合，按真实 `read_at` 与 `read_flag` 同通知 ID 计，缺关联或旧已读行缺 `read_at` 时主值不可用，另保留已知量与缺时数。
- 旧 `weeklySwipe` 实际供页面显示滑动直达转化，却用已读数乘 `0.031` 估算；本轮按原允许的“去掉无源字段”分支停止返回该估算，机器原因 `LEGACY_ESTIMATED_CONVERSION_REMOVED`。真实已读量另在 `stats.basis` 返回，不将阅读推断成跳转或转化。没有新增人话标签/模板/说明下发，也不要求 PC 已消费新机器字段才验收后端。
- 旧缺关联/已物理清除的记录不补造或回填；SQL 失败照常失败，不吞错为零。仅源码候选与必要 Java 17 双 skip 生产编译，未执行 HTTP、DB、E2E、发送、标读或部署。
