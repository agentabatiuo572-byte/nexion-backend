# K2 检测参数首次配置（BUG-129）

2026-11-04。范围为后端 K2 参数读取和首次配置，不修改 PC 页面、检测算法、H4 触发器或其他风控配置。

## 正式来源与交付责任

采用《Nexion_运营控制后台_开发落地规格》§4.7 的三个默认阈值。字符串格式沿用后端现行校验器和 PC 严格解析器；这些值与 `OpsRiskService.refreshK2AuthoritativeProjection` 原有缺项分支实际使用的值一致。

| 参数 | 首次交付值 | 允许范围 |
|---|---|---|
| `trialCycleThreshold` | `>= 3 次 / 30 天` | 次数 2–10，周期 7–60 天 |
| `welcomeGiftAnomalyThreshold` | `>= 2 笔 / 实体` | 笔数 1–5 |
| `leaderboardVelocityMultiplier` | `> 5x 基线` | 倍数 2–20 |

后端维护并随代码交付上述内置定义，缺项时由现有参数读取层提供，与六个验证码参数合并为完整九项；不会在启动或读取参数时新增参数表记录。上述三个检测阈值的首次运营配置由具备 `risk_k2_write` 权限的操作者通过既有 PATCH 接口完成。实际检测消费者为 K2 `refreshK2AuthoritativeProjection`；本次不另建 H2 参数源、不变更既有信号产消关系。

## 读取与写入约定

- `GET /api/admin/risk/arbitrage/overview`：内置缺项的版本为 `0`；数据库现有有效行覆盖内置定义，保留其值、说明和版本。空表或部分缺项都能返回完整参数集合。
- `PATCH /api/admin/risk/arbitrage/params/{key}`：继续要求 `Idempotency-Key`、理由及 `expectedVersion`。三个检测阈值从未持久化时以 `expectedVersion=0` 首次写入，成功后版本为 `1`；六个验证码参数适用下述首次生效审批。已有行按原版本比较并递增；旧版本冲突拒绝，未知键及非法值拒绝。
- 成功写入沿用现有事务与 `K2_PARAM_CHANGED` 审计，记录操作者、理由、幂等键、真实生效的修改前后值及版本。已有权限、校验、幂等、软删恢复和审计失败回滚机制保持原样。
- 重启不会覆盖已有配置，不重置版本，不产生初始化审计。严格拒绝不完整或非法返回的 PC 校验继续保留。

## 整体验收

使用隔离真实 Java/MySQL 环境，先从无三条检测参数的环境读取完整九项，再由授权角色首次配置三项并回读数据库及审计。核对部分缺项时已有值/版本保留、旧版本冲突、只读角色拒绝写入、未知键/非法值拒绝、相同幂等键重放不重复变更。重启后再次核对既有配置和版本。实际执行结果由本轮验收记录提供，不以本文代替通过证据。

## BUG-286：六个验证码参数首次生效审批（2026-11-06）

按规范 Q-01 落实 K2-A08 的首次录入审批。范围仅为 `otpGate.resendSeconds`、`otpGate.dayLimit`、`otpGate.otpTtlSeconds`、`otpGate.maxVerifyAttempts`、`captchaGate.alwaysScenes`、`captchaGate.afterSends`；不扩展 K1 页面、授权、菜单或三个检测阈值。

认证消费者 `AppOtpPolicy`、`CaptchaOtpGate` 只读取 `nx_config_item` 中对应的有效 `auth.risk.*` canonical 配置，缺项时使用代码默认。`nx_admin_risk_arbitrage_param` 的内置定义、历史 risk 行及页面 `version=0` 都不能单独证明验证码规则已经配置。首次判定按本轮核实的实际生效来源落实 Q-01：

| 有效 risk 行 | 有效 canonical 行 | 本次行为 |
|---|---|---|
| 无 | 无 | 首次配置，必须审批 |
| 有（含迁移或手工历史行） | 无 | 首次配置，必须审批 |
| 无 | 有 | 已配置，保留原 PATCH 普通调整；risk 展示版本可为 0 |
| 有 | 有 | 已配置，保留原 PATCH 普通调整 |

有效 canonical 指 `status=1` 且 `is_deleted=0`；处于有效状态但数值、TTL 或场景非法时返回 `503 K2_OTP_CANONICAL_INVALID`，不退回默认、不借首次配置覆盖。禁用或软删源仍以真实存在状态、旧值和版本绑定审批。

- `GET /api/admin/risk/arbitrage/overview` 仍提供完整九项；新增 `otpInitializationRequired`，按六个键返回实际首次配置布尔值。GET 不播种任何参数源。
- 首次经原 PATCH 直写返回 `409 K2_OTP_INITIAL_APPROVAL_REQUIRED`，两源不变。已有配置的普通调整保持原 `risk_k2_write`、理由、幂等及版本要求，不额外要求 A2 权限。
- maker 必须同时具备 `risk_k2_write` 和既有 A2 提案权限（`platform_a2_proposal_create` 或 `platform_a2_write`）。通过既有 A2 `POST /api/admin/platform/audit/operations` 提交 `domain=K`、`op=k2_otp_initial_config`；`sourceDomain=K2`、`obj={key}`，唯一 target 为 `{domain:K,type:k2_otp_param,id:{key}}`。`params.values` 严格为 `{key,value,expectedVersion}`。
- 服务器绑定真实 maker、两源存在性与旧值、risk 行 ID/版本/软删状态、canonical 行 ID/启停/软删状态；客户端提供的源快照无效。canonical 表无独立版本列，不以无关更新时间代替业务版本。
- 另一位有 `platform_a2_operation_approve` 的有效超管批准，且票据对象、分类与锁匹配后，才在一个事务中按绑定快照比较并写两源。risk 版本递增，canonical 按同一值生效；TTL 的 API/risk 单位为秒、canonical 单位为分钟，必须整分钟且范围仍为 60–900 秒。
- 待审、拒绝、缺权限、本人自批、错误目标、非法值以及旧 risk 版本、canonical 被抢先初始化或旧值变动时，都不写业务参数。过时票返回 `409 K2_OTP_SOURCE_CHANGED` 并保持待审，需拒绝或撤回后重提。
- 复用 A2 原提案键恢复、同键幂等与单次审计；没有 A2 通用读取权限的合法 maker 仅能按本人原提案键恢复本类票据，不获得通用 A2 读取或其他域权限。成功 `K2_PARAM_CHANGED` 保存真实两源前后态、maker、批准者、理由与票号；重启不重新初始化。

验收覆盖四种源组合、六项逐项提案/批准、普通调整、旧票与权限拒绝、幂等/本人恢复，以及真实注册/登录/找回密码 OTP 和滑块消费者。PC 页面由后续已确认方案接入上述契约，本次后端交付不等于 PC 页面验收或 BUG-286 整单关闭。
