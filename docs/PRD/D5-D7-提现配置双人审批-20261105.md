# D5 和 D7 提现配置审批

D5 `PUT /api/admin/withdraw/limits` 和 D7 `PATCH /api/admin/finance/payout-vnd/config` 继续接收原有版本化更新。收紧按原入口保存并审计。放宽请求返回 `409 D5_WITHDRAWAL_LIMITS_APPROVAL_REQUIRED` 或 `409 D7_PAYOUT_VND_CONFIG_APPROVAL_REQUIRED`，当前值和版本保持原样。

放宽用 `POST /api/admin/platform/audit/operations` 提交。提案须同时具备对应字段或整组写权限，以及 A2 提案或写权限。D7 强制使用倒挂价继续校验原专项权限。

| 模块 | 指令 | 来源 | 锁类型 |
| --- | --- | --- | --- |
| D5 | `d5_withdrawal_limits` | `D5` | `withdrawal_limits` |
| D7 | `d7_payout_vnd_config` | `D7` | `payout_vnd_config` |

指令域为 `D`，`obj` 与锁 ID 为 `current`，锁域为 `D`。把原有业务变更和 `expectedVersion` 放在 `params.values`，理由填在提案外层。审批摘要由服务端根据当前版本和拟改值生成。

只有另一位具备 A2 审批权限的有效超管可以批准或驳回。发起人可撤回。批准重新校验版本、放宽方向、当前 B1 覆盖率和业务规则。红线按 B1 原始比例判断，显示值的四舍五入不影响判定。业务更新与 A2 审批同一事务提交，业务审计记录提案理由及 A2 单号，A2 审计记录审批理由。驳回、撤回或校验失败时当前配置保持原样。待审期间仍可直接收紧，已被新版本取代的提案需要重提。D7 已提交订单继续使用提交时的金额。
