# App 与 H5 实时连接会话续签

App 与 H5 继续通过 `POST /api/app/support/realtime-ticket` 获取一次性票据，再用 `auth` 帧认证 `/ws/conversations`。票据有效期为 30 秒。首次认证成功后，用户连接收到 `{"type":"ready","reauth":true}`。旧客户端可以沿用原有的票据和重连流程。运营端继续使用原有的会话和 `ready` 帧。

支持续签的客户端刷新登录凭据后，可用新的访问令牌获取同一入口签发的票据，并在原连接发送 `{"type":"reauth","ticket":"…"}`。服务端只接受同一用户、同一鉴权环境、同一会话链中原会话直接轮换出的有效会话，且轮换仍在原有 10 秒宽限期内。服务端更换连接凭据后回复 `{"type":"reauth-ready"}`，并保留当前会话订阅。票据重复使用、不同会话链、错误身份、轮换过期或凭据失效时，客户端沿用鉴权失败和重连处理。关闭码 `4401` 表示需要重新验证会话，最终会话状态由既有认证 API 判定。

JSON `ping` 继续回复 `pong`。票据请求、连接鉴权、心跳、在线与正在输入状态、事件广播和续签均按当前权限和会话状态做只读校验。访问令牌到期、会话有效期及闲置期、主动退出、App 登录替换、账户停用、封禁、密码重置及客服权限继续生效。创建会话、回复及标记已读等业务命令继续走原有的活动会话校验和业务授权。

验证覆盖旧客户端连接和心跳、新客户端在原连接续签并继续收发、独立登录和已撤销会话无法续签、客服权限变化后停止发送无权查看的事件，以及仅运行心跳和后台状态广播时 `nx_user_session` 活动字段保持原值。

## 多进程 WebSocket

共享同一环境 Redis 的 Java 进程可以互相消费票据。30 秒有效期、账号与主体类型绑定，以及签票和认证时的权限校验继续生效。票据只可成功消费一次。每环境最多保留 10,000 张待消费票据，同一账号和主体类型最多 8 张。Redis 只保存票据摘要、配额状态和加密授权。App、H5 和客服端继续使用现有的领票、鉴权和续签协议。

会话、归属、客服权限和公共配置变更提交后，经共享事件流通知连接所在进程。多个进程为同一条会话通知使用相同事件 ID，客户端从业务查询接口补拉正文和状态。每个进程只向当前有权查看的连接投递。在线租约为 60 秒，输入状态为 5 秒。事件流约保留 4,096 条通知，读取中断或游标超出保留窗口时以 `1013` 触发现有重连和补拉。若进程在提交业务后、写入事件流前退出，客户端下次补拉可读取已提交数据。

`NEXION_WEBSOCKET_MAX_CONNECTIONS` 设置单 JVM 的连接上限，默认 2,000，包含已认证和待认证连接。待认证连接同时受每 JVM 100 条、每来源 IP 8 条和 5 秒认证窗口约束。达到连接上限时以 `1013` 关闭新连接，认证、断开或超时后释放相应名额。过期或已消费票据继续按 `4401` 处理。扩大配置前，应在隔离环境按实际在线行为验证连接和查询容量。
