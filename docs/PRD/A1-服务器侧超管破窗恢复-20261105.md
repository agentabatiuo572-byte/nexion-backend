# A1 服务器侧超管破窗恢复（S09 / BUG-297）

有效超管沿用 A1 的定义：未删除、启用、超管角色、已绑定 MFA（`tfa_required=1`、密文非空、绑定时间非空）。最少两位。低于两位时，可以由有服务器和数据库运行凭据的运维人员执行本地命令，把一位已有管理员提升并启用为超管。目标可以是普通管理员，也可以是停用超管；无需预先保留第二位停用超管。

命令要求目标已通过正常登录流程完成 MFA 绑定，且现有 MFA 密文能用服务器密钥解密。不存在、已删除、未绑定 MFA 或已是有效超管的目标拒绝处理；已有两位有效超管时拒绝处理。零位时每次也只恢复一位，仍须再次恢复另一位才能结束治理恢复状态。命令不新建账号、不改密码或 MFA，不改已有客服/主管资格。账号没有可用密码或 MFA 时，应先通过正常账号凭据与 MFA 流程准备另一位合法管理员，不能靠该命令绕过验证。

网页及公开 API 不提供破窗入口，原 A1 恢复动作仍需另一位超管批准，不能自批。有效超管不足两位时，直接调用已有创建超管、账号角色/启用 HTTP 写接口也不能恢复，只接受服务器批准后的 A2 回放上下文；直接调用返回 `ADMIN_GOVERNANCE_RECOVERY_REQUIRES_APPROVAL`。创建拒绝发生在生成临时密码和写入账号之前。达到两位后的既有接口行为不在本次改动范围。命令使用独立无 Web、无调度的最小上下文，不启动后台业务服务。它与后台使用同一套数据库环境解析、MFA/有效超管定义及 A2 理由、审计 schema、保留期配置；配置不可用时拒绝成功。

## 服务器用法

在运行后端的服务器上，使用已部署且含本修复的可执行 JAR、Java 17 和受保护的后端运行环境。先按现有运维方式加载 `SPRING_PROFILES_ACTIVE`（`dev` 或 `prod`）、完整的 `NEXION_DB_URL` / `NEXION_DB_USERNAME` / `NEXION_DB_PASSWORD` 及 `NEXION_ADMIN_MFA_ENCRYPTION_KEY`；不要把秘密写进命令行、仓库或工单。命令必须显式提供这组数据库变量，不回退默认数据库。

```bash
java -Dloader.main=ffdd.maintenance.RestoreSuperAdmin \
  -cp /opt/uvel/nexion-backend.jar \
  org.springframework.boot.loader.launch.PropertiesLauncher \
  42 'oncall@example.com' '事故单 INC-123：唯一超管无法完成双人审批，恢复指定管理员'
```

三个位置参数依次是精确目标账号 ID、执行人（1–64 字符）、恢复原因（遵守当前 A2 最少可见字符数，最多 200）。账号 ID 应从当前库确认，不能把用户名当 ID。成功返回 `RECOVERED`、恢复流水号、目标 ID、有效超管数；异常返回非零退出码。执行后使用目标原密码与原 MFA 登录，并在 A2 读取审计确认结果。未知执行结果先按流水号/目标查询审计和 A1 当前人数，勿手工改库冒充命令成功。

审计动作 `A1_SUPER_ADMIN_BREAK_GLASS_RECOVERED`，资源 `A1_ADMIN_ACCOUNT/{id}`；记录服务器执行人、操作系统用户、原因、目标用户名/ID、原角色/状态、新角色/状态及有效人数前后值。账号更新、主角色关系及必需审计同事务提交；审计关闭、策略缺失或审计写入失败时回滚。A2 沿用 `GET /api/admin/platform/audit/logs?action=A1_SUPER_ADMIN_BREAK_GLASS_RECOVERED&resourceId=42` 及现有读权限查询；记录不会伪装成双人审批票。

## 验收

使用隔离副本：一位有效超管、一位已绑定 MFA 的普通管理员，执行命令后从一位变两位；目标以原密码/MFA 登录并读到 A2 审计。再执行被拒绝，账号、密码、MFA 和成功审计数不变。另验无执行人/非法理由、不存在/未绑定目标、目标本身已有效、审计写入失败均不产生半完成账号更新。网页同人审批仍被拒绝。公共 TEST 不降级现有账号来造恢复状态。
