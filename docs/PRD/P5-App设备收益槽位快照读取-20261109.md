## 最小实现约定

仅修改 `AppCanonicalBoundaryService.deviceEarnings` 的三处投影计数：

- `lockReservedDeviceOrderCount(userId, false)` 改为既有 `reservedDeviceOrderCount(userId)`。
- `lockReservedTrialSlotCount(userId)` 改为既有 `reservedTrialSlotCount(userId)`。
- `lockActiveDeviceCount(userId, false)` 改为既有 `activeDeviceCount(userId)`。

三种无锁计数与原锁定计数使用相同的数量、状态、环境、履约排除和 trial 条件，区别为移除当前锁读。它们与当前GET中的钱包、设备列表及已实现收益一起使用原事务的普通一致性读取；在实际 REPEATABLE READ 下共享读取快照，期间提交的新状态可在下一次请求看到。`slotsUsed` 仍为 active + reserved + trial；返回字段、金额精度、设备规格与E3校验、错误顺序及 sandbox 分支保持。

保留原 `@Transactional` 和 `productionDeviceUserGate` 内的账户 `FOR UPDATE`，不改成只读事务；拒绝客户端造数参数时的原 tamper 发布也保持。创建订单、钱包支付、激活、试用、组合购买、容量替换和手机激活继续使用原 owner 锁、当前锁读、容量与资金资格。GET投影不作为写入准入依据，写侧必须重新校验；不删除 mapper 锁方法，不修改 SQL、隔离级别、重试、索引、资金、幂等、UNKNOWN或调度配置。本批不含尚未发布的16-worker候选，不修改前端。
