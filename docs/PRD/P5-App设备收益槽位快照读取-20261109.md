## 最小实现约定

仅修改 `AppCanonicalBoundaryService.deviceEarnings` 的三处投影计数：

- `lockReservedDeviceOrderCount(userId, false)` 改为既有 `reservedDeviceOrderCount(userId)`。
- `lockReservedTrialSlotCount(userId)` 改为既有 `reservedTrialSlotCount(userId)`。
- `lockActiveDeviceCount(userId, false)` 改为既有 `activeDeviceCount(userId)`。

三种无锁计数与原锁定计数使用相同的数量、状态、环境、履约排除和 trial 条件，区别为移除当前锁读。它们与当前GET中的钱包、设备列表及已实现收益一起使用原事务的普通一致性读取；在实际 REPEATABLE READ 下共享读取快照，期间提交的新状态可在下一次请求看到。`slotsUsed` 仍为 active + reserved + trial；返回字段、金额精度、设备规格与E3校验、错误顺序及 sandbox 分支保持。

保留原 `@Transactional` 和 `productionDeviceUserGate` 内的账户 `FOR UPDATE`，不改成只读事务；拒绝客户端造数参数时的原 tamper 发布也保持。创建订单、钱包支付、激活、试用、组合购买、容量替换和手机激活继续使用原 owner 锁、当前锁读、容量与资金资格。GET投影不作为写入准入依据，写侧必须重新校验；不删除 mapper 锁方法，不修改 SQL、隔离级别、重试、索引、资金、幂等、UNKNOWN或调度配置。本批不含尚未发布的16-worker候选，不修改前端。

## B94 设备槽位替换（2026-11-25）

`POST /api/devices/slot-replacement` 沿用两台设备的版本号和原请求键。空闲旧设备同事务停用并激活新设备，返回 `COMPLETED`。Compute V2 从未开始的排队作业和已经确认物理退出的旧作业允许立即接替。符合条件的排队作业会取消，回调中断时由现有调度补收尾。已开始的作业返回 `PENDING`，用户可通过原撤销接口取消等待。按原请求键重放返回首次命令的结果。设备当前状态从 `GET /api/devices/earnings` 读回。

Compute V2 离线后，旧代租约到期并且同代终态已经持久化时，换机可释放设备槽位。未完成的作业拒绝迟到续租与结算，也不发收益。已经验证的作业照常结算。计算执行位继续等待真实退出凭据，换机会保留原执行代次与许可。服务恢复时会继续发送已经登记的原事件。 在 Redis、RocketMQ 与 MySQL 正常时，按剩余租约、最多 10 秒回收轮询、最多 60 秒写入检查点窗口、最多 10 秒接替轮询及处理耗时计算。默认 45 秒租约下，调度与检查点等待预算合计 125 秒。运行态无法确认同代终态时继续等待核实。

TEST 连续执行器释放最后一项作业时，取消作业、停旧、启新和解除关系在同一事务完成。还有作业时继续等待。执行器原键可读回相同释放回执。退款回收旧机时，仍符合槽位及归属条件的新机接替。退款或撤销赠机回收待接替的新机时，解除换机关系和旧机为本次换机设置的停用计划。同一退款涉及两台设备时，先处理两台设备的归属，再清理换机关系。

`GET /api/devices/earnings` 在可选择换下的已激活设备行增加 `slotReplacementTiming`。`IMMEDIATE` 表示预计当场完成，`PENDING` 表示预计等待作业收尾，`UNKNOWN` 表示执行侧不可确认。预判只反映读取时的作业和设备状态。V2 在同一次读取中核对设备、归属、代数和退出证据。恢复中、并发清理留下的数据暂缺或快照无效时，对应设备显示 `UNKNOWN`，其他设备、槽位和收益照常读取。提交结果以换机回执和设备回读为准。

原生 App 当前会话退出取消最后一项旧版手机作业时，已经排期的旧机停用、新机接替和解除关系与作业取消同一事务提交。V2 暂无法确认时，退出和作业取消先提交，接替等待运行状态恢复后再核对。仍有作业时继续等待，普通退出保留设备槽位。

模拟作业和 V2 历史记录共存时，只要模拟作业仍占用当前执行位置，V2 的退出或恢复不能提前释放设备。模拟作业到期结算后，才执行接替。换机及 TEST 连续执行器释放的原键回执保留 24 小时。
