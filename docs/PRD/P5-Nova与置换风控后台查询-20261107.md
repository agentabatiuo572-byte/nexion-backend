# P5 Nova 与置换风控后台查询

## 目标与范围

减少单主机后台事件读取和 K2 置换风控统计产生的排序、临时文件及重复扫描。当前 PROD 为 backend #28 / main 73ab021e；本批不改变 App、H5、管理端页面、消息频率或风险规则。TEST 仅保留代码，不运行压力测试。

## Nova 事件读取合同

- 保留全部历史事件范围，按 `COALESCE(event_ts, created_at), id` 升序最多读取原配置数量；事件时间为空仍使用创建时间，同时间使用 id 排序。
- 仅读取未删除、服务端权威、满足原 analytics/schema 条件、非 DEAD 且在渠道允许事件名集合内的事实。
- 已有终态渠道回执排除；PROCESSING 回执继续允许原恢复路径。无 user_id 的事实仍交由原业务记录 SKIPPED，不在查询中静默跳过。
- 先确定最多 100 个窄候选，再按主键读取原全部字段及 JSON user_id；单事件名查询可使用事件名、删除标识、权威标识、原时间表达式、id 的非唯一索引。多事件名仍按全局原顺序取数。
- 不新增水位、时间截断、跳过积压或停止后台通知。认领、重试、通知幂等及投递范围保持原规则。

## K2 置换风控合同

- 近 30 天内至少 3 次有效完成置换，且同期存在原规则下的有效返佣或入账礼金，才产生对应风险行。
- 先按用户统计完成置换，再分别按用户读取返佣和礼金真实次数，避免三份来源相互连接放大中间结果。
- 保留原删除、状态大小写处理、时间、方向、正金额条件；保留 rowId、所有文案/次数字段、level、actions 及后续处置版本字段。
- 保持普通 MVCC SELECT 和原风险行 upsert；不把来源读取改为 INSERT…SELECT，不改变资金、订单或风险处置状态。
- origin/test b73f 已有独立预聚合版本；本批在该基线上改为按候选用户相关计数。正式候选只携带本次方法变更，不整分支合入其他 TEST 业务。

## 迁移与回退

`20261107_nova_business_candidate_index.sql` 登记到既有启动迁移。先增加 `DATETIME(3)` 类型的 `nova_business_occurred_at` 虚拟生成列，表达式为原 `COALESCE(event_ts, created_at)`；再单独增加非唯一读取索引。两步分别使用 INPLACE/LOCK=NONE，不修改业务行或既有唯一约束；实际验证重复执行及列/索引定义。无法按指定方式执行时失败，不回退为复制全表或更强的表锁。

代码可先回退原读法，索引可保留；需要移除时按迁移头部 DROP INDEX 语句执行。索引构建消耗 IO，部署期间不得与压力发生器并行。正式部署须先完成本批 main 合并批准。
