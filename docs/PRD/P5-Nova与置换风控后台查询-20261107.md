# P5 Nova 与置换风控后台查询

## 目标与范围

减少单主机后台事件读取和 K2 置换风控统计产生的排序、临时文件及重复扫描。当前 PROD 为 backend #28 / main 73ab021e；本批不改变 App、H5、管理端页面、消息频率或风险规则。TEST 仅保留代码，不运行压力测试。

## Nova 事件读取合同

- 保留全部历史事件范围，按 `COALESCE(event_ts, created_at), id` 升序最多读取原配置数量；事件时间为空仍使用创建时间，同时间使用 id 排序。
- 仅读取未删除、服务端权威、满足原 analytics/schema 条件、非 DEAD 且在渠道允许事件名集合内的事实。
- 已有终态渠道回执排除；PROCESSING 回执继续允许原恢复路径。无 user_id 的事实仍交由原业务记录 SKIPPED，不在查询中静默跳过。
- 先确定最多 100 个窄候选，再按主键读取原全部字段及 JSON user_id；单事件名查询可使用事件名、删除标识、权威标识、原时间表达式、id 的非唯一索引。多事件名仍按全局原顺序取数。
- 不新增水位、时间截断、跳过积压或停止后台通知。认领、重试、通知幂等及投递范围保持原规则。

## K2 置换风控合同

- 近 30 天内至少 3 次有效完成置换，且同期存在原规则下的有效返佣或入账礼金，才产生对应风险行。
- 先按用户统计完成置换，再分别按用户读取返佣和礼金真实次数，避免三份来源相互连接放大中间结果。
- 保留原删除、状态大小写处理、时间、方向、正金额条件；保留 rowId、所有文案/次数字段、level、actions 及后续处置版本字段。
- 保持普通 MVCC SELECT 和原风险行 upsert；不把来源读取改为 INSERT…SELECT，不改变资金、订单或风险处置状态。
- origin/test b73f 已有独立预聚合版本；本批在该基线上改为按候选用户相关计数。正式候选只携带本次方法变更，不整分支合入其他 TEST 业务。

## 2026-11-17 补充：I2 读取链不再建表、补种子或改数据

三个真实 GET（`GET /api/admin/content/nova/overview`、`/social-events`、`/social-events/sample`）此前一进来就调用 `novaRepository.ensureTables()`——它建表、补列、写 V3 频道/模板种子并做一次模板隔离清理；`social-events` 与样本链还会顺手把过期事件 UPDATE 成 `EXPIRED`。读接口因此带写副作用。

本轮把副作用搬出读链，并在既有 Java Mapper 中以只读 SQL 计算有效状态（未新增 schema 或脚本）：

- 现有的 `NovaSocialRuntimeScheduler` 兼作启动初始化（`implements ApplicationRunner`），启动时执行一次 `novaRepository.ensureTables()`，沿用本包既有的 `ApplicationRunner` 范式（同理 `SupportSlaBaselineInitializer`）；不新增类、不新建迁移框架或全局 hook。
- 三个 GET 移除 `ensureTables()`；写入路径（同步、模板/频道维护、派发等）保留各自原有的 `ensureTables()` 调用，写入口职责不变。
- 事件过期从读链移到 `NovaSocialRuntimeScheduler` 的既有调度类里，新增 `@Scheduled` 作业（默认 80s 首跑、60s 间隔，可用 `nexion.ops.content.nova-social-expiry-*` 覆盖），调用新增的 `OpsNovaService.expireOverdueSocialEvents()`；过期仍是写，只是不再由 GET 触发。
- 样本链原本就只读 `status='ACTIVE' AND expires_at > now` 的未过期事件，去掉过期写后结果不变。
- 列表链（`social-events`）的过期状态改为**查询时按同一 `asOf` 计算**（见下方 R1/R2 校正），不再存在「等扫描」的滞后；`asOf` 取自 `OpsNovaService` 既有 `Clock`，与过期作业同源。
- 未改：查询结果字段与排序、有效期过滤、写入口、频道/模板/事件数据、客户端与说明文案、schema 脚本。
- **2026-11-17 R1 校正**：列表与计数的「过期」不再依赖调度扫描——查询时按同一个 `now` 计算有效状态：仅 `status='ACTIVE'` 且 `expires_at <= now` 视为 `EXPIRED`，投影、`status` 筛选与 `count` 用同一表达式，排序/分页/`LIMIT` 语义不变；正常未过期与非 `ACTIVE` 的原状态不受影响。样本链仍只取 `expires_at > now` 的 ACTIVE 事件，不重写；三个 GET 依旧无 DDL/种子/隔离清理/过期 UPDATE。

## 2026-11-18 I2-BE-01：Nova 概览三个统计字段的真实口径

`GET /api/admin/content/nova/overview` 的 `stats` 里，旧字段名与实际数据不符。本次只按原验收的「改名」分支，在 `NovaStats` 增加语义明确的兼容机器字段，取值与旧字段完全同源（同一次 `NovaMapper.stats` 结果、同一次映射），不新增查询、不改变时间窗或空态：

| 字段 | 真实口径 |
| --- | --- |
| `socialNotificationRecordsToday` | 业务日（LEGACY 日历当天，起止同 `BusinessPeriodSql`）内 `nx_notification` 中 `type='NOVA_SOCIAL'`、未删除、`push_status` ∈ {SENT, DELIVERED, READ, SUCCESS} 的**记录数**；不是去重用户数，也不是投递回执的最终送达统计。 |
