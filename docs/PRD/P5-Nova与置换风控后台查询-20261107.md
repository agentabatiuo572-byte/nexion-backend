## Nova 事件读取合同

- 保留全部历史事件范围，按 `COALESCE(event_ts, created_at), id` 升序最多读取原配置数量；事件时间为空仍使用创建时间，同时间使用 id 排序。

- 已有终态渠道回执排除；PROCESSING 回执继续允许原恢复路径。无 user_id 的事实仍交由原业务记录 SKIPPED，不在查询中静默跳过。

## 2026-11-18 I2-BE-11：真实 `social` 频道禁止改触发来源

`social` 的真实派发线是 `NovaSocialRuntimeService` 按 canonical key 使用专用事件池；即使触发文字被改成目录内合法 `a4:` 来源，social 仍会按自身派发，而业务目录又可能把同频道投影为另一条派发线。因此 `social` 不能通过通用目录改触发来源。

- 仅 `PATCH /api/admin/content/nova/channels/{key}` 且请求 key 查到的当前记录持久身份 `current.key() == social`、记录已存在时：请求触发必须与已保存触发按原口径 `trim()` 后相等且两者均非空，才允许更新名称、间隔或冷却。
