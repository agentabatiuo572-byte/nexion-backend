# H4-BE-08 转盘每日真实用量只读投影

日期：2026-11-15
范围：独立管理端只读 GET；不改 App 抽奖/预算/库存/派发、旧 H4 overview/写回执、PC/App/H5 或页面文案。

## 1. 已实现子范围

新增：

`GET /api/admin/growth/quest-events/wheel-daily-usage`

- 方法权限 `growth_h4_read`；`AdminRbacAuthorizationFilter` 的 `/api/admin/growth/**` 默认 growth 域读检查仍生效，无新权限、无新过滤器名单。
- 返回：

```json
{
  "serverDate": "2026-11-15",
  "timeZone": "UTC",
  "realPayoutUsdt": 12.340000,
  "realPayoutAsset": "USDT",
  "spinCount": 37,
  "tiers": [
    {"tierId": 101, "tierName": "1 UVT", "dailyStock": 100, "usedToday": 4}
  ]
}
```

- `serverDate`/`timeZone` 使用 UTC 自然日，与 `AppGrowthWheelService` 的 `LocalDate.now(Clock.systemUTC())` 同一时基；不使用业务时区。
- `realPayoutUsdt` 直接复用 `AppGrowthWheelMapper.currentDailyRealPayout(date)`：`nx_growth_wheel_spin.spin_date=日期 AND real_outflow=1 AND is_deleted=0` 的 `SUM(reward_amount)`；与正式每日预算 guard 同一表、同一天窗、同一状态过滤。
- `realPayoutAsset=USDT`：抽奖校验要求 `usdt` 与 `real_outflow` 一致，不能把 UVT/USD 按名字换算。
- `spinCount`：`nx_growth_wheel_spin` 中同一 `spin_date`、`is_deleted=0` 的成功抽奖行 `COUNT(1)`；拒绝/入口失败没有 spin 行。
- `tiers`：当前有效奖档（`nx_growth_wheel_tier.status=1 AND is_deleted=0`）的稳定数字 `tierId`、当前名称、`dailyStock` 和当天 `usedToday`。`usedToday` 来自同一 spin 表按 `tier_id` 的 **一条 GROUP BY COUNT(1)**，不是每档 SQL；与 `currentTierDailyAwards` 同过滤。`dailyStock=0` 是既有“不限量”语义。
- 金额保留 `BigDecimal` 原精度（DB DECIMAL(18,6)），计数用 `long`；查询异常直接报错，不吞成 0。

## 2. 明确缺源/未实现

- **geoBlocked 未实现**：当前 `nx_event_quest.geo_scope` 是自由文本，既有 J2 地区规则/事件目录/用户被拒事件不是同一张权威集合；“限地区活动数”没有可证的统一口径。不能把运营活动 `geo` 字符串、J2 endpoint policy 或用户被拒次数混为一类，也不凭空把 `geo_scope` 非空数当 geoBlocked。
- 奖档历史：当前只返回有效奖档；已退役/改名奖档若不在有效配置中不会被当前 tier 列表补回。虽然 spin 行有稳定 `tier_id`，但没有当前奖档配置时不能反推历史名称/库存，故不伪造 0 或补历史行。
- 未改旧 `questEventOverview`/`h4Stats.wheelToday`/`geoBlocked` 页面字段；独立 GET 是后续 PC 接入候选，旧 overview 不因新查询失败。
