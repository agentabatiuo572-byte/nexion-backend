# H4-BE-08 转盘每日真实用量只读投影

日期：2026-11-15
范围：独立管理端只读 GET；不改 App 抽奖/预算/库存/派发、旧 H4 overview/写回执、PC/App/H5 或页面文案。

## 1. 已实现子范围

新增：

`GET /api/admin/growth/quest-events/wheel-daily-usage`

- 方法权限 `growth_h4_read`；`AdminRbacAuthorizationFilter` 的 `/api/admin/growth/**` 默认 growth 域读检查仍生效，无新权限、无新过滤器名单。
- 返回：

```json
{
  "serverDate": "2026-11-15",
  "timeZone": "UTC",
  "realPayoutUsdt": 12.340000,
  "realPayoutAsset": "USDT",
  "spinCount": 37,
  "tiers": [
    {"tierId": 101, "tierName": "1 UVT", "dailyStock": 100, "usedToday": 4}
  ]
}
```

- `serverDate`/`timeZone` 使用 UTC 自然日，与 `AppGrowthWheelService` 的 `LocalDate.now(Clock.systemUTC())` 同一时基；不使用业务时区。
- `realPayoutUsdt` 直接复用 `AppGrowthWheelMapper.currentDailyRealPayout(date)`：`nx_growth_wheel_spin.spin_date=日期 AND real_outflow=1 AND is_deleted=0` 的 `SUM(reward_amount)`；与正式每日预算 guard 同一表、同一天窗、同一状态过滤。
- `realPayoutAsset=USDT`：抽奖校验要求 `usdt` 与 `real_outflow` 一致，不能把 UVT/USD 按名字换算。
- `spinCount`：`nx_growth_wheel_spin` 中同一 `spin_date`、`is_deleted=0` 的成功抽奖行 `COUNT(1)`；拒绝/入口失败没有 spin 行。
- `tiers`：当前有效奖档（`nx_growth_wheel_tier.status=1 AND is_deleted=0`）的稳定数字 `tierId`、当前名称、`dailyStock` 和当天 `usedToday`。`usedToday` 来自同一 spin 表按 `tier_id` 的 **一条 GROUP BY COUNT(1)**，不是每档 SQL；与 `currentTierDailyAwards` 同过滤。`dailyStock=0` 是既有“不限量”语义。
- 金额保留 `BigDecimal` 原精度（DB DECIMAL(18,6)），计数用 `long`；查询异常直接报错，不吞成 0。

## 2. 明确缺源/未实现

- **geoBlocked 未实现**：当前 `nx_event_quest.geo_scope` 是自由文本，既有 J2 地区规则/事件目录/用户被拒事件不是同一张权威集合；“限地区活动数”没有可证的统一口径。不能把运营活动 `geo` 字符串、J2 endpoint policy 或用户被拒次数混为一类，也不凭空把 `geo_scope` 非空数当 geoBlocked。
- 奖档历史：当前只返回有效奖档；已退役/改名奖档若不在有效配置中不会被当前 tier 列表补回。虽然 spin 行有稳定 `tier_id`，但没有当前奖档配置时不能反推历史名称/库存，故不伪造 0 或补历史行。

## 2026-11-16 补充：H4 概览统计的两项与转盘估值的精度/币种

`GET /api/admin/growth/overview`（`h4Stats`、`wheelEvUsd`）此前缺少「转盘今日次数」和「地区限制数」，且 `wheelEvUsd` 被舍到 2 位、没有任何币种标记。

本次只补真实可取的部分，不造口径：

- `h4Stats.wheelSpinsToday`：`nx_growth_wheel_spin` 按 `spin_date`（转盘自己记录并据以执行每日限次的那一列）统计当天真实抽奖行数；业务表不可用时返回 `null`，不返回 0。同处给出 `wheelSpinsTodayBasis = "nx_growth_wheel_spin.spin_date"` 说明口径。注意：该日期是转盘记录的 UTC 日期，**不是** `BusinessCalendar` 的账务业务日；若后续要求按账务业务日统计，属另一个口径决定。
- `h4Stats.regionRestrictionCount = null` 且 `regionRestrictionsAvailable = false`、`regionRestrictionsReason = "H4_REGION_RESTRICTION_SOURCE_MISSING"`：H4 转盘没有地区限制的持久记录或配置源，事件定义、奖池档位与总用户数都不是该指标，因此如实留空而不是给 0。H3 的 `weekly_region_policy` 属周任务，不是 H4 来源。
- `wheelEvUsd`：去掉 `setScale(2, HALF_UP)`，保留原来「金额 × 概率 ÷ 100」的同一算法与 6 位中间精度，只不再进位；同时新增 `wheelEvByAsset`，按档位的 `reward_kind` 分组给出各自的期望值，避免把 UVT 与 USDT 的金额相加；`wheelEvUsd` 在有 USDT 档位时取 USDT 那组，否则退回全部合计（与旧口径一致），不再隐含混币。
- 未改动：奖池档位/概率/日库存、抽奖与实际派发、转盘护栏与审批、权限、页面与文案、表结构；概览键名与其它统计保持原样。

## 2026-11-16 补充（H4-BE-08 剩余项）：奖池读取的「今日已发」

上一小节已交付「转盘今日次数」（`h4Stats.wheelSpinsToday`，按 `nx_growth_wheel_spin.spin_date`，UTC 日，沿用不改）。本小节只补同源的另一半：今日**已发**。

真实发放源与事务边界（`AppGrowthWheelService.executeSpin`）：抽奖在同一事务内先 `insertSpin(...)` 落 `nx_growth_wheel_spin`（含 `reward_kind` / `reward_amount` / `real_outflow` / `spin_date`），再 `award(...)` 完成钱包入账（UVT/USDT）或券发放（coupon）；任一步失败整体回滚。因此**已提交的 spin 行本身就是成功发放事实**，不是预算、预览 EV 或失败尝试。

新增只读投影 `wheelAwardsToday`（与 `wheelEvUsd`、`wheelEvByAsset` 并列，均在 H4 概览响应内）：

- `basis = "nx_growth_wheel_spin.spin_date"`；`spinDate` 为转盘写入并限次所用的同一个 UTC 日（不改成账务业务日）。
- `byAsset`：按 `UPPER(reward_kind)` 分组，每组给 `count`（发放笔数）与 `amount`（`SUM(reward_amount)`，保留 `DECIMAL(18,6)` 原精度，不混币、不折算）。
- 业务表不可用（mapper 为空）时 `available=false` + `reason="GROWTH_BUSINESS_TABLE_UNAVAILABLE"`、`byAsset` 为空，不返回 0 冒充「已发 0」。
- `coupon` 档的 `amount` 是档位面额，实际兑付是券发放；`count` 才是该资产的发放笔数，二者按同一行如实给出。

未改动：概率、档位、库存、派奖与钱包/券发放、护栏与审批、权限、页面与文案、表结构与数据。
