# 登录并发和优惠券规则缓存

App 和 H5 的账号校验、旧会话替换、登录凭据恢复与退出规则沿用现有契约。密码、验证码、双因素和 OAuth 会话签发事务使用 READ COMMITTED，缩小更新旧会话时的锁范围。同账号签发仍以账号行锁串行执行，撤销旧会话、记录本次尝试和写入新会话一起提交。

访问令牌有效小时数、续期令牌有效天数和会话闲置有效天数作为一份共享 Redis 快照，30 秒过期。登录及续期使用同一份时效设置；HTTP 与 WebSocket 的 JWT 会话有效性、过期原因和续期后继关系校验从该快照读取闲置期限，仍为 7–90 天、默认 30 天。C5 修改这三项中任一项成功提交后使快照失效，Redis 不可用时回源读取。原有填充比较与失效标记、旧 REPEATABLE READ 事务不得填充共享快照的限制保持。已签发凭据、账号状态、封禁、密码、双因素和个人会话仍按原路径实时校验，退出及会话撤销不使用此配置快照保存个人状态。

全局限流入口在读取并校验每分钟额度后，将值保存在当前 HTTP 请求中；后续已鉴权主体限流使用同一额度。全局入口未处理该请求时，主体限流仍按原路径读取并校验额度。额度不跨请求缓存，原 Redis 计数、429 拒绝和配置不可用时的 503 行为保持。

正常优惠券列表从共享 Redis 读取已缓存的规则展示字段。MySQL 实时决定可见券、定义版本、有效窗口、发行余量、个人券和弹窗状态。缓存版本不一致或不可用时回源。创建、更新、启停、删除及撤销未使用券提交后清理共享快照。领取、报价、下单和取消继续依据事务内的最新规则与用户权益。

容量验收先按上一轮的隔离双 JVM、4,400 个独立账号、每秒 16 次发起和 155 秒观测窗复测。每个有效在线账号须有已鉴权连接、45 秒内的 pong 和 90 秒内的业务查询。之后按实际资源和错误率逐档增加，记录登录、连接、查询、CPU、内存及数据服务压力。
