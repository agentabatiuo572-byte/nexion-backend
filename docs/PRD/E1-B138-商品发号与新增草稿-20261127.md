# E1 B138 商品发号与新增草稿

新增商品分别从 E1 直写和 A2 审批执行时发号。编号使用小写的「档位码-系列码-三位序号」。每个前缀独立递增，既有商品占用的号继续有效，包括软删除记录。两张商品表使用同一个编号。商品建成后的档位、系列和生命周期操作继续按实际编号定位。

| 档位 | 编码 | 系列 | 编码 |
| --- | --- | --- | --- |
| Entry | `e` | S1 | `s1` |
| Pro | `p` | PRO | `pro` |
| Flagship | `f` | PRO_V2 | `pv2` |
| Share | `s` | RACK_P1 | `rp1` |
| | | RACK_P2 | `rp2` |
| | | CLOUD_SHARE | `cs` |

## E1 新增和 A2 审批

- 每份草稿使用一个 UUID `createRequestId`，回执和对象锁使用小写形式。直写 `POST /api/admin/devices/skus` 在请求体传入该字段。A2 `e1_sku_create` 在 `command.params` 传入该字段，锁对象使用 `E / device_sku_create / createRequestId`，对象名为草稿商品名。待批审核使用冻结的商品名、档位、系列和业务条件。
- 同一发起人、同一草稿号、同一业务内容，直写和提议入口各自支持原操作键及新操作键重试。直写返回原商品，提议返回原工单的当前状态。改动业务内容时需使用新草稿号。当前草稿关联审批后，直写保持审批约束。
- 建单回执、审批详情和原号查询可回读 `createRequestId`。批准成功时返回 `resultSkuId`。原发起人具备当前 E1 读写和 A2 提议权限时，可按本人原键查回该工单。编辑、上下架和删除继续使用 `E / device_sku / 实际商品编号`。
- 月收益、任务池、发布状态和资金覆盖率继续按既有业务口径检查。上架状态按 E1 规范化后执行任务池检查。未发号草稿的月收益结构化拒绝带 `createRequestId`，`affectedSkuIds` 仅列已有商品。批准直接上架时，既有上架证据可按实际商品编号关联审批。待批、撤销、驳回和审批执行失败不会占用正式编号。

## 切换与验收

- 共享切换前结清旧格式的 E1 新增待批单，并按商品目录联动约定核对 PC 支持 `createRequestId`。历史新增、修改、上下架及删除工单继续按既有权限和原号读取。
- 隔离验收覆盖直写、真实双人审批、原号与换键重试、异参冲突、双表同号、前缀隔离、占号与并发、权限及资金门禁。使用同一真实商品目录校验后续编辑和上架证据。B140 的全新安装目录与环境重建按原单另行验收。
