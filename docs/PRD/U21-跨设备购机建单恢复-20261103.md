# 跨设备恢复购机订单

U-21 适用于正式 App 和 H5 的 `POST /api/orders` 与 `POST /api/orders/bundle`。已登录用户在第一台设备提交后丢失响应，第二台设备使用新的 `Idempotency-Key` 提交相同购买条件时，服务端返回第一笔仍可付款订单的建单回执。订单号、金额、券、订单行、活动预留和建单事件都沿用原单。

## 怎样识别同一次购买

* 普通建单匹配登录账号、商品、数量和券。系统核对服务器保存的原价与当前商品单价。商品可以用 ID 或编号指定，两者同时传入时须指向同一商品。省略数量按一件处理。
* 组合购匹配每个 SKU 的数量、报价金额和折扣策略版本。调整明细顺序不改变意图。旧版 `productNos` 每个 SKU 一件，与同样数量的 `items` 等价。无活动报价时各行单价也须一致。
* 带服务器报价的购买独立匹配。重新报价会核对活动、版本、券、商品数量、各行定价和折扣分摊、策略、奖励条款及受益账户。条款相同且原单仍可付款时优先返回原签发报价。无待付单时可复用仍有效且未消费的等价报价。订单号及报价的支付截止时间继续取原单。改价、换政策或变更奖励需重新确认相应报价。已用于终态订单的报价不能再开订单。
* 支付渠道在后续订单付款接口选择。钱包与外部通道都绑定服务器订单号。置换和容量替换使用各自的带来源命令。这两个建单入口只接受本节列出的购买条件。

重读报价时，`serverTime` 取本次服务端时间。未消费报价使用原签发的 `expiresAt`，已有可付款订单的报价使用原单 `payBy` 表示恢复期限。签发快照和付款期限保持原值。恢复订单时核实该单已占用的券、活动名额或预算，并按现行活动及受益条件对照原权益。真正新购按当前库存、名额和容量执行检查。

## 有效期与再次购买

从原订单创建时间起搜索 24 小时，并同时检查待付款状态、原订单支付期限和活动付款截止。原单可付款期间，同条件换键继续原单。需要建立另一笔同条件购买时，可先取消原单，或在原单完成、到期后用新键提交。已用的活动报价须重新取得。实际可付时间可能短于 24 小时，普通订单默认 30 分钟。

原请求键和已恢复成功的请求键都保留当时的建单回执，原单结束后重放这些键仍返回原订单号。订单当前状态从订单查询读取。新键与原请求键共用账号隔离和购买资格边界。相同键更改载荷返回幂等冲突。旧版组合购成功键按已保存的金额及策略验证，回放原回执；老协议没有记录的字段按原回放规则处理。

服务重启和版本升级使用同一数据库。历史普通或组合单须有该账号正式建单入口的成功回执及可核实的订单事实。若升级前已有多笔重复单，优先恢复最早仍可付款的一笔，逐笔保留历史记录。事务失败时沿用原命令错误和重试规则。

升级前两份已签报价若条款等价，建单按原订单返回 `promotionQuoteId`，另以 `recoveredQuoteId` 标识本次提交的报价。新键可用本次提交的报价号查询命令结果。新签发流程直接复用原报价号。正式客户端只在本账号当前建单成功或该命令成功读回时接收等价指针，并在核对订单号、商品、金额、数量及奖励条款后保存。
