# H3 已存奖励策略读取兼容

已存的首日任务三段奖励策略可以使用历史 NEX 后缀。读取时仅将该后缀投影为当前 UVT 语义，继续按原三段数值、冻结全奖与资格时窗、倍率和节奏月计算；不改写现有配置、实例、快照摘要或已发奖励，不用当前配置重算历史。

首页和任务中心读取已有实例时，已过期实例的当前阶段奖励仍为 0。资格窗内的合法旧实例沿原合同领取，仍须满足完整冻结成员组、任务完成、资格窗和一次领取要求，沿用原幂等编号、金额精度和资金校验；过期、缺失成员、重复领取及非法策略仍按原规则处理。读取兼容不补发或重置任何奖励。

注册读取合法旧配置创建新首日实例时，保留相同奖励数值并将新实例策略冻结为规范 UVT 文本；已有实例直接复用，不重建。后台新提交的策略继续只接受 UVT，原金额、三段关系、精度、时窗及资金放大审批规则保持不变。

此改动仅恢复后端已存策略读取和原合同执行，不包含 App、H5 或管理端页面单位、文案、布局和交互调整。

## 2026-11-17 H3-BE-03 任务契约字段的实际含义

管理端既有 `taskContracts` 按原要求的“准确字段含义”分支提供可核对的读取合同，不把配置任务号或静态提示当成实际事件归因。仅修正该读取，不改 H3-BE-02 的经营统计、完成生产、任务状态、发奖或事件路由。

- `sample24h` 和新增的规范字段 `completed24h` 同值：按每个未删除任务定义，统计其未删除 `nx_user_mission` 中当前状态为 `COMPLETED` / `CLAIMABLE` / `CLAIMED` 且真实 `completed_at` 落在 `[DB NOW()-1 DAY, DB NOW()]` 的实例数。`markMissionCompleted` 真实写入完成时间，重复完成保原时间；表唯一键 `(user_id,mission_id,instance_key)` 保证每实例只计一次，后续领取不重复计。没有完成时间的旧行不借 `created_at` / `updated_at` 伪造，字段明确为有完成时间的事实数；未计入的旧行不代表已完成 0 次。本次不新增历史回填或查询故障的伪零兜底。
- `completionBasis` 随行返回源表、时间列、状态集合、滚动 24 小时 DB 时钟窗口及唯一实例去重依据。原查询使用 DB `NOW()`，继续与完成 writer 的 `NOW()` 同源，不切换成自然日或其它业务周时区。
- 新增 `missionCode` 是 `nx_mission.mission_code`；原 `taskKey` 与 `serverEvent` 保持兼容，其中 `serverEvent` 仅为任务码的旧别名，不代表 `event_type` 或实际完成事件。`fieldSemantics.serverEvent = MISSION_CODE_COMPATIBILITY_ALIAS` 明确该含义。
- 新增 `b3Default` / `retentionOnlyDefault` 分别给出原 `b3=true` / `retentionOnly=false` 的静态兼容默认值；原字段保留类型和值，`fieldSemantics` 标明 `STATIC_DEFAULT_COMPATIBILITY_ALIAS`，`attributionAvailable=false`。这些字段不是实际 B3、留存或报表归因结果。现有 canonical binding 的 `quest_code` 与 `event_type` 是不同字段，且首日、周任务有冻结路由上下文，不能凭任务同名推导真实链路或承诺发奖/报表一致。
- `anomalyPct` 保持原“过去一天创建实例中，当前状态为 FAILED / ANOMALY / REJECTED 的比例”，不改成完成事实的异常率；`fieldSemantics.anomalyPct = CREATED_INSTANCE_CURRENT_STATUS_RATIO` 将其与真实完成数区分。旧空下游占位不冒充实际链路。
- 本轮只追加机器字段与来源元数据，不修改原人话标签、页面说明、前端或 App，不要求既有页面已消费新字段才验收后端合同。仅源码候选与必要 Java 17 双 skip 编译，未执行 E2E、HTTP、DB、业务请求或部署。
