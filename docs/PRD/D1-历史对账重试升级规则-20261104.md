# D1 历史对账重试与充值策略升级

日期：2026-11-04。范围：旧库首次安装充值策略；不改变充值、提现、余额或页面规则。

历史对账尝试失败后会保留 `INCOMPLETE`，后续重跑成功另写 `COMPLETE`。安装策略时不再要求每一条历史尝试都曾成功：已经结束的失败尝试，只有被同项目、完成时间不早于该失败、稳定至少两轮且完整覆盖原时间窗口的成功记录覆盖，才不再计为未解决项。

- 原失败和成功记录全部保留，不改状态、失败原因、时间或金额。
- 未结束、没有后续完整覆盖、未知状态或仍在运行的对账继续阻止安装。
- 成功记录仍须满足稳定轮数及完成时间要求。
- 充值事件、已接受通知、人工复核、退款、重组等原有闭环检查保持不变。
- 不推进扫描水位，不据此证明水位之后没有未发现的入款，不启用外部通道。

生产库副本升级验收：3,167 条成功记录覆盖了 5,246 条已结束的历史失败；修复后 80 项版本迁移完成。未覆盖失败、仅有更早成功、尚未结束失败、活动对账四种情形仍被拒绝，测试事务回滚后原对账数据一致。钱包金额、账本业务字段（按既定 NEX→UVT 资产更名归一）、历史运行记录和扫描水位的摘要与升级前一致。

恢复数据库副本时还须核对例程定义者。资金结构读取函数沿用现有部署规范：锁定的 `nexion_support_schema@localhost` 仅获五张指定表的 `REFERENCES, TRIGGER` 及该函数的 `EXECUTE`，应用获得该函数 `EXECUTE`；不改函数正文或以 root 替代定义者。缺失此身份不能仅凭 HTTP 健康接口认定资金链路可用。

以上是数据库升级验收，不代表生产发布、外部支付或全流程容量测试已通过；这些结果单独记录。
