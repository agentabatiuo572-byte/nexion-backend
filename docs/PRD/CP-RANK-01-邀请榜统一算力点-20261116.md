# CP-RANK-01：邀请榜统一为团队算力点

## 本轮范围与状态

用户于 2026-11-16 确认排名业务口径；随后明确任何前端代码不改，本轮只修后端和现有 App 读取，PC F4 页面接线暂缓。本文为后端候选合同，发布与业务验收结果由本轮验收回执另记，不能把编译通过当作业务通过。

## 排名口径

- 参与人为同一环境中有效、活跃的用户；使用与 App 团队网络一致的邀请关系 `nx_user.sponsor_user_id`，递归计算 L1–L7 下级，不含本人，不跨 sandbox，不重复经过环形关系。
- 排序分数为下级有效已付款订单的 `nx_order.compute_points` 快照之和。只读取快照，不从佣金、实付金额、商品现价或设备 TOPS 换算算力点；订单中的置换差额也不再次计算。
- 订单须未删除，付款状态为 `PAID` / `CONFIRMED` / `SUCCESS`，订单状态不是 `REFUNDED` / `CHARGEBACK`，快照点数大于 0。没有正点数的用户不进榜。
- 付款时间优先 `paid_at`；仅遗留已付款订单缺少 `paid_at` 时，沿用既有算力汇总的 `created_at` 回落。付款时间和订单创建时间均不能晚于本次快照边界。
- 日、周、月、总榜继续使用 `BusinessCalendar.growthTeam()` 的版本化业务时区和现有周期边界；周从周一开始，日/周/月为左闭右开区间，总榜不限起始时间。数据库 DATETIME 仍为原存储时区，不改存储或历史已结算周期。
- 分数降序，同分按用户编号升序。保留原周期名额上限：日 20、周 50、月/总 100。
- 保留现有成员取消资格、欺诈、风险处置排除条件；本次不改变既有处置的到期规则。

## 门槛、发奖与权限

- 新权威键为 `team.ui.F.leaderboard.minComputePoints`，缺失时有效值为 **1 点**，管理配置键为 `F.leaderboard.minComputePoints`。允许非负整数，最大 `9007199254740991`；配置为 0 也不会让零点用户进榜。
- 旧 `minUsd` 的存储和历史保留，不迁移、不换算、不参与新排名。旧管理写入（含审批回放）明确拒绝：`409 / F4_LEADERBOARD_MIN_USD_RETIRED_USE_COMPUTE_POINTS`。
- 新门槛沿用原门槛的 `network_f4_write` 权限，普通保存和审批回放保持同一权限映射及现有对象锁、审计、幂等规则。
- App 榜单、PC 后端投影、新暂停快照、F4 排行榜派奖候选共用同一条排名 SQL。派奖仅按该候选顺序分配；奖池仍为 USDT，原名次权重、Top1/Top5 封顶、审批、资金账本和幂等结算键均不改。已结算周期不会因指标切换重发。
- 新派奖审计注明 `rankingMetric: COMPUTE_POINTS`、`minComputePoints`，避免继续把门槛记为美元。

## 读取合同与冻结

- App `GET /api/app/team/insights/leaderboard` 继续原 period/page/pageSize/snapshotAt/snapshotVersion 参数；响应增加/兑现 `rankingMetric: COMPUTE_POINTS`、每行整数 `computePoints`、整数 `gapToNextComputePoints`。不把算力点写入旧 `earnedUSDT` 或金额差值字段。
- 继续使用首页生成的不可变候选快照分页；版本材料使用算力点及新版本前缀，跨周期、跨环境、版本缺失或过期仍按现有规则拒绝，防止混页。无资格的当前用户 `myRank` 为 null。
- 新暂停快照 envelope/ref 的 `schemaVersion` 为 2，周期 basis 为 `TEAM_PAID_ORDER_COMPUTE_POINTS_V1`，保存整数点数、当时奖池、门槛和业务时区；冻结状态不重算名次和点数。
- 原 schema 1 佣金快照不覆盖、不删除、不转换为点数。暂停期间遇到旧快照明确为 `UNAVAILABLE / SNAPSHOT_SCHEMA_UNSUPPORTED`；依原受控恢复流程恢复后可重新读取实时算力榜，下一次受控暂停才建立新快照。
- 显式 SANDBOX 分支继续返回 SANDBOX/RunID 来源，生成稳定、降序的整数点、名次差值和快照标识；不读取生产订单，也不进入生产派奖候选，奖池和可派奖名额为 0。

## PC F4 暂缓的可见影响

本轮不修改任何前端文件。后端各周期投影会返回 `rankingMetric`、`computePoints`、`minComputePoints`、真实点数 `gmvLabel`（例如 `1200 点`）和业务时区。原 PC 解析器仍只接受美元 `gmvLabel`，因此旧 F4 周期可能显示不可用；不得为通过旧解析器把点数伪装为 `$1200`。原 F4 门槛按钮仍提交旧 `minUsd`，将被明确拒绝。PC 对点数协议、说明、门槛、审批摘要和业务时区的页面接线属于用户暂缓范围，不计为本轮已完成。

## 既有订单能力边界

- 现有 E4 允许退款金额小于原款，但仍将整订单变为 `REFUNDED` 并回收整单资产，没有按订单行扣回点数的实现。因此该订单全部点数退出新榜，不能声称已支持“部分退款按行扣点”。本轮不扩改退款业务。
- `TRADE_IN` / `CAPACITY_KEEP` 已把非负目标点数减来源点数写进新订单；新榜直接读取该快照。其既有来源点数取自当时商品配置，并非回读旧订单快照；本轮不调整置换规则。
- 普通单和组合单的既有点数快照在建单时形成，转正/置换在对应新订单形成时写入；只有付款状态有效后才计入排名。本轮不改变商品调点与存量未付款订单的快照时机。
