# B4 下次调整数值格式

「下次调整」摘要使用与本月重点相同的十进制格式呈现 H1 配置数值。整数费率显示为 `20%`，小数保留有效位数。单位、布尔值和两期比较规则沿用 B4 的现有合同。格式化仅作用于摘要文本，计算和配置值继续使用 H1 权威数据。

## 阶段名称读取（2026-11-17）

B4 概览的阶段分布、月份分布各行附 `phaseName`，筛选项附 `phaseName`、`phaseNames`，当前节奏附 `currentPhaseName`。名称与 H1 归因目录共用 `GrowthRhythmSnapshot.phaseNames()`，沿用现有 P1–P6 的六个名称。原阶段代号、筛选选项、分布数值、八项参数、摘要文字和 CSV 导出合同保持；读取名称无需另取 H1 查看权限。

## B4-BE-02 阶段参数范围（2026-11-17）

八项阶段参数以 H1 已有正式保存的 `OpsGrowthService.normalizePhaseDialValue` 为权威；当前值保存 `updatePhaseDial` 与月份值保存 `updatePhaseMonthDial` 均在写入前调用它。`GrowthRhythmSnapshot.validateRequiredFacts` 按相同的已持久化单位校验当前或指定月份的参数，不另设更宽的读取范围。

| 参数 | 持久值的合法范围（含端点） |
| --- | --- |
| `newUserBonusMultiplier`、`inviteRewardMultiplier`、`reinvestMultiplier`、`questBonusMultiplier` | `1–4` 倍 |
| `withdrawPenaltyFeeRate` | 归一费率 `0–1`；现有百分比展示换算保持 |
| `withdrawCooldownDays` | `0–90` 整数天 |
| `binaryDailyCap` | 新增保存值 `>0` 且 `≤50000`，沿原金额单位；存量读取边界见下节 |
| `complianceHoldEnabled` | 原持久值 `0/1` |

本次仅将四项倍率、冷却天数、每日上限的过宽读取边界对齐既有写入边界。缺失、空白、格式非法或越界仍按原配置键进入 `reliabilityErrors`、`reliable=false`，不钳制成合法值或用默认值替代；已有总月数、当前月、进度、阶段码、整数性、费率和布尔校验不变。`binaryDailyCap=0` 的读取合法性保持，本项不决定 B4-BE-05 的 App 零上限行为。未改 H1 writer、审批/权限、奖励/结算、标签/说明文本或前端。

## B4-BE-05 每日上限保存拒零（2026-11-17）

采用原要求“写入时就拒绝”的分支，与现有 `AppBinaryProjectionService` 和正式 `BinarySettlementPolicyProvider` 拒绝零上限的执行规则一致，不将 0 定义为停发。`normalizePhaseDialValue` 仅在 `binaryDailyCap` 分支内，沿原解析、非负/50000范围及六位小数归一化后，拒绝实际归一化为 0 的值，沿既有错误处理返回 `H1_BINARY_DAILY_CAP_INVALID`。输入 `0`、`0.0` 等数值零，以及原归一化后为零的值，均不能写入；原非零合法值、范围/精度算法、负值/缺失/不可解析拒绝保持。

当前值 `updatePhaseDial`、月份值 `updatePhaseMonthDial` 及 `h1_phase_dial` 批准执行共用该写前校验，早于配置持久化和成功审计。原权限、命令锁、hash、scope、成功幂等回执优先恢复、其它阶段参数和奖励/结算算法保持，不新增通用 positive helper 或其它字段限制。
