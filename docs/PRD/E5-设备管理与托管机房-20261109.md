# E5 设备管理与托管机房

日期：2026-11-09。依据 PLAN-v3 / v3.1 的 R1、R2、R9、R10、L6；本文件覆盖旧 E5 的机房登记、遥测列表和计数说明。

## 范围与边界

E5 只列出 `source_channel IN ('ORDER','TRADE_IN','TRIAL','PROMOTION_GIFT')` 的非手机设备，保留停用、解绑等历史记录。尚未转正的试用没有设备记录。排除软删除记录、非 PRODUCTION 环境、非空 run_id 和 sandbox 用户。列表、列表总数、状态/来源/商品/关键词筛选、概览共用同一范围。

手机身份为 device_type=MOBILE/PHONE，或 product_code=phone/mobile，或 product_tier=PHONE/MOBILE，比较不区分大小写。手机列表放在 E6，读取和操作仍使用 E5 权限；E6 配置权限不会获得设备操作权限。每户 6 台上限和槽号继续按全部已激活设备及已有预约规则计算，包含手机。

托管机房只是一段 SKU `datacenter` 文字，交付时复制到设备 `dc_location`。交付后改商品不改变设备；订单仍显示设备交付快照，推广赠机仍使用发放时冻结的商品快照。此次迁移不更新任何设备标签、SKU 标签、订单或赠机快照。SKU 上架校验、标签建议、任务池及切换由另一后端分支实现。

首页在网客户的 city、name、分组标识及来源说明直接使用设备标签；不再查询机房登记或从任务客户端名称推导托管名称。H9 地球配置和现有在线资格规则保留。

## E5 状态

列表状态来自激活生命周期、普通设备暂停原因和 SIM runtime，独立于硬件心跳。总开关关闭时统一显示 SIM_OFF，只读展示，不据此推断硬件在线。

| simState | 含义与优先级 |
| --- | --- |
| UNBOUND | 设备 status 或 ownership_status 为 UNBOUND |
| CLOSING | pending_deactivate=1；或未结束的 SIM stop_after_current / CLOSING |
| STOPPED | 已有 deactivated_at，或 DEACTIVATED/RECYCLED/RETIRED；或 SIM 已 STOPPED/EXPIRED |
| WAITING_ACTIVATION | 尚无 activated_at |
| PAUSED | 普通 paused_reason 非空，或 SUSPENDED；已结束的生命周期优先于暂停原因 |
| ERROR | SIM state=ERROR，返回 last_error 与 next_action_at，沿用自动重试 |
| WAITING_CONFIG | 已激活但没有 SIM runtime，或 runtime=WAITING_CONFIG；重新激活/恢复后仍残留的已结束旧区间也表示等待初始化；不伪造当前任务 |
| RUNNING | 剩余正常运行态，当前单读取 SIM 当前任务，单间调度时可以暂时没有当前单 |
| SIM_OFF | 模拟任务总开关关闭；优先于上面各显示态 |

执行时的优先级为：UNBOUND → pending_deactivate → 已结束生命周期 → 未激活 → 普通暂停 → ERROR → 重新激活/恢复后的旧区间 → 已结束 runtime → stop_after_current/CLOSING → 等待配置/无 runtime → RUNNING。终态 runtime 即使保留历史 stop_after_current，也不误显示为停用中。

SIM ERROR 无手动修复接口：保留系统原有约 30 秒自动重试。旧任务“终结资格/重新核对”及其权限、案件条件保持原样，不能拿来修复 SIM ERROR。

E5 手动激活在 SIM 开启时把非手机设备置为 ACTIVE，使其能被既有 SIM 初始化调度发现；SIM 关闭和手机继续使用既有激活行为。按用户暂停在同一命令事务内记录 SIM 的最早截止时刻并唤醒；恢复只唤醒，保留截止，防止快速暂停后恢复漏掉整个暂停段。手机有效期不延长。单台取消激活仍经过既有生命周期 requestStop，保留旧任务排空。

## API

沿用 ApiResult / PageResult 和现有业务时区日期序列化；本月收益对象不变。列表按设备 id 降序分页。

| API | 权限 | 响应 |
| --- | --- | --- |
| GET `/api/admin/devices` | device_e5_read | 商城设备分页，筛选 keyword、simState、source、productCode、pageNum、pageSize |
| GET `/api/admin/devices/overview` | device_e5_read | `{total,running,waitingActivation,stopped}`；一条分组 COUNT 查询 |
| GET `/api/admin/devices/observability` | device_e5_read | 只有 activity：设备事件，最近 24 小时，最多 50 条 |
| GET `/api/admin/devices/phones` | device_e5_read | 手机分页，keyword、pageNum、pageSize；保留原有手机遥测字段 |

商城行保留身份、用户、商品、购买/激活和槽位字段，新增 sourceChannel、hostingLabel、simState、simLastError、simNextActionAt、currentTask、maxDevicesPerUser=6。hostingLabel 原样取设备标签。currentTask 为 null 或 `{taskNo,name,taskClass,startedAt,dueAt}`，取 SIM 当前运行单的冻结内容。本月收益继续返回 monthlyTarget。

商城列表不返回 runtimeStatus、lastSeenAt、activeTaskNo、heartbeatAt、heartbeatAgeSeconds、电量、充电、网络、温控、GPU 遥测。手机列表保留这些已有字段。未知 simState / 非商城 source 返回 422（E5_SIM_STATE_INVALID / E5_SOURCE_INVALID）。

激活、取消激活、强制激活、解绑、按用户暂停/恢复沿用既有路径和权限（device_e5_write、device_e5_device_force_activate、device_e5_device_unbind），高敏动作仍要求 A2。未新增 SIM 修复按钮或放宽 E6 权限。客服按用户设备分页读取全部来源和手机，独立于 E5 范围。

## 已删除功能

- E5 机房列表、创建、修改、删除、暂停/恢复，及对应 DTO、服务、repository、mapper。
- `/api/app/network/regions` 及整个旧查询链；App 没有页面调用该接口。
- 机房登记/运行状态两张表的建表、种子、历史 ALTER/INSERT、启动链引用。
- SIM、AppTaskAssignment、TestCloud 和首页 SQL 对机房状态的 JOIN/过滤；SIM 建单/结算不再持有机房共享锁。
- 五个 e5_datacenter_* A2 操作、device_datacenter 锁目标、device_e5_datacenter_pause 权限及其角色授权。A2 提案边界对旧机房命令/锁目标返回 422 RETIRED_FEATURE，超级管理员也不能通过通用提案入口重建旧票据/锁。
- admin.datacenter_* outbox allowlist、A4 注册及观测 feed 机房事件。
- 只供旧机房选择器使用的 options 分支；其他支持工单 options 保留。

保留 E5 read/write、force/unbind 权限、设备/用户暂停、H9、SIM 总开关关闭时的旧引擎派单/排空、手机在线有效期及所有标签交付链。

## 退役执行顺序与暂停处置

必须按 **停应用 → 迁移 → 启动新代码** 执行。不能让旧应用或其调度器读取已经删除的表。部署窗口先执行报告 report-be-dc.md 中的只读核对 SQL，保存结果和逐台处置决定。

1. 核对机房状态、所有 runtime 暂停原因、暂停审计、五类待审票据及对象锁；同时保存设备标签快照。
2. 旧 DeviceOpsMapper 的机房暂停和按用户暂停都写入原始自由文本 reason，机房暂停还可能覆盖先前的普通原因。**理由相等不是来源证明。可自动解除的安全集合为空，谓词是 FALSE。** 本迁移不猜测前缀、不自动清除任何 paused_reason，也不调用旧恢复/删除。
3. 对来源不明、重叠或匹配机房 reason 的行逐台人工决定保留/解除，按设备主键、原值和审计证据执行并读回。普通暂停必须保留。若决定保留一个恰与机房 reason 相同的普通暂停，应先完成该机房所有设备的人工核对，再在停机窗口解除已退役的机房状态标志，保留设备 reason。不能先运行旧 resume。
4. 执行 `scripts/migrations/20261109_datacenter_retirement.sql`。仍有当前机房暂停 reason 匹配设备时，迁移列出候选并报 `DC_RETIREMENT_MANUAL_PAUSE_RESOLUTION_REQUIRED`，在任何票据/标签修改前停止。
5. 迁移把五类 pending 票据置为既有终态 expired，写历史，删除对应对象锁和孤立机房锁；删除专属权限授权、A4 注册；不删除历史审计或设备/订单数据。
6. 使用已有 nx_schema_migration_state 保存 `20261109_datacenter_retirement`：事务完成后 UNWOUND，删表后 FINAL。重启或 fresh post 重放不会重复暂停/票据处理；中断后的 DDL 可继续执行。
7. 启动新代码，核对标签逐值不变、普通暂停仍在、票据不能回放、锁已释放、两张旧表不存在。只有现场证据支持的纯机房暂停才由人工按设备解除。

新库 schema 不创建这两张表；启动链移除两份纯机房迁移，20260721_e5_device_operations.sql 只删除机房部分，保留设备事件与共享权限。fresh post 末尾重申退役，以覆盖 fresh A4 恢复步骤。

## 查询成本与验证边界

E5 页只按设备主键/唯一键连接普通 runtime、SIM runtime、SIM 当前单、SKU；当前单校验用户、实例和 generation。计数不读当前任务。周期收益继续由 DeviceMonthlyTargetReadService 的 projections + mapper.batch 按本页设备批量读取，不连接全月任务明细，不新增逐设备 SQL 请求。槽位/置换效率沿用原有索引相关子查询。

四个概览值来自一次状态分组查询；全局准确计数仍需扫描其设备范围，并非零成本。没有新增线程、调度器或缓存。新增/修改 SQL 的本地 EXPLAIN ANALYZE、实际行数/耗时、整体 HTTP 验证、空库/已有库链结果及未验证项见 report-be-dc.md。小型本地副本测量不能推导生产容量。
