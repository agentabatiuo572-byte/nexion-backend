# BE-21 今日概览 JSON 快照导出留痕

新增 `POST /api/admin/ops-dashboard/exports`，由有效超管持 `overview_b0_export` 调用。接口仅记录现有概览 JSON 下载意图，不读取或生成资金快照，不接收业务金额、客户资料或调用方指定的操作者。请求只接受 `reason`，其他字段拒绝；调用方携带 `Idempotency-Key`。

```json
{"reason":"核对本次资金概览并保存快照"}
```

理由沿用 A2 当前有效规则，至少八个可见字符、最多二百个；缺少或非法规则时拒绝，不用本地默认值跳过。权限过滤器对这条 POST 精确检查新码，并验证真实管理员主体；控制器使用现有有效超管检查，普通自定义角色即使误拿该码也不能调用。

成功返回标准 API 包装下的四项回执，例如：

```json
{"code":0,"message":"success","data":{"exportNo":"B0-EXP-<唯一编号>","recordedAt":"2026-11-05T09:00:00Z","format":"JSON","fileName":"uvel-overview-B0-EXP-<唯一编号>.json"}}
```

幂等作用域包含真实管理员 ID。同一管理员在现有二十四小时幂等窗口内，用同键、同一标准化理由重试，返回原编号、时间和文件名，不新增审计；同键换理由返回幂等冲突。不同管理员的同键分开处理。丢响应时保留原理由及命令号，重试原 POST；没有新建查询或导出任务引擎，过期命令不可当作仍受去重保护。

成功审计为 `B0_SNAPSHOT_EXPORT_RECORDED`，资源类型为 `B0_SNAPSHOT_EXPORT`，资源编号和业务号均为 `exportNo`，来源域 `B0`。操作者取真实登录身份，审计只保存回执元数据、理由和幂等键，不保存下载内容。必达审计失败时事务回滚，没有成功回执；调用方必须在成功收到回执后才允许继续原 JSON 下载。

权限通过前向迁移 `20261105_b0_snapshot_export_permission.sql` 注册，仅授有效 `SUPER_ADMIN`，并清理这个新码已有的其他角色或失效超管绑定。经典角色种子同时从审计 READ 通配及普通角色 `overview_%` 通配中排除此码；重复迁移和种子不应再次扩大授权，不改变其他权限。

本轮只交付后端合同与权限。PC 按钮、理由确认及收到回执后下载的接入仍待页面方案授权和实现，不据后端完成宣称现有页面已经留痕；本项不包含 B32 指标或 CSV 开发。
