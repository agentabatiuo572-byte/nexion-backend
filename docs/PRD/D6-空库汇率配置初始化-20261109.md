仅当 `VND_USDT` 主键不存在时插入原 `20260725_vietnam_payment_real_tables.sql` 的安装初值：`base_rate_vnd_per_usdt=26000`、`buy_spread_pct=1.50`、`lock_window_minutes=30`、`version=0`、`is_deleted=0`。现有主键一律跳过，包括自定义运营值、版本、操作者、理由、时间及软删除墓碑，不更新、不复活。初始化不创建汇率变更历史、审批、订单或资金流水。

安装初值不代表当前市场牌价；后续维护仍沿原 D6 权限、版本检查、双人审批和审计流程。该修复仅作用于 local/fresh 后置链，不修改原历史迁移、Java、前端或其他业务种子，也不向正式受管迁移目录加入新配置写入。

## 业务验收

1. 从完全空库按文档运行整条 baseline bootstrap；在任何人工 D6 配置准备前，以有读权的管理员读取原接口，应 HTTP 200／`code=0`，来源为 `nx_finance_fx_quote_config`，单例初值和版本正确，历史仍为空。
2. 沿原 D6 业务流程保存一组合法运营值，记录整行及历史。重跑安装链后，基础汇率、价差、锁价窗口、版本、操作者、理由、创建／更新时间、软删除位和历史均不变；再次读取返回原运营值。
3. 在隔离库保留一条同主键软删除记录后重跑该初始化，逐字段核对墓碑没有复活或重置；原读接口继续按既有缺活动配置规则拒绝。
4. 复用本轮 D6 审批和原键恢复流程，核对未改变原授权、maker/checker、版本和拒绝语义，不重复写业务历史或资金动作。

本候选仅完成静态变更检查；上述完整服务和数据库业务验收由主控接续，不以源码或安装脚本退出成功代替通过。
