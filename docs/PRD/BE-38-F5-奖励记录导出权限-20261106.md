# BE-38 F5 奖励记录导出权限

F5 奖励记录查询和异常列表使用 `network_f5_read`。`POST /api/admin/commissions/export` 使用 `network_f5_export`，继续校验导出理由、筛选条件及行数和大小上限，并记录脱敏 CSV 导出审计。

首次迁移只给旧接口已授权的有效角色补发导出权限。旧接口同时要求 F5 读取权限与网络域的非只读权限。标准角色中，超级管理员、增长运营、财务主管和风控主管满足这两项。自定义角色也须在同一角色内满足两个条件。导出权限只用于该导出接口。

隔离验收覆盖原有导出角色、既有自定义导出角色、只有读取权限的账号和只有导出权限的账号。检查拒绝状态、授权下载、导出理由、脱敏标识和审计记录，并核对迁移重跑后保留已撤回的授权。

## 2026-11-17 F5-BE-09：解冻申请前校验丢失的到期时间

采用原要求的建申请前拒绝分支：`f_commission_status` 将冻结奖励恢复到 `COOLING` 时，先读取该事件的真实 `status`、`unlock_at` 和既有结算组 `source_type`。无分组旧记录与 `network` 组沿用回放的判断：`FROZEN -> COOLING` 且 `unlock_at` 缺失，返回同一 `409 F5_COOLDOWN_DEADLINE_UNRECOVERABLE`，不创建待审申请。提案与原两处批准执行共用同一判断函数。

非 network 的直接购买/设备结算组仍按原组级恢复规则，不因事件到期时间为空而新增拒绝；不从当前配置推造历史到期时间，不调用会恢复或补写到期时间的执行函数。不新增 `canUnfreeze` 或混用已有 `canUnlock`，不改变原版本/CAS、权限、对象锁、请求指纹、旧成功键、钱包/奖励/结算、状态转换、页面与说明。本轮未执行 E2E/HTTP/DB/业务或部署。

## 2026-11-17 F5-BE-02：异常检测分币种计算

金额 z-score 在原最近 200 笔样本内按 `kind + currency` 分组，均值、方差与每笔偏离都只使用同类同币金额；阈值、算法和原说明字面保持，金额异常行追加真实 `currency`。高频用户次数不是金额比较，沿原跨币笔数口径保持。

层比例异常只在各币种自己的 network 金额总额、各层实际金额内归一；USDT 理论分布继续取原 `usdt_rate * 100`，UVT 理论分布取已有 `nx_commission_rule.nex_per_usd`，分别按同币理论合计归一后比较。两者不相加，不把 UVT 金额与 USDT 费率比较，不做 FX 或假设 UVT=1 USDT。原规则有效/未删筛选、层顺序、比例阈值与舍入保持；无对应理论数据或合计不正的币种不产生该比较结果，不伪造基准。

层比例异常返回 currency，id 包含币种与层号以区分同层两币记录，原 evidence 说明字面保持。读取样本范围、角色权限、奖励/钱包/结算 writer、参数保存与奖励结算算法不改，不新增 schema、历史回填、页面或说明。本轮未 E2E/HTTP/DB/业务/部署。
