# H4 规则开放、创世抽奖与转盘护栏审批

本批对应 BUG-286 的 A62（含护栏 POST）、A67、A70。只增加后端审批约束；不改 PC/App 页面、生产角色授权、原玩法或奖品消费者。A50/A51 旧奖励、A57～A59 奖池及跨权益方向留待后续，不因本批交付而视为已完成。

## 方向与原业务行为

| 入口 | 必须先审批 | 保留直接写 |
| --- | --- | --- |
| `PATCH /api/admin/growth/event-rules/{eventCode}` | 从未激活且当前关闭的规则首次 `enabled=true`，本次完整拟规则和 UTC 期限随批准一起生效 | 关闭草稿编辑、已启用同规则保持、关闭。已激活条款/期限冻结，关闭后不可重开 |
| `PATCH /api/admin/growth/genesis-raffle/{id}` | `DRAFT→OPEN` | POST 即使传 true 仍建 DRAFT；DRAFT 编辑、OPEN 零报名退 DRAFT。再开放仍审批；有报名及 PROCESSING/DRAWN 的原锁定不变 |
| `PATCH /api/admin/growth/quest-events/wheel-guards/{key}` | budget 提高、kill 按真实旧值语义从关闭变开启 | budget 降低、kill 关闭、历史真值等价规范化 |
| `POST /api/admin/growth/quest-events/wheel-guards` | 不存在时创建正 budget、开启 kill，堵住同源新建旁路 | 创建关闭 kill。cap 仍由库存派生，写入拒绝 |

放大直写返回 `409 H4_APPROVAL_REQUIRED`，不提前保存规则、开放报名或写 shadow 配置。提案仅创建 A2 单据和对象锁，不改变业务 revision/enabled、q 状态、护栏、抽奖状态、用户票和经济事实。批准复用原事务、校验、审计、`OpsGrowthCommandBoundary` 幂等回执及 `admin.growth_config_changed` 事件。

预算和 kill 仅控制原 USDT 真实奖；UVT comfort、UVT 奖和券仍按原轮盘消费者兑现。`growth.wheel.*` 是既有 shadow 配置，不新增同步到活奖池/护栏的消费者。历史 kill 的 `1/true/on/enabled/open/开` 按真实消费者的真值比较，避免把已经开启误判成关闭。

## 固定 A2 合同

仅支持以下专用 op，`command.domain=H`、`sourceDomain=H4`；`obj` 必须为精确目标 ID，禁止额外 targets。params 的客户输入只有 `values`，maker、原状态、原提案原因由服务端绑定；before/after、资金方向及审核分类也由服务端生成。

| op | target.type / ID | values |
| --- | --- | --- |
| `h4_event_rule_enable` | `h4_event_rule` / 九个原 eventCode 之一 | eventCode、expectedRevision、enabled=true、startsAt、endsAt、完整 rules |
| `h4_genesis_raffle_open` | `h4_genesis_raffle` / draw ID | id、expectedRevision、enabled=true、三语标题、startsAt、drawAt、完整 prizes；可带 titleTranslations。奖项保留原三语和附加语名称、权益及数量等字段 |
| `h4_wheel_guard_create` | `h4_wheel_guard` / budget 或 kill | guardKey、guardLabel、guardValue、note（键存在，可空） |
| `h4_wheel_guard_update` | 同上 | guardKey、value、expectedValue |

规则/抽奖 maker 使用原 `growth_h4_write`，护栏 maker 使用 `growth_h4_wheel_pool_write`。只放行这两类业务权限的精确提案和本人原 idempotency key 恢复，不授予泛 A2、跨域或他人单据读取。批准/驳回须另一名当前有效超管并持 `platform_a2_operation_approve`；本人批准、App、只读或非超管不能执行。

审批绑定规则的 revision、enabled、activated_at、disabled_at、rules/期限及 q 状态/删除；抽奖绑定 revision/status、完整奖快照、期限、开放记录、翻译及报名；护栏绑定真实存在性和旧行。批准重新锁读、比较绑定状态，并重跑原文案、期限、商品、券、正式促销及按商品汇总库存等 readiness。后来草稿编辑、关闭、删除或资源失效，旧票不得覆盖新事实。资金分支在提案和批准两端保留原可靠性约束，使用 B1 精确 `redlineBreached`，实际低一微但显示 100.00% 仍拒绝；未修改全局 coverage 方法。

`evt-anniversary-spin` 是唯一历史只读发布专例：首次发布仍须双人审批和完整 CAS，审核分类为 `param / amplifies=false`，摘要明确“发布历史活动只读记录”；保留过去 UTC 期限及原 coverage 豁免，不开放抽奖或新奖励。

## 完整审核与部署前置

合法 20 奖、每奖三语及六附加语长名称会使完整旧/拟快照超过 TEXT 65535 bytes。必须先应用新增正向迁移 `scripts/migrations/20261106_h4_approval_command_capacity.sql`，把既有 `nx_audit_operation_ticket.command_json` 从 TEXT 扩至 MEDIUMTEXT；保留旧命令字节、NULL、注释、字符集和排序规则，已是 MEDIUMTEXT/LONGTEXT 时不降级，迁移可重跑。初始化 schema、mapper 建表和启动迁移清单同步，不改历史迁移。

ticket 的短 before/after 列只存有界对象摘要；A2 返回、批准回执及本人原 key 回读从不可变 command 的 `expectedState/values` 投影完整审核内容，不能截断或压缩丢条款。A2 审计保留短摘要、原键、对象、原因、身份和分类，通过原票关联完整命令，避免超出全局审计限长后原 key 被包进 preview。全域审计限长不变。

创世抽奖待审不能报名，不提前扣票、开奖或发奖。批准后仍由原 App enter 扣可用票，原调度固定赢家/原奖快照，再经原币钱包、账本或设备交付；失败保留原结果重试。结构化 reward 文案仅展示，不参与派奖。H4 钱包余额/持仓观察触发器需求已取消，本批不创建、恢复或兼容它们，不运行旧 H4 迁移触发器段。
