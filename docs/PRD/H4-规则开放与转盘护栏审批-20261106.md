### B110：批准复核失败

转盘护栏、奖池和旧活动的共用资金检查在批准时取得可靠估值、有实际负债且 B1 精确覆盖率低于红线，返回 `422 COVERAGE_BELOW_REDLINE`。A2 会驳回原单、释放对象锁并记录复核失败。估值不可用时继续待批并持锁，恢复后可重新批准。

创世抽奖批准开放时按同样条件区分可靠破线和估值不可用，两者均保留 `409 COVERAGE_REDLINE`。可靠破线结案时抽奖维持原草稿，估值恢复后仍可批准暂时失败的原单。创世抽奖预览和派奖沿用各自的资金检查结果。

预算更新批准时，如果同一条有效护栏记录的旧金额和最新金额均合法且确有变化，返回 `409 H4_CONFIG_STALE`，原单驳回并释放对象锁。只有存储格式变化或金额无效时，同一错误保留原待批状态。终态的原批准键和原提案键均可回读，原操作不写入业务配置。

## 2026-11-22 B65-BE-01 活动参与、领取和提醒原键查询

登录用户通过 `GET /api/events/{eventCode}/commands/{operation}` 查询自己的原命令，`operation` 取 `join`、`claim` 或 `reminder`，原键从 `Idempotency-Key` 请求头传入。读取复用对应提交入口的回执命名空间与指纹。领取可读取加规则前后的原回执。

- `PROCESSING` 表示命令仍在处理。`SUCCEEDED` 的 `result` 为本人该活动的原成功结果。`FAILED` 的 `error` 含已保存的业务码和原因标识，无可证明的原业务原因时返回 `EVENT_COMMAND_FAILED`。
- 没有对应本人回执时返回 HTTP 404 和 `status=NOT_FOUND`。指纹冲突、无法确认的回执或两种领取路径同时有匹配记录时返回 `UNKNOWN`。查询只读，不参与活动、不发奖励、不创建提醒订阅或更改命令记录。
- `POST /api/events/{eventCode}/reminder` 收到非空 `Idempotency-Key` 时按本人保存原命令回执，活动编号绑定于请求指纹。原订阅提交和成功回执在同一事务完成，写入前的明确业务拒绝保留原业务码和原因。旧客户端可以省略该头，仍按原订阅逻辑处理。历史订阅没有原键回执，不回填。
