## 版本化内容的正常变更路径

I4 当前已发布 `nexNarrative` 的三语 `hero` 和版本描述需保留旧版本，复制当前全部字段建立新草稿，仅将已确认的 NEX 代币字样改为 UVT。不得直接修改 `nx_trust_section_version` 历史行，也不能仅修改 `nx_trust_section_field` 快照就声称用户页已修复。

现有接口为 `POST /api/admin/content/trust-disclosure/trust-sections/nexNarrative/versions`，请求携带新版本、描述、结构、完整字段及当前版块版本／状态；随后通过正常 A2 提案确认链发布。直接调用 `.../publish` 在非 A2 replay 上下文固定返回 `A2_CONFIRMATION_REQUIRED`。发布时按新草稿 revision 和原版块版本／状态校验，发布完成后回读 `/api/admin/content/trust-disclosure/published-snapshot` 与 `/api/content/trust/sections/current`。

Nova `nx_nova_template` 当前以 `channel_key` 唯一，尚无同频道独立历史版本链。官方 `POST /api/admin/content/nova/templates` 对已有模板返回 `NOVA_TEMPLATE_EXISTS`；`PATCH /templates/{channel}` 仅接受 DRAFT，状态链只允许 DRAFT → PUBLISHED → ARCHIVED。归档、删除后重新创建会由现有 upsert 覆盖原频道行，不能视为保留历史的新版本发布。

因此本次 SQL 不更新 Nova 模板正文。当前 TEST API 已确认模板无旧代币名，不增加新机制。其他安装环境若已发布模板仍含旧代币名，须确定保持历史的最小处理路径后再实施。已发通知始终不回写。
