## 1. 背景与权威待办

A4 积压诊断 `GET /api/admin/platform/events/outbox-diagnostics` 与 H3 重投预览 `GET /api/admin/platform/events/outbox/{eventId}/redrive-preview` 只返回事件编号、类型、状态、尝试次数和错误，没有该事件属于哪位用户。运营需要判断某位用户的奖励/任务是否卡住，并去用户详情核对。

权威待办：`uvel-docs` `origin/main` 的 `handoffs/2026-10-28/backend/20-backend-pending-20261031.md:1563` A4-BE-04。A4 页面 D1 之外的相关治理：A4 事件页只读/写权限分离、重发预览只允许 H3 五类、PC 不推断归属；C1/A9/K4 的用户编号字段只在有用户查看权时显示。

目标：在不改变事件写、重投、清理和公开输出的前提下，为有可信用户来源的积压行及 H3 重投预览增加可空 `userNo`；没有可信归属、无用户查看权或对象越界时返回 null。

## 2. 目标与非目标

目标：

1. 积压明细的 H3 五类周任务行返回 `userNo`（可空）；H3 重投预览 GET 当次返回可空字段；POST 重投回执不返回/不固化 userNo。
2. 只使用服务端 H3 生产链写入的 canonical `payload.user_id`，再通过 `nx_user` 得到用户编号；不从 actor、管理员 ID、aggregate_id、显示名或任意字符串猜用户。
3. 仅当认证账号有既有 `user_c1hub_read`（用户详情读权）且满足客服对象范围时返回编号；不新增 grant/角色/读策略。
4. 诊断/预览 GET 仍是只读；不触发 seed、重投、认领、清理、锁票、快照或事件写入；POST 原业务回执/执行不变且不带敏感 userNo。
5. 其他事件类型、null/老坏 payload、非 server-authoritative 行、删除/不存在用户一律 `userNo=null`。

非目标：

- 不新增事件写、重投/清理行为、DDL、索引、回填或通用用户归属框架。
- 不改变 A4/outbox schema、worker、App/H5/导出或公开输出；不改 PC 页面/文案。
- 不改 `platform_a4_read/write` 权限、重投 A2 合同、H3 原事实/投递状态、幂等/事务/审计。
- 不猜测 `ADMIN_USER_PROFILE_VIEWED` 等其他事件的归属，不以 `aggregate_id` 或内部 ID 拼 U 号。

## 3. 真实来源与权限合同

### 3.1 可信用户 ID

- 五类 H3 周任务由 `H3WeeklyParticipationEvaluator:115-129` 通过 `publishUserEventAt(..., userId, ...)` 产生；`H3WeeklyExchangeReferralEventConsumer:102-110` 也以 `fact.ownerUserId()` 产生 H3 exchange/referral 事件。
- `EventOutboxService.publishInternal:214-220` 对 `publishUserEvent*` 将 canonical `userId` 写入 payload `user_id`，并移除客户端 `userId`。因此 H3 的 `payload.user_id` 是服务端认证/事实链的用户 ID，不是 actor/管理员 ID，也不是展示名。
- `A4OutboxDiagnosticsMapper` 只对以下五类取 `payload.user_id`：
  - `H3_STOREFRONT_THREE_PRODUCTS_VIEWED`
  - `H3_GENESIS_SECONDARY_MARKET_VIEWED`
  - `H3_COMPUTE_COMPLETED_50`
  - `H3_REFERRAL_REGISTERED`
  - `H3_EXCHANGE_COMPLETED`
- 额外要求 `is_server_authoritative=1`、`JSON_VALID(payload)`、`user_id` 匹配 `^[1-9][0-9]{0,18}$`；否则 null。
- `H3DeadLetterRedriveService` 只在**预览 GET** 使用这五类 H3 的 payload userId；POST 重投不解析/不查 userNo，不把敏感值写入可重放回执。不解析 `aggregate_id`，不使用 H3 event type 之外的 payload。
- 用户编号来自 `nx_user`（`is_deleted=0`）的现有编号投影；不在 Java 里把任意内部 ID 拼成 U 号。用户不存在/已删除则 null。
- 其他 backlog 类型固定 null；包括 `ADMIN_USER_PROFILE_VIEWED` 的 `target_user_id`、`H8_REFERRAL_REWARD_SETTLED` 的多用户字段均不在本单猜归属。

### 3.2 查看用户权限与对象范围

- 新增 `A4UserNumberService`：先检查 `SupportOwnershipService.hasAuthority("user_c1hub_read")`；这正是 C1 用户详情读权，不新增授权。
- 无 `user_c1hub_read`：所有 `userNo=null`，不查询用户编号、不返回标识。
- 非客服全局查看者（有 `user_c1hub_read`，不是 SUPPORT 非超管）：按现有用户详情合同返回编号。
- 客服非超管：调用 `SupportOwnershipService.currentSupportReader()`；命中时只保留 `readableCustomerIds(ids)` 中可读的客户，沿用 PERSONAL/MANAGED/ALL 既有对象范围；跨组/未绑定/本人队列外自然为 null。
- 超管/非客服：`currentSupportReader()` 为 false，按全局用户详情读权；不另造专属过滤。
- 查找/对象范围校验只在 GET 当次执行；异常返回空 map（字段 null），不泄露错误中的用户标识。`A4UserNumberService` 以 `@Transactional(propagation=NOT_SUPPORTED)` 暂停调用方的诊断 read-only 事务；support scope 查询异常不会把原诊断事务标 rollback-only。
- 用户编号本身不是姓名/手机号；仍只在上述权限与范围内返回。

## 4. 现有接口、DTO 与副作用

### 4.1 积压诊断

- `OpsEventCenterController:57-65`：类级 `platform_a4_read`；`A4OutboxDiagnosticsService.read` 为 `@Transactional(readOnly=true)`。
- `A4OutboxDiagnosticsMapper.page` 在同一 SELECT 增加内部 `userId` 表达式（不直接暴露 userId）；`EventRow` 增加内部 `Long userId`。
- `A4OutboxDiagnosticsService` 批量解析可见 userNo，`OutboxDiagnosticsView.Event` 末尾新增 `String userNo`；旧行字段/顺序/语义不变。
- 该接口只读：不创建/seed/quarantine/锁票/生成快照，不做重投/认领；`userNo` 查询为额外只读 SELECT。

### 4.2 H3 重投预览 GET / POST 结果

- `OpsEventCenterController:129-133`：类级 `platform_a4_read` + 方法 `platform_a4_write && platform_a2_write`；`H3DeadLetterRedriveService.preview` 只有两个 SELECT（outbox/delivery）及当次 userNo 查询，无写。
- `EventOutboxMapper.findDeadH3ThresholdEvent`/`lockDeadH3ThresholdEvent` 增加内部 `userId`；`H3DeadLetterRow` 增加可空 userId，保留原 4 参数构造。
- `H3OutboxRedriveView` 末尾保留可空 `userNo` 兼容预览；`view(..., includeUserNo)` 仅 preview 传 true，POST `redriveLocked` 传 false。POST 成功回执的 userNo 为 null，不查 userNo/不把敏感值写入幂等缓存。
- `redrive` 在 `idempotencyService.execute` 返回后仍调用 `withoutUserNo()`，即使读到旧候选写入的缓存也对外清空；R0 未发布、无真实新回执，不做数据迁移。
- 预览不调用 `redrive`、cleanup、claim 或任何写动作；userNo 查询只读 `nx_user`/支持范围。

### 4.3 共享消费者

- `OutboxDiagnosticsView`：仅 A4 诊断 Controller/PC；未发现 worker、App/H5、导出或其它业务消费者。
- `H3OutboxRedriveView`：仅 A4 Controller/PC 预览/重投结果及现有测试；POST 结果 userNo 固定 null，preview GET 当次受权；未发现 worker/App/H5/导出消费者。
- PC 当前 strict normalizer 只读已知字段，额外 `userNo` 可被忽略；本单不改 PC，因此不声称页面已显示。后续页面接入需按 `user_c1hub_read` 显示用户链接/编号，不改后端字段。

## 6. 失败/空值/权限矩阵

| 场景 | userNo |
|---|---|
| H3 五类、server-authoritative、payload user_id 合法、有 C1 且对象可见 | 用户编号 |
| H3 但 payload 缺 user_id/非法/非 server-authoritative | null |
| H3 user_id 对应用户删除/不存在 | null |
| 非 H3 backlog 类型 | null（不猜） |
| 无 `user_c1hub_read` | null |
| 客服非超管、用户不在 PERSONAL/MANAGED/ALL 可读范围 | null |
| 用户无客服角色、有 C1 | 按现有用户详情读权返回 |
| userNo 查询或 scope 校验失败（GET） | null，诊断/预览原结果保持；NOT_SUPPORTED 隔离不会回滚原诊断事务 |
| POST 重投成功/缓存回放 | userNo 固定 null；不查 userNo、不缓存敏感值；旧候选缓存值返回前清空 |
| 重投预览未达 DEAD/对象无效 | 原有 409，不加 userNo 逻辑 |
