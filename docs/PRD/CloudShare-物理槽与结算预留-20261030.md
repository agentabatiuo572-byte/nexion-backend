# Cloud Share 物理槽与结算预留

日期：2026-10-30，2026-10-31按17后发决定更新。范围：正式 App、共享 H5 所使用的 Java 后端；TEST 候选，业务验收由发布主线记录。

## 已确认规则

- 每个账号共用服务端 6 个物理槽。每份 Cloud Share 占 1 槽，与普通设备、手机及有效试用共同计数。Share 多份及混合订单按数量求和，不能按商品种类或持仓分组去重。
- 总占用 = 有效已激活资产 + 已支付待履约订单预留 + 已付未交付赠送承诺 + 有效试用预留。新未付单及其未付DEVICE赠品不占槽。尚未核清/迁移的旧`inventory_reserved=1`未付单保留历史预占，不能推定外部付款未知单可释放。正式数据使用同账号、正式数据环境及空 run_id。
- 等待当前任务结束后停用的设备仍是已激活资产，`pending_deactivate=1` 期间继续占1槽，直到实际取消激活才释放；首页 `activeDevices` 和 `slotsUsed` 同样保留该设备。原任务按既有规则完成，待停用设备不得领取下一任务。
- 正常 Share 交付逐份生成 `nx_user_device`。已完成订单不重复预留；历史试用转购、保留旧机购买的已交付识别沿用现有精确关联事实。
- 报价及新待付单不预占槽或商品库存/终身销售名额；创建仍校验即时资格与容量作为提示。实际占槽由试用领取、激活、付款在服务端当前锁内竞争；多个未付单可以并存，创建成功不代表占槽或支付授权。
- 新单付款在当前总占用上加本单购买份数及相关DEVICE赠品份数，旧预占1单不重复加；逐个受益人复核。在买家/受益人、活动预算、商品/SKU锁内，重查期限、维护、当前商品与资格、终身/月名额和库存，资金写前原子消耗买单与gift商品库存并记`inventory_reserved=1`。失败整体回滚；已付回放先于新资格/目录检查，不因商品后来删除而失败。
- 新未付单取消/到期只关闭原单并释放相应优惠券/活动承诺，不返还未曾占用的商品或名额，不释放别的资产/试用。待任务完成停用继续占槽，直到真实终态。资金未知先恢复原命令，不能把关闭页面或超时当作未付确认。
- 试用转购将原试用槽替换成购买设备，不能重复占槽。已支付结果、同一幂等请求重放不得重复扣款或交付；可恢复付款失败允许释放槽后复用原付款意图。
- 存量超额资产如实保留和展示，不静默取消或删除；限制新增占用。历史已付订单的成功回执仍可读取。

## 接口合同

`GET /api/devices/earnings` 保留现有 `slotCap`，新增同层字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `slotsUsed` | 整数 | 上述总占用，包含 Share 份数、有效试用和有效订单/赠品预留；允许大于 6 |
| `reservedSlotCount` | 整数 | 订单及未交付赠品预留数量 |
| `trialSlotCount` | 整数 | 有效试用预留数量 |
| `slotCap` | 整数 | 服务端上限 6 |

`GET /api/app/home/overview` 的 `onboarding` 新增相同四个字段；已有 `activeDevices` 仍表示已激活设备数量。客户端直接采用 `slotsUsed`，不能再次叠加本地试用或订单计数。

普通订单报价仍使用现有 Promotion quote 合同和金额字段。所选份数不足时返回 HTTP/业务 409、`CAPACITY_REPLACEMENT_REQUIRED`，不写报价或耗券。普通付款超槽使用同一业务错误；DEVICE 赠品受益人超槽返回 `PROMOTION_DEVICE_CAPACITY_UNAVAILABLE`，赠品库存不足返回`PROMOTION_DEVICE_STOCK_UNAVAILABLE`。试用领取继续使用 `TRIAL_CAPACITY_FULL`。前端直接读权威总量，不能把本地未付订单数量重新加回。

取消普通报价/活动订单时，初次响应和已取消恢复响应均附带该订单冻结的 `promotionQuoteId`、`items`、`rewards`、`payBy` 等投影，并返回 `canonicalStatus=cancelled`。不重新报价，不依赖商品当前价格或活动当前内容。

2026-10-31 TEST 实际付款验收发现：设备生命周期字段为秒精度 `DATETIME(0)`，正常钱包交付与赠品交付曾写 `NOW(6)`，在秒的小数部分达到 0.5 后可能被数据库进位到下一秒，导致即时读取被正确的未来时间校验拒绝。交付写入现与字段精度一致使用 `NOW()`，单件、组合及同根赠送入口同步。保留未来生命周期拒绝，不修改收益公式、已支付金额、时间字段精度、全局时区或历史资产；无数据迁移。试用转购和置换原先已使用秒精度写入，保持不变。
