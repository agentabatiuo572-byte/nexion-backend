## 操作与验收

1. 对已确认的本机或共享 TEST，查环境的 MySQL UUID、旧目录、待审新增单、外部资金和客服账务证据。停止所有业务写入，包括后台执行器，保存全库备份和校验值，并恢复到独立的候选服务器。处理过程保留原库。
2. 核对待清零的收益、账号和原客服凭证摘要。在候选库为符合条件的收益生成独立清零凭证，保留原笔凭证和收益来源。随后用 [维护脚本](../../scripts/maintenance/render_b140_test_cutover.py) 生成绑定候选 UUID 的 SQL。例如 `python3 scripts/maintenance/render_b140_test_cutover.py EXPECTED_UUID /private/b140.sql`。使用 MySQL 默认遇错即停止的批处理模式，禁用 `--force`。目录和活动账本切换的成功回执为 `B140_COMMITTED`，同时读回 `E.catalog.b140.numbered`。状态不明时先读回标记、目录和旧业务数量。
3. 验证原 App 和管理员能登录，用户及权限行保持，约定业务记录为空，测试钱包及账本归零。验证失败或连接中断时目录、业务数据、钱包和标记一并回滚。
4. 验证两表的 9 个编号、资料、下架状态、配置引用和续号。重跑正常启动后对比编号和配置，在已有商品上准备符合规则的上架样本。
5. 本机通过后发布共享 TEST。核实后端及三端实际运行版本。PC 实做 E1 新增和 H3 选品，App 和 Lite 用保留账号实做商城跳转、合格 S1 的回本任务、试用与钱包读取。

### 指定收益的维护入口

在 dev 模式和显式候选数据库连接下，使用以下命令。

    java -Dloader.main=ffdd.maintenance.B140TestWalletReset -cp <jar> org.springframework.boot.loader.launch.PropertiesLauncher <候选UUID> <账号ID> <收益编号> <原凭证SHA256>

该入口针对已确认的单笔 60 UVT 首日任务收益，校验出生和原入账凭证、钱包版本及余额。钱包变动与清零凭证在同一个事务提交，原收益记录和原凭证保留。候选发生其他资金变动或存在别的需核验资金来源时，按对应来源单独处理。
