# E3 / E6 A2 资金放大方向

2026-11-05，BUG-307；依据 T11：仅放大资金流出时检查 B1 覆盖率。用户本轮明确选择按实际奖励档位和资格判断；同档位内点数上升、实际奖励没有增加，不算放大。

## E3

A2 依据当前配置和规范化后的拟改值，复用 E3 直接执行的方向规则，不能按参数名固定标记放大。后期月变化从 `-23.7` 改为 `-30` 是收紧，`amplifies=false`；从 `-30` 改为 `-20` 是放大。冷却天数增加是收紧，减少是放大。不变提案标记为非放大，执行仍保留现有 `E3_VALUE_UNCHANGED` 拒绝规则。

## E6 手机校准

PC 调用 `POST /api/admin/config/phone-calibration/direction`，请求体与 A2 `e6_phone_calibration` 的 `params` 相同。读取权限为 `device_e6_read`，不赋予写入或审批权限。返回 `expectedRevision`、`baselineVersion`、`effectiveAt`、`amplifies`。A2 提案和批准回放复用同一方向实现；客户端传入的放大标记不能覆盖服务端结果。

方向使用现行手机校准语义：iOS 以规范化型号及别名匹配，Android 以 SoC 别名匹配；新分配值在闭区间内按 `0.01` 均匀抽取，通过四个阈值映射档位，再读取当前 `nx_onboarding_phone_tier_config` 的 USDT / UVT 实际奖励。

- 新增可匹配硬件、启用原不可校准规则、扩大强制校验允许的机型事实范围，属于资格扩张。Android 删除/合并别名可能解除原 `SOC_CONFLICT`，应按实际匹配结果判断，不能一律当作收紧。禁用规则仍保留芯片匹配和冲突关系。
- 对任一实际奖励增加的档位分界，候选区间获得该档及以上奖励的概率增加，即为放大。按区间内合法分配值个数与总个数进行整数交叉比较；奖励相同的相邻档位不形成资金边界，不预测人数、未来兑换或未来收入。例如范围 `25–45`、升档阈值 `40`，高档为 `501/2001`；改为 `26–46` 后为 `601/2001`，因此放大。
- 旧分配值仍在新区间时保持复用；比较新旧阈值下该值的真实奖励。若区间排除旧值，或 Android 规则 ID / iOS 规范化型号改变分配键而触发重抽，候选可能给原较低奖励分配更高实际奖励时也算放大。同奖励档位内的分配键、区间变化不因此放大。
- 型号备注、展示分类、预设删除记录、仅生效时间变化，若不改变匹配资格和奖励，不算放大。Android 预设删除记录仅记录 PC 重新装载预设的行为；真正发布的规则和别名决定匹配。
- 以拟生效时已生效的当前/预约版本为比较基线。已有预约发布的禁止覆盖规则保持不变：批准发布另一份预约仍返回 `PHONE_CALIBRATION_PUBLICATION_PENDING`；旧 revision 返回 `PHONE_CALIBRATION_VERSION_CONFLICT`。

低于 B1 红线时，收紧和中性配置仍可由另一位合法审批人批准；放大返回 `COVERAGE_BELOW_REDLINE`，票据保持待审批，配置不生效。批准时重新读取配置、奖励表及强制机型校验规则判断，不能依赖创建票据时的旧标记。原业务写权限、A2 权限、自批禁止、锁、幂等及版本检查保留。
