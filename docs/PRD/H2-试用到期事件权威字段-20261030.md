# H2 试用到期事件权威字段（2026-10-30）

## 状态读取契约

`GET /api/trial/state` 及复用同一状态投影的领取、取消、延长响应增加以下可空字段。原有状态、版本、资格、收益、宽限和延长期限字段保持原语义。

| 字段 | 类型 | 来源与语义 |
| --- | --- | --- |
| `endReason` | `"expired" \| "cancelled" \| null` | 该领取单已持久化为 `CANCELLED` 或 `FAILED`，且 `cancel_reason` 明确为 `auto_end` / `auto_settlement_window_expired` 时为 `expired`；其他 `CANCELLED` 为 `cancelled`；活跃、已购机和原因不明的历史 `FAILED` 为 `null`。 |
| `finishedAtEpochMs` | `number \| null` | 该领取单持久化 `closed_at` 的业务时区时间转为 Unix 毫秒。未保存结束时间时为空，不以请求时间或当前时间补齐。 |

没有领取单时两个字段均为 `null`。业务时区沿用 `Asia/Shanghai`，与现有 `serverNowEpochMs` 和期限字段一致。

## 提醒规则与兼容

`endReason=expired` 是服务端明确自动到期的终态事实，真实结束时间只用于证据和展示，不将任何时间差作为提醒门禁。客户端只有先确认过同一账号绑定、同一领取单的活跃状态，再接收到更新版本的明确到期终态，才可以产生一次到期提醒。历史终态首次加载、断网/503、未知结果、取消与已购机不产生“刚到期”事件。此次不新增最终期限推断；原有定时到期仍按其现有配置规则执行。

旧后端响应不提供上述字段时，客户端保持兼容并停止推断到期。旧客户端忽略新增字段即可继续工作。此次只增加读取事实，不补写旧快照，不迁移数据，不调整定时到期、取消、结算、权限或账务规则。

## 2026-11-01 退款后资金证据读取

正式 E4 退款及奖励回收后，历史转购快照仍保持原字节和 digest。资金 reader 必须先验证完整 raw、原 receipt、原消费和 H2 USER 审计，再以同客户、同订单、唯一全额退款来源及完整历史覆盖为依据，允许比较视图中的 `PAID/ACTIVE/OWNED` 对应当前 `REFUNDED/DEACTIVATED/REFUNDED`。订单双状态必须都已退款；身份、设备、claim、金额、原 paid/settled 时间、环境、删除边界等仍严格不变。缺少正式 E4 history/ADMIN 审计或任一来源证明时继续 UNKNOWN。

H2 奖励回收只接受已核原 compound 奖励身份及冻结审计的 `FULL_TERM_ON_CONVERSION` 政策，并核同订单 E4 退款、原 entry/sourceRef/币种/金额/wallet/debit baseline。既有保守可回收量、其他来源回收扣除、零现金 checkpoint、累计回收及反向覆盖校验保留；部分回收或缺终态不能被解释为全额成功，旧政策不凭当前状态补造应回收证明。

E4 来源关联继续要求同单同用户全额原退款账、有效 ADMIN 成功审计、相同 operator/reason/idempotencyKey 和唯一 audit/history 组合。旧未标记备注保留原精确时刻规则；新增兼容仅接受完整未截断且两侧严格少于255码点的原 canonical 备注，operator/key 不含字段分隔串。新退款内部备注在截断前写入 `key_hash_v2` 和最终 trim key 的完整 SHA256，保留人类可读前缀；读取时严格重构匹配。识别到标记命名空间后，错 hash、畸形、截短或未知版本均不得回落旧时间分支。hash 只是同单命令关联，不替代 ADMIN 授权，不补写旧账、审计、快照或 hash。

上述两个新增备注关联分支同时要求 history 与 ADMIN 审计的 operator、reason、idempotencyKey 逐字节完整相等；数据库大小写或尾空格比较规则不能把不同命令合并。原精确时刻历史分支保持原规则。本轮真实只读 SQL 反例先确认审计单侧大小写变化会误关联，再验证大小写及尾空格差异均拒绝。
