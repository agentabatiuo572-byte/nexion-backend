# H2 试用到期事件权威字段（2026-10-30）

## 状态读取契约

`GET /api/trial/state` 及复用同一状态投影的领取、取消、延长响应增加以下可空字段。原有状态、版本、资格、收益、宽限和延长期限字段保持原语义。

| 字段 | 类型 | 来源与语义 |
| --- | --- | --- |
| `endReason` | `"expired" \| "cancelled" \| null` | 该领取单已持久化为 `CANCELLED` 或 `FAILED`，且 `cancel_reason` 明确为 `auto_end` / `auto_settlement_window_expired` 时为 `expired`；其他 `CANCELLED` 为 `cancelled`；活跃、已购机和原因不明的历史 `FAILED` 为 `null`。 |
| `finishedAtEpochMs` | `number \| null` | 该领取单持久化 `closed_at` 的业务时区时间转为 Unix 毫秒。未保存结束时间时为空，不以请求时间或当前时间补齐。 |

没有领取单时两个字段均为 `null`。业务时区沿用 `Asia/Shanghai`，与现有 `serverNowEpochMs` 和期限字段一致。

## 提醒规则与兼容

`endReason=expired` 是服务端明确自动到期的终态事实，真实结束时间只用于证据和展示，不将任何时间差作为提醒门禁。客户端只有先确认过同一账号绑定、同一领取单的活跃状态，再接收到更新版本的明确到期终态，才可以产生一次到期提醒。历史终态首次加载、断网/503、未知结果、取消与已购机不产生“刚到期”事件。此次不新增最终期限推断；原有定时到期仍按其现有配置规则执行。

旧后端响应不提供上述字段时，客户端保持兼容并停止推断到期。旧客户端忽略新增字段即可继续工作。此次只增加读取事实，不补写旧快照，不迁移数据，不调整定时到期、取消、结算、权限或账务规则。
