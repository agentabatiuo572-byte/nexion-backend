# B114 风险信号分页与详情

## 风险信号接口

`GET /api/admin/risk/radar/signals` 和 `GET /api/admin/risk/radar/signals/{signalNo}` 均要求 `overview_b5_read` 权限。

- 列表支持 `signalType`（重复参数或逗号分隔）、`handlingStatus`（`open`、`handled`、`resolved`）、`userNo`、`pageNum` 和 `pageSize`。默认第 1 页、每页 20 条，每页最多 200 条。按入库时间倒序，同一秒按记录 ID 倒序。
- `startAt`、`endAt` 接受带时区偏移的 ISO 8601 时间。按信号入库时间筛选，开始时间包含在内，结束时间排除。缺少结束时间时取当前入库秒的下一秒，缺少开始时间时向前取 7×24 小时。返回筛选后的 `total`、去重账户数 `accountCount`、`pageNum`、`pageSize`、`records` 和实际的 `startAt`、`endAt`。
- 列表和详情都返回 `signalNo`、`signalType`、`level`、`userNo`、`createdAt`、`handlingStatus`、`handlingVersion`、`handledBy`、`handledAt`、`deliveryStatus` 和 `facts`。篡改信号另返回 J3 同一事件的 `occurredAt`，缺少对应事件时返回空值。时间均带时区偏移。
- 列表、详情和旧版最近 20 条告警使用同一套 `facts`。篡改信号保留 `tamperPath`、`attackEffect` 和 `blockedAtEndpoint`，供原有调用和技术排查使用。已登记类别且证据格式有效、内容完整时，另返回 `blockedAtEndpointName`（例如「验证码校验」）和 `attackEffectSummary`（例如「阻止未通过校验的验证码被接受。」）。类别未知、证据不完整或格式异常时省略新字段，按历史解析规则继续提供可读的旧字段。无法解析的证据返回空值。旧版最近告警使用原有时间格式。
- 标记处理继续通过 `PATCH /api/admin/risk/radar/signals/{signalNo}/status`。使用列表或详情返回的 `handlingStatus` 和 `handlingVersion` 作为 `expectedStatus` 和 `expectedVersion`，由现有处理权限和版本检查控制写入。详情可按原编号查询超出列表窗口的信号，已删除或不存在的编号返回 `B5_SIGNAL_NOT_FOUND`。

## 今日概览

`GET /api/admin/treasury/b-domain` 的 `riskRadar.feed` 篡改条目提供 `signalType=TAMPER_DETECTED`、`count`、`accountCount`、`latestAt`、`startAt` 和 `endAt`，保留原有的 `t`、`m` 和 `href`。按返回的 `signalType`、`startAt` 和 `endAt` 查询列表时，列表总数和去重账户数与首页使用相同口径。J3 原有按阈值聚合的查看方式继续适用。
