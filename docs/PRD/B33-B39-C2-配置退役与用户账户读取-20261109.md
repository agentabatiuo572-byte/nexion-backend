# B33、B39 与 B43-C2 后端契约

范围：退役 H2 自动推送管理配置；用户 360 的全渠道最近充值和最近提现；完整冻结账户分页；独立保留注销申请原始理由。本轮仅后端和本文档，PC／App／Lite 页面继续待接入；C2 信任名单是否接入风控仍待产品决定。

## B33 H2 自动推送管理配置退役

- `GET /api/admin/growth/trials` 的 `params` 不再包含 `autoPushEnabled`、`autoPushDelayMs`、`autoPushCooldownHours`、`autoPushMaxPerSession`，响应也不再有 `autoPushKilled` 或该历史开关的数据源说明。
- `PATCH /api/admin/growth/trials/params/{paramKey}` 提交上述四个字段，返回业务码 `422 / TRIAL_AUTO_PUSH_CONFIG_RETIRED`，不写配置、不发布成功事件。其他参数沿用原权限、校验、审批及幂等契约。
- `POST /api/admin/growth/trials/auto-push/kill` 不再注册，正常已授权管理员调用得到 404，不修改历史开关。
- 旧四字段、历史 `growth.trial.auto_push_killed` 数据保留；管理端不再读取、写入或补种该开关。公共 App／Lite 试用配置保持现有兼容字段，点击领取相关参数与独立 M5 `AutoPushPolicy` 保持原契约。首页是否自动弹窗及点击领取交互属于前端验收，不能以本轮后端结果代替。

## B39 用户 360 最近资金记录

既有 `GET /api/admin/users/profiles/{userKey}/360` 及受客户归属限制的客服 360 调用增加以下顶层字段：

| 字段 | 含义 |
|---|---|
| `latestDeposit` | 按创建时间最新的一条充值来源记录；所有状态均参与，无记录为 `null` |
| `latestWithdrawal` | 按 `created_at DESC, id DESC` 最新的一条提现；所有状态均参与，无记录为 `null` |
| `latestDepositStatus`、`latestWithdrawalStatus` | 对应来源查询成功为 `READY`，读取失败为 `ERROR`；`READY + null` 表示确实无记录 |

每条记录字段为 `sourceType`、`sourceId`、`bizNo`、`createdAt`、`amount`、`currency`、`status`、`paymentAmount`、`paymentCurrency`。`amount/currency` 为同一来源中的金额及币种；不是累计到账额或“已经到账”的判断。时间保留来源实际 `created_at`，不以入账时间、更新时间或当前时间替代缺失创建时间。

充值来源：

| `sourceType` | 数据与金额 |
|---|---|
| `DEPOSIT_ORDER` | `nx_deposit_order`，`amount/asset`，链上等既有充值状态 |
| `PAYMENT_RECORD` | `nx_payment_record` 中有同用户国际卡准入记录或真实 `CARD_TOPUP` 账本归属证据的充值，`amount_usdt/USDT`；普通购机支付不混入 |
| `CARD_ADMISSION` | 尚无后续充值／支付记录的国际卡准入，`amount_usdt/USDT`；拒绝、失败、过期、待确认均保留；孤立的已结算声明用 `ABNORMAL`，不伪称到账 |
| `HDPAY` | `nx_vietqr_intent.payment_rail=HDPAY` 的 `WALLET_TOPUP`，`requested_usdt/USDT`；付款 `payable_vnd/VND` 另列 |
| `VIETQR` | 同表的手工银行 `WALLET_TOPUP`，同上；HDPay 与银行状态复用 D1 既有订单显示判定，包含提交失败及结果未知 |
| `VIETQR_RECONCILIATION` | 无同用户有效意图单的历史 `nx_vietqr_reconciliation`，`received_vnd`（无则 `payable_vnd`）／VND，保留实际来源状态 |

同一充值的后续支付／准入重复投影不重复参与；有有效意图单的银行回执由原意图单代表，避免把收到回执的时间冒充下单时间。每个分支精确限制 `user_id`，不借用银行订单 `keyword` 模糊搜索。跨来源时间相同按 `sourceType DESC, sourceId DESC` 稳定选择，同来源按数值 ID 倒序。

新增字段沿用该 360 原有资金投影范围；没有该范围的角色完全省略这四个字段。客服必须先通过既有客户归属校验。没有新增 D1 路由、D1 读取权限、写入或支付能力；原有资金列表、风险队列排序与字段脱敏不变。360 既有访问审计／事件仍照常记录。

## C2 完整账户状态分页

新增 `GET /api/admin/users/account-actions/accounts`，只要求既有 `user_c2_read`，不要求 C1／风险／财务读取权，不授予任何写权限。

| 参数 | 规则 |
|---|---|
| `status` | 默认 `FROZEN`；支持 `ACTIVE`、`FROZEN`、`BANNED`、`RESTRICTED`、`DISABLED`，忽略大小写和首尾空白 |
| `pageNum` | 默认 1，合法范围 1～100000 |
| `pageSize` | 默认 20，合法范围 1～100 |

非法状态返回 `422 / ACCOUNT_ACTION_STATUS_INVALID`；非法分页返回 `422 / ACCOUNT_ACTION_PAGE_INVALID`。响应为既有 `PageResult` 形状：`total`、`pageNum`、`pageSize`、`records`。总数和记录在同一数据库读取快照内，排除软删用户，按 `c2_frozen_at DESC, id DESC` 排序；静态数据完整翻页不重复或遗漏，不受最近注册 50 人或冻结事实 100 条截断影响。

每条只返回 `id`、`userNo`、`nickname`、`status`、`registeredAt`，以及 `freezeSource`、`freezeSourceRef`、`freezeReason`、`freezeOperator`、`frozenAt`、`d2FrozenWithdrawalCount`。最后一项仅计原 C2 冻结标记为真的 D2 冻结提现。新列表不查询或返回钱包余额、风险分、手机号、邮箱或登录信息。

既有 `/account-actions/overview`、单账户及上下文契约保留；PC 应后续接新分页获取完整冻结名单。本轮不改这些页面，也不把原概况当成完整名单。

## C2 注销原始理由

- App `POST /api/app/security/account-deletion` 既有请求体新增可选 `reason`。此字段只在创建时接收并去除首尾空白，最长 255 字符，超长返回 `422 / ACCOUNT_DELETION_REASON_INVALID`。省略或空白保存为 `NULL`，保持旧客户端可用。
- 新字段 `nx_user_account_deletion_request.original_reason` 在创建时写入，此后审查、阻断、取消和完成均不更新它。既有 `reason` 继续表示最近一次流转／审查理由，`blockReason` 保持原阻断契约。
- App 本人状态／命令回执、管理员列表／详情／流转回执均增加 `originalReason`。创建申请的命令先按本人及原幂等键查询保留记录，再检查最新活动申请；取消 A 后新建 D，再重放 A 的创建键，仍返回 A 和 A 的原理由，不误返回 D，也不修改 D。取消后使用新创建键重提生成独立申请和独立原理由。
- 取消回执保留实际取消的申请原理由；旧取消命令的跨申请幂等绑定不在本次新增保证内，不将创建键的准确回读承诺扩展到该旧行为。
- 旧记录的 `reason` 可能已被覆盖，迁移不从它回填 `original_reason`；历史原话不可考时诚实返回空值。没有填写新字段的旧客户端申请同样为空，不以默认提示或管理员理由冒充用户原话。
- 原密码验证、本人身份限制、管理员 C1 读写权限、版本控制、流转和幂等规则不扩权。PC 展示原理由、App／Lite 原理由输入仍保留待办。
