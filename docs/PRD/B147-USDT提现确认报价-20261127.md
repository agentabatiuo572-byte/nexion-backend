# B147 USDT 提现确认报价

用户确认的网络确认费、UVT 抵扣数量和实际到账金额，必须与本次提现最终采用的三项金额一致。UVT 余额增减只要改变报价，就要重新确认。余额变化后报价仍相同的请求可继续提交。

## 接口约定

- `POST /api/withdrawals/eligibility` 带布尔值 `useNexFeeOffset`，可用网络的返回数据增加 `quote`，其中 `networkFee` 和 `netReceive` 单位为 USDT，`nexBurned` 单位为 UVT。这三个字段为六位小数的十进制字符串，客户端可原样回传。成功查询的政策版本沿用 `data.configVersion`。到账金额小于或等于零时，报价可查看，`canSubmit` 为 `false`。
- `POST /api/withdrawals` 在现有请求上带 `confirmedQuote`。App 和 Lite 使用同一份服务端报价显示和确认，并原样提交三个字段以及对应的金额、网络、地址、抵扣开关和政策版本。锁定钱包后，后端用实际余额重算这三项金额。三项相同时继续原提现流程，部分字段、负值、超精度或非正到账确认值返回 `422 WITHDRAWAL_CONFIRMED_QUOTE_INVALID`。
- 政策版本仍按现有规则验证。版本一致而锁内报价变化时返回 `409 WITHDRAWAL_QUOTE_CHANGED`，`data` 含 `policyVersion` 和新 `quote`。此时钱包、账本、订单及出款事件不写入。新报价可提交时，客户端提示并等待用户重新确认，再用新键提交。新报价到账小于或等于零时，用户需要调整金额或抵扣选择。
- 原键和完整原请求重放仍返回原结果，包括已保存的报价拒绝。报价参与请求指纹。重放如调整原报价仍按现有请求冲突拒绝。按原键只读查回原单仍用原接口，若查回报价变化拒绝，可用资格查询取当前报价。放弃请求需携带当次的完整原报价。
- 旧版 App 和 Lite 未发送确认报价时，过渡期继续使用原请求、原指纹和原算法。旧版在用户确认与扣款之间仍不能绑定报价。两端接入后再收紧此过渡入口。D7 银行提现使用既有银行报价、审批和入账规则。

提现事件继续保留链上订单的合规阈值。A4 的 `withdraw.submitted` 事件在当前版本登记该数值字段，银行和历史事件可省略。
