# L6 行为日/周趋势统一既有业务时区（B48 L6-BE-01）

- 来源：`uvel-docs/handoffs/2026-10-28/backend/20-backend-pending-20261031.md` L6-BE-01（34c02b0 第 1555 行）。
- 基线：`nexion-backend` `origin/test@dd7ff8cd`（A2/E6 + 历史摘要补正，#523 已受管发布）。
- 范围：只统一 `dailyTrend` 与 `weeklyTrend` 的分桶时间基准；不改统计定义、周起点、窗口边界、筛选/去重/总计/权限或前端。

## 1. 当前事实（基线静态核对）

- 事件表 `nx_behavior_event_fact.occurred_at` 是 `DATETIME(3)`；生产者 `BehaviorAnalyticsService.normalizeClientTime` 把客户端毫秒时间转成 `ZoneOffset.ofHours(8)` 的 `LocalDateTime` 后写入。schema 注释也写明存储为 UTC+8（480 分钟）。
- 业务 Clock/部署：应用 Hikari 初始化 +08，20 个应用账号会话实际 +08；业务 Clock 为 Asia/Shanghai。普通 MySQL 新会话/全局默认 +07 不是应用会话，本次不据此改服务器全局时区。
- `dailyTrend` 使用 `BusinessPeriodSql.Legacy.BUSINESS_TIME_HEAD/MID/TAIL`：对每行 `occurred_at` 加“业务日历偏移 − 480”分钟，再按业务日期 `%Y-%m-%d` 分桶。
- `weeklyTrend` 直接用存储时间 `DATE_FORMAT(occurred_at,'%x-W%v')` 分桶，没有应用同一业务日历偏移；当业务日历版本偏移不等于 480 时，周桶会与日桶使用不同的时间基准。按当前部署合同（业务 Clock Asia/Shanghai/+08），若 `nx_business_calendar` 生效偏移也是 480，则 delta=0、现有桶值通常不变；实际日历行未在本地/DB 查询，公共 TEST 核对。但 SQL 合同与日趋势不一致，属可达差异（业务日历版本支持非 480 偏移）。

## 2. 修复口径

只改 `BehaviorAnalyticsMapper.weeklyTrend`：

- 把 `occurred_at` 包进与 `dailyTrend` 相同的 `BusinessPeriodSql.Legacy.BUSINESS_TIME_*` 表达式，再 `DATE_FORMAT(...,'%x-W%v')`；
- `GROUP BY 1 ORDER BY bucket`，与日趋势同一写法，只对业务时间分组一次；
- 保持 `%x-W%v` 原 ISO 周定义（周一为周起点）、bucket 字符串格式、窗口 `occurred_at BETWEEN #{startAt} AND #{endAt}`、device/locale 过滤、PV/点击汇总、事件去重和总计不变；
- 不对存储时间做二次转换：存储已按 +08，表达式只加一次“业务日历偏移 − 480”；当前 +08 时 delta=0，不改变既有日/周数据；
- 不改 `dailyTrend`、服务层 `BUSINESS_ZONE`、Hikari 会话、MySQL 全局时区、保留期或统计定义。

## 3. 时间与时区合同

| 层 | 事实 |
|---|---|
| 事件存储 | `occurred_at DATETIME(3)`，写入时使用 +08 的 `LocalDateTime` |
| 应用会话 | Hikari/应用账号 +08；业务 Clock Asia/Shanghai |
| 日趋势 | 每行 `occurred_at` + `(业务日历偏移−480)` 分钟 → 业务日期 |
| 周趋势（修复后） | 同一业务时间 → `%x-W%v` ISO 周 |
| 周起点 | 不变，ISO 周一 |
| 窗口 | 不变，仍按存储时间 `BETWEEN startAt AND endAt` |

当前 legacy +08 下 `(偏移−480)=0`，因此修复对当前已发布数据通常不改变桶值；它保证业务日历版本偏移变化时，日/周仍基于同一业务时间，不出现双重转换或 PC 重分桶。

## 4. 前端接入影响

- 接口字段、bucket 格式、筛选和合计不变；PC 继续展示服务端返回的日/周桶，不需要重分桶或改文案。
- 若业务日历偏移变化，周桶可能随业务时间移动，这是与日趋势一致的正确含义；页面语义说明由对应文档登记，本候选不改 App/PC/H5。

## 6. 公共 TEST 业务验收（未执行）

前置：真实 L6 行为接口（`behavior` 窗口读取）和自然现有事件；不发真实用户行为、不改库/时钟造边界，不使用私有函数或本地 fixedClock。没有自然跨日/跨周样本则记未验。

1. **自然跨日/跨 ISO 周事件**：找现有事件中业务时间落在周一 00:00 边界附近（或业务日历偏移与 +08 不同的版本生效期）的自然样本，分别读 `dailyTrend`/`weeklyTrend`；同一事件应归入同一业务日/业务 ISO 周，周桶与日桶时间基准一致。
2. **合计一致**：同一窗口内日/周趋势的 PV/点击总计与 `activity` 过滤后的总量一致；分桶只改变归属，不丢/不重复。
3. **筛选不变**：device/locale 过滤在日/周两接口返回相同过滤集合。
4. **空数据/无权**：空窗口返回空趋势；无 L6 读取权仍原 403，不因本改动放宽。
5. **当前 +08 基线**：若现有业务日历偏移为 480，确认日/周桶值与修复前一致（delta=0），不产生无意义变化。
6. 不导出/不记录真实用户行为明细，只记录聚合桶和业务事实。

## 7. 兼容与回滚

- 无数据库/迁移/配置/接口字段/角色/前端变化；不改全局时区、事件数据、保留期或统计定义。
- 行为变化仅限：`weeklyTrend` 使用与日趋势相同的业务时间基准；当前 +08 下通常无桶值变化。
- 回滚只需还原 `weeklyTrend` 的表达式；已产生事件/审计不受影响。
- 本候选未启动本地/隔离业务服务，未做 HTTP/DB/页面验收；构建通过不等于业务通过。
