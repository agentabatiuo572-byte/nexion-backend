## 最小实现约定

- 回执缓存未命中时，`receipt`保留本次调用已解析的原JSON树和规范字符串；`exactReceipt`仍逐字段核对完整回执，遇到与已解析原字符串相同的JSON时复用其规范字符串。事件仅在原始摘要认证成功后从已解析events树解码，原`LegacyUvtProof.current`深拷贝及NEX→UVT单向兼容保持。临时映射仅属于一次`decodeReceipt`调用，不放入长期回执缓存或operation wrapper。
- 写入端仍执行原事件验证、原规范化及`exactReceipt`全部字段比较，未传入读取端复用结果；原摘要格式、精确缓存键、64MiB总上限、256KiB单项上限及8192项上限保持。每次解码的id、recordedDbUtc、协议、参与方及分录验证保持。
- 注册资金出生最后的birthJournal比较复用该次`authBirth`已解析的原source，保持原规范化和完整RAW比较，不新增当前币种投影。
- `OperationRows`只在自身物理只读RR快照内保留最近JSON页，LRU最多8页、估算8MiB；每页仍最多32个operation ID。估算按每页256字节、每行2048字节加所有字符串每字符4字节计算，并非精确JVM对象尺寸承诺。超限页清空局部LRU，只作为原有当前页使用，不另留副本；当前页不得因此被截断或拒绝。缓存命中前继续核对原物理RR连接，切页命中同样调用原续租回调；未命中继续执行原完整查询、ID及顺序核对和MyBatis缓存清理规则。
- 不给每个wrapper缓存完整JSON，不将全历史JSON放入新缓存。目录、全量ID、RAW、参与方、分录、回放events及原少量试用退款树的持有范围保持，因此不能称为全部历史内存有界或每份JSON全程只读取一次。

保留`validateRaw → authBirth → directReversals → 主循环 → coverage`顺序、全部判断及异常转换分支。金额、资格、来源、符号、READY/UNKNOWN原因、贡献顺序、历史范围、4096人闭包上限及RR边界均不变。本次不改页面、权限或业务流程，也不通过修改冻结压力工具或门槛制造通过。
