# L3-BE-01 财务覆盖率返回同源估值可靠性

日期：2026-11-15
范围：后端只读候选（B1 canonical coverage → L3 treasury snapshot），不改前端、导出、资金检查、权限、配置或数据。

## 1. 问题

L3 财务报表的覆盖率由 `L3FinanceReportService.treasurySnapshot()` → `TreasuryL3FinanceFacadeAdapter.currentL3FinanceSnapshot()` → `OpsTreasuryService.coverage()` 读取。`coverage()` 返回储备、应付款、覆盖率、净敞口、红线/健康线和覆盖率序列，但没有返回这次覆盖率所用的估值是否可靠。

B1 同一次 `dualLedgerSnapshot.snapshot` 已经带有 `valuationReliable`：有 UVT 锁定/奖励应付款而 NEX/USDT 最新价缺失或非正时为 `false`；没有 UVT 应付款时没有需要估值的项，保持 `true`。`liabilities()` 和净敞口已有 `valuationReliable`、`valuationStatus` 与 nullable `valued*` 字段，但 `coverage()` 没有把这组同源状态带出。

因此缺价时：

- `coverageRatio` 仍可能是一个正常外观的百分比；
- `netExposureUsdt` 仍可能以缺价时低估的应付款计算；
- 旧 PC 只读这些 raw 数字，无法知道本次覆盖率不能作为可靠估值结论。

本项只解决“把同一 B1 快照已有的可靠性状态读出”，不新增价格、估值算法或资金政策。

## 2. 权威来源与时点

`OpsTreasuryService.coverage()` 在一次调用中只执行一次 `dualLedgerSnapshot()`，再读取该次返回的 `snapshot`。本次新增字段全部从同一个 `snapshot` 读取：

- `snapshot.valuationReliable`：B1 在 `readDualLedgerSnapshot()` 内按 `uvtValuationReliable(nexLiabilityUnits, currentNexPrice)` 计算；
- `snapshot.coverageRatio`：同一快照内的覆盖率；
- `snapshot.reserveUsd`、`snapshot.liabilitiesUsd`：同一快照的储备和应付款；
- `snapshot.redlinePct`、`snapshot.healthyPct`：同一快照的阈值。

不重新读取价格、不重新计算应付款、不另调用 `liabilities()` 或第二次 `dualLedgerSnapshot()`，也不从 `coverageRatio` 的数值反推可靠性。

`ensureD3FallbackSeedData()` 当前为空实现，不存在读时写种子；`coverage()` 的 `@Transactional(rollbackFor = Exception.class)` 和 L3 facade 的 `REPEATABLE_READ` 事务均未改变。

## 3. 接口合同（仅新增字段）

`GET /api/admin/treasury/coverage`（权限 `overview_b1_read` / `finance_d3_read` / `bi_l3_read` 保持）以及 L3 `GET /api/admin/bi/finance/treasury-snapshot` 的 `coverage` 段新增：

| 字段 | 类型 | 语义 |
|---|---|---|
| `valuationReliable` | boolean | 与本次 `coverageRatio` 同一 B1 快照的 `snapshot.valuationReliable`；缺失/非 true 按 `false` 处理，不默认为可靠 |
| `valuationStatus` | string | 复用现有 `valuationStatus`：`AVAILABLE` 或 `VALUATION_UNAVAILABLE` |
| `valuedCoverageRatio` | number \| null | 可靠时与 `coverageRatio` 同一个值；不可靠时为显式 `null`，不写 0 |
| `valuedNetExposureUsdt` | number \| null | 可靠时与 `netExposureUsdt` 同一个值；不可靠时为显式 `null`，不写 0 |

raw 字段保留且数值/单位不变：`reserveTotalUsdt`、`liabilityTotalUsdt`、`coverageRatio`（百分数）、`netExposureUsdt`（USDT，2 位）、`redLine`、`yellowLine`（百分数）、`redlineBreached`、`series[].coverageRatio`、`breaches`、`asOf`、`source`。

`redlineBreached` 仍是 raw 快照字段，本次不改为 nullable；消费方若要做可靠估值结论，必须先看 `valuationReliable`，不能单独把 raw `redlineBreached` 当成可靠判定。

零负债哨兵不变：`pct()` 在应付款为 0 且储备大于 0 时返回 100；若同时存在 UVT 应付款但缺价，`valuationReliable=false`，`valuedCoverageRatio=null`。零负债且没有 UVT 应付款时可靠性为 true，哨兵 100 可继续作为可靠读数。

## 4. 消费方核对

- **L3 后端 facade**：`TreasuryL3FinanceFacadeAdapter.requiredCoverage()` 只校验既有 keys 并复制 section，新增字段会原样透传，不重算、不丢弃。本项不收紧既有 keys，避免无合同依据地改变 L3 503 边界。
- **L3 PC（固定源码及当前页面）**：`assertL3FinanceContract` / `l-client` 只映射 raw `coverage` 字段，不读取新增字段；页面 `num()` 对缺失/非数字回退 0。因此旧 PC 会忽略新字段，缺价时仍可能显示 raw 数值。后端新增 flag 不等于页面已经正确；PC 接入须另行修改并验收。
- **导出**：L3 汇总 CSV 和高敏明细从 `TreasuryFinanceAnalyticsFacade.currentFinanceSnapshot()`（`dualLedger()`）及 L5 任务读取，不读 `coverage()`；本项不改导出列、CSV 内容、理由、权限或回执。B1/B2/D3 的应付款 CSV 走 `liabilities`/`liabilitiesCsvPayload`，不受本项影响。
- **写回执/资金检查**：现有资金检查使用 `TreasuryCoverageFacadeAdapter` 读取 `dualLedgerCoverageSnapshot()` 的 `snapshot.valuationReliable`，不是 HTTP `coverage()`；本项不改变该 facade、阈值、审批、J1 闸门或任何写链。
- **L3 treasury-snapshot 的其他消费者**：`OpsBiService`/`OpsRegulatoryReportService` 的财务证据读取 `financeAnalyticsFacade.currentFinanceSnapshot()`，不读 `coverage()`；本项只增加 `coverage` 段字段。

## 5. 兼容与失败边界

- 新增字段为 additive；raw 数值合同保留，旧消费者不因字段增加而改变。
- 不可靠时 `valuedCoverageRatio`、`valuedNetExposureUsdt` 必须显式为 `null`，不能用 0、100 或当前 raw 数字替代。
- `valuationReliable` 与 `valuationStatus` 必须来自同一 `snapshot`；不把读取失败、缺字段或解析异常默认成 true。
- 不新增错误码；本次 `coverage()` 仍按原路径失败（例如来源缺失时 L3 facade 继续抛 `L3_TREASURY_SOURCE_INVALID`）。
- 不改变 `redlineBreached` 的 raw 值，也不把它升级为可靠结论；可靠结论须由消费方用 `valuationReliable` 与 `valued*` 组合判断。
