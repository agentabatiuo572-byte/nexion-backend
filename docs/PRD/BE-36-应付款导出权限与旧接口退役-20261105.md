# BE-36 应付款导出权限与旧接口退役

依据：uvel-docs `a8305f3` 的 `admin-console/decisions-landing.md` BE-36、PCN-07，以及后端交接 B30 第 36 项。统一应付款导出不依赖旧 B2 菜单下线，旧菜单与角色授权范围沿现行规则保留。

| 接口 | 权限与行为 |
| --- | --- |
| `POST /api/admin/treasury/liabilities/export` | 持 `overview_b2_export` 或 `finance_d3_export` 任一权限即可导出。继续使用 `TreasuryExportRequest`、`Idempotency-Key` 与现有 `sensitiveExportCsv("liabilities", ...)`。 |
| `POST /api/admin/treasury/reconciliation/export` | 继续只接受 `finance_d3_export`；仅持 B2 导出权限的账号不能导出对账文件。 |
| `GET /api/admin/treasury/b2/liabilities/export` | 沿用原 `overview_b2_export` 鉴权。授权请求返回 HTTP 410、JSON 错误 `B2_LIABILITIES_EXPORT_RETIRED`，不再调用 CSV 生成服务。原调用方须改用上述带理由 POST。 |

统一应付款导出继续要求操作者填写 8～200 字理由。真实操作者由服务端登录态解析，幂等重试复用原文件与 required 审计；审计写入失败不得返回成功文件。CSV 列、中文应付款名称、UTF-8 BOM、单元格转义及数据范围均沿用现有实现。

两个 CSV 导出接口的业务错误明确返回 `application/json`，包括请求声明 `Accept: text/csv` 的情况。HTTP 状态及 `ApiResult` 错误码、错误信息沿用原服务：缺理由、缺幂等键均为 422，幂等冲突为 409；成功响应仍为原 CSV 文件。

验收通过真实 API 业务入口核对：B2-only 与 D3-only 均能带理由下载应付款 CSV；缺理由拒绝；同键重放只有一条成功审计；B2-only 对账导出为 403；旧 GET 为明确 410 且不能下载 CSV。主验收记录保存于 `artifacts/treasury-priority-20261105`，本 PRD 不代替实际执行结果。
