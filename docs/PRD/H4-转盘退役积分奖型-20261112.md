依据 `uvel-docs/admin-console/decisions.md` T04：「积分：转盘奖项不能再选积分，已有奖项只读，上线环境换掉」。

## 后端改动

- `AppGrowthWheelService` 的奖型白名单移除 `points`，只保留 `uvt`、`usdt`、`coupon`。
- 移除积分派奖分支和整数积分校验辅助方法；不再写 `nx_points_ledger`。
- 保留 UVT/USDT/券三类现行派奖：UVT/USDT 走钱包与账本，券走 H7 发券。
- 历史积分档仍可读（后台只读、历史抽奖记录不改）；不删除、不改概率、不改共享数据。

## 运行影响

- 若目标环境奖池仍存在 active 积分档，App 会按现有配置校验拒绝整池（`WHEEL_TIER_CONFIGURATION_INVALID`），不会静默改发其他奖品；这是退役后的显式失败，需运营按 T04「上线环境换掉」用现行三类奖补足概率总和 100%。
- 不在启动迁移中自动改奖池，避免静默修改共享业务数据；清退动作需在目标环境按运营变更流程执行并留证。

## 受控清退/替换旧积分档

- 新增 `POST /api/admin/growth/quest-events/wheel-tiers/{tierName}/retire`，权限 `growth_h4_wheel_pool_write`，Header `Idempotency-Key`。
- Body：`reason`（8–200）、`operator`、`confirmed=true`、`expectedSignature`（当前 `wheelSignature`）。
- 仅允许 `reward_kind=points` 的历史档；`status` 置 0、保留 `is_deleted=0`，历史行仍可读，但不进入 active 池。审计 `H4_WHEEL_TIER_RETIRED`。
- 不恢复积分派奖，不修改其他奖档；清退后 active 概率总和会低于 100，运营须通过现行 `POST /wheel-tiers`（可能走 H4 A2 审批）或既有奖档调整补足到 100。
- 验收：active points 24% + 现行三类 76% → retire 后 active 合计 76，points 行 status=0/is_deleted=0；补入 24% UVT 经 A2 批准后 active 合计 100，App 抽奖成功且不出现 POINTS。公共 TEST 目标库仍不自动改，由运营按 T04 执行。
