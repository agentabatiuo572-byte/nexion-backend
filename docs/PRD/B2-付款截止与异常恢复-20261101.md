# B2 付款截止与异常恢复（2026-11-01）

依据：用户2026-10-31后发付款合同，uvel-docs 20-B2及本轮P01–P06测试计划。钱包继续要求PIN；外部三通道不读PIN。费用维持未配置，不开通或发起实款。

- 订单自创建30分钟截止；既有促销pay_by更早时从严。付款单expiresAt=deadlineAt，报价有效期≤15分钟且≤deadline。无既有订单的换购/体验转正等从不可变业务报价时刻计30分钟。
- BEP20确认宽限3分钟、ERC20/银行卡5分钟。宽限只接截止前已付款而确认慢的款项；付款链接/地址在用户视图截止后不再提供，paymentAllowed=false。银行卡还取已核供应商expirationTime较早值；confirmationGraceEndsAt始终从订单截止起算。
- 到宽限终点先查原意图，再与订单PAYMENT_TIMEOUT终止、原有预占库存/配额/券/促销释放同事务；新未预占不增加库存。查询失败不延长可付款窗口，reconciliationStatus=QUERY_UNKNOWN单独持久保留；EXPIRED意图仍由原编号持续查单，后到款进入人工处理，不生成替代收款或自动退款。任何已确认资金或已交付事实不会被超时覆盖。旧失败单不得取消正在进行的新尝试。所有曾直付订单（含失败可重试）均退出generic TTL关单，统一由直付固定截止与宽限终止，防止旧TTL配置10/90分钟改变用户窗口。冻结账号仍按硬截止释放。
- HDPAY5→EXPIRED/PAYMENT_FAILED，截止前允许新报价/新付款键重试；4→MANUAL_REVIEW/PAYMENT_REFUNDED_REVIEW。首次截止后观察成功但无可信付款时间→PAYMENT_TIME_UNVERIFIED；到宽限外或确实截止后付款→PAYMENT_LATE_REVIEW。不得以查单时刻填供应商实际付款时间。
- 正常交付仍原子复核商品、库存、槽位、配额、优惠等。只有服务端已经验证及时到账的直付作用域允许宽限期交付，钱包付款截止规则保持原有行为。
- 交付/超时/人工分别提交唯一结果事实；现有消息中心/原生推送投影按事实去重，超时按订单跨重试去重。推送订单目标再次校验归属。丢响应/回调重放不多扣钱包、不多交付设备。

API字段与迁移见[直付合同](../direct-purchase-payment-contract.md)。本轮源码与隔离MySQL自测不代替供应商沙箱、真实资金、TEST发布、App实景或原生推送送达验收。供应商30分钟有效期、H5内嵌能力及时间字段语义需官方商户资料/运行态核实；未获证据不编造。

补修（2026-11-01）：活跃业务批次同时包含仍关联PENDING订单的EXPIRED失败意图，不能按付款意图终态把尚未结束的商务截止移入历史配额。只有已结束商务单的纯资金对账使用历史轮转；600条历史记录下失败待付单仍在deadline+宽限的下一次观察正常关单。
