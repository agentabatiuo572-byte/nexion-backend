## 1. 背景与缺口

G2 批量兑换队列处理使用 `POST /api/admin/market/exchange/queue/process` 发起，原命令键的回执由同路径 `GET` 查询。当前 `GET` 与 `POST` 同用 `finprod_g2_write`，而服务层 `queueBatchReceipt` 已按认证 adminId 校验回执内的 `g2QueueBatchOwnerAdminId`。原操作者被收回 `finprod_g2_write`、仍持有 `finprod_g2_read` 时，无法再读取本人原批次结果；页面上的未决记录因此无法了结。

权威待办：`uvel-docs` `origin/main@d5984fa` 的 `handoffs/2026-10-28/backend/20-backend-pending-20261031.md` 第 1586 行 G2-BE-04。

## 2. 目标与非目标

目标：

1. 仅将精确路径 `GET /api/admin/market/exchange/queue/process` 的入口权限从 `finprod_g2_write` 放行到既有 `finprod_g2_read`。
2. 服务层继续要求认证 adminId 等于回执 owner；只返回该批次的 `batch`，不返回完整概览、owner、operator 或他人/别域记录。
3. 保持 `POST` 批量执行仍要求 `finprod_g2_write`，保持旧 POST 兼容回执、TTL、恢复/失败/未知语义不变。

非目标：

- 不新增权限、角色、授权数据或全局 `origin`/`readAuthority`/A2 读权；不把 `finprod_g2_read` 变为写权。
- 不修改 `queueBatch.process`、队列/资金/行情/幂等原记录、POST 旧成功键、TTL、`executeRetained` 或恢复逻辑。
- 不改变老回执；不为无 owner 的 legacy 回执猜 owner 或回填。
- 不改 PC/App/H5 页面或下发文案；PC 接入只登记前置条件。
- 不把找不到回执解释为“未执行”；无 owner、非 owner、legacy、FAILED、PROCESSING、UNKNOWN、缺失、过期不可恢复均保持明确的 404/400，不返回“未执行”。

## 3. 现有合同与精确改动

### 3.1 HTTP 与 RBAC

- 控制器：`OpsExchangeController`，`@RequestMapping(OpsAdminApi.ADMIN_PREFIX + "/market/exchange")`；`GET /queue/process` 接受可选 `Idempotency-Key` 头，认证主体经 `Authentication.getName()` 解析为正整数 adminId。
- 泛路径过滤器：`AdminRbacAuthorizationFilter` 对 `/api/admin/market/**` 使用 `finprod_` 域；GET 要求至少一个 `finprod_*_read`。因此持有 `finprod_g2_read` 的请求已能通过过滤器，原先被方法级 `finprod_g2_write` 拒绝。
- 既有权限种子：`scripts/rbac-classic-seed/GH.sql:17` 已有 `finprod_g2_read`；`02-role-permission-seed.sql:374-399` 中 FINANCE 同时具备 G2 读写、GROWTH 具备 G2 读而无 G2 写。本单不新增任何 role/permission 行。
- 本单唯一源码改动：方法级 `@PreAuthorize` 从 `hasAuthority('finprod_g2_write')` 改为 `hasAuthority('finprod_g2_read')`，并保留 controller 中认证 adminId 解析。没有新增/覆盖过滤器规则。
- 过滤器是“任一 `finprod_*_read`”，方法级再做精确 `finprod_g2_read`；两步都通过才进入服务。

### 3.2 服务层 owner 与返回

- `G2G3AdminCommandService.queueBatchReceipt(key, adminId)`：
  1. 缺 key 或长度 >128：`400 IDEMPOTENCY_KEY_INVALID`；有效 key 先 `trim()`。
  2. `idempotencyRecords.selectCurrent("ADMIN:G2:QUEUE_BATCH", key)`；不存在/无成功回执/非 SUCCEEDED 均不能返回 batch。
  3. `idempotency.recoveryResult(...)` 反序列化保留的成功 `ApiResult`；仅当 `data.g2QueueBatchOwnerAdminId` 是 `Number` 且等于认证 adminId，且 `data.batch` 是 Map 时返回。
  4. 成功响应只含 `{"batch": {...}}`；移除 owner，不返回 POST 的完整概览、operator 或展示名。
  5. 其它分支统一 `404 G2_BATCH_RECEIPT_NOT_FOUND`。
- `POST`：`processQueue` 仍由 `finprod_g2_write` 保护；新成功回执在业务事务内写入服务端认证 adminId 的 owner；旧回执不含 owner 时，POST 原兼容返回不变，GET 继续拒绝。
- owner 的可信来源是服务端认证 principal 传给 `processQueue`，不是请求体 operator/展示名；GET 不接受客户端指定 owner。
- 不改变 `executeRetained`、`DEFAULT_TTL`（24h）、`recoveryResult` 的 READ_COMMITTED/readOnly 合同；成功回执即使超过 `expires_at` 仍按现有 retained 语义可读，不重领、不重置、不执行。

### 3.3 GET 是否有技术写副作用

- 业务数据库：只读 `nx_admin_idempotency_record` 的 `SELECT`；`AdminIdempotencyTransactionExecutor.recoveryResult` 标注 `@Transactional(readOnly = true, isolation = READ_COMMITTED)`，不加锁、不 claim、不更新、不删除、不迁移过期记录。
- 认证/RBAC 过滤器成功路径不写审计；拒绝路径才写既有 `A1_RBAC_ACCESS_DENIED` 审计。
- 运行时技术副作用：`AuthenticatedPrincipalRateLimitFilter` 对已认证请求在 Redis 增加分钟限流计数并设置过期时间；这是反滥用限流，不是 G2 业务回执/队列/资金写。若限流不可用，既有行为返回 503。
- 因此本 GET 不是“完全无任何副作用”的纯函数，但无 G2 业务表、幂等回执、队列或资金写。

### 3.4 失败/边界语义

| 场景 | 结果 |
|---|---|
| 本人新 POST 成功回执，持 `finprod_g2_read`、无写 | 200，仅本人 `batch` |
| 非 owner（含另一读权管理员） | 404，不泄露存在性/内容 |
| 无 `finprod_g2_read` | 403（方法级或过滤器），不进入服务 |
| legacy 回执无 owner | 404，不猜 owner、不当作未执行 |
| POST 失败/取消/回滚，无成功回执 | 404；不把缺失当未执行 |
| PROCESSING/UNKNOWN/FAILED | 404；不返回推测结果 |
| key 缺失/空/超过 128 | 400 |
| 已过期但仍有保留成功 JSON | 现有 retained 只读语义；不重执行 |
| 非 G2 域/他人批次 | 404；scope 固定为 `ADMIN:G2:QUEUE_BATCH`，不跨域 |

### 6.1 纯源码/注解/既有回执读取（本单计划）

1. **owner 有读无写**：取既有批次的原操作者 adminId 与原 `Idempotency-Key`；确认其当前仅有 `finprod_g2_read`、无 `finprod_g2_write`；调用 GET，预期 200 且 `data` 仅含本人原 `batch`，与 POST 回执键/批次一致。
2. **非 owner**：另一持有 `finprod_g2_read` 的 admin 用同一 key 调用，预期 404 `G2_BATCH_RECEIPT_NOT_FOUND`，不返回 batch/owner。
3. **无读权**：无 `finprod_g2_read` 的 admin 调用，预期 403；不进入服务、不返回回执。
4. **legacy 无 owner**：若存在自然 legacy 成功回执，读 GET 预期 404；不猜 owner。
5. **失败/未知/处理中/缺失**：自然存在的 FAILED/UNKNOWN/PROCESSING 或无回执 key，预期 404；缺失/无效 key 预期 400；不将其解释为未执行。
6. **源码/注解核对**：静态核对 GET 方法为 `finprod_g2_read`、POST 方法仍为 `finprod_g2_write`，泛过滤器 GET 仅要求 `finprod_*_read`；**不通过实际 POST 来证明权限或回执保持**。本项不需要 HTTP 请求。
7. **恢复/过期语义**：只读查询既有回执，不触发过期重领或业务执行；若无可读保留回执则记未验。
8. **副作用核对**：GET 前后核对 `nx_admin_idempotency_record`、队列/资金无业务变化（若有只读访问条件）；仅允许 Redis 限流计数变化。没有 DB 访问条件则不声称已验证，只记录代码事实。

### 6.2 写请求单独计划（当前未批准，不执行）

以下全部是写请求，不能归入“只读计划”，即使预期是 403 也不以名称或预期结果当只读：

- **owner 无写 POST 负向**：需要在实际执行前指定自然批次、原 key/原 body、执行人、时间窗口和影响，并取得批准；当前未批准，不发送。
