# P5：收益事件认领与准备事务合并

日期：2026-11-13。适用于直推消费者的合法 `earnings.credited / COMPUTE_TASK` 包络。

## 问题和目标

每人六设备的隔离恢复期，收益事件处理仍落后。原消费者分别提交 delivery 认领、佣金准备和最终 SUCCESS；新生成且不合资格的零额 REJECTED 佣金也经过这些提交。本批减少准备阶段提交次数，保持资金、资格、来源、金额、锁和去重规则。

## 行为

- 合法收益包络沿用原消费组、topic 和事件幂等键。一个事务完成原 claim 和原 `prepareSettlement`。
- 仅原准备逻辑返回“本次新生成的 REJECTED 收益佣金”时，同一事务记录 SUCCESS、处理数零，然后结束。三次提交合为一次，不生成佣金资金。
- 正常新佣金和已有佣金重试，提交认领与准备后，继续在外部执行原 `resumeSource` 和 SUCCESS 路径。计算、物化、释放等后继事务边界不合并。
- 重复事件已 SUCCESS/SKIPPED 时直接返回；PROCESSING 等状态保留原拒绝重复执行行为。
- 购买、退款及不满足快速路径条件的包络走原消费者流程。坏 JSON 保留原 claim 和 FAILED 路径；缺失或非标准字段沿用原解析、业务校验及其成功或失败结果，不因预解析改变原结果。

## 异常和恢复

新事务中的准备异常，包括来源或政策冲突、SQL 错误和提交失败，会回滚本次 claim、attempt 和准备写入。此时 delivery 可能没有新增行或保留此前快照，不再保证像旧流程一样留下本次 PROCESSING/FAILED 和 attempt；错误由原 outbox 有界重试及 DEAD 机制记录和承接。

准备事务已提交后的续算异常，仍用原 delivery FAILED 和 outbox 重试路径。正常佣金、已有记录和失败重放仍须实测无重复资金或部分写入。本批不修改 outbox 发布、重试次数、任务时间或客户端行为。

## 验收

只在 PROD 隔离环境验证，TEST 仅保留代码，不构建、不压测。

1. 新 REJECTED 收益事件：来源及原拒绝原因、零额佣金、一次 SUCCESS；重复请求和重复事件不产生重复记录或账本。
2. 合格收益佣金及已有记录重试：原金额、状态转换、计算和物化、收益与钱包结果一致。
3. 购买、退款、坏 JSON、错误来源和用户：走规定路径；准备失败回滚，续算失败记录及重放符合上述恢复约定。
4. 验证任务、收益、资金和重复请求后，保持 1000→5000→10000、每人六设备、原 600 秒任务；不改变 1800 秒预热、SQL 10 秒及原计量窗口或门槛。

本地打包和静态复核不代表以上业务、异常恢复或容量通过。主分支发布需本批明确批准。
