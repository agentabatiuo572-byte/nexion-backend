# H7 代金券删除与批量作废审批

删除券模板和批量作废未用券提交至 A2。原直接删除及批量作废接口对有权调用者返回 409 `A2_CONFIRMATION_REQUIRED`。

A2 接收 H 域 `h7_voucher_delete` 和 `h7_voucher_revoke_available`，参数为 `voucherId` 和 `expectedVersion`。现有 `growth_h7_write` 授权可发起这两类提案并按原请求键找回本人的票。两类提案使用同一券模板锁。

另一位具有 `platform_a2_operation_approve` 与 `growth_h7_write` 的管理员可批准。执行时核对原票券模板和版本。删除保留已领取的券，批量作废只更新执行时状态为 `AVAILABLE` 的券。执行前及拒绝或撤回时，模板和领取记录保持原样。

## 2026-11-17 补充：可拆分配置退役

`nx_growth_voucher.splittable` 只有定义读写，核销仍是整张券置为已用，没有剩余额或分次核销消费者。按原 H7-BE-01「接上或退役」选择最小退役支：

- 管理读取 `vouchers[]` 保留原 `splittable` 历史事实值，供旧协议读取，同时新增 `splittableConfigurable=false`、`splittableRetired=true`、`splittableWriteBlockedReason=RETIRED_FEATURE`，不再把它表示为可配置项。
- 新建或更新请求若把 `splittable` 设为 `true`，在进入业务写入前返回既有 422 `H7_VOUCHER_SPLITTABLE_RETIRED`；请求省略该字段时，更新保留原数据库值，不偷偷把历史 true 改成 false，也不把它重新启用。
- 更新事务的模板锁定查询同时投影 `splittable`（`nx_growth_voucher` 同列 `TINYINT(1)`）；省略字段时该值参与上述原值保留判断，不再因锁定行缺列而恒为 `false`。
- 整券核销、订单/资金/金额精度/有效期、已用成功恢复、历史已存事实、权限、幂等/对象锁均不变；不实现部分核销/拆账，不新增 schema/回填/前端或页面说明。原成功幂等回执仍先于新校验返回。
