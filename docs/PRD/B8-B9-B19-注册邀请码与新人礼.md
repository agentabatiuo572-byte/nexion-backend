# 注册邀请码与新人礼

## 邀请码和客服归属（B8）

手机号注册、已验证身份的第三方新注册和公开预览按相同规则处理邀请码。空码表示无邀请人。好友码沿用账号唯一性、环境隔离、团队关系和邀请事件。有效客服码以 CS 开头，尾部为六位不含 0、O、1、I 的字母或数字。比对不区分大小写。客服码客户没有邀请人、团队投影或 referral.bound 事件，事务内直接形成 ADVISOR_CODE 来源的根绑定。好友随后邀请的新用户按现有继承规则处理。客服停用、个人资格失效或邀请码在注册期间作废时，注册整体失败，返回 USER_REGISTRATION_SPONSOR_NOT_FOUND。重置和作废不改变历史归属。

公开 `GET /api/public/referrals/{code}/preview` 返回 `kind`（USER 或 ADVISOR）、同一脱敏格式的 `sponsor.displayName` 和当前礼包。ADVISOR 的 `sponsor.vRank` 为 null。不存在或已作废的客服码返回 `REFERRAL_PREVIEW_NOT_FOUND`。

客服码操作的路由前缀为 `/api/admin/content/support-agents`。本人 `GET/POST /self/invite-code` 要求有效个人服务资格，可以未分组。POST 传 `expectedVersion`，首次生成或作废后重新生成时传 null，重置传有效码的版本。主管只可对自己管理组成员执行 `GET /{adminId}/invite-code` 和 `POST /{adminId}/invite-code/revoke`，总管理员可跨组。作废传 `expectedVersion` 和 8–200 字理由。成功回执含 `code, link, version, issuedAt`，没有有效码时四项为 null。分享地址未配置时 `link` 为 null。每次写入需要 `Idempotency-Key`，24 小时内同键同请求返回原回执，状态不符返回 409。`GET /api/admin/content/support-workbench/commands/{key}` 只对原操作者在当前权限内提供回查。历史记录保留签发、重置和作废的时间、原因及管理员。成员详情增加 `inviteCode` 摘要。客户资料 `service.assignmentSource` 仅投影给当前有个人服务资格、主管资格或总管理员且可读该客户的操作者。

## 新人礼、审核与回执（B9）

有无邀请人均可成为新人礼候选。有效邀请人还获得配置的邀请奖，无有效邀请人的结算行 `inviter_user_id` 为 null、`inviter_nex` 为零，邀请人数与上级奖励统计不计入这些行。沿用 H8 生效时间、风控分桶、资金覆盖、正式 A2 审核、唯一新人结算及沙箱 RunID 隔离。注册事务快照记录账号、注册尝试、渠道、脱敏邀请人、金额和状态。手机号或第三方注册响应丢失后，原设备、尝试号、证明和认证引用通过 `POST /auth/users/login/attempts/{id}/recover` 恢复原回执。普通登录不附注册回执。无邀请人时 `sponsorCode`/`sponsorDisplayName` 同为 null。

现行独立服务要求唯一的 dev 或 prod 运行态。H8 旧沙箱数据按 RunID 保留，数据库升级将无邀请人结算限定为邀请奖零。正式注册和 A2 审批通过现行 HTTP 路由验证。历史沙箱验证覆盖迁移、同 RunID 去重、跨 RunID 区分及正式账隔离，未通过退役 test JVM 的 HTTP 结算。

## H5 Lite（B19）

`X-NexGrid-Client-Surface: H5` 或既有 cookie 刷新模式识别浏览器，浏览器刷新凭据通过 HttpOnly Cookie 交付。`X-NexGrid-Installation-Id` 是最长 128 字符的浏览器设备标识。H5 注册验证码在启用 H5 开关时，每次有效码发送都消耗 REGISTER 场景且绑定客户端地址的人机票据。设备标识缺失时仍要求人机并执行 IP 限额。验证码发码和注册须使用同一设备，App 原有验证码频控继续生效。手机号和第三方新账号共享按注册成功时间计算的 IP 和 H5 设备滚动 24 小时配额。达到 IP 或设备上限分别返回 `USER_REGISTRATION_K1_IP_LIMIT`、`USER_REGISTRATION_DEVICE_LIMIT`。已注册用户普通登录不占注册名额。

总管理员在 PC A3「平台参数」读取和编辑同一权威配置。GET /api/admin/platform/config/overview 的 platformParams 返回名称、值、单位、可写权限及边界。PUT /api/admin/platform/config 传 kind=param、flagKey、value、expectedValue、理由及 Idempotency-Key。沿用平台参数的原值比较、审计、幂等和权限。auth.risk.h5_register_captcha 和 auth.risk.h5_freeze_newcomer_gift 接受 0/1，默认 1。auth.risk.h5_register_device_limit 接受 0–100，默认 3，0 关闭设备限额。K1 的同 IP 限额沿用原入口。设备、渠道及礼金条件在注册时记录，后续修改只改变新注册账号的条件。H5 浏览器的受控 Origin 或浏览器发送的 Origin 和 Sec-Fetch-Mode 会先于 APP 请求头判断渠道。

已启用礼包的 H5 冻结回执为 `FROZEN`，金额不计入注册时可用余额。审核通过后，若尚未有实付购买，正式 H8 写待发放流水 `REGISTRATION_GIFT_HOLD/PENDING` 并保留当时批准的金额。设备、算力和 Cloud Share 订单经钱包、银行卡或 USDT 成功付款后，按持久 `checkout.completed` 通知复核 `nx_order` 的本人、PAID、实际正金额和付款时间。先购买再审核时审核也复核同一订单。零元权益单、未付和失败不释放。释放沿用 H8 风控、钱包及既有收益释放政策，同一已批准礼金只入账一次。沙箱礼金只写沙箱 RunID 对应的证明账。App 注册保持正常 `PENDING_REVIEW` 状态。
