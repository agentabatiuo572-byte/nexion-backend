# App 充值与试用并发

VietQR 充值创建事务使用 `READ COMMITTED`。同一账号的创建继续由用户行锁串行化。相同幂等键和金额返回同一意图，异金额请求返回冲突。余额入账、支付提供方状态和活跃意图上限沿用原规则。

试用状态与资格查询读取一致性快照。用户开始试用或转购时，由后端在写事务中核对当前设备和预留订单槽位并判定是否允许操作。

验收覆盖八个不同账号并发创建充值、同账号同键重试、金额冲突、重复回调和唯一入账。试用验收覆盖查询与下单同时发生、五槽和满槽边界、试用到期与转购状态。实际结果记录在本轮验收台账。

## B93 按原请求号查询

- `GET /api/trial/commands/{kind}?commandKey=...` 接受 `start` 和 `cancel`，使用当前用户和原请求头 `Idempotency-Key` 查回执。返回 `NOT_SEEN`、`PROCESSING`、`SUCCEEDED`（含原领取单号）、`REJECTED`（含原错误码）或 `INDETERMINATE`（已有记录但无法确认结论）。查询不执行命令，也不依据当前试用状态推断结果。
- `GET /api/app/purchase-payment-intents?kind=...&commandKey=...` 有付款单时沿用原返回。建单请求正在执行且付款单尚未提交时，返回 HTTP 409 `PURCHASE_PAYMENT_INTENT_PROCESSING`。当前没有建单记录或进行中的请求时，沿用 HTTP 404。已有试用报价变更拒绝照常返回。

## B96 试用转购清单与付款单互斥

- `GET /api/trial/purchase-options` 的原试用设备保留 `WALLET`，并按现行费用配置、支付服务和业务开关返回可报价的 `CREGIS_USDT_BSC`、`CREGIS_USDT_ERC20`、`CREGIS_USDT_TRC20`、`HDPAY_BANK`。银行卡还需有效的换汇配置。其他可购设备只返回 `WALLET`。
- 原试用设备排首位并保留领取时的名称与价格。单款商品读取或算价异常时，该款返回不可购原因。非业务读取错误使用 `TRIAL_PRODUCT_QUOTE_UNAVAILABLE`。其他款按各自报价、名额和库存返回。图片读取失败时对应 `imageUrl` 为空，已确认缺失或未上架的其他设备按原规则过滤。
- 同一次试用的非迟付人工复核持续占用原单。状态、用户取消、延长、余额转购、外部报价和建单使用相同的占用条件。受阻请求带回原付款单号与领取号，自动到期等待原单出结论。
- 未付且渠道终结、已完成退款的原单按结案规则处理。渠道结果未知继续等待。迟付复核可在确认宽限到期后重选，条件包括可信的付款与确认时间、达到有效付款截止以及到账金额和笔数符合原报价。有效截止取原单与渠道截止的较早值，确认宽限沿用原付款单口径。旧单缺少足够的到账证据时继续占用，等渠道核实或财务结束复核。

### B96-BE-04 余额转购原回执

`GET /api/app/payment-commands/trial-convert/{commandKey}` 的余额终态返回原商品 `productNo` 和原领取单 `claimNo`。首次成交或明确拒绝的回包与查询回执使用同一笔命令的商品。受理前的拒绝取本次已保存的原请求，受理后的结果取本次受理快照。命令遇到原购买占用时，继续提供占用单据的商品，额外用 `requestedProductNo` 区分本次提交商品。用户、原键与领取单保持原有隔离。旧回执有原受理快照时可读回商品。仅剩请求摘要的旧拒绝没有可还原的商品编号。

## B98 普通下单与取消试用

- 在试用有效、可抵扣或延期有效期间，用户新建或新发起付款的单件、无券、无活动普通订单若购买本人试用商品，返回 409 `ORDER_TRIAL_DEVICE_REQUIRES_CONVERSION`。订单准入拒绝时不创建订单、不占库存。付款准入拒绝时不扣余额、不建外部付款单。试用转购入口按试用报价继续受理。
- 其他商品、多件、用券和活动订单沿用原规则。既有订单回执可读回，已受理外部付款沿原流程交付。
- `POST /api/trial/cancel` 可带 `claimNo`。服务端锁定当前用户的领取单并核对单号。当前无领取或单号不同，返回 409 `TRIAL_CLAIM_MISMATCH`，试用保持原状态。原请求号可查到拒绝回执。旧客户端省略该字段时，继续按当前领取单取消。付款占用和取消资格沿用原规则。

## B124 试用开通确认

- `GET /api/trial/eligibility` 和 `GET /api/trial/state` 在首次领取或可重开的状态下，于有效商品的 `config` 返回 `trialProductId` 和 `trialTermsVersion`。条款版本基于商品编号、试用天数、日 USDT 收益及其依据、日 UVT 收益、购买抵扣上限和商品价格。购买抵扣上限按领取记录保存的精度四舍五入到小数点后六位。名额、购买优惠和运营提示等字段独立变化。已领取的条款继续取原领取快照。
- App 应从同一次资格结果保存并展示试用条件，用户确认后将当时的 `trialProductId` 和 `trialTermsVersion` 放入 `POST /api/trial/start`。服务端核对受理时的 H2 条款和 E1 商品，提供商品编号时优先匹配编号。只传 `deviceName` 的旧客户端继续按商品名匹配，其请求只能校验商品名。即使省略版本，首次开通仍需提供商品编号或名称。
- 商品确认缺失、商品不一致或已提交的条款版本不一致时，返回 HTTP 409 `TRIAL_TERMS_CHANGED`。保留原请求回执，且不创建或重开领取、不初始化或扣减名额、不写入 H2 开通审计和 `trial.started` 事件。App 收到该错误后刷新领取层，待用户再次确认后使用新请求号。
- 同一用户以同一请求号和相同请求重发时读回原结果。变更请求内容后复用原请求号仍按原幂等冲突处理。已有的旧请求回执可按原请求读回。

## B125 试用购买按设备设置优惠

- H2 的 `discountRate`、`discountCapUSD` 和 `earlyPurchaseDiscountUSD` 是默认值。用户购买此次试用的设备始终按默认值算。其他可购买设备可独立设置折扣组（比例和上限同填或同空）与专享立减。每组空值跟随默认，零是明确的优惠金额或比例。
- H2 清单读取通过 `purchaseOptionsPricing` 表示支持逐款设置。整份替换仍核对清单版本及确认账号。新格式 `items` 的有序回执同时返回 `items`、`productNos` 和新版本。同一请求号与原始提交值一致才重放。旧格式继续按原签名和回执，只替换成员，保留仍在清单内的优惠。移除再加入时跟随默认。下架的保留款可以保留已有设置。操作审计记录前后值、版本和理由。
- 余额转购按所买设备的实际价格和适用优惠重新核价。报价返回百分数字符串 `discountRate`、六位 USDT 字符串 `discountCapUsdt` 和 `earlyDiscountConfiguredUsdt`。实际适用的三项优惠值相同时，切换跟随或单独设置不使确认版本失效。价格或实际适用条件变化时，保留带当前报价的拒绝回执，用户重新确认后用新请求号。领取时锁定的抵扣上限和原试用期内整期结算规则继续适用，立减填零仍按整期结算。
- 外部付款限本人试用设备，继续按默认优惠报价。新报价视图和变价拒绝带实际折扣参数，建单后的交付沿用冻结报价及其校验口径。既有回执按原号读回。普通商城、代金券和组合购买走各自的原有定价入口。
