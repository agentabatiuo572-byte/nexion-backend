# B25 商城目录算力点

`GET /api/store/catalog` 的每个商品增加 `computePoints`，供 App 和 H5 Lite 商品详情显示「每台为团队增加 N 算力点」。该字段表示当前 SKU 每台贡献的算力点，不使用价格推算，不读取订单快照或团队统计。[B25 交接规则](https://github.com/agentabatiuo572-byte/uvel-docs/blob/67993fc/handoffs/2026-10-28/backend/20-backend-pending-20261031.md#b25-商城目录下发每件商品的算力点用户-2026-11-03)

## 响应字段

| 字段 | 类型 | 规则 |
|---|---|---|
| `products[].computePoints` | JSON 非负整数 | 等于该商品的 `nx_product.compute_points`，包括值为 `0` 的商品；不得返回字符串、小数或 `null`。 |

App 和 H5 Lite 收到正整数时显示算力点说明，值为 `0` 时隐藏。已发布客户端也兼容缺失或 `null` 的旧响应，但其他类型会导致整个目录解析失败。

## 数据来源

| 模式 | 算力点来源 | 目录范围 |
|---|---|---|
| 正式 | `AppTradeinMapper.listPurchasableCatalogTargets` 直接选择 `nx_product.compute_points`。 | 保留现有商品可见性、发布及登录主体规则。 |
| 验收沙箱 | `CommerceAcceptanceSandboxMapper.listSandboxCatalog` 从现有的 `nx_product` 关联行选择 `compute_points`，与该查询中的商品号、名称、价格使用同一来源。 | 保留当前 run 的 `nx_commerce_sandbox_catalog` 范围；库存与已售仍来自沙箱。服务分支要求严格 `test` profile 的 `LOCAL_SANDBOX` 模式。 |

两条路径共用商品响应投影，以 Java `Long` 输出 JSON 整数。沙箱不新增算力点副本或价格换算。订单快照、团队统计及其他接口的业务规则保持原样。

## B70-BE-01 商城营销角标类型（2026-11-23）

`GET /api/store/catalog` 的商品投影增加 `badgeKind`。六种预设类型为 `recommended`、`bestSeller`、`trending`、`upgradePick`、`flagship`、`lowBarrier`。按 App 九种语言已有预设文字匹配，兼容旧越语「Lựa chọn nâng cấp」的 `upgradePick`。自定义文字返回 `custom`，没有角标时类型为空。`badge` 继续携带原始文案，正式和验收沙箱沿同一投影。

B70-BE-03（2026-11-23）：哈萨克语旧角标文案「Жақсартуға ұсынылады」经 NFKC、空白折叠与小写规范化后为「жақсартуға ұсынылады」，本次作为 `upgradePick` 的匹配别名补入；原有「жаңарту үшін」、其余语言预设及自定义/空值口径不变，正式 `/api/store/catalog` 与验收沙箱继续共用同一个 `badgeKind`。

本段覆盖后端目录类型字段。E1 的预设编辑由客户端接现有保存入口；后端在 E1 新增、编辑及既有 A2 审批回放共用的 SKU 文本校验中，对 `nx_product.badge` 的实际存储值（`VARCHAR(64)`，按 trim 后的 Unicode 字符数）校验，超过 64 个字符返回 `422 SKU_BADGE_TOO_LONG`。空角标、原已有自定义文案及既有英文校验保持；副标题 `tagline` 的边界单独处理，不在本项缩短。

## 编辑生效

服务每次请求查询目录，没有目录缓存或基于 `revision` 的短路。PC E1 SKU 更新会写入 `nx_product.compute_points` 并递增 `updated_at`，正式目录的 `revision` 为返回商品中最新的 `updated_at`。验收沙箱每次请求先同步本 run 的目录，随后从关联的商品行读取当前算力点。运营修改在下一次目录读取生效，无需重启或清缓存。

## 本地旧库迁移

首次为旧库新增商品算力点列时，按商品价格乘以 10 取整，价格为零的商品记为 0。首次新增订单算力点列时，单品订单按数量乘以商品算力点建立快照，组合订单按未删除明细分别计算并求和，没有匹配商品明细的组合订单记为 0。商品列和订单列独立升级，已写入的数值（包括 0）始终保留。补算中断后再次启动只补仍为 `NULL` 的行。

Windows 的 `scripts/apply_startup_schema_migrations.ps1` 和 macOS/Linux 的 `scripts/local/bootstrap_db.sh` 共用 `scripts/local/20261028_compute_points.sql`，包括后者在初始化末尾的补跑。运营将有价格的 SKU 设为 0 后，重跑迁移仍返回 0。此前创建的订单继续使用各自的算力点快照。

## 验收

- 主代码与现有测试调用方均能编译。
- 正式和验收沙箱两种目录模式下，登录用户读取目录时，每个商品的 `computePoints` 均与 `nx_product.compute_points` 一致，且为 JSON 非负整数。
- 在 PC E1 修改 SKU 的算力点后，下一次目录读取立即返回新值，无需重启或清缓存；正式目录的 `revision` 随 `updated_at` 更新。
- 算力点为 `0` 时仍返回整数 `0`，App 和 H5 Lite 隐藏该行；正整数时显示对应的每台算力点说明。
- 对修改前后的正式和沙箱目录 SQL 执行 `EXPLAIN`，新增投影列不引入新的全表扫描。
- 旧库首次升级时核对单品及组合订单的补算结果。将有价格的商品设为 0，再次执行本地迁移，核对商品仍为 0 且历史订单的零值和正值快照均保持不变。

## B75-BE-01 目录每日 USDT 预估区间覆盖普通设备（2026-11-23）

`/api/store/catalog` 每个商品的 `dailyEstimateLowUsdt` / `dailyEstimateHighUsdt` 改为只取决于已发布月目标与浮动比例：有 `monthly_target_usdt` 且 `monthly_target_band_pct` 已配置时，按「月目标 ×（1 ∓ 浮动%）÷ 30」计算，保留原 6 位小数、HALF_UP 舍入，数值与原 Share 分支完全一致；原先的 `!share` 条件已去掉，普通设备（含收纳机）同样下发区间。缺少月目标或缺少浮动比例时两个字段为 null，`dailyEarn`、`monthlyEstimateUsdt`、`dailyEarnNEX` 单值与其他字段、排序与选品口径不变。区间计算抽到 `MonthlyTargetProjection.dailyLow/dailyHigh`，与首页共用同一实现；同时避免月目标存在但浮动比例缺失时的空指针。验收数据由运营在 PC E1 补配 `monthly_target_band_pct` 后核对。

## B75-BE-02 目录每日 UVT 预估区间（2026-11-24）

正式目录和验收沙箱的每个商品（含普通设备和 Share）返回两个 JSON 数值字段。设 `U` 为每台或每份的每日 UVT 单值 `dailyEarnNEX`，`b` 为该 SKU 的 E1 浮动比例 `monthly_target_band_pct`（百分数点）。

| 字段 | 计算 |
|---|---|
| `products[].dailyEstimateLowNex` | `U × (1 − b / 100)` |
| `products[].dailyEstimateHighNex` | `U × (1 + b / 100)` |

两端都按六位小数 `HALF_UP` 舍入。浮动比例为空时两端返回 `null`，继续使用原 `dailyEarnNEX`。有浮动比例且 `U` 为零时两端为零。比如 `U = 10`、`b = 15`，区间为 `8.500000–11.500000` UVT/日。该区间只用于目录预估，`dailyEarnNEX`、USDT 区间和实际收益结算沿用原规则。

## B137 商品系列与系列代表（2026-11-27）

正式商城与验收沙箱的 `GET /api/store/catalog` 在每件商品上增加两个字段。

| 字段 | 类型 | 规则 |
|---|---|---|
| `products[].seriesCode` | 字符串或 `null` | 返回商品表中的系列值。系列包括 `S1`、`PRO`、`PRO_V2`、`RACK_P1`、`RACK_P2` 和 `CLOUD_SHARE`。未配置系列时明确返回 `null`。 |
| `products[].seriesRepresentative` | 布尔值 | 同系列的可购买商品按目录售价从低到高排列。同价取创建时间最早的，再以商品 ID 从小到大排序。第一件返回 `true`。空系列或一件可购买商品都没有的系列均无代表。 |

正式目录与验收沙箱各自使用当前目录的可购买条件和售价。代表须满足该目录的发布及阶段条件、购买规格和库存要求。两个字段不改变目录的展示顺序。首页与赚取页的 `deviceRankings` 行增加 `productNo`，值为当行商品的编号。

后端基于正式商城代表为同系列缺图商品查找合规图片，沿用图片校验与签名。E2 的 S1、Pro、Rack 显存样本分别读取 `S1`、`PRO`、`RACK_P1` 的代表。客服 Cloud Share 年化读取 `CLOUD_SHARE` 的代表。无合格代表时沿用各入口的空值或无数据提示。
