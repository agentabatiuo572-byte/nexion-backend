## 行为聚合 CSV 导出理由

页头固定近 7 天全端和当前筛选两个 CSV 导出均要求 `bi_l6_export` 及本次操作理由。`GET /api/admin/bi/export/behavior` 接收 `reason` query 参数，首尾 trim 后总 Unicode 码点限定 8–200，同时由服务执行现行 A2 最小可见字符策略，不能用空白、控制、零宽或纯组合标记凑数。缺失或越界在取数和成功留痕前拒绝，补充平面字符按一个码点计算。客户端用 UTF-8 query 编码保留 `&`、`+` 等实际文本。

操作记录的 `detail.reason` 和 `admin.report_exported` 事件的 `reason` 保存同一实际理由，不再使用固定模板。导出与必需审计、事件处于同一事务，任一留痕失败不返回 CSV，也不留下另一条成功记录。原筛选、排序、固定八列、聚合无 PII 和生产／验收来源隔离保持。PC 两处理由确认及错误回执由对应 PC 任务接续，不将后端合同交付记为页面完成。

## 充值线路

- 可用目录只保留既有 USDT 网络及银行卡支付，旧 `card` 不出现在可用目录，也不能重新启用或受理新 admission；即使旧数据库开关仍为 true 也拒绝新单。原 admission 按冻结费用快照幂等回读，原结算/失败/拒付/对账回调照常处理。
- 银行卡通道保留原 `finance.topup.channel.vietqr.enabled` 总开关，名称为「银行卡支付」（Bank card payment / Thanh toán thẻ ngân hàng）；只通过 HDPAY。服务商未配置或关闭时配置返回不可用、创建返回 `HDPAY_CONFIGURATION_INCOMPLETE`，不得回落到 MANUAL 或收款账户池。
- 内部旧人工转账入口只允许原键历史重放，新键返回 `VIETQR_MANUAL_TOPUP_RETIRED`。历史归属、整数本金、最低充值额、锁定汇率、USDT 地址归属沿用原校验。
- 本轮不写费率、不改购买费用 `configured=false`，不发起实款。
