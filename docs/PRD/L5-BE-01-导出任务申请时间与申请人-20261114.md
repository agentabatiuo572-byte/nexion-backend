# L5-BE-01 导出任务申请时间与申请人显示名（2026-11-14）

## 1. 背景与结论

L5 任务列表 `GET /api/admin/bi/reports` 的 `BiReportPage` 目前只返回任务行和 `approvalEligibility`；任务行没有申请时间，待放行记录只返回 `ELIGIBLE/SELF/MAKER_UNVERIFIED`，不返回申请人显示名，也刻意不下发 maker 内部编号。

本轮基于现有持久源补两个**只读元数据**：

1. `records[].requestedAt`：`nx_admin_fourth_batch_report.created_at`，任务创建时写入、当前无更新路径修改；
2. `requesterDisplayNames`：只对待放行记录、且当前账号有 `bi_l5_task_approve` 时返回，值为 `nx_admin.nickname`（空则 `username`），找不到/已删除则 `null`；绝不返回内部 ID、邮箱或从失败审计拼凑的名字。

`approvalEligibility` 的 `ELIGIBLE/SELF/MAKER_UNVERIFIED` 与禁止本人批准的逻辑完全不变，显示名不参与权限判定。

## 2. 申请时间来源

`nx_admin_fourth_batch_report`（`scripts/schema.sql:4661-4687`）有 `created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`。

写入/更新路径：

- 创建：`BiReportMapper.java:64-85` `INSERT ...` 只写业务字段与 `last_action_at`，`created_at` 由默认值写入；`ON DUPLICATE KEY UPDATE` 不更新 `created_at`。
- 快照：`:88` 只更新 `snapshot_csv, updated_at`。
- 下载令牌：`:94` 只更新 `download_token_hash, download_token_expires_at, updated_at`。
- 批准/重发：`:634-641` 只更新 `status, last_action, last_action_at, reason, updated_at`。
- 全仓 `grep "UPDATE nx_admin_fourth_batch_report"` 仅上述路径；没有 `created_at` 更新。

因此 `created_at` 是**任务首次创建/申请时点**；批准、重发、下载都不会把它改成 `lastActionAt` 或当前时间。任务列表查询和单任务查询都增加 `created_at AS requestedAt`（`BiReportMapper.java:567,624`）。

> 说明：`created_at` 与现有 `lastActionAt` 一样是无 offset 的 `LocalDateTime`；本轮不做时区转换，保留原合同。页面/CSV 显示方式由前端另定。

## 3. 申请人显示名来源

现有 `AuditLogService.findBiReportMakers`（`shared/audit/AuditLogService.java:122-129`）只返回：

- 精确的 `L_BI_REPORT_CREATE`、`result=SUCCESS`、`actor_type=ADMIN`、`actor_id>0`；
- 线上 `nx_audit_log` + 有内容 hash 的 `nx_audit_log_archive`；
- 同一 report 若有多个不同 actorId，返回 `-1` → `MAKER_UNVERIFIED`；
- 从不返回 makerId 给页面。

新增 `findBiReportMakerIdentities`（`AuditLogService.java:132-160`）：

1. 只对**待放行** reportId 调用上述精确 maker 查询；
2. 对唯一正 makerId 批量查 `nx_admin`（`adminMapper.selectBatchIds`），过滤 `is_deleted=1`；
3. 显示名 = `nickname`，为空回退 `username`；两者都空则 `null`；
4. **不回退 id，不使用 email**；账号不存在/已删除/无名称 → `null`；
5. 不把 makerId 或 email 放进响应。

这是**当前管理员资料**的显示名，不是请求时的历史名称快照；管理员改名后显示当前名。任务只要求显示名，不要求历史名；找不到时明确 `null`，不伪造。

> 现有 `findBiReportMakers` 保持原样，批准路径继续只用 makerId；新方法只用于任务列表的显示名投影。

## 4. 响应变化

### 4.1 任务行（`records[]`）

新增 `requestedAt`（`BiReportView` 末尾，`LocalDateTime`）：

```json
{
  "reportId": "EXP-...",
  "name": "...",
  "status": "PENDING_CONFIRM",
  "lastActionAt": "2026-11-14T01:23:45",
  "snapshotAvailable": true,
  "requestedAt": "2026-11-13T09:10:11"
}
```

`requestedAt` 对所有任务行返回；旧字段（`reportId/name/type/cycle/format/scope/fields/rowCount/containsPii/maskingPolicy/status/note/lastAction/lastActionAt/reason/snapshotAvailable`）不变。

### 4.2 待放行显示名（`BiReportPage`）

仅在当前账号有 `bi_l5_task_approve` 时填充；key 是待放行 reportId：

```json
{
  "approvalEligibility": {
    "EXP-1": "ELIGIBLE",
    "EXP-2": "SELF",
    "EXP-3": "MAKER_UNVERIFIED"
  },
  "requesterDisplayNames": {
    "EXP-1": "张三",
    "EXP-2": "李四",
    "EXP-3": null
  }
}
```

- 无审批权：`requesterDisplayNames` 为空对象（与 `approvalEligibility` 一样不暴露）。
- maker 唯一、账号存在且有显示名：返回名字。
- maker 缺失/冲突/账号已删除/无 nickname 且无 username：`null`（明确未知）。
- 不返回 makerId、email、手机号或审计原始 payload。
- 不改变 `approvalEligibility` 的三种值和禁止本人批准逻辑；显示名不参与判定。

## 5. 权限与消费者

- 任务接口权限仍为 `bi_l5_read`；`OpsBiController.reports` 不变。
- 显示名只在 `bi_l5_task_approve` 分支填充，和现有 `approvalEligibility` 同一条件；没有新增权限或扩大可见范围。
- 任务列表的 `requesterDisplayNames` 是新增 map，旧 PC `l-client.ts:675-690` 只读 `approvalEligibility`，忽略 extras；页面仍只显示三种资格文案，不会自动显示姓名/时间。
- `requestedAt` 是 `BiReportView` 新增字段；PC `l-client.ts` 的任务映射忽略未知字段，CSV 生成按原字段手工拼装，不受影响；App/H5 不消费该 DTO。
- 导出 CSV、批准、重发、下载、结案、资金、导出审计内容均未改。
- 页面/下发文案冻结；L5 时间/姓名列由前端另开改动读取 `records[].requestedAt` 和 `requesterDisplayNames`。

## 6. 自然业务矩阵（本轮未运行）

| 场景 | 前置 | 预期 |
|---|---|---|
| 待放行、maker 唯一、有显示名 | 有 `bi_l5_task_approve`，成功创建审计 + 管理员资料 | `requestedAt` 为任务创建时间；`approvalEligibility` 按 makerId 判定；`requesterDisplayNames[id]`=nickname/username |
| 本人发起 | makerId == 当前 adminId | `approvalEligibility=SELF` 不变；名字仍按当前资料显示；不能批准 |
| maker 缺失/冲突 | 无成功 create 审计或多 actorId | `MAKER_UNVERIFIED` 不变；名字 `null`；不返回 makerId |
| 账号已删除/无 nickname/username | makerId 有，但 `nx_admin` 无有效昵称/用户名 | `ELIGIBLE/SELF` 仍按 makerId 判定；名字 `null`；无 ID/email 回退 |
| 无审批权 | 有 `bi_l5_read`、无 `bi_l5_task_approve` | `approvalEligibility` 和 `requesterDisplayNames` 都不填充；旧响应不变 |
| 批准/重发 | 原流程 | 只更新状态/动作/理由/updated_at；`requestedAt` 不变；批准行为不变 |
| 下载/CSV | 原流程 | DTO 多字段不改变 CSV 内容/下载行为；App/H5 无消费 |
| 旧 PC | 现有 `l-client.ts` | 忽略 `requestedAt` 和 `requesterDisplayNames`，不报错；页面不自动展示新字段 |

本轮不操作 TEST/DB/账号/角色/浏览器，不造导出申请；以上为静态预期，不是业务通过证据。
