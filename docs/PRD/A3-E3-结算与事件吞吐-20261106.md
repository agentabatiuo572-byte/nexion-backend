# A3 / E3 任务结算与事件吞吐

2026-11-06

## E3 任务与收益

- 后台工作线程按到期时间和设备 ID 取下一条任务。在 MySQL 事务内先锁账号，跳过其他事务持有的账号，再核对设备所有权、运行代次和到期条件。不同账号可以并行，同账号仍按原顺序更新设备和钱包。
- 结算读取数据中心暂停状态时使用共享锁。设备、运行记录和资金更新继续持有原有写锁。暂停操作仍可与正在进行的结算互斥。
- 任务终态、计算回执、按资产生成的收益、钱包入账和对应 Outbox 事件在同一事务提交。事务中断会释放账号锁。失败重试只推迟尚未被其他事务推进的同一到期记录，已退款的设备不会被恢复为待结算。

## A3 事件投递

- `task.completed` 和 `earnings.credited` 各使用 4 条投递通道。每条通道在同一个数据库中最多由一个 JVM 处理，每轮最多 40 条，分别取最多 35 条最新到期记录和 5 条最旧到期记录，各批内按 ID 升序处理。在磁盘写入额度内优先缩短新增事件的等待，历史积压持续处理。
- 每个事件仍使用原有逐事件锁、消费者业务键和失败重试。进程退出后同一数据库的其他 JVM 可以接管。其他事件继续按各自的调度处理。
- 仅供记录的事件仍须满足原有类型名单和 15 分钟宽限期。归档扫描按类型和状态索引取最旧记录，扫满一批后继续处理，少于一批时等 15 秒再扫。C1 审计反查沿用原条件。
- F5 设备收益按事件发生时点读取生效规则。读取可并行，规则发布仍互斥。分佣来源、接收人、钱包与重放去重规则保持原有约束。

## 验收口径

在 PROD 同机隔离数据库、缓存和支付替身上运行 7,200 人混合档，达标后运行 9,500 人档。每档记录登录、前台活跃、WebSocket、查询、订单、提现、任务结算和正式公网探测结果。按任务号和回执号核对账本唯一性及金额，按固定事件 ID 和时间窗比较新增与实际发布，分别记录历史积压、失败和死信。TEST 分支用于代码保留。
