## 2. 最小实现

### 2.1 Controller

`GET` 追加可选参数 `sortDirection`：

- 未传或空白 → 保持原 `DESC`；
- 传入 `ASC`/`DESC`（忽略大小写、先 trim）→ 对应排序；
- 其他非空值 → `422 DEVELOPER_ACCESS_SORT_INVALID`，不静默回落。

### 2.2 Service

`OpsDeveloperAccessService.page` 多一个 `sortDirection` 入参，只在入口归一化一次：

```java
String normalizedSort = text(sortDirection);
if (normalizedSort != null) normalizedSort = normalizedSort.toUpperCase(Locale.ROOT);
if (normalizedSort != null && !Set.of("ASC", "DESC").contains(normalizedSort)) return 422;
boolean ascending = "ASC".equals(normalizedSort);
```

- 内部只传 boolean 给 Mapper；不把用户字符串拼入 SQL。
- `status`/`keyword`/`sourceEnvironment`/分页校验/权限不变；查询失败正常报错。

### 2.3 Mapper

`OpsDeveloperAccessMapper.page` 多一个 `ascending` 参数，只选择两个固定片段：

```sql
<choose>
  <when test="ascending"> ORDER BY created_at ASC,id ASC</when>
  <otherwise> ORDER BY created_at DESC,id DESC</otherwise>
</choose>
```

- 同一时间戳用 id 同向排序，保证分页稳定。
- `count`、`countByStatus`、过滤条件、`LIMIT/OFFSET` 均不变。
- 不新增通用排序/分页框架、字段、表、索引、缓存。

## 3. 行为/兼容

- `sortDirection` 未传：与旧客户端一致，`created_at DESC,id DESC`。
- `sortDirection=asc`/`ASC`：`created_at ASC,id ASC`；`desc`/`DESC` 同上原顺序。
- 只影响 `records` 顺序；`total`、`statusCounts`、`pageNum`、`pageSize`、字段形状不变。
- 非法值 422；空/空白视为未传默认 DESC，不当作非法。
- 无 `developer_access_read` 且非 `ROLE_SUPER_ADMIN` 仍 403；不改权限、软删/环境/状态过滤、App 申请/审批写链、时间解释、userNo/隐私投影。
- PC 当前不传该参数，行为完全不变；未来排序入口只标文档，不改 PC/App/H5/文案。

## 5. 最少公共 TEST 只读计划（未执行）

1. 现有申请不传 `sortDirection`：与旧 `created_at DESC,id DESC` 顺序一致；total/statusCounts/字段不变。
2. `sortDirection=ASC` 与 `asc`：`created_at ASC,id ASC`；第一页最早提交在前，最后一页最晚。
3. `sortDirection=DESC`：与不传顺序一致。
4. 两条同 `created_at`：ASC/DESC 分别按 id 同向，无重复/漏项；翻页边界稳定。
5. 带 `status`/`keyword`/`sourceEnvironment`：只改 records 顺序，total/statusCounts 与不传同一筛选一致。
6. 非法值（如 `SIDEWAYS`）→ 422；空白/未传 → 默认 DESC。
7. 无读权仍 403；App 列表/申请/审批写链和 PC 旧行为不变。
8. 无自然申请样本时记未验，不造申请/审批/授权数据。
