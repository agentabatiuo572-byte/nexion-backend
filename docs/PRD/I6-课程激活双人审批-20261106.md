# I6 课程激活双人审批

2026-11-06 · BUG-286 · 后端

## 生效规则

- A12 首次发布正奖励课程、A19 发布正奖励 DRAFT，以及 A20 回滚到目标版本有奖励（奖励大于 0）的 SUPERSEDED 版本，须由另一位具有 A2 批准权的有效超管批准。正奖励新版按 S30 新增按版本领取的资格，金额比当前版低或相同也须批准。回滚按 T11-7 一律走审批：只要目标历史版本奖励大于 0，等额、降额同样须批准，只查当前覆盖率；理由是按 `用户 + 课程 + 版本` 记领奖，回滚后没领过目标版本的人可以再领，单人金额低不代表总支出低。目标版本奖励为 0 的回滚不产生新的资金义务，仍直接写入。
- 发起人必须是有效管理员，同时具有 `content_i7_write` 与 `content_i7_course_reward_adjust`。提案和本人原键回读复用 A2。工单只授权一次已审阅的课程激活，审批读取和决定沿用 A2 行级授权。
- 待审期间保持当前课程、测验、进度和账本。批准时比对锁下主行的版本、修订、状态和奖励，以及锁下目标的版本、修订、状态、内容、译文、测验和奖励。合法改稿、删稿及下架仍可执行，改变已审阅事实后原单批准返回 409。
- 首次发布检查实际选中的 DRAFT。旧课程没有版本快照时，以锁下的主行及对应三语译文和测验为审批对象，批准后发布该主行和已审核译文。历史回滚保留原正文质量门。
- 提案及批准均核 B1 当前估值可靠性、有效 UVT 价格和未舍入红线。课程拟值的承诺人群、预算和 H3 风险计量待产品定义。等额或较低奖励的历史回滚按 T11-7 与本文件第一条一致：目标版本有奖励即须审批，不再按「高于当前奖励」分类。
- 学习奖励继续按 `user + course + version` 去重。旧完成、旧奖励金额和原账本保持。回滚后首次完成该版本的用户按该版本金额领取。

## 接口约定

原 A12/A19/A20 POST 入口在需要审批时返回业务码 409 和 `LEARNING_COURSE_ACTIVATION_APPROVAL_REQUIRED`。原幂等命令范围保留。需要审批时向 `POST /api/admin/platform/audit/operations` 提交 `Idempotency-Key` 和原理由，长度为去空格后 8–200 字符。

| 用途 | `command.domain` | `command.op` |
| --- | --- | --- |
| A12 首发 | `I` | `i7_course_first_publish` |
| A19 版本发布 | `I` | `i7_course_version_publish` |
| A20 回滚到有奖励的课程版本 | `I` | `i7_course_version_rollback` |

`sourceDomain` 固定为 `I`，`obj` 为课程 ID，`target` 为 `{"domain":"I","type":"learning_course_activation","id":"<courseId>"}`。沿用 A2 的 `action`、`type` 等提交字段。返回的动作、状态对比、方向、批准角色和审阅对象由服务端计算。

`command.params` 使用 `courseId`、`version`（拟激活版本）、`expectedRevision`（目标行修订）、`expectedCurrentVersion`、`expectedCurrentRevision`、`expectedCurrentStatus`。两处修订用 JSON 非负整数。A12 无版本行时，`version` 为主行版本，`expectedRevision` 为 JSON `null`。返回的 `beforeValue` 和 `afterValue` 是服务器生成的 JSON 文本，奖励数额为十进制字符串，拟激活版本的 `sourceStatus` 区分 DRAFT、SUPERSEDED 和 LEGACY_DRAFT。

通过原 A2 批准、驳回和撤回接口处理工单。因 B1 失败的批准保留原待审单，条件恢复后可用原批准键和原请求重试。发起人通过 `GET /api/admin/platform/audit/operations/proposals/by-idempotency-key?idempotencyKey=<key>` 回读本人的工单。

I7 同版本奖励调整使用独立的 A14 命令与课程对象锁。PC 页面接入和公共 TEST 验收单列。

目标环境应具备现有 A4 `learn.course_completed` 注册、钱包可见账本视图和 A2 命令 MEDIUMTEXT。以目标库读回确认现有迁移生效。

## A14 线上课程调奖

沿用 `POST /api/admin/platform/audit/operations` 和 `I/i7_course_reward_adjust`。客户端命令参数为 `courseId`、`rewardNex`，`obj` 使用同一课程 ID，`sourceDomain` 使用 `I7` 或 `I`，对象锁为 `I / learning_course / {courseId}`。发起人持有 A2 提案权和 `content_i7_course_reward_adjust`。发起人通过 A2 原键入口查本人工单。

服务端在提案时绑定线上课程版本、修订、原奖励和发起账号 ID，并生成资金分类、方向和前后值。另一位同时具备 A2 批准权及 I7 调奖权的有效超管批准。账号改名后仍按同一账号判断自批。批准时锁定当前课程并比对审阅事实，变更返回 `409 LEARNING_COURSE_REWARD_SNAPSHOT_CHANGED`。旧待审批单缺少服务端绑定时返回 `409 LEARNING_COURSE_REWARD_REPROPOSE_REQUIRED`，可按 A2 驳回或撤回后重提。

有效批准按原调奖服务复核资金覆盖红线，更新已审阅的当前线上版本奖励，审计带版本、审阅修订和 A2 工单编号。原课程版本快照、历史领奖与账本按实际发生时的金额保留。
