# App 和 H5 并发登录保护

密码登录先检查请求来源的一分钟尝试额度，再检查当前环境、区号和手机号对应的账号保护记录。同一出口的不同账号共用来源额度，同一账号从不同出口登录共用账号的错密计数。新的保护记录从零开始。遇到已有记录时，请求在同一主键上依次取得写锁，再读取当前计数、窗口起点和锁定期限。入口按此顺序处理每次尝试，保留已记录的失败和仍有效的锁定。

* 密码错误返回 HTTP 401 和 `USER_CREDENTIAL_INVALID`。累计达到配置阈值后，后续尝试在锁定到期前返回 HTTP 429 和 `USER_LOGIN_TEMPORARILY_LOCKED`，正确密码同样受此限制。来源额度用尽后，后续尝试返回 HTTP 429 和 `USER_LOGIN_RATE_LIMITED`。
* 符合登录条件的请求按原规则完成认证，并清除该账号的错密计数。H5 通过 HttpOnly Cookie 接收刷新凭据，原生 App 从响应体接收。恢复已完成的登录时，服务端核对原尝试的恢复凭据与客户端上下文，再返回原会话的状态。
