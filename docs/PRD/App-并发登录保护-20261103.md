# App 和 H5 并发登录保护

密码登录先检查请求来源的一分钟尝试额度，再检查当前环境、区号和手机号对应的账号保护记录。同一出口的不同账号共用来源额度，同一账号从不同出口登录共用账号的错密计数。新的保护记录从零开始。遇到已有记录时，请求在同一主键上依次取得写锁，再读取当前计数、窗口起点和锁定期限。入口按此顺序处理每次尝试，保留已记录的失败和仍有效的锁定。

* 密码错误返回 HTTP 401 和 `USER_CREDENTIAL_INVALID`。累计达到配置阈值后，后续尝试在锁定到期前返回 HTTP 429 和 `USER_LOGIN_TEMPORARILY_LOCKED`，正确密码同样受此限制。来源额度用尽后，后续尝试返回 HTTP 429 和 `USER_LOGIN_RATE_LIMITED`。
* 符合登录条件的请求按原规则完成认证，并清除该账号的错密计数。H5 通过 HttpOnly Cookie 接收刷新凭据，原生 App 从响应体接收。恢复已完成的登录时，服务端核对原尝试的恢复凭据与客户端上下文，再返回原会话的状态。

## 2026-11-17 C6-BE-05：短锁升级长锁事件

验证码或密码失败在已有未到期短锁内把失败计数跨过长锁阈值时，本次失败完成原计数写入后，按实际新锁定状态补发一次既有 `auth.login_locked` outbox 事件。事件复用原 `USER_SECURITY` 聚合、`targetUserId/loginKeyHash/lockType/ruleId/failedCount/lockedUntil/occurredAt` 字段和原事务，仅 `lockType=LONG`；正常首次上锁仍按原条件发 SHORT 或 LONG。已在长锁内的后续失败或仅续期不重复发事件；同一轮条件命中只发一条。

不改短/长阈值、窗口、锁定时长、锁定期间失败是否累计、锁定入口、密码重置/解锁/配置、查询权限或页面文案；缺 userId 时仍不发布，不造匿名 ID。原长锁统计 consumer 从该事件计数得到补齐；旧历史事件不回填。未执行 HTTP/DB/E2E，root 合批覆盖构建。

## 2026-11-17 C6-BE-03：登录锁截止时间

密码登录的 `UserLoginResponse` 和验证码入口的 `UserOtpLoginChallengeResponse` 各增加可空 `lockedUntil` 字符串，保留全部既有构造/字段；正常成功、验证码挑战、刷新和 ended 响应该字段为 null。仅当密码登录或 `beginOtpLogin` 读取到当前已识别用户、且原持久 `nx_user_login_guard.locked_until` 仍晚于当前时间时，使用既有 `ApiResult.fail(429, message, data)` 返回各自响应类型中的真实 `lockedUntil`；凭据、身份及验证码编号均为 null，验证码失败载体的原整型 `resendAfterSec` 为结构缺省值 0，不表示已发验证码或锁定时长。未知用户、无锁或无来源仍返回原 null-data 429，不额外查用户、不改认证顺序、不新增匿名枚举接口。

值直接取 `UserLoginGuardRecord.lockedUntil` 的持久值（既有 `LocalDateTime.toString()` 形式），不由固定时长或当前时间重算。reset/2FA/provider 等 guard 早于 user 的入口本轮保持原响应；阈值、失败累计、OTP/IP、强制重置密码、事件、权限、页面/文案均未改。未执行 HTTP/DB/E2E，整 C6-BE-03 不预关。
