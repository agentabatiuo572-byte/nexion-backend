# App 和 H5 并发登录保护

密码登录先检查请求来源的一分钟尝试额度，再检查当前环境、区号和手机号对应的账号保护记录。同一出口的不同账号共用来源额度，同一账号从不同出口登录共用账号的错密计数。新的保护记录从零开始。遇到已有记录时，请求在同一主键上依次取得写锁，再读取当前计数、窗口起点和锁定期限。入口按此顺序处理每次尝试，保留已记录的失败和仍有效的锁定。

* 密码错误返回 HTTP 401 和 `USER_CREDENTIAL_INVALID`。累计达到配置阈值后，后续尝试在锁定到期前返回 HTTP 429 和 `USER_LOGIN_TEMPORARILY_LOCKED`，正确密码同样受此限制。来源额度用尽后，后续尝试返回 HTTP 429 和 `USER_LOGIN_RATE_LIMITED`。
* 符合登录条件的请求按原规则完成认证，并清除该账号的错密计数。H5 通过 HttpOnly Cookie 接收刷新凭据，原生 App 从响应体接收。恢复已完成的登录时，服务端核对原尝试的恢复凭据与客户端上下文，再返回原会话的状态。

## 2026-11-17 C6-BE-05：短锁升级长锁事件

验证码或密码失败在已有未到期短锁内把失败计数跨过长锁阈值时，本次失败完成原计数写入后，按实际新锁定状态补发一次既有 `auth.login_locked` outbox 事件。事件复用原 `USER_SECURITY` 聚合、`targetUserId/loginKeyHash/lockType/ruleId/failedCount/lockedUntil/occurredAt` 字段和原事务，仅 `lockType=LONG`；正常首次上锁仍按原条件发 SHORT 或 LONG。已在长锁内的后续失败或仅续期不重复发事件；同一轮条件命中只发一条。

不改短/长阈值、窗口、锁定时长、锁定期间失败是否累计、锁定入口、密码重置/解锁/配置、查询权限或页面文案；缺 userId 时仍不发布，不造匿名 ID。原长锁统计 consumer 从该事件计数得到补齐；旧历史事件不回填。未执行 HTTP/DB/E2E，root 合批覆盖构建。

## 2026-11-17 C6-BE-03：登录锁截止时间

密码登录的 `UserLoginResponse` 和验证码入口的 `UserOtpLoginChallengeResponse` 各增加可空 `lockedUntil` 字符串，保留全部既有构造/字段；正常成功、验证码挑战、刷新和 ended 响应该字段为 null。当密码登录或 `beginOtpLogin` 的原持久 `nx_user_login_guard.locked_until` 仍晚于当前时间时，使用既有 `ApiResult.fail(429, message, data)` 返回各自响应类型中的真实 `lockedUntil`，不再根据手机号是否对应用户决定 data 是否为空；凭据、身份及验证码编号均为 null，验证码失败载体的原整型 `resendAfterSec` 为结构缺省值 0，不表示已发验证码或锁定时长。未命中原锁定条件的路径保持原响应和认证顺序，不额外查用户、不新增匿名枚举接口。

值直接取 `UserLoginGuardRecord.lockedUntil` 的持久值（既有 `LocalDateTime.toString()` 形式），不由固定时长或当前时间重算。reset/2FA/provider 等 guard 早于 user 的入口本轮保持原响应；阈值、失败累计、OTP/IP、强制重置密码、事件、权限、页面/文案均未改。未执行 HTTP/DB/E2E，整 C6-BE-03 不预关。

## 2026-11-18 C6-BE-06：锁定回包不区分注册状态

密码与验证码入口对所有已锁定的登录保护记录返回同样结构的截止字段，包括尚无用户实体的手机号。截止时间只来自原保护记录，不从用户存在性推导，不补造用户或锁时间；429 及原业务码、其余安全空字段保持一致。保留用户绑定、失败计数、阈值、限速、成功认证和其它入口逻辑；本次仅消除新截止字段按 `user == null` 分支造成的注册状态差异，未执行探号 HTTP、数据库、启动或 E2E。

## 2026-11-22 B64-BE-01：两步验证挑战重发

- 登录用户在安全设置调用 `POST /api/app/security/two-factor/challenge`，校验当前密码后发码。成功响应保留 `challengeNo`、`phoneMasked` 和 600 秒有效期 `expiresInSeconds`，增加 `resendAfterSeconds`。重发间隔复用 K2/C6 的短信配置 `auth.risk.otp_send_cooldown_seconds`，缺省 60 秒，允许 30–300 秒。
- 同一账号的启用与关闭挑战共用最近一次成功发码的重发间隔。间隔内返回 HTTP 429、`USER_OTP_SEND_RATE_LIMITED` 及剩余整数秒的 `Retry-After`。已允许的跨域来源可以读取该响应头。
- 间隔结束后成功发新码时，原挑战随新挑战一起提交并作废。短信发送失败时回滚本次挑战写入，原有效挑战仍可使用。


## 2026-11-23 B71-BE-02：登录会话设备展示名

密码登录 `POST /auth/users/login`、验证码登录完成 `POST /auth/users/login/otp/verify`、两步验证完成 `POST /auth/users/login/2fa`、注册完成 `POST /auth/users/register`、OAuth provider 完成 `POST /auth/users/oauth/provider/complete`、OAuth exchange `POST /auth/users/oauth/exchange` 的 JSON 请求体顶层增加可空字符串 `deviceName`（大小写敏感，位置为请求体字段，不是请求头）。客户端传 App 的“品牌 型号 · 系统”或 H5 的“浏览器 · 系统”时，服务端在同一签发边界写入 `nx_user_session.device_name`；字段缺省、空白或清洗后为空时沿用原会话组名（App/H5），旧客户端无需改动。OAuth exchange 保留原请求字段和既有构造重载，新增字段仍为可选。

`deviceName` 只用于会话展示：去除 Unicode 控制字符，去除首尾空白，超过 `VARCHAR(128)` 容量时截断到 128 个 Unicode 码点；不参与安装 ID、会话组、登录尝试指纹、认证、刷新令牌或权限计算。登录尝试恢复仍按原上下文指纹核对，刷新沿用已保存的展示名。字段为可选，非法展示名不会改变登录成功/失败、锁定、限速、验证码或注册规则；认证请求体保留既有字段和旧构造重载。
