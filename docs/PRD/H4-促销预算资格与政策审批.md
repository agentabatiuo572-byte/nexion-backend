# H4 促销预算资格与政策审批

## 预算资格（BUG-268）

`RULE_STOP` 按购买规则判断新预留的可用性。App/H5 活动列表、首页推广位及详情读取当前预算净额、活动可用名额及赠品库存。全部规则停止新增预留时，首页停止投放，活动列表仅保留供团队页读取既有进度的直邀活动。已知链接仍可读取详情和原条款。保留的活动记录继续使用原生命周期，返回 `INELIGIBLE` 和可用性原因。已有订单可继续按原预留处理。

部分规则仍可用时，继续展示该活动及可用奖励。`ANY` 返回仍可领取奖励的商品，`ALL` 保留完整组合所需的商品。规则资格预估使用最小合格数量，已登录且符合活动人群的用户按实际受益人及使用记录计算。实际订单按所选商品、数量、受益人和实时资源重新计算。资源释放后，后续读取恢复可用资格和推广投放。

显式选中活动但没有任何可发放奖励时，`POST /api/orders/quote` 返回 `PROMOTION_NOT_ELIGIBLE_OR_UNAVAILABLE`。未指定活动时，满足购买条件的普通报价仍可继续，`expectedRewards` 为空。报价不占用额度。

## 政策批准（BUG-272）

每个政策版本必须由与创建人不同且持有 `growth_promotion_policy_approve` 权限的管理员批准。以当前登录管理员和成功创建该版本的服务端审计为准，创建审计移入冷档后继续适用。创建人本人批准返回 `PROMOTION_MAKER_CHECKER_REQUIRED`，创建人无法可靠核实时保留草稿，返回 `PROMOTION_POLICY_MAKER_UNAVAILABLE`。

批准沿用版本校验、审批人的审计证据或已批准的 H 域 A2 凭证，以及按管理员、操作、政策版本划分的幂等范围。成功重放读取原回执，审批审计与状态变更只写入一次。
