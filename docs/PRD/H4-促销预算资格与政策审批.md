# H4 促销预算资格与政策审批

## 预算资格（BUG-268）

`RULE_STOP` 按购买规则判断新预留的可用性。App/H5 活动列表、首页推广位及详情读取当前预算净额、活动可用名额及赠品库存。全部规则停止新增预留时，首页停止投放，活动列表仅保留供团队页读取既有进度的直邀活动。已知链接仍可读取详情和原条款。保留的活动记录继续使用原生命周期，返回 `INELIGIBLE` 和可用性原因。已有订单可继续按原预留处理。

部分规则仍可用时，继续展示该活动及可用奖励。`ANY` 返回仍可领取奖励的商品，`ALL` 保留完整组合所需的商品。规则资格预估使用最小合格数量，已登录且符合活动人群的用户按实际受益人及使用记录计算。实际订单按所选商品、数量、受益人和实时资源重新计算。资源释放后，后续读取恢复可用资格和推广投放。

显式选中活动但没有任何可发放奖励时，`POST /api/orders/quote` 返回 `PROMOTION_NOT_ELIGIBLE_OR_UNAVAILABLE`。未指定活动时，满足购买条件的普通报价仍可继续，`expectedRewards` 为空。报价不占用额度。

## 政策批准（BUG-272）

每个政策版本必须由与创建人不同且持有 `growth_promotion_policy_approve` 权限的管理员批准。以当前登录管理员和成功创建该版本的服务端审计为准，创建审计移入冷档后继续适用。创建人本人批准返回 `PROMOTION_MAKER_CHECKER_REQUIRED`，创建人无法可靠核实时保留草稿，返回 `PROMOTION_POLICY_MAKER_UNAVAILABLE`。

批准沿用版本校验、审批人的审计证据或已批准的 H 域 A2 凭证，以及按管理员、操作、政策版本划分的幂等范围。成功重放读取原回执，审批审计与状态变更只写入一次。

## 2026-11-16 补充：促销命令原键只读恢复

`GET /api/admin/growth/promotion-commands/{idempotencyKey}?operation=&targetId=` 的恢复读取不再要求该 operation 的写权限：当前已认证管理员持有 `growth_promotion_read`、且 operation 属于合法命令即可。记录仍按 `PROMOTION_ADMIN:{actor}:{operation}:{sha256(target)}` 限定为本人原记录，原成功／失败／处理中／结果未知／不存在的回执形状不变；非原操作者、换 operation 或 target 仍返回原 `NOT_FOUND`。读取不重跑命令、不写审计、不续期、不结案，也不授予任何写权。

## H4-BE-14/15：复制与保存的预期版本（2026-11-16）

复制活动的请求同时携带活动 `expectedRevision`、所见源 `expectedSourceVersion` 和 `expectedSourceRevision`。后端比较真实源版本及其内容修订号，避免源草稿在版本号不变时已被他人保存。保存草稿除原 `expectedRevision` 外还比较 `expectedVersion`，避免删除重建后的同修订号草稿接收旧请求。缺失或不一致均沿用 `PROMOTION_CONCURRENT_CHANGE`，成功原键仍先恢复。

新增字段只在对应复制或保存入口要求，不影响共用动作的其它操作。只更新后端请求合同，未修改 PC、下发文案或运行数据；按本轮代码口径验收，未 E2E。

## 2026-11-16 补充：政策读取按真实批准人给出可空姓名与账号

政策版本的读取此前只回 `approvedBy`（`nx_promotion_policy.approved_by` 的原样编号），管理端无法显示批准人是谁。现在管理端两个只读投影（`GET /promotion-policies` 列表与 `GET /promotion-policies/{policyId}/versions/{version}` 详情，权限仍是 `growth_promotion_policy_read`）在原有字段之外追加可空结构 `approvedByAdmin`：

- `approvedByAdmin` 由 `approvedBy` 的真实编号查询**当前未删除**的 `nx_admin` 得到，形如 `{ id, displayName, username }`；`displayName` 沿用仓库既有规则（优先 `nickname`，为空回退 `username`）。
- `approvedBy` 保持原样（含空值与历史编号），不改数值、不改字段含义；`approvedByAdmin` 在该编号对不上当前管理员、或从未有批准人时为 `null`，不用操作者、最近修改人或其它人冒充历史批准人，也不补历史快照。
- 共用解析器 `PromotionPolicyResolver.view` 与 App/H5 侧输出**不新增**任何管理员姓名或账号；本次只改管理端服务层投影，公开读取、可见范围与权限不变。
- 姓名查询失败按「无真实来源」处理为 `null`，不影响政策读取本身；不新增表、缓存、配置或页面文案。
