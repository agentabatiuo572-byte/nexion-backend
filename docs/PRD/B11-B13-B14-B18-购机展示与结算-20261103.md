# 复购活动、试用转购和购买回执

产品依据为 2026-10-28 交接的 20 号文档 B11、B13、B14、B18，以及正式 App P-58、P-59 和后台 H2 的协议。

## 复购活动

公开活动列表和详情均返回已发布版本的人群间隔 `repurchaseWindow.minDays/maxDays`。任一端点可为空。登录用户的 `lastValidPurchaseAt` 使用与资格预估相同的最近有效购机时间，格式为 UTC RFC 3339。匿名、没有有效订单或其他模板均不披露用户时间。取消和已退款订单排除在外。其他模板的 `repurchaseWindow` 为 null。

## H2 领取和转购

`trialOffsetCapUSD` 缺省或清空表示不设上限。H2 可设置 0 至 1,000,000，0 表示不使用收益抵扣。领取时将上限写入 `nx_trial_claim.offset_cap_usdt`，新单的 SQL NULL 表示不设上限，历史数值随原单保留。H2 读写使用空字符串表示留空，App 配置和报价使用 JSON null。更新时可回传读到的 `expectedValue`，发生冲突返回 409。

### 购买折扣率（BUG-331）

H2 配置读写和存储统一使用 0 至 100 的百分点，默认 15。新保存的 0 表示没有购买折扣，0.15 表示 0.15%，1 表示 1%。转购报价和结算均按购买时的最新配置计算，购买折扣为售价乘以折扣率除以 100，并应用单独的 `discountCapUSD` 上限。App 配置的 `discountRate` 按现有客户端契约返回 0 至 1 的比例，报价金额仍由服务端提供。

切换时将大于 0 且小于等于 1 的旧值乘以 100，保留当时的实际折扣。例如旧 0.15 迁为 15，旧 1 迁为 100。存量配置无法单独证明原操作者想设的折扣，业务确认后可用新的操作键另行修改。迁移与完成标记在同一事务内提交，旧值格式需要复核时中止切换。迁移前停止旧后端，完成后启动匹配版本。迁移仅调整 H2 当前配置和迁移标记，历史报价、已结算金额、试用快照、审计与原幂等回执保留。

在原试用期内且早购优惠启用时，USDT 和 UVT 总权益按原期限结算。抵扣金取当前已产出的 USDT，并受领取时的上限和扣除通用试用折扣后剩余商品金额约束。固定早购立减最多抵到剩余应付金额。满期 USDT 减去实际抵扣的部分及全部 UVT 在同一笔转购成功后入钱包，按原奖励来源记账。宽限期使用实际满期收益。取消、超窗或付款失败不发奖励。

钱包转购重算服务器当前产出。仅随时间增长的抵扣不要求重新确认。规则切换或新金额高于确认的金额时重取报价。已签发的外部付款单按签发时间和当时规则核价，旧版在途付款单继续履行原报价。成功订单、实际抵扣和购后入账各有独立快照。退款按商品实付退回，奖励追索继续定位本单入账记录并仅追回可证明未花用的金额。

### B91 商城上架、试用交付与原购买恢复

- **B91-BE-01** H2 的候选与保存、用户的转购清单、余额转购和外部付款均复用商城发布门。带测试标识或两种日收益均无有效值的商品会被拦截。已选的其他商品保留在 H2 并标出原因，可移除，恢复上架后自动回到用户清单。试用原商品仍排首位，被拦截时显示原因并禁止购买。在售且可发布的售罄商品仍可加入清单，用户端显示为不可买。
- **B91-BE-02** 规格和库存满足商城购买条件的实体设备，只配置一种有效日收益也可转购。成交设备取所购商品的收益配置，试用抵扣与奖励取领取单快照。领取试用仍要求原试用商品的两种日收益均有效。
- **B91-BE-03** 精确零实付的 Cloud Share 转购仍需验密。成交并交付后按购买份额的规则领取任务收益和每日 UVT。同一份额每天最多发一次。零实付订单无扣款流水或邀请购机奖励。TEST 固定执行器继续检查绑定、订单和份额归属。
- **B91-BE-04** 新余额提交若遇到同一领取单的在途购买，先按本人和领取单返回原购买身份。外部付款返回 `TRIAL_EXTERNAL_PAYMENT_IN_PROGRESS` 和原付款单号，余额提交返回 `TRIAL_BALANCE_SUBMISSION_IN_PROGRESS` 和原提交号。找回请求不消耗密码尝试次数。原键可读取已完成回执，继续未终结的原余额提交时仍须有效验密。此前允许重选的外部复核分支沿用原判定。
- **B91-BE-05** H2 其他可购商品保存与余额转购接受 1 至 64 字符的商品编号，允许英文字母、数字、点、下划线和连字符。保存仍校验重复商品、商品状态、发布条件和清单版本。

## 订单实付

App 订单列表和详情共用 `GET /api/orders` 的订单投影。普通、组合及活动订单的 `paidTotalUsdt` 为两位小数字符串。钱包实付等于商品订单金额，银行卡、BEP20、ERC20 使用本订单已交付付款单的 `quote_json.totalUsdt`，包含通道费和网络确认费。未付款为 null，缺乏支付凭据的历史记录保留 null。外部交付回执和旧回执重读返回同一金额。退款后仍可查询原实付，退款金额继续由原字段说明。商品金额 `amountUsdt` 和付款小计字段维持原语义。

## 邀请活动的首购条件（B69-BE-01，2026-11-23）

`GET /api/promotions` 与 `GET /api/promotions/{activityId}` 继续共用同一已发布版本的公开投影。模板为 `DIRECT_REFERRAL` 且发布规则里至少一条配置了 `inviterReward` 时，响应新增可选对象 `firstPurchaseCondition`，只含同一 `resolved_policies_json` 快照中 `firstPurchase` 策略已发布的 `mode`（`FIRST_ELIGIBLE_ORDER`／`FIRST_ELIGIBLE_UNIT`）与 `restoreAfterRefund`，与每条规则现有的 `minBuyQty`、`repeatMode`、`maxGroups`、`maxGroupsPerPerson` 一起说明邀请人奖励的成立条件。该对象不含 policyId、contentHash、executorCode 或其他内部快照字段。

其他模板、没有 `inviterReward` 的活动、以及没有首购策略的历史发布版本，`firstPurchaseCondition` 为 `null`，`rewardRules`、奖励类型与金额、资格预估、库存与结算规则均保持原语义；旧客户端可忽略该新增可选字段。匿名与登录用户读取同一条件。
