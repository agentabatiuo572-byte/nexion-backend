# B142 充值与提现上线默认值

依据运营和用户 2026-11-27 确认的 B142 规则，金额均以 USDT 计。

| 配置 | 上线默认值 | 读取入口 |
| --- | --- | --- |
| D1 链上充值 | 最低 5，手续费 0，各链沿用现有确认数 | `GET /api/deposits/policy`、`GET /api/deposits/address?network=…` |
| D1 订单支付 | HDPAY_BANK 最低 5，BEP20、ERC20、TRC20 跟随链上充值最低额 | `GET /api/app/purchase-payment-policy` |
| D5 链上提现 | 最低 3，ERC20、TRC20、BEP20 的网络确认费均为 1 | `GET /api/withdrawals/policy`、`GET /api/admin/withdraw/limits` |
| D7 越南盾提现 | 单笔最低 3、最高 100000，管理端返回同样的推荐默认值 | `GET /api/withdrawals/bank/config`、`GET /api/admin/finance/payout-vnd/config` |

## 安装与升级

前向迁移登记在 PowerShell 启动清单中，Bash 全新安装也使用同一清单。迁移只替换可确认的旧默认字段。D1 向充值策略增加一个版本，已识别的交易继续使用原版本快照。银行卡最低额由订单支付和 VietQR 充值共同读取。银行卡最低额变化时递增一次订单支付策略版本，未提交的旧报价按既有规则重新报价。链上订单最低额直接读取 D1 充值策略。

D5 的最低额和 `wallet.withdrawal.min_usdt` 镜像同事务更新，旧配置缺少镜像时同时补齐。ERC20 确认费按现有配置键更新。任一目标值变化时，D5 版本只增加一次。D7 按字段替换旧最低和最高额，保留同一 JSON 中的其他字段。如果已配置的最低手续费达到 3，原最低提现额保留，以满足手续费必须小于最低提现额的校验。D7 金额实际变化时，版本增加一次。

D1 充值、D5 提现和 D7 提现分别检查 A2 的当前对象锁。迁移遇到待审批对象时跳过该对象，并完成一次性登记，待审批版本保持有效。之后可按既有业务入口和审批规则处理该对象。重启重跑启动清单保留此后运营设置的值，包括运营重新选用旧数值的情况。

## 发布验收

隔离库先跑全新安装，再验证旧出厂值、运营自定义字段、A2 对象锁和重跑。通过上表入口回读配置，并核对策略版本、D5 账面镜像及 D1 历史快照。共享环境按现有发布和数据变更权限通过受管迁移执行。发布后核对实际运行版本以及对应配置回读结果。

## D5 小额免审与 D2 提交日期筛选（2026-11-27）

- **D5** 首装默认将小额免审线设为 0 USDT。正额提现沿用风控及人工审核。前向迁移只更新规范键和钱包镜像均为出厂值 50 且没有在审对象锁的配置。改动时管理版本推进一次，并同步已有的报价版本。运营已改的阈值与镜像保留，重复执行保持稳定。
- **D2** `GET /api/admin/finance/withdrawals` 支持可单独填写的 `createdFrom` 和 `createdTo`，格式为 `YYYY-MM-DD`。下限含起始日，截止日覆盖当日全部时间，按越南业务日换算为数据库存储时区。非法日期或反向区间返回 HTTP 400 和 `WITHDRAWAL_DATE_RANGE_INVALID`。列表和分页总数使用同一组日期及风险关键词条件，权限、对象过滤和其他筛选规则沿用现有合同。
- **验收** 隔离真实接口验证越南日边界、单边、反向和非法日期、风险关键词分页总数及权限。D5 验证首装、旧值、运营自定义、审批锁和完整启动链重跑。B142 所改最低额度或费用会参与 USDT 策略摘要，有旧报价数字版本的库在规则变化后仍会拒绝旧策略。
