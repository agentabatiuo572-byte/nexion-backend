# B150 银行卡充值下单结果待核对

提交银行卡充值生成付款单后，客户端用原意图号或原幂等键查询进展。列表和详情沿用已有的 `providerStatus` 字段。

| 通道结果 | 提交和按原键读取 | 充值单列表和详情 |
| --- | --- | --- |
| 下单明确拒绝 | HTTP 422 `HDPAY_ORDER_CREATE_REJECTED`。存在已核实且可公开的通道原因时返回 `providerReason`。 | `rejected`，无付款链接。 |
| HTTP 错误、超时或结果未确认 | HTTP 503 `HDPAY_ORDER_SUBMISSION_UNKNOWN`。原单由同键请求和后台查单继续核对。 | `submit_unknown`，无付款链接。D1 仍显示待核对。 |
| 查回同一笔可支付订单 | 原单号、商户、通道、金额核对一致，原充值意图处于可付款状态且链接通过信任校验时，返回原单。 | `created`，附付款链接。 |
| 查实原单失败 | 原键返回不可付款。 | `rejected`，无付款链接。 |
| 查回已支付或存在退款的记录 | 已支付沿现有入账校验处理。渠道退款保留原人工核对流程。 | 到账结果以已入账回执为准。 |

已保存为拒绝的历史未确认下单沿用待核对语义，仍按原意图查单。下单前已过期的记录保留不可付款的状态。原键续查只调用查单接口，充值单归属、支付期限和钱包入账核对沿用现有规则。

## B151 按原创建键确认托管充值

下单结果未知时，App 可调用 `GET /api/app/deposits/vietqr/intents`，按提交时的 `Idempotency-Key` 匹配本人托管充值列表项的 `createIdempotencyKey`。该字段直接返回原创建键，在待核对、已生成、已到账和已拒绝时保持一致。同一账号的两笔同额订单各自返回自己的原创建键。列表仅限登录账号本人的有效记录，历史手工充值列表项以及创建、详情和回执接口不添加该字段。

### 已结束的原单回放

原键重试时，已生成的原单若已过期、取消、退回，或按原单号与冻结金额核对后查实渠道已退款或失败，返回 HTTP 409 `HDPAY_ORDER_NOT_PAYABLE`。列表和详情继续提供原单的状态。已到账原单仍可按原键读回到账回执。提交结果未确认时继续使用 HTTP 503 `HDPAY_ORDER_SUBMISSION_UNKNOWN`。

## 验收

在隔离后端用本机模拟通道执行明确拒绝和 HTTP 错误，比较创建响应、详情、列表与数据库。由查单恢复同一笔的付款链接，并核对通道创建次数和钱包流水。旧版生成的未确认记录升级后继续可查。用共享 TEST 的实际运行版本和归档确认部署。

用不同键提交两笔同额托管充值，核对本人列表在待核对、已生成、已到账和已拒绝时返回原创建键。用另一账号和匿名请求核对读取权限，并确认手工充值列表项无此字段。

生成可付款单并等到期，先按原键重试，再用详情读回过期状态并重试。两次均返回 409，通道只收到原来一次创建。核对已核实退回、仍可付款和已到账的原单回放。
