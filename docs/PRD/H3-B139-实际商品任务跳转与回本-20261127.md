# H3 B139 实际商品跳转与首日回本

本轮交付后端。本次沿用现有商品编号和数据库。App、H5 Lite 和 PC 页面待单独接入。

- H3 原任务读取在 `growth_h3_read` 下返回 `productActionTargets`。候选包含 `productNo`、`name`、`actionRoute`、`openable`、`seriesCode` 和 `roiEligible`。正式商城发布状态已开放才可作新跳转。售罄及规格提示均可打开，规格提示没有预计收益卡，不能作首日回本目标。首日回本需要当前系列为 S1 且目录预计日收益（有月目标时按月目标除以 30）为正的普通设备详情。新建和更换任务跳转复用同一规则，原样携带旧路由可继续改任务类别。
- 通过 A2 送审的新建任务冻结提交时的商品名称和实际路由。A2 审批读回提供 `missionTarget`，旧单可读取原路由。批准仍按实时商品可打开性重新核实。任务请求、发起和审批权限沿用原合同。
- `POST /api/growth/day-one/page-observations/s1-roi` 接受 `{ "productNo": "实际商品编号" }`。未开放、非 S1、规格不全或无正 USDT 预计收益的目标返回已接收但不记进度。在 App 和 H5 Lite 客户端接入前，不带请求体的旧调用只按原固定 `stellarbox-s1` 且通过同一目录校验处理。新版须传实际编号。收益页和商城首页的观测继续接受无请求体。
- 合格观测在未结束的首日实例窗口内对已冻结的回本任务只记一次。只冻结过错误绑定的历史实例也可经合格观测完成，原成员、路由、进度和截止时间保留。普通业务事件不能推进此任务。目标打不开只影响该任务，注册和其他任务照常。已完成回本的用户仍可按现有窗口和整组规则领取。
- 前端待接入范围为 PC H3 新建／编辑动态候选、A2 审批摘要，以及 App 和 H5 Lite 的实际商品路由、目标不可用状态和预计收益卡观测。接入完成后再验三端实际页面和移除旧包无请求体的兼容路径。
