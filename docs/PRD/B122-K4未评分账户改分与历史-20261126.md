# B122 K4 未评分账户改分与历史

`POST /api/admin/risk/scoring/users/{userNo}/override` 需要现有改分权限和原有幂等键、理由及评分版本。尚无系统评分时，业务码为 409，`message` 为 `K4_SCORE_NOT_YET_SCORED`，`data.reason` 说明评分后才能改分。拒绝会沿用现有审计，保留账户版本及既有改分、评分历史和事件。已有系统评分的账户可以改分，系统分为真实 0 的账户也可改分。

## 改分记录

`GET /api/admin/risk/scoring/overview` 的改分分页记录增加 `systemScoreState` 和 `systemScoreBefore`，表示人工改分之前的系统评分状态与分数。

| `systemScoreState` | `systemScoreBefore` |
| --- | --- |
| `SCORED` | 已知的系统分，包括真实 0 |
| `UNSCORED` | `null`，有证据证明改分发生时仍待首次评分 |
| `UNKNOWN` | `null`，旧记录缺少当时的评分状态，历史占位 0 无法确认 |

新写入记录保存当时已评分的事实。旧非零系统分可确认已评分。旧零分只有在其对应的原评分行仍待首次评分、且该行创建时间早于改分时间时才记为未评分。其余未经证明的旧零分标记未知。之后重算、定期刷新或处理风险信号时会保留已确认的未评分状态。原 `modelScore` 字段用于兼容现有客户端，接入新状态的页面从 `systemScoreBefore` 取数。

## 恢复系统评分

历史遗留的未评分且有人工改分的账户按现有权限调用 `POST /api/admin/risk/scoring/users/{userNo}/recompute`。按当前模型产生系统评分，使原人工改分失效，并保留评分历史和操作审计。用相同幂等键重试读取既有回执。批量恢复的账户数限制仍为 1000。
