# H5 连签权益与收益里程碑资金放大审批

BUG-286 本轮仅交付 H5-A03/A04 的后端能力。基线 `a9964388`；保留 B17 已确认的实时签到加成规则、停用的原质押入口和已领取记录。H5-A02 跨权益类型、初始复活卡、tick 权限及 PC 页面不在本次范围。

## 资金方向和直接修改

- 连签权益的 `day` 提前属于放大。`CHECKIN_MULTIPLIER` 类型的 `note` 实际写入 `effect_value`，App 按 `DECIMAL(12,4)` 读取并乘后续签到奖励，因此倍率提高也属于放大。任一项放大都须 A2，不能用另一项收紧抵消。
- `ROUTE_BADGE` 的说明、延后解锁、降低有效签到倍率以及无变化沿现有入口即时保存，不强制审批。`effect_type`、启停及历史权益状态不由这些修改改变。签到倍率必须为正数、最多四位小数并可精确表示为消费者的 `DECIMAL(12,4)`；不接受无效文本或依赖 CAST 隐式转换的值。
- 收益里程碑 `thresholdUsd` 降低或 `rewardNex` 提高，任一成立即为放大。提高门槛、降低奖励及无变化沿旧四字段 DTO 直接保存，不要求新 before 字段。金额保持原有范围，接收原始值后先验证最多六位有效小数，再写入，不能隐式四舍五入。
- 旧单项 power-up PATCH、新整组 `/config` 和收益里程碑 PATCH 均在业务层拒绝放大，返回 `409 H5_APPROVAL_REQUIRED`。整组天数和期望天数只接受 JSON 整数，旧单项天数也不能带非整数部分。

## A2 命令和批准

`growth_h5_write` 可以创建以下精确业务提案，也可以按原幂等键恢复本人该类提案；这不授予其他人的票、其他业务类型或泛 A2 读取权限。批准者必须是另一名有 `platform_a2_operation_approve` 的有效超管。提案中的 maker 身份、资金方向、展示前后值和锁目标均由服务端核实，不能由客户端伪造。

提案入口为 `POST /api/admin/platform/audit/operations`，使用原 `Idempotency-Key`、理由和 A2 外层合同，`sourceDomain` 必须是 `H5`，`type=fund`。两个命令的 `domain` 都是 `H`，`params` 的业务输入放在 `values` 中：

| op | 必填 values | 唯一 target |
| --- | --- | --- |
| `h5_power_up_config` | `powerUpId`、`day`、`note`、`expectedDay`、`expectedNote`；id/day 为正整数，note 为字符串 | `{domain:"H",type:"h5_power_up",id:"<powerUpId>"}` |
| `h5_earn_milestone` | `milestoneKey`、`thresholdUsd`、`rewardNex`、`expectedThresholdUsd`、`expectedRewardNex`；四个金额是十进制字符串，最多六位小数 | `{domain:"H",type:"h5_earn_milestone",id:"<milestoneKey>"}` |

外层 `obj` 必须等于 target.id，不接受多目标。before 必须与持久业务行一致；待审只保存票和锁，不写规则或发奖励。批准校验唯一活动票锁、原理由、不同 maker/checker、当前 B1 估值可靠性及精确红线判断；展示值四舍五入为 100.00% 不能覆盖实际低于 100% 的结果。

批准时重新核实 day/note 或 threshold/reward 成对原值。里程碑沿既有 `H5_MILESTONE` 互斥执行，并重新验证相邻门槛顺序，再以 CAS 更新。原入口仍可收紧或改普通说明；其后旧票原值不符返回 `409 H5_CONFIG_STALE`，不覆盖新值。排序失效返回 `422 EARN_MILESTONE_THRESHOLD_ORDER_INVALID`。成功沿原增长命令边界留一份命令、业务审计、outbox 和持久结果；重复成功批准键返回原结果。
