# H5 连签权益与收益里程碑资金放大审批

BUG-286 本轮仅交付 H5-A03/A04 的后端能力。基线 `a9964388`；保留 B17 已确认的实时签到加成规则、停用的原质押入口和已领取记录。H5-A02 跨权益类型、初始复活卡、tick 权限及 PC 页面不在本次范围。

## 资金方向和直接修改

- 连签权益的 `day` 提前属于放大。`CHECKIN_MULTIPLIER` 类型的 `note` 实际写入 `effect_value`，App 按 `DECIMAL(12,4)` 读取并乘后续签到奖励，因此倍率提高也属于放大。任一项放大都须 A2，不能用另一项收紧抵消。
- `ROUTE_BADGE` 的说明、延后解锁、降低有效签到倍率以及无变化沿现有入口即时保存，不强制审批。`effect_type`、启停及历史权益状态不由这些修改改变。签到倍率必须为正数、最多四位小数并可精确表示为消费者的 `DECIMAL(12,4)`；不接受无效文本或依赖 CAST 隐式转换的值。
- 收益里程碑 `thresholdUsd` 降低或 `rewardNex` 提高，任一成立即为放大。提高门槛、降低奖励及无变化沿旧四字段 DTO 直接保存，不要求新 before 字段。金额保持原有范围，接收原始值后先验证最多六位有效小数，再写入，不能隐式四舍五入。
- 旧单项 power-up PATCH、新整组 `/config` 和收益里程碑 PATCH 均在业务层拒绝放大，返回 `409 H5_APPROVAL_REQUIRED`。整组天数和期望天数只接受 JSON 整数，旧单项天数也不能带非整数部分。

## A2 命令和批准

`growth_h5_write` 可以创建以下精确业务提案，也可以按原幂等键恢复本人该类提案；这不授予其他人的票、其他业务类型或泛 A2 读取权限。批准者必须是另一名有 `platform_a2_operation_approve` 的有效超管。提案中的 maker 身份、资金方向、展示前后值和锁目标均由服务端核实，不能由客户端伪造。

提案入口为 `POST /api/admin/platform/audit/operations`，使用原 `Idempotency-Key`、理由和 A2 外层合同，`sourceDomain` 必须是 `H5`，`type=fund`。两个命令的 `domain` 都是 `H`，`params` 的业务输入放在 `values` 中：

| op | 必填 values | 唯一 target |
| --- | --- | --- |
| `h5_power_up_config` | `powerUpId`、`day`、`note`、`expectedDay`、`expectedNote`；id/day 为正整数，note 为字符串 | `{domain:"H",type:"h5_power_up",id:"<powerUpId>"}` |
| `h5_earn_milestone` | `milestoneKey`、`thresholdUsd`、`rewardNex`、`expectedThresholdUsd`、`expectedRewardNex`；四个金额是十进制字符串，最多六位小数 | `{domain:"H",type:"h5_earn_milestone",id:"<milestoneKey>"}` |

外层 `obj` 必须等于 target.id，不接受多目标。before 必须与持久业务行一致；待审只保存票和锁，不写规则或发奖励。批准校验唯一活动票锁、原理由、不同 maker/checker、当前 B1 估值可靠性及精确红线判断；展示值四舍五入为 100.00% 不能覆盖实际低于 100% 的结果。

批准时重新核实 day/note 或 threshold/reward 成对原值。里程碑沿既有 `H5_MILESTONE` 互斥执行，并重新验证相邻门槛顺序，再以 CAS 更新。原入口仍可收紧或改普通说明；其后旧票原值不符返回 `409 H5_CONFIG_STALE`，不覆盖新值。排序失效返回 `422 EARN_MILESTONE_THRESHOLD_ORDER_INVALID`。成功沿原增长命令边界留一份命令、业务审计、outbox 和持久结果；重复成功批准键返回原结果。

## App 消费者和交付边界

App 签到与收益里程碑继续读取原业务表。未批准保持原值；批准后新领取按生效配置发放一次。B17 已激活签到加成继续实时读取当前同类最大有效倍率，不新增快照语义。已领取的收益里程碑金额和历史权益状态不改、不重发、不重新启用。

PC 尚未接入这些新提案：旧按钮直接放大将收到上述 409；`CHECKIN_MULTIPLIER` 上旧“运营备注”实际为资金倍率的页面提示和交互需要另批页面方案。本次不宣称 PC 页面验收完成。

BUG-314 明确零奖励里程碑的完成语义。已达到合法零奖励档时，自动评估和指定档领取沿原规则记录一次 `FIRED`，生成里程碑完成审计和 `milestone.fired` 事件。奖励字段为 0，钱包和账本没有金额写入。原键重试返回原回执。后来上调奖励只对尚未完成的用户生效，已完成零奖励档保留原完成时间和零金额快照。

## 2026-11-23 B72-BE-02：非倍率权益的审批摘要只显示连签天数

新建或预览 `h5_power_up_config` 提案时，`H5ConfigReview` 的最终 before/after 摘要按权益类型生成。`effect_type` 不是 `CHECKIN_MULTIPLIER` 时只输出原值和新值的连签天数，例如 `连签 14 天` → `连签 10 天`，不再拼 `备注：`、已退役的说明文字或多余分隔符。`CHECKIN_MULTIPLIER` 保持原格式 `连签 N 天；签到倍率：<旧值>` → `连签 N 天；签到倍率：<新值>`，倍率值仍由原校验和 A2 审批决定。

本次只改新票预览/新建时的摘要输出；已生成工单、审计和命令回放中的历史 before/after 字符串不重算、不改写。`previewPowerUpApproval` 的输入验证、非倍率 `note` 的读写兼容与投影仍按 B72-BE-01 及其既有合同处理，本项不改变配置写入、资金方向或批准条件。

## 2026-11-23 B72-BE-01 补充：非倍率说明文字退役

非 `CHECKIN_MULTIPLIER` 连签权益的 `note` 不再作为可编辑配置：管理 `powerUps` 投影不返回该字段，旧单字段 `note` 写返回 `422 RETIRED_FEATURE`，新整组配置允许省略 `note`/`expectedNote` 并只更新 `day`，旧客户端多带两字段也不覆盖历史 `effect_value`。`CHECKIN_MULTIPLIER` 的 note 值、旧比较、放大/提前解锁审批、版本/身份/幂等和审计保持；A2 `h5_power_up_config` 对非倍率接受三键或五键，倍率仍要求完整 note 对。已存值、历史工单和审计不删；审批摘要的前后文案由 B72-BE-02 处理。

## 新增收益里程碑的并发提交

`POST /api/admin/growth/earn-milestones` 新建提案时，A2 在同一个事务中取得 `H5_MILESTONE` 锁、校验规则键和门槛顺序、取得待审对象锁并保存工单。批准新增和直接编辑继续使用同一把锁。同一规则键仍待审时返回 `409 OBJECT_ALREADY_PENDING`。若批准已先完成，换请求键重提返回 `409 EARN_MILESTONE_KEY_ALREADY_EXISTS`。使用原请求键和原内容可查回原提案或批准回执。驳回释放待审对象锁后，尚未启用的规则键可重新提交，已存在的停用或软删除规则仍保留原键。

## 2026-11-23 B72-BE-03：徽章与入口权益提前解锁直接生效

- `PATCH /api/admin/growth/check-in/power-ups/{id}/config` 对非 `CHECKIN_MULTIPLIER` 权益（徽章、入口类）提前解锁不再返回 `409 H5_APPROVAL_REQUIRED`，也不再调用 B1 覆盖率检查；按原 `expectedDay` 直接 `updatePowerUpDayCas` 生效并返回 200，note 退役规则保持。日后再提交同类非倍率变更也不生成新 A2 票。
- 只有 `CHECKIN_MULTIPLIER` 的提前解锁或提高倍率仍按原 A2、覆盖率和锁定合同要求批准；倍率的 day/note 比较、CAS、幂等和审计不变。
- 新 A2 提案资格：非倍率 power-up 的 preview 返回 `422 H5_APPROVAL_NOT_REQUIRED`，不建票。已在途的旧票不使用新 preview 资格拒绝；批准/驳回继续按原锁、原键回放、CAS、决定权和审计执行。旧非倍率票批准时仍走配置 CAS，不因新直接生效政策丢失原票结果。
- 不改其它 H5 审批、前端、共享审计数据或 B72-BE-01/02 已退役 note/摘要合同。

## 2026-11-26 B110 审批失败结案

连签倍率和收益里程碑调整在双人审批回放时重新读取同一有效配置。倍率使用 1 至 365 的天数及 `DECIMAL(12,4)` 范围内的正倍率比较。收益档使用 1 至 100000000 的门槛和 0 至 100000000 的奖励比较，最多六位有效小数。当前值和提案预期值均有效，且至少一项数值确实变化时，返回 `409 H5_CONFIG_STALE` 并按 A2 B110 结案。天数相同、只有倍率格式不同的旧值冲突继续返回同一 409，原单保持待审。

调整前的配置完整匹配且通过业务校验，B1 估值可靠并低于红线时，返回 `422 B1_COVERAGE_BELOW_REDLINE` 并结案。新增收益档在取得 `H5_MILESTONE` 互斥，且通过规则键与门槛顺序校验后，适用同一覆盖率结案规则。找不到有效配置、必要值无效、条件更新失败、新增校验失败或 B1 估值不可用时，原单仍为待审并保留对象锁。

失败结案先回滚配置写入，再驳回原单、释放对象锁并保存原批准号的失败回执。原提案号可读回 `rejected` 和 `approvalFailureReason`。正常批准沿用原命令回执、业务审计和配置事件，领取记录、钱包与奖励发放沿原业务入口处理。
