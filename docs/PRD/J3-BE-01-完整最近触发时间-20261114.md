## 2. 目标与非目标

目标：

1. 保持原 `last` 字段及 `HH:mm:ss` 格式不变。
2. 在同一 GET 账户行新增 `lastOccurredAt`，为 `MAX(e.occurred_at)` 的完整 `yyyy-MM-dd HH:mm:ss`，与 `last` 同源。
3. 无值时明确 `null`；不取当前时间、更新时间、开始时间或步骤顺序代替。
4. 原阈值、24h/7d/30d 过滤、计数、排序/分页、权限、冻结/确认/处置写判断与报告/审计/预览不变。
5. 只登记 PC 日期显示接入位置，不改页面/文案。

非目标：

- 不改 `last` 的含义或格式；不改既有 JSON 字段。
- 不改 `tamperAccounts`（报告/全量）查询、报告 CSV/报告 payload、审计 detail、写判断/预览；不为排除配置保存响应而复制查询或造包装层。
- 不新增查询、表、索引、缓存、心跳、快照、回填或通用框架；不新增权限/对象范围。
- 不补 Z/猜时区；没有权威时基声明就只按存储值原样下发。
- 不改 PC/App/H5 或既有下发文案。

## 3. 真实时间源与时基

- 表：`nx_emergency_tamper_event.occurred_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP`；无时区列。
- 生产写入：`OutboxTamperDetectionPublisher` 写 `occurredAt = LocalDateTime.now().toString()`；`TamperDetectedEventProjector` 解析为 `LocalDateTime`，缺省 `LocalDateTime.now()`，再 `insertTamperEvent` 写入同一 DATETIME。
- 读取窗口 `range.startAt()/endAt()` 也由服务端 `LocalDateTime.now()` 生成；本项沿用这一存储时钟，不新增时区转换。
- `last` 与新增 `lastOccurredAt` 都取同一个 `MAX(e.occurred_at)`；后者不得取 `updated_at`、当前时间或其它事件。
- 现有 PC 把该页时间标成北京时间，但后端 schema/写入没有权威时区字段；本项只新增完整存储时间字符串，**不声称 Z 或任何时区**；页面若保留北京时间文案，需另核时基，不在本项改。

## 4. 总览读取投影增量（GET 与配置保存响应/回执）

`GET /api/admin/emergency/tamper/overview?window=...&accountPage=...&accountPageSize=...` 的 `accounts[]` 每行增加：

```json
{
  "userCode": "138****3778",
  "last": "17:41:09",
  "lastOccurredAt": "2026-11-13 17:41:09",
  "...": "原字段不变"
}
```

规则：

- `last` 保留原值/格式，原字段和原顺序不被替换。
- `lastOccurredAt` 来自同一 `MAX(e.occurred_at)`，`DATE_FORMAT(..., '%Y-%m-%d %H:%i:%s')`；无值/历史异常时 `null`，不补当前/开始时间。
- 仅分页投影查询增加该列；`tamperAccounts` 报告查询和 `tamperAccountView` 原视图保持不变，报告 CSV/payload 与审计 detail 不出现新字段、没有新增数据源/查询依赖。
- `updateTamperAlertConfig` 成功后会调用 `tamperOverview("24h",1,5)`，其 `ApiResult` 进入原幂等回执；因此**配置保存响应/新幂等回执的 `accounts[]` 也会带 `lastOccurredAt`**，不是 GET-only。该字段与 GET 同源、同一 `MAX`，无新增查询/依赖；旧回执在部署前生成时可能没有该字段，按缺失处理。
- 配置保存的原判断、审计、幂等键/回执结构、报告/处置逻辑未改；PC 仍忽略新字段。
- 原 `accounts` 行范围、阈值 `HAVING SUM(event_count) >= threshold`、7d/30d/24h 窗口、排序 `count DESC, MAX(occurred_at) DESC, userCode ASC`、分页/limit/offset、计数 `countTamperAccounts` 均不变。
- 权限仍为 `emergency_j3_read`；不扩对象/角色/全域读。
- GET 查询失败仍按原接口失败传播；不吞错、不伪装空账户。
