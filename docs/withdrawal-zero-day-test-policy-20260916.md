# 0 天提现审查与公开测试配置

- H1 到账审查窗口接受 0–90 整数天，拒绝负数和小数。显式 0 合法；缺失或损坏的 H1 快照仍不可用。
- 0 天、K3 pass、K4 LOW、低于 A3 强审阈值且低于 1000 USDT 的订单跳过常规人工审核，进入到期自动审核队列。银行单重新锁定用户、HDPay 本地订单和收款人，核对快照及披露确认，复核资金覆盖和现行风控，保存审批指纹并记录 D3 准备金。
- 到期后保留可派发的时间，自动审核不把订单标为已到账；HDPay 调度、查询和签名回调仍负责真实出款结果。调度周期内的短暂处理时间仍存在。
- 既有冻结、K3 人工/延期、K4 非低风险、强审、大额、资金覆盖、收款人不一致、J1/J2/I5 等独立约束保留。
- D5 每日次数采用业务自然日；复审与派发使用订单在其创建日的序号，不再把昨日 K3 的滚动 24 小时次数误作今日 D5 配额。
- 临时开关 `withdrawal.k4_time_validation_enabled=false` 仅在严格单 `dev` profile 且 `nexion.deployment.public-test=true` 时关闭 K4 时间有效性校验。评分、模型、时间字段存在性及所有其他风险规则仍必需。生产、混合 profile、缺失或非法开关保持校验。

## 测试配置操作

`scripts/ops/configure_test_withdrawal.py --plan --expected-backend-sha <完整 SHA>` 只读输出摘要。
人工/执行方核对计划后，用同一 SHA 与 `--expected-source-sha <计划摘要>` 执行 `--apply`。

操作限定当前 M3：审查 0 天、每日 10 次，D5 版本加一，测试时间校验关闭。只取消指定旧待审单 `WD-E68CF7F89B9444B0806A01E2A7437E0C` 的 H1 等待，并保留 REVIEW_PENDING、HDPay READY、零出款尝试及空审批指纹。不会自动批准已有订单，也不会调用代付接口。

执行持有部署锁和数据库行锁，要求运行的 test SHA 精确匹配，拒绝已有自动出款或执行中订单，提交前保存权限受限的备份并写入明确的运维审计。再次执行先核对状态；已应用即只读退出，避免重放。

## 恢复

时间校验可把开关恢复为 true；H1 天数与 D5 次数通过各自管理接口恢复。参照服务器备份恢复旧订单的等待时间前，必须确认该订单仍待审且尚无代付尝试。已经发送 HDPay 的订单不能通过回退配置撤销，也不能改回待审重发。
