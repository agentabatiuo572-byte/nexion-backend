# 正式 PRD 回写与资料生命周期

## 回写原则

临时目录是本次批准方案的输入，不能成为产品永久依赖。**按章节合并已实现且已验收的最终合同，不整份覆盖现有 PRD**。输入中的完整前后端PRD可能含较旧无关章节，根工作区版与随仓版也不是整篇相同；禁止把历史内容、品牌名或已退役机制覆盖回当前仓。

用户本次明确要求“完成后把改动分别写入对应的PRD文档，然后删除任务文档”。本次远端交接以当前正式仓可共享文档为落点，不依赖仅发起人拥有的PLAN目录。旧skill中的`admin-ops`指针规则不表示当前`nexion-frontend-pc/docs/PRD`文件已退役：本轮已核实后者是实际完整PRD。保留其现有文件名，做下表的定向合并；若团队另有更新后的权威文档入口，先核实并维护可追踪映射，不凭猜测建第三份真源。
