# HDPay 银行卡代付参数与服务端出口 IP

代付 `publicWithdrawal` 使用 `payType=BANK`；代收继续使用 `BANKQR`。所有参数确定后统一签名，不能复用修改参数之前的签名。已有 App 的配置能力标记、银行卡显示别名暂保留 `BANKQR`，它们不决定供应商代付参数。

代付 `ip` 读取服务端环境变量 `NEXION_HDPAY_SERVER_IP`（Spring 属性 `nexion.finance.hdpay.server-ip`），仅接受公网 IPv4。它属于部署网络配置，不是 PC 业务开关。不得从客户端请求、转发头、历史订单 `client_ip`、内网网卡或回调 URL 推导。原 `client_ip` 仍保留为用户提交时的审计数据。

部署前在**后端所在服务器**、按 HDPay Java HTTP 客户端实际代理设置发起只读出口检测。对比公网检测服务观察到的 IP 与同一 HDPay 域名 `/cdn-cgi/trace` 返回的 `ip`；EC2 公网元数据可作辅助核对。只有结果一致且 HDPay 确认白名单后，才能把接口成功视为已恢复。探测不携带商户密钥、签名或收款人资料，不调用代付建单接口。

测试环境使用 `/srv/nexgrid/secrets/backend.env` 持久注入实测值，写入前备份并持有部署锁，随后通过正常 `test` 发布加载。公网地址、代理、NAT 或路由变更后必须重新核对出口与白名单。该属性读取部署核验结果，并非每笔提现都实时调用外部 IP 检测服务。

缺少有效服务端 IP 时禁止新建代付；已有订单的签名回调、查单和核对结算继续工作。`DISPATCHING` / `PENDING` 只查原商户单号，不因配置修正自动重发或生成替代单号。代付 HTTP 200 或建单受理不代表到账，资金最终结算继续依据原有供应商核对结果。
