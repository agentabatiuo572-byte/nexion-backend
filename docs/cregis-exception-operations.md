# USDT-BEP20 异常资金操作说明

## 后台入口与手续费

PC 管理后台 → D1 资金渠道 → Cregis 状态 → 异常入金处置。

退款手续费由此处“配置退款手续费”提出，另一位有权限的管理员复核后生效：

|方式|实际退回金额|
|---|---|
|待配置|禁止提交退款；不替运营选择扣费规则|
|全额退回，平台承担网络费|退回原 USDT 毛额，平台准备网络费|
|扣除固定 USDT 费用|原毛额减配置的固定费用；净额必须大于零|

费用配置带版本和审计；已经创建的退款工单保留毛额、费用、净额与费率版本，不随后续配置改变。本次用户尚未决定规则，发布后应保持待配置。退款还要求 D1 渠道管理和 D2 提现审批权限。

## 认领和原路退款

1. 选择真实低额或未归属入金。已归属的低额入金只可原路退款；未归属观察可申请认领。
2. 认领时填写真实用户编号，生成绑定本环境、资金来源、动作和目标用户的钱包签名原文。
3. 原 USDT Transfer 转出钱包签名，粘贴签名并核对证据。无需转账或提供私钥。
4. 核对毛额、费用、净额、原地址及证据摘要，填写理由提交提案，由另一位管理员复核。认领沿用固定 1 USDT 入金费，毛额不大于费用时不能入账。
5. 退款只退回独立核验的原 Transfer.from，不支持自由填写收款地址。交易所、合约无法提供所需原钱包签名时保留调查，需原平台补证；公开交易哈希不足以证明所有权。

系统在提出与复核时独立查询 Cregis 和 BSC，要求固定项目/代币/网络、精确 Transfer、canonical 区块和至少 15 个确认。原资金在认领、退款、自动入账之间只能被一项处置占用。处理过未归属资金的污染地址永久退出分配池，并继续扫描后续入金。

## 退款结果不明

- 发款前持久保存原业务号和发送意图；超时、丢 CID、供应商结果不明时保持 UNKNOWN，不自动重新发送。
- 无 CID 时，在原退款工单“核对原单 CID”填写供应商原单 CID 和理由。系统匹配原业务号、项目、地址及净额后继续查询原单。
- 供应商表示成功仍须 BSC 证明一致才完成。明确未转出时才允许“重新提案”，仍要重新复核。
- 旧失败单后来出现进行中或成功证据，未发送的新提案自动撤销并返回原单调查；新单已经发送时保留双方证据并关闭资金闸门，不能自动决定哪笔钱不存在。
- 尚未批准的提案可由发起人取消；取消或拒绝只释放本案占用。

从未入账的退款不会创建普通提现单，也不增加或扣减用户钱包、待提现额、累计充值。个案退款不会自动打开普通提现开关；紧急关闭、其他 P0 和在途未知出款仍阻断派发。

## 重组、冲正、恢复和追偿

- 原已入账资金出现链重组或供应商冲突，系统保留事件并冻结相关账户、待处理提现及可覆盖余额。已向供应商发送的提现继续观察原单，不重新发送。
- “核实重组并冲正”需要可靠的消失/重组证据和另一管理员复核。RPC 不可用不是资金消失证据。
- 冲正优先取回本事件冻结额，再取当前可用余额；差额形成可追偿欠款，不扣其他事件冻结资金或产生负余额。累计充值、储备和归因保留原账并追加冲正事实。
- 原入金重新成为可靠 canonical 时可“恢复账务”；只恢复实际扣回部分，撤销未收欠款，避免重复加钱。能识别原 sender 的新记录支持同一交易重挖到新日志位置；历史缺 sender 的记录仅接受原位置的可靠恢复证明。
- 账户后来有可用余额可双人申请“追偿本事件欠款”。调查、欠款或其他来源冻结未清，不允许解除账户冻结。
- 所有恢复只针对本事件，不自动重开全局收付开关。恢复后再次重组创建新事件周期和新流水，保留之前处置历史。

## 验证边界与发布

三份前向迁移是 `20261022_01_cregis_exception_claim.sql`、`20261022_02_cregis_exception_refund.sql`、`20261022_03_cregis_reorg_resolution.sql`。PROVIDER 启动检查所需表、列、金额精度和唯一索引，缺失时拒绝启动。

行为、并发和 SQL 验证使用固定隔离 MySQL `cregis_exception_test`，不向 TEST 业务库写模拟资金或成功回调。真实供应商签名通知、真实充值入账、链上退款和提现到账仍需用户持有资金的钱包完成受控交易后验收。
