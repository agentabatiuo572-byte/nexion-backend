# 按注册手机号区号划分的每周任务周期

## CAPABILITY

2026-10-18 用户在“UVEL 测试修复与验收总控”中要求纳入“梳理跨时区每周任务”会话的设计，并明确以注册手机号国家区号确定地区。服务器及默认业务时区采用 `Asia/Ho_Chi_Minh`；不同地区账号的每周任务分别按当地周一 00:00 开启下一周。此决定取代尚未部署的“所有账号周任务统一越南零点”方案。

## CONSTRAINTS

- 权威来源为服务端认证账号的 `nx_user.country_code`，兼容 `84/+84`、`86/+86`。初始映射为 `84 → Asia/Ho_Chi_Minh`、`86 → Asia/Shanghai`。未知有效区号采用越南默认值；本次不扩大现有注册或短信服务支持的国家范围。
- 不从手机时区、界面语言、IP 或可编辑的个人资料 timezone 推断任务地区。映射使用 IANA 时区名称，并由正常 PC/A2 流程维护。
- 已开始的账号任务周冻结区号、映射版本、时区、任务快照和实际起止时刻。区号或映射变化在后继周期采用，不移动当前进度、截止时间或奖励。
- 保留旧实例、进度、已领取和未领取奖励的原身份及原截止时间。新周读取新实例，不能批量清零旧数据、复制奖励或在迁移时入账。
- 任务发布、事件归属、累计进度、完成校验、过期和领取共用账号的冻结周期，使用左闭右开的绝对时间窗口。客户端继续使用服务端返回的绝对 `eligibleFrom/eligibleUntil`。
- 同一账号、同一业务周、同一任务只领取一次；保留既有 CAS、幂等键、事务及台账引用语义。换地区不能产生另一个同周奖励集合。
- 团队结算、佣金、领导池、排行榜运营窗口和硬件月配额继续采用另已批准的越南业务日历。本能力只改变个人每周任务的周期归属。
- 现有数据库 DATETIME 的 +08 存储语义与绝对时间传输继续显式转换，不借修改服务器显示时区重新解释历史时间。

## IMPLEMENTATION CONTRACT

### 账号与实例

复用现有周任务定义、冻结任务项、事件绑定及进度表。周定义增加时区、本地周一日期和日历版本元数据；新增账号周期关联，记录账号、单调递增的业务周日期、冻结区号、映射版本及实例引用。旧 `WEEK:2026-W42` 等键完整保留；新实例使用 `WEEK:` 加标准 UUID（不带连字符），保持现有 48 字符上限。通过时区、本地周一日期、实际起止时刻及日历版本的自然唯一键复用快照。

所有生产周任务调用携带服务端解析的账号和实例身份。任务领取不能仅凭客户端提供的有效全局键选择另一地区快照。领取前校验账号关联、当前窗口和冻结奖励。删除或禁用账号不能因默认时区重新获得任务资格。

### 配置与生效

H3 新增专用读取接口及 `h3_weekly_region_policy` A2 提案/回放操作。策略包含版本、固定越南默认时区、区号映射，以及首次切换的最后旧实例和绝对生效边界；生效信息只有这一份权威来源，不另建手工激活记录。后续修改保留首次切换边界。

首次正常审批选择仍在未来的旧周期结束时刻 T0，并在提案和执行摘要中显示原旧实例和起止信息。旧实例完全不改。首个地区周承接 T0，其结束时刻为后继业务周再下一周一的当地零点；随后为正常当地周一至周一。首次承接周可以为 167/168/169 小时，不能产生仅一小时却发完整周奖励的新周期。若原提案边界已过去，按正常版本/时间冲突处理并重新准备未来边界，不能追改过去的事实。

例：若实际最后旧实例仍为 W42，原截止为 2026-10-18 16:00Z，则首个地区 W43 从该时刻开始；上海结束于 10-25 16:00Z，越南结束于 10-25 17:00Z。例子不构成对已过去边界的执行许可。未启用区域策略前，周任务按实际旧实例和旧上海日历接续，不能混用尚未生效的越南全局周键。此前延长 W42 的手工 SQL 在本方案中停用。

### 事务与事件

锁顺序为账号 → H3 配置/发布互斥 → 定义/进度/事实 → 台账。账号感知的周解析加入既有事务，避免在已锁账号的外层事务中启动另一个事务再次锁同一账号。配置变更不在持有 H3 锁后反向锁账号，也不遍历所有用户。

可信事件保留原发生时刻、受益账号和冻结实例。旧期事件不能进入新期；到达时已过期的事件沿用现有跳过规则，不新建历史奖励期。负时区、夏令时及跨年周分别计算本地周一和下一周一，再转换为绝对时刻；不能假定所有周都是 168 小时。

### PC 与 App

PC H3 展示映射、默认时区、策略版本及首次切换边界，配置提交走正常理由、A2 提案和不同管理员执行。现有周汇总按越南运营口径明确标注；周冠军如有真实发奖路径，先核清既有归属契约，不能因改变个人周键而静默改变派奖口径。

App/H5 现有 `WEEK:` 键及绝对截止时间兼容新模型；目前没有需要修改源码的证据。若后续发现真实兼容缺口，按正式 App 门禁另行修复，保留现有 WIP。

## NON-GOALS

本批不扩大注册国家、手机号更换能力或短信服务，不增加用户自行切换业务时区的入口，不改变团队财务周期，不迁移历史台账时间，也不恢复已取消的电脑算力或已延后的真实 USDT 测试。

## OPEN QUESTIONS

用户的时区来源决定已明确。发布时需从现场选定实际的最后旧实例和未来 T0；当前文档不预先声称某个已过去的边界仍可切换。周冠军真实调用链由实现者核实后补充，未证实前不更改其发奖规则。

## HANDOFF

核心实现负责周定义、账号周期关联、时间窗口和必要迁移；配置实现负责区号策略、账号来源 facade 与正常 A2 接线；主控整合所有生产任务调用、事件、完成和领取链，并负责发布和真机。PC 实现负责 H3 与对应客户端/操作注册。冻结接口后并行实现，再进行独立复核、必要全量检查、正式 test 构建与 TEST 实测。

Multi-beneficiary projection prelocks active candidate accounts in sorted order before H3. Disabled or deleted secondary candidates cannot block an active beneficiary; they receive no completion or reward. Regional fact identity includes beneficiary, frozen instance and source mission. Legacy IDs remain unchanged. H3-protected account assignment reads occur after H3 mutex; policy State is read once with a current row lock and used for region resolution, avoiding an earlier repeatable-read snapshot.
