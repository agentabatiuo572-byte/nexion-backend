# 七层购买奖励与直属双币分成方案

状态：主人于2026-10-06批准第7节推荐组合并授权实施。规则上线须经过本文验收与显式切换，不因文档批准自动启用生产。

## 1. 目标与裁决范围

原始目标是增加直属购买和设备收益的双币分成；主人随后明确：原七层购买奖励继续，C 及后续按原规则；NEX 拆分只作用于直属。实施范围涵盖后端、管理后台、App及H5，采用隔离worktree并行开发。界面改动必须先生成设计图，再转换实现；Janus继续暂停。

批准规则：**购买仍是一套七层订单佣金；L1 将原佣金预算拆成 USDT 和 NEX，L2–L7 保持原计算。另加一套只给直接邀请人的设备收益分成，同样拆双币。**

### 已批准的金额边界

| 项目 | 本方案口径 | 确定程度 |
|---|---|---|

| 旧 L1 额外 NEX | 启用新拆分的来源用拆分所得 NEX 替代旧额外 NEX；不在同一笔上叠加旧系数奖励 | 主人已批准 |

L1基础费率固定10%；拆分不改变原七层预算、资格或出口上限。设备收益总比例与两类拆分比例可配置，购买不另建第二个总比例。

“不再叠加旧 L1 额外 NEX”只针对新拆分生效的未来来源，是实际权益差异，不能隐藏在技术实现中。历史已经计提的两币金额一律保留。L2–L7 的旧额外 NEX 继续。

## 2. 关系与奖励矩阵

设 A 邀请 B，B 邀请 C，C 邀请 D：

| 事实来源 | A 获得 | B 获得 | C 获得 |
|---|---|---|---|
| B 购买设备 | 原 L1 预算按新比例拆双币 | 无本人邀请佣金 | 无 |
| C 购买设备 | 原 L2 奖励，含原额外 NEX | 原 L1 预算按新比例拆双币 | 无本人邀请佣金 |
| D 购买设备 | 原 L3 奖励 | 原 L2 奖励 | 原 L1 预算按新比例拆双币 |
| B 的设备实际收益 | 新直属设备双币分成 | 完整保留本人设备收益 | 无 |
| C 的设备实际收益 | 无此项分成 | 新直属设备双币分成 | 完整保留本人设备收益 |
| B 收到 C 的佣金、注册礼、团队奖励 | 不触发设备收益分成 | 按其来源本身记账 | 按其来源本身记账 |

“只拆直属”对每个订单的相对层级生效：C 的订单对 B 是 L1，适用拆分；对 A 是 L2，适用旧规则。不得误解为全系统只给最顶层 A 使用拆分。

## 3. 金额规则

### 3.1 七层购买先算预算，再处理 L1 发放构成

复用原引擎的顺序和精度：订单基数 × 层费率，L2–L7 乘受益人的 Influence，再乘活动倍率，最后按 L1 到 L7 顺序分配整链合并上限。暂停或资格不符不压缩层级。旧 NEX 系数按该层最终 USDT 预算计算，原有舍入保持。

以 `U1` 表示原引擎算出的最终 L1 预算（已含活动倍率、门槛和封顶），`s` 为直属购买 USDT 占比，`p` 为锁定的 USDT/NEX 价格：

```
L1.USDT = floor6(U1 × s)
L1.NEX  = floor6(U1 × (1-s) / p)
```

推荐口径不再加 `U1 × 旧L1.NEX系数`。L2–L7 的 USDT 和额外 NEX 计算保持原样。用于七层合并上限的 L1 占用始终是 **U1**，不是拆分后的 USDT，也不是随 NEX 市价浮动的价值。舍入零头不转送其他层、不补高金额。

原合并上限的含义是七层佣金预算上限；它从来不是包含全部旧额外 NEX、对碰、领导池和新增设备奖励的全平台总成本上限。不得因新增拆分而暗改这一含义。

示例为验收数据，不是正式配置：订单 1,000 USDT，原最终 L1 预算 100 USDT，拆分 60%/40%，p=0.01，得到 60 USDT + 4,000 NEX。假设旧 L1 另送 200 NEX，推荐方案的新来源不再叠加这 200 NEX；历史账仍保留。原 L2 若最终预算为 50 USDT、旧系数为 2 NEX/USDT，仍得到 50 USDT + 100 NEX。

### 3.2 直属设备收益单独计算

以真实已入账且通过来源校验的设备结算凭证为单位：

```
Q = 凭证已入账USDT + 凭证已入账NEX × p
R = Q × 设备收益总分成比例
邀请人.USDT = floor6(R × 设备收益USDT占比)
邀请人.NEX  = floor6(R × (1-设备收益USDT占比) / p)
```

例如设备产生 10 USDT + 100 NEX，p=0.01，总比例 5%，拆分 60%/40%：A 得 0.33 USDT + 22 NEX，B 仍完整取得 10 USDT + 100 NEX。设备收益奖励不占购买订单七层额度。

合格免费手机真实任务沿用现有资格；充值、影子收益、注册礼、活动礼、邀请佣金、Team 奖励、开发模拟和测试工作器产出不算设备收益。不得在 H5 开放原生手机任务执行。

### 3.3 精度、价格与失败

- 复用既有 NEX 价格来源。拆分字段以十进制保存，最终向下取六位；旧 L2–L7 的 HALF_UP/DOWN 顺序不统一重写。
- 生效政策按订单支付或设备凭证确认时间选择。第一次成功取到价格时锁定价格值和取价时间，之后重试、解锁和退款都不重估。已有来源快照先于金额写入持久化，避免等价格期间换受益人或政策。
- 缺价格属于可恢复的“等待计算”，不等于关闭、不合格或已到账；不得默认 p=1、改发全 USDT 或向更上层代发。L1 等价预算已保留，L2–L7 按原预算正常计提，设备分成失败不阻断 B 原收益。
- 新双币奖励若任一币舍入为零，记为小额未发，不伪造另一币已到账，不自动累积。L1 原预算占用不因此转给 L2–L7。旧深层原本允许 NEX 为零的行为保持。
- 持久化和价格重试失败可追踪；页面显示待计算或待发金额，只有钱包与到账时间均证实的记录才能称已到账。

## 4. 唯一配置归属

| 设置 | 权威归属 | 推荐行为 |
|---|---|---|
| L1 总预算比例、暂停、七层倍率/门槛/合并上限 | 原 F2 七层配置 | L1 总比例继续原固定 10%，L2–L7 可按旧规则配置 |
| L1 USDT/NEX 拆分 | F2 新“直属购买奖励拆分” | 仅开关和 USDT 占比可编辑；NEX=100%-USDT；总预算与冷却从原七层只读引用 |
| 旧 L1 NEX 系数 | 原七层配置及历史政策 | 新拆分启用时不消费该系数，显示适用范围；未启用拆分的未来来源沿用原完整 L1 |
| L2–L7 NEX 系数 | 原 F2 七层配置 | 继续实际生效，不误改为拆分比例 |
| 设备收益总比例、两币拆分、开关、冷却 | F2 直属设备收益配置 | 复用现有政策版本与审批能力，各值可配置 |
| NEX 价格 | 已有 NEX 价格服务/后台能力 | 只引用，不在 F2 建第二套行情 |
| Partner、其他奖励冷却 | 现有独立配置 | 不与购买拆分或设备收益冷却混用 |

新拆分关闭意味着未来 L1 恢复原发放构成，不意味着七层购买停用。暂停某一购买层仍用原层暂停；暂停设备分成只影响设备分成。关闭不得改变已锁定来源模式或旧待发账。由于关闭拆分可能增加 USDT 支出，审批不能一概把“关闭”当收缩。

F2 暂停七层时不自动暂停设备分成；全平台现有停发/风险闸仍优先。空配置显示未配置，启动检查不得用代码常量悄悄写入正式运营费率。

购买冷却继续引用 `commission/cooling-days`，以首次整链准备时间 preparedAt 起算并锁定；新拆分L1不再使用旧直属purchase的独立冷却。设备分成冷却继续按凭证确认时间加设备规则天数。缺价期间计时不重置，到期仍必须等价格、风险和两币事务均满足才能到账。历史组原releaseAt不改。

七层参数与拆分批准、订单准备必须读到同一一致配置快照；在后端现有事务/版本锁上协调，不能只靠两个不同A2目标锁。为影响结算的原七层配置及冷却维护一个七层配置revision，所有相关批准写入均递增；新政策提案同时提交expectedVersion和expectedSevenLayerRevision，并保存引用值。批准时任一版本变化即拒绝并要求重新预览、重提，禁止自动把新的支出规则塞进旧批准。新拆分启用期间，旧L1 NEX系数入口只读、旧待批修改不能绕过新模式生效；关闭拆分的审批须明确展示即将恢复的旧系数及USDT增加值。所有资金放大判断在执行时回源重算。

#### [FEAT-RS01] 七层订单计算与直属双币发放

**① 用户故事**：作为邀请人，我想继续获得原网络购买奖励并看清直属双币构成，以便核对每笔订单；作为财务运营，我想对同一来源只计一次并能完整撤销，以便避免重复支出。

**② 验收 GWT 与异常路径**：Given A→B→C，When B/C 各自购买，Then A 分别取得拆分 L1 和不变的 L2，两笔可追溯各自订单。同一冻结输入下，新旧 L2–L7 的应计 USDT/NEX 逐位一致。

- 异常1：Given 同一订单被两个事件号并发重投，When 两个处理器竞争，Then 订单模式及整链预算只生成一次，既有层的预算不能在重试中遗失，不能追加第二份 L1。
- 异常2：Given L1 缺价格或钱包风险冻结，When 七层预算已生成，Then L1 保持预留与等待/冻结，L2–L7 不因少发 USDT 获得更多额度，也不受新增设备价格问题阻断。
- 异常3：Given 第二币插入/入账失败，When 事务失败，Then 同组两币和状态均回滚；恢复只能沿原快照，不能以当前关系或参数重算。
- 异常4：Given 购买订单确认退款，When 处理退款，Then 新模式订单中 L1 及 L2–L7 两币均进入真实撤销/追回；余额不足记录每位受益人每币欠额，不影响购买者应得退款。人工冲正仅影响批准的单账项/直属双币组，不因点击一笔就撤回其他上级；本方案不新增全订单人工冲正按钮。
- 异常5：Given 邀请人字段与关系链 L1 不一致、环路或跨环境身份，When 准备快照，Then 阻断该订单计佣并记录待处理原因，不自动改关系、压缩层级或换人发奖。

**③ 数据字典与生成规则**：全部服务端权威，client 仅作展示。复用政策、佣金事件、账本、直接奖励组；新增最小订单结算快照是必要防重与整链预算事实，建议一个订单一行、层明细保存结构化 JSON，不预建通用奖励引擎。

| 对象/字段 | 类型 | 必填/默认 | 生成与约束 |
|---|---|---|---|
| 订单结算快照 | 新增持久事实 | 必填 | 唯一键 environment + runId + orderNo；包括没有合格受益人的订单，防止以后重放补发 |
| settlementMode | enum | 必填 | LEGACY_7 / DIRECT_ONLY_V1 / SEVEN_V2，表示结算代际；由切换边界和历史事实确定，终身不变 |
| splitEnabled | boolean | SEVEN_V2必填 | 来源时刻是否启用L1拆分；与结算代际独立，false仍走新七层快照/封顶/退款链 |
| orderNo/sourceUserId/sourceOccurredAt | string/long/time | 必填 | 锁定真实支付订单，事件金额和客户端受益人均不可信 |
| preparedAt | time | 必填 | 首次准备整链快照的服务端时间 |
| chainAndRules | json | 必填 | 原链L1–L7、资格判定、费率、影响分、活动倍率、暂停、NEX系数、冷却、上限、逐层预算和不计原因 |
| originalBudgetUsdt/allocatedBudgetUsdt | decimal | 必填 | 各层拆前预算和整链累计，重试按原值恢复，不从当前USDT账推断 |
| formulaVersion/policyVersion | enum/long | 必填 | 原公式版本与直属拆分生效版本；版本不进入防重唯一键 |
| price/priceLockedAt | decimal/time | 待价格时null | 一次锁定，金额形成后不变 |
| L1关联双币组 | string/null | 拆分且可计时必填 | 复用 direct_purchase 来源分类，但含义为七层L1；不另算订单×新购买比例 |
| L2–L7关联佣金事件 | ids | 按层资格 | 沿用 network 类别；指向既有 USDT/NEX 行，不复制收益计数 |
| refund/recovery事实 | 每受益人每币金额 | 默认0 | 应撤销、实追回、待追回及反向账本引用；累计不得超过原到账 |

新订单的原账及合法补发账必须保留同一原订单关联，不能只按账项当前order_no查退款；现有F5补发会生成新order_no，须沿佣金操作的source/result事件关系追溯。全额退款的原来源禁止再补发。每层因封顶、资格或暂停而不计提也持久记入决定，重投不能让这些层重新占一轮额度。

原七层当前没有完整历史参数查询。本方案保持其首次结算时取值的实际语义，在第一次权威准备时冻结七层配置、上级链与资格；直属新政策按来源发生时间选版。不得宣称已按支付当刻还原旧七层参数。后续若要统一按支付时刻取七层政策，属于另一项版本化改造。

**④ 状态机与禁止动作**：订单先锁定模式及预算，再物化佣金，再发放。单层状态为待计算→冷却/冻结→实际到账；无资格/小额为不计提终态。缺价格保持待计算；风险解除只恢复同一奖励，不重算。退款可以从待计算/冷却/冻结取消，从到账进入追回完成或待追回。整链快照记录每层状态，不拿一层成功冒充整单完成。

禁止动作：重复预算、半币成功、反转后补发、绕过冷却、修改受益人、负可用余额、关闭功能后重算旧账、退款后向其他层重新分配释放额度。旧 network 历史处置按原路径，不能将新组限制错误施加于旧账。

**⑤ 交互四态**：默认态按订单显示直属购买/网络购买及两币；空状态显示无对应奖励；加载态保留列表骨架；报错态显示可重试，待计算、冷却、冻结、待追回各有可读说明。期望奖励与实际到账分开展示，不显示内部枚举码。

**⑥ 点击流矩阵**：

| 触发元素 | 目标 | 反馈 |
|---|---|---|
| 购买奖励记录 | 现有奖励详情/有权限订单关联 | 展示原金额、来源及状态 |
| F5冻结/恢复 | 对应同一奖励 | 拆分L1按组；旧层沿用安全处置；确认、理由、失败回查 |
| F5冲正 | 既有审核流程 | 核实证据，显示两币及实际追回范围；禁止通用改状态代替冲正 |
| 重试查询 | 同一筛选与快照 | 不重复计提、不改变账 |

**⑦ 跨文档一致性**：F2定义参数，A2批准，F5管理，D4与钱包提供到账事实；App网络版税页展示现行七层。参数不能在新增直属表单和旧L1行各维护一份。后续实施须同步第8节各仓PRD。

#### [FEAT-RS02] 直属设备收益与资金安全

**① 用户故事**：作为直接邀请人，我想获得直属成员设备真实产出的双币奖励，以便查看持续贡献；作为设备持有人，我想完整保留自己的收益，以便核对设备账单。

**② 验收 GWT 与异常路径**：Given B 已入账设备收益，When 按第3.2节结算，Then A 获双币分成，B原入账不减少；Given C收益，Then只给B设备分成，不给A。

- 异常1：Given 相同凭证重投、账号或政策变化，When 重试，Then沿原受益人和原有效政策，USDT/NEX只发一份；等待价格前也要先保存这些事实。
- 异常2：Given 佣金、试用影子、开发模拟或跨环境凭证，When 校验，Then不生成正式设备分成，拒绝原因可追溯；不凭事件名称或PRODUCTION字符串通过。
- 异常3：Given 冷却、风险冻结或第二币写入失败，When 发放，Then不留可消费半账；B既有设备收益不回滚。
- 异常4：Given 原设备后来退款但过去设备收益仍是真实有效收入，When 处理订单退款，Then不自动撤回历史设备收益分成；只有原收益被权威纠正并有证据时，才能沿原奖励执行审核冲正。

**③ 数据字典与生成规则**：复用 direct_device_earning 和 settlementNo、receiptNo、sourceDeviceId、sourceUserId/beneficiaryUserId、policyVersion、price、两币金额、releaseAt、creditedAt、recoveryPending；唯一来源键仍为环境+批次+类型+凭证。新增等待计算需要源快照而非一条会随重试变化的日志。价格、钱包、有效凭证均服务端权威。

**④ 状态机与禁止动作**：待计算→冷却/冻结→到账；无资格→不计提；有证据冲正→撤销/待追回。冻结恢复不改原金额；佣金事件不得再次作为 earnings.credited 设备凭证。禁止复制补发或将当前NEX价用于历史追回。

**⑤ 交互四态**：默认态列真实设备分成，两币同组；空状态保留Team邀请入口；加载态用同形占位；报错态保留期间与重试，禁用时说明新来源停用但旧奖励可查。

**⑥ 点击流矩阵**：

| 触发元素 | 目标 | 反馈 |
|---|---|---|
| 设备收益分成分组 | 同一Team版税页对应记录 | 双币、设备来源及到账状态 |
| 期间/加载更多 | 当前查询快照 | 切期间重置分页，追加去重，失败可重试 |
| 规则说明 | 现有说明页 | 读取当前已发布且版本匹配的说明 |
| 返回 | Team原入口 | 对碰、等级、领导池仍可进入 |

**⑦ 跨文档一致性**：设备收益资格来自实际设备结算，邀请关系来自服务端；平台额外支付由F2政策说明，钱包负责实际到账。App/H5共享同一协议和三语文案，H5保留手机执行权限边界。

#### [FEAT-RS03] 后台审批与App/H5呈现

**① 用户故事**：作为运营者，我想在一个页面核对七层购买和两类直属拆分，以便配置后知道影响范围；作为成员，我想同时看见直属购买、网络购买和设备收益分成，以便不遗漏原有权益。

**② 验收 GWT 与异常路径**：Given 有权限且完成批准，When 刷新F2与App，Then读取同一生效政策；网络版税既有七层入口、深层购买奖励、直属购买拆分及设备分成均可查询。

- 异常1：Given 两个编辑者版本冲突、旧客户端提交旧purchase对象或历史A2待批，When 保存/重放，Then服务端拒绝语义不匹配的请求并保留草稿，不能把旧独立购买比例悄悄用于新L1。
- 异常2：Given 未配置、无权限、低覆盖率或API错误，When 操作，Then有禁用原因/重试/取消；不得显示假默认、少一个区块仍报整页成功或绕审批写入。
- 异常3：Given 切账号、切期间和旧响应晚到，When 更新界面，Then不串账号、不重复汇总；分页总额取服务端完整期间聚合，不累加当前页冒充总收益。
- 异常4：Given 一笔L1同时被网络聚合和直属接口命中，When 展示总额/导出/榜单，Then仅按唯一奖励事实记一次；两币账项不当成两个订单或两个成员。

**③ 数据字典与接口**：复用现有路由。以下为批准的实施契约；落地状态以本轮验收记录为准。

| 入口 | 契约 |

读取明确通过schemaVersion=2查询参数协商，省略视为v1；政策PUT由body声明schemaVersion=2。发布顺序：后端先支持两版但不切业务代际，v2响应显式带当前代际及原语义只读投影；随后PC/App/H5支持两种代际显示，再批准切换T。T后这些受影响的Team配置/版税/说明读取对v1明确返回版本不支持和更新提示，不发送会被旧端误解的金额结构；账户、设备本人收益和钱包原接口不因此停用。发布前必须演练旧端的更新引导，不能只抛原始协议错误就启用新业务。旧端读取与新政策启用顺序是发布硬门，不自动依赖一个未知现有最低版本能力。

切换T后仍未执行的v1直属购买政策提案明确失效，只允许按v2重新预览提交；已批准历史policy保持原义供历史来源查询。不得把旧purchase.totalRatePct悄悄转换成新L1拆分设置。已发布说明只在正常内容发布流程更新，不覆盖运营自定义正文。

聚合采用明确口径：`/insights/unilevel` 是新页面购买两类列表、总额和计数的唯一来源，支持服务端direct/extended筛选后分页；`/insights/direct-referral?kind=direct_device_earning`只提供设备分组，不将其历史purchase总额再次相加。跨接口共用请求快照边界，旧账以服务端生成的稳定奖励组标识映射；同一新L1的标识始终为其settlementNo。没有证据能合并的旧账仍按账项显示，不臆造一笔奖励。现有总佣金的extendedUSDT是“总佣金减直属”，包含其他奖种，不能重新命名为L2–L7购买分成。总佣金保留账项数，专页统计奖励组数，贡献人数按成员去重。现有已解锁USDT排行榜保持USDT口径，不新增NEX估值排名，但撤销、待追回金额不得计入有效净收入。

## 5. 最小实现方向

1. 购买沿用既有可靠事件消费者的 checkout 分支，按订单号重读支付/退款/环境事实，统一进入七层结算；VRank消费者继续只评等级，避免两个入口。普通、组合、三种置换及试用转正全部覆盖。
2. 原七层计算复用；抽出“生成并保存整链预算”，L1只把已算预算交给双币组落账，不调用现有独立购买总比例公式。金额插入失败必须回滚，不能跳过后继续标成功。
3. 新订单快照固定模式、受益人、预算及事件引用，成为重复事件、价格恢复和退款的共同依据。复用现有两币组发放、审计、F5和账本能力；不重建钱包。
4. 设备凭证仍走现有直属设备收益入口，补齐等待价格前的来源/政策快照。七层订单和设备收益失败相互隔离。
5. App/H5恢复完整网络购买视图，同时保留新增直属设备收益。后台、API、A2摘要、F5、钱包、汇总、导出、奖金榜及说明同轮校准。

## 6. 历史切换与回滚

设置一次明确发布切换边界 T，并记录环境、审批/发布证据，不把代码重启时间当隐含业务生效点。

| 来源事实 | 处理 |
|---|---|
| 已有旧network佣金 | 保持原账、原金额，不补一个新直属组，不重算历史链 |
| 已有direct_purchase组（含REJECTED/撤销等终态） | 归属已有直属模式；不因为恢复七层自动补L2–L7；如需历史补偿须另审批 |
| 同订单存在混合旧新记录或无法确认适用模式 | 隔离为人工核对，不猜测、不自动继续发奖 |
| T前尚无结算、积压或失败来源 | 按原事件/政策证据处理；证据不足进入待核对。不得按新程序默认补整链 |
| T后合格新购买 | 统一SEVEN_V2结算；L1根据来源时刻有效splitEnabled决定原构成/新构成；关闭拆分仍保留新快照、防重、整链退款与欠额处理 |

历史扫描先做只读数量和状态盘点，不自动批量补发。核对邀请关系与团队链的一致性、完整七层规则、价格和环境；没有正式费率时保持未配置，不能靠测试种子完成生产初始化。

所有SEVEN_V2订单退款均联动整链，不论L1拆分开关：确认退款事实后先持久标记禁止后续解锁/新计提，再按每受益人每币撤销/追回。每次佣金物化和解锁都必须锁定、重读权威原订单仍未退款，不能只等异步退款消费者写禁止标志；订单退款确认、计提、释放使用相同来源锁顺序，封住outbox延迟窗口。某位余额不足或暂不可用不得阻断其他可追回奖励，也不得阻止买家退款；记录欠额可安全继续。钱包扣减、反向账及欠额更新原子执行。原订单退款只有全额能力时，本版仍拒绝未经支持的部分退款。

退款枚举包括与原来源关联的F5补发账；已冲回金额不再扣第二次，欠额重试只扣尚欠部分。初始准备、计提、自动到期、F5释放/冲正/补发和退款使用一致的来源锁顺序，处理每个受益人的钱包时用稳定次序；并发验证必须证明没有死锁导致遗漏、没有退款后解锁和重复扣减。

历史network当前是单账项审核冲正，不能声称已有自动整单退款和余额不足欠额能力。本方案只为新七层模式补齐这条资金闭环，不自动迁移全部历史佣金。设备退款不等于过去真实设备收益失效，两种追回证据不得混用。

故障回退优先暂停新来源计提并保留待处理事件；不得回滚到会重新按旧方式给同一订单发钱的程序。解除拆分是批准后的未来政策调整，不是删除历史；数据库备份不能用于抹掉后续真实交易。

## 7. 已批准的实施组合

主人已整体批准：**直属购买和直属设备收益都拆；新购买L1的拆分NEX替代原额外NEX；购买L1继续原固定10%基础费率，USDT/NEX占比可调；设备收益总比例和拆分独立可调。**

实施不得叠加旧L1额外NEX或开放第二个购买总比例。历史奖励保持原快照，不自动改算。
