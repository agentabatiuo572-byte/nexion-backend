## 后端边界

1. 新政策版本不可覆盖旧版本；整组审批/比较版本/生效时间。新佣金算法单点复用，两个可靠来源消费者，不复制钱包实现。
2. 移除真实购买事件对旧七层引擎的调用；保留历史查询和独立奖励。缺配置时不再套旧规则。
3. checkout.completed覆盖普通/组合及三换购入口；试用转正补同一订单来源事件。device.purchase_completed不再同时计第二笔。
4. earnings.credited回查已到账双币设备凭证，加入dispatcher；order.refunded同样接可靠重试。测试/开发事实不能仅凭PRODUCTION字符串被当真。
5. 当前仓已有真实钱包佣金释放能力，回源复用；不按旧审查快照假设仍缺该能力。冷却/冻结不提前给available；F5所有写入口按双币结算组处理。
6. 防重、资金锁顺序、退款与发放并发在数据库实测；仅Mockito绿不能证明闭环。

## 前端与文档边界

PC沿用F2现有表单、确认和审批样式，App沿用现有Team页与列表；本轮是同类界面调整，不建设新视觉体系。PRD先改功能正文，再实现；详细交互与测试独立文档，不把变更流水塞进PRD。旧外部PRD仓不是写入权威。

API契约不得各端自行改名；必要调整由主线同时更新三端和规格。真实后端验收与前端transport fixture分开记录。H5共享内容通过app-h5-sync完成，不整仓覆盖。

## 切换、恢复和回滚

首次政策未启用时不制造正式费率；只有批准配置后对生效点后的来源计提。既有已计提network奖励保持原账，不自动回算历史。切换验收包含排队旧事件及重复事件，不能同时命中新旧引擎。

故障时暂停新规则并保留来源/失败回执；已经入账只用追溯冲正，不删除账本或回滚数据库至丢失真实交易。代码回滚不能恢复旧七层消费入口继续给相同新来源发钱。生产启用、数据迁移执行及生产费率设置须以独立发布动作记录，不把源码推送称为上线。
