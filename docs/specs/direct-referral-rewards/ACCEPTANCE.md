# 直属分成验收方案

## 环境与资料

只在本机隔离MySQL数据库、隔离Redis/服务端口及测试账号运行。记录四仓HEAD、工作树路径、运行时source、数据库名及端口；日志不得泄露口令、令牌或真实个人资料。App/H5的模拟transport验收只能证明界面和协议，资金通过必须有真实数据库事务证据。

## 验收标准

| ID | 目标 | 必须提供的证据 |
|---|---|---|
| DR-01 | A→B→C→D直接归属 | B/C/D两来源分别只付上一位，A无C直接分成；sourceID与钱包/两币账本查询 |
| DR-02 | 总分成拆双币，B不减 | 1000/10%/60%/p0.01=60+4000，设备10/5%/60%=0.3+20；B前后余额对比 |
| DR-03 | 所有购买来源 | 普通/组合、换购、容量替换、保留旧购新、试用转正；订单实付、零元和同订单双事件防重 |
| DR-04 | 真设备收益与防套奖 | USDT+NEX同receipt、免费手机真任务可计；H2/H8/Team/影子收益/DEV/测试工作器不可计 |
| DR-05 | 政策版本与配置审批 | 两规则完整保存、GET刷新一致；权限/理由/并发CAS/资金放大拒绝及收缩通过；批准即时生效，来源按发生时间选择版本 |
| DR-06 | 原子性与重复恢复 | 第二币故障回滚、并发/新eventId重投只付一次；冷却与冻结期间无可花余额 |
| DR-07 | 退款与待追回 | 发放前取消、发放后双币追回、重复和并发退款、余额不足保留待追回；钱包/佣金/账本一致 |
| DR-08 | PC可操作 | 两类参数、合计100%、权限禁用、确认/取消/理由、审批状态、刷新；F5两币组处置和错误反馈 |
| DR-09 | App/H5真实页面 | 配置/期间/分页/详情金额/状态/重试/账号切换；zh/en/vi、亮暗和320px/常规屏幕截图及console |
| DR-10 | 旧功能保留 | 对碰、等级、培育、领导池原测试和入口交互；历史network查询及原结算处置不丢 |
| DR-11 | 环境与身份隔离 | 伪造来源、账号/钱包跨环境、来源篡改、重放换上级失败；公开不泄露成员原始ID |
| DR-12 | 全量质量与同步 | 后端相关及架构测试、PC fullverify、App/H5 fullverify、来源pin、独立Java/TS review当前快照 |

## 对抗性预演

最可能失败的是：旧7层还在收订单、试用转正漏事件、收益只读USDT遗漏NEX、第二币失败留下半账、后台F5绕过整组资金动作、退款和到期释放并发、改政策后事件重试重算、端上未知kind被严格parser拒绝、后台发布说明仍为旧七层、H5遗漏同步。每项都必须有用例，不能只看改动文件通过编译。

## 通过与未通过

静态校验、单测、MySQL/API运行、浏览器与生产分别报告。没有实际证据的格子标未验证，不用全绿替代。修补后验证受影响用例并在最终提交树上执行仓库要求的full门；保留失败首份日志。不以隐藏入口、跳过测试、降低权限或假数据宣称完成。
