# USDT-BSC 自动归集与甲方付款

## 已确认合同

用户要求充值后全自动处理，不再依赖人工准备单或逐笔在 Cregis 点击。用户已确认：归集实际充值毛额，向甲方支付用户入账净额，充值手续费留平台，链上手续费由平台另付。原充值入账只发生一次；资金搬运不重复给用户加款，也不扣用户余额。原准备单保持独立，不会变成自动任务。

仅 BSC USDT；固定平台钱包与甲方地址沿用已核验的资金准备配置。每笔已入账充值事件只有一个自动任务；归集得到供应商成功和至少 15 次链确认后，才允许付款。两段均验证链 ID、代币、来源、目标、金额和规范链。每次发送前重新检查原入金、原归集及现有项目风控。

执行总闸 `nexion.finance.cregis.auto-forward-enabled`（环境变量 `NEXION_CREGIS_AUTO_FORWARD_ENABLED`）默认 false；数据库自动归集、自动付款均默认 false。启用需未来另行授权，确认 Cregis 自动审批/签名及套餐权益、绑定钱包、BNB 手续费安排，打开运行总闸后再由两个不同有效管理员审核开关。当前交付不得打开任一闸门。默认每 60 秒轮转最多 20 个任务，避免持续突破供应商每分钟 30 次的单接口查询限制。

首次启用记录当前充值事件水位，只纳入之后新事件；暂停不重置水位，已发送单即使暂停仍继续只读核对。单来源仅一张未完成任务。金额取不可改写的充值事件，禁止客户端输入自动付款金额/地址。固定金额逐笔归集，不使用“全部余额”。

持久化发送意图后才调用 Cregis；崩溃、超时、响应身份异常进入 UNKNOWN，绝不自动重发。归集接口没有业务幂等号，因此更不能重试不明请求。可在后台填写原 CID，独立查询身份及交易确认后恢复跟踪。付款同时使用稳定业务号及已验签回调提示恢复 CID。回调不直接确认成功。明确拒绝且没有 CID/交易的任务可由有权管理员重试；UNKNOWN 不提供重试。

## 状态

WAIT_COLLECTION → COLLECTION_SUBMITTING → COLLECTION_PENDING → WAIT_PAYMENT → PAYMENT_SUBMITTING → PAYMENT_PENDING → COMPLETED。

SUBMITTING 超时或不明请求 → 对应 UNKNOWN；明确创建拒绝/供应商无交易终态失败 → 对应 FAILED。存在交易哈希的失败不能当作未付款释放。错误只保留安全错误码、原业务号与 CID。关闭发送开关不停止已发送交易的查询。重组、余额不足、BNB 为零、供应商或链读取失败均保持原任务且暂停新发送。

## 验证计划

- AF-01：总闸/两个开关默认关闭；关闭时扫描、发送及供应商写调用为零。
- AF-02：只接入启用水位后的 CREDITED 事件；毛额/净额/手续费一致，固定目标且不改余额/账本。
- AF-03：完整假供应商与链证据路径，一次归集毛额、一次付款净额；供应商成功但链不足不能前进。
- AF-04：重复调度、并发 CAS、崩溃意图、超时及未知不重复发送；关闭发送后仍查询原单。
- AF-05：原入金/归集重组、项目/来源/目标/金额/CID/交易哈希错误、风险或 gas 缺失均拦截。
- AF-06：原 CID 恢复需查询核验；UNKNOWN 无重试；明确拒绝才允许重试；已完成任务不可再次发送。
- AF-07：双人开关提案、失效账号、权限不足、旧版本和幂等冲突；回调签名、来源 IP、时间及业务身份校验。
- AF-08：管理端实际页面读回关闭状态、金额口径、空任务和错误提示；无真实转账。
- AF-09：独立权限/异常/恢复复核；后端与 PC 必要门禁、TEST 构建及当前页面验收。

## 官方 API 依据

- [归集](https://developers.cregis.com/en/reference/waas-api/initiateCollection/)：from_address/to_address/amount，返回 cid，没有 third_party_id。
- [历史交易查询](https://developers.cregis.com/en/reference/waas-api/tradePage/)：按 cid、business_type=5 核对归集。
- [钱包付款 V2](https://developers.cregis.com/en/reference/waas-api/initiatePayoutV2/)：明确指定平台 from_address 和甲方 to_address，稳定业务号；沿用现有付款查询与回调接口。

回退时关闭运行总闸及数据库开关，保留任务、原 CID 和审计。已发送交易不能用代码回退撤销，须继续只读跟踪；绝不删除资金历史或直接把未知任务改成成功。
