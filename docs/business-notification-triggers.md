# First-batch business notifications

Apply `scripts/migrations/20261029_business_notifications.sql` once before enabling `nexion.business-notifications.enabled=true` (default disabled). Restart retains the cutover and receipts; rerunning migration does not reset them. Apply the native transport migration separately. Direct FCM/APNs provider acceptance, device receipt and notification opening are distinct; legacy `nx_notification.push_status` never proves OS delivery.

| Category | Authoritative source | Trigger / target |
|---|---|---|
| DEVICE_EXPIRY | `nx_trial_claim` written by `AppTrialLifecycleService` | Existing trial `expires_at`; active deduction retention = `expires_at + graceDays`, or extended `expires_at` when `extended_at` exists. Current 24h / 1h / ended stage once each; `/pages/me/trial`. Terminal auto-closure uses persisted `closed_at` for an ended-stage fact only; future policy edits cannot reopen it. Explicit cancellation/conversion does not remind. |
| DEVICE_ALERT | `nx_user_device` + `nx_user_device_runtime` | Same activated/owned and effective abnormal predicates as PC E5, plus 15 continuous minutes of server observation. Recovery ends the cycle. Deactivation/retirement/pending stop excluded. Detail route uses current server device ID. |
| FUNDS_RESULT | Existing `wallet.topup_confirmed`, `withdraw.confirmed`, `withdraw.refunded`, `order.refunded` outbox; Cregis `nx_deposit_order` | Committed success/returned results only. Withdrawal and order owners re-read by business number. Cregis requires CREDITED + ledger link. `/pages/me/wallet-bills`. |
| ACCOUNT_SECURITY | Successful security/password/payment/account-status audit rows; password-reset/lock/refresh-reuse events; server session chains | Successful changes only. Password reset keeps the existing registered event schema, including revoked-session count. Card bind/reactivation/default changes now persist safe required audit facts; sandbox sources excluded. New APP sign-in environment means first server-accepted installation ID + server-observed IP + session surface; H5 or legacy APP without an installation ID falls back to IP + surface. This accepted identifier is not physical-device attestation. Token rotation and repeated same installation/peer do not remind. `/pages/me/security`. |
| SUPPORT_REPLY | `nx_support_human_message` ADMIN metadata joined to committed agent message and exact conversation customer | New human operator/advisor reply for its recipient only. No user-authored, system/bot, intermediate token, deleted or mismatched-customer messages. `/pages/support/chat?cid=<server conversation number>`. |

User-confirmed expiry scope is trial end and deduction-retention end. Paid owned-device policy has no fixed lifetime: `cycleMonths` is a graph forecast, not expiry. No paid-device expiry field, fabricated dates or blanket backfill was introduced.

Each scan locks one control row; inserts its permanent receipt and station notification in the same transaction. Existing HDPay and card-unbind station rows are adopted with their original business idempotency keys, avoiding duplicate inbox entries; native transport discovers them through the receipt. New messages use `NATIVE1:<sha256 fact key>`. Outbox financial results deduplicate by event kind + business aggregate; repeat publishing does not generate another notification. Receipts survive user deletion of station messages. Scans are bounded to 100 candidates per source and anti-join permanent receipts rather than advancing a MAX timestamp/ID cursor, so transactions committing later remain visible. The initial cutover excludes historical facts; only current deadline stages are considered, never catch-up reminders for elapsed stages. Deadline identity includes its authoritative time, so extension creates a new legitimate reminder schedule.

Business notifications have Chinese, English and Vietnamese static text selected by user language. No source payload, credential, IP, amount, card token or support text is copied into the new messages. Funds/account security are critical; device/support are high and respect existing system/service preferences. None depends on the marketing switch. Native lock-screen text is independently generic in transport.

Rollback: disable `nexion.business-notifications.enabled`, disable the native transport worker, then restore the prior application. Preserve receipts/control/state and existing messages for restart safety; never clear the baseline to retry. Existing source business/financial tables and ledgers are untouched by scanning. The only producer changes add durable security audit/event facts after successful changes, in the existing transaction.

Validation commands: run `BusinessNotificationServiceTest`, `BusinessNotificationMySqlTest`, `AppPaymentMethodServiceTest` and affected auth/payout tests. SQL integration requires `NEXION_BUSINESS_NOTIFICATION_IT=true`, `NEXION_ISOLATED_MYSQL_ENDPOINT` and `NEXION_ISOLATED_MYSQL_PASSWORD` pointing to disposable MySQL. It creates and drops only a fresh random test schema. SQL tests cover real mapper projection, same aggregate replay, late facts, wrong support recipient, multilingual text, device debounce/recovery/deactivation, true extended retention and existing-message adoption. These checks do not establish deployed TEST, actual Android/iOS delivery or vendor configuration acceptance.
