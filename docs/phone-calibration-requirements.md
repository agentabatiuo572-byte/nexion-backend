# 手机硬件自动校准实施契约

## 目的与授权
正常手机激活自动匹配服务端规则；人工只审核共用规则变更，不逐人审核。2026-10-03 用户明确采用最小手机校验：普通 USER 登录认证、有效安装标识和当前业务绑定即可，不要求 APK 包名/签名白名单、Android 硬件密钥证明、挑战、证书吊销或额外证明有效期。

此决定取代 2026-09-28 的原生证明门槛（superseded）。不新增安全开关、密钥或 TTL；普通登录认证的现有生命周期继续有效。

## 基本事实与不变量
现有服务端用品牌关键词、核心数、浏览器内存和屏幕值推算 TOPS，五段整数范围造成小数空隙落入最高档。已有 A2 审批、E6 参数事务、校准快照和激活事务可复用。
手机平台算力值不声称物理 TOPS；未知或冲突硬件不猜档。H5 客户端继续跳转下载，不采集或提交手机校准/激活；服务端的安装标识属于普通业务识别，不证明调用者来自原生 APP。换机只影响手机，已购设备、历史结算、普通注册奖励保持原契约。
最小实验：同一小数算力在四个严格递增阈值下只命中一个档；未知/冲突硬件不能激活；电脑安装包空值不能阻塞独立手机配置。

## 功能与数据
1. 服务端持有版本化手机规则：平台、精确机型（可选）、SoC、GPU、内存下限/上限、平台算力值、核验依据。精确机型优先；同优先级歧义拒绝。禁止品牌/屏幕参与评分。
2. 五档仅有四个分界值，区间左闭右开，末档无上限。规则/阈值整体原子发布，带版本、理由、审批与生效时间；无合法规则时待核验，不提供虚构生产种子。
3. E6 维护规则、试算、待核验样本和发布版本；E2 展示/编辑档位分界，复用同一份配置。A5 索引入口，A2 双签发布。直写、过期版本、并发覆盖均拒绝。
4. 校准保存硬件原始信息、匹配规则、规则版本和计算结果；激活前复核最新规则及当前设备绑定。换机遵守后台开关/间隔，原手机下架并取消其任务，禁止仓库旧手机冒充当前手机。原机重测不消耗换机次数。
5. APP 采集原生硬件信息并请求服务端结果，不在浏览器猜测硬件。安装标识区分应用安装，不冒称物理手机标识或硬件真实性证明；卸载重装可能按换机处理。H5 先守卫再采集。
6. 校准展示平台算力值及可恢复状态；公共 phoneBinding 配置贯通 APP/H5。规则生效仅影响后续校准/任务，不重写历史结算。

## 最小接口合同

- `phone-installation/login`、`calibrate`、`activate`、`defer` 已含字符串 `deviceId`：要求普通 USER 认证及 `[A-Za-z0-9._:-]{1,128}` 的安装标识，不查询原生证明、会话证明或安装密钥。
- `phoneRuntime` 使用现有 `calibrationDeviceId`，必须匹配当前 execution binding；后续服务仍核对当前激活手机的归属和设备绑定。
- 数字设备任务 `claim` / `complete`：PHONE/MOBILE 请求须携带 `X-Phone-Installation-Id`，并匹配当前 execution binding 与该用户该设备的 phone binding。其他设备不要求此请求头。账号/设备/任务归属、事务锁、任务证明及结算幂等继续有效。
- `defer` 统一调用正常事务转换；首次无校准时保存空能力的 DEFERRED 记录，已有校准按 revision 和幂等键暂缓。不保留 `deferWithoutProof` 特判，也不授予算力或收益。
- 旧 `/phone-installation/challenge`、`/verify` 返回 HTTP 410 / `PHONE_NATIVE_PROOF_RETIRED`，不读写业务状态；历史证明表迁移保留，不新增活动读写。

## 异常与权限
配置缺失、硬件未知、匹配冲突、采集不支持、规则过期、安装不匹配均有可读状态和重试入口，不按成功处理。运营编辑沿用 E6 权限；规则发布经 A2 不同管理员确认，记录前后版本/理由/时间。E6 无经核实的硬件规则时保持待核验，不造规则或返回成功绕过。

## 分步验收
- guard：E6 手机独立单写/批量写在电脑开关开但下载地址空时成功；电脑相关非法配置仍拒绝；A2 原因可读。
- catalog：规则规范化、重复/重叠、四阈值、小数边界、未知/冲突、版本冲突、定时生效均有行为测试。
- activation：普通 USER、错误账号/安装、解绑、换机开关/间隔、同机重测、过期规则、重复暂缓/激活、旧手机任务停止与已购设备不受影响均有测试。旧证明入口 410 且零写入。
- clients：APP 使用服务端结果和原生信息；H5 不发校准写请求；后台完整编辑/预览/审批/回读；双币双语不退化。
- integration：服务端测试、前端全检与本机实景证据完成后提交；真机/部署迁移/生产硬件规则核验明确交给同事，不写成已通过。

## 范围边界
不启用 Janus，不新建点击演示，不改无关工作区，不强推，不填虚构硬件性能。正式 APP 为 `NX1.0-UniApp`，正式后端为 `nexion-backend`，运营后台为 `nexion-ops-console`；原型不作为后端事实。日常交付使用 `test`，合入 `main` 须用户单独批准。部署及真机通过须有当次实际证据。
