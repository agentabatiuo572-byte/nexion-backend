# TEST BGE-M3 fleet parallel execution

`uvel-cloud-bge-fleet.service` runs at most two independent device workflows. Each device still has one workflow and its original durable journal. Discovery and health run independently. A stopped or ambiguous instance must not be cleared or replayed to make capacity available.

The installed Ollama 0.33.3 scheduler forces embedding models to parallel=1. Raising `OLLAMA_NUM_PARALLEL` cannot provide concurrent BGE-M3 execution. The fleet therefore leases two separate loopback model servers, `127.0.0.1:11436` and `127.0.0.1:11437`, for the complete tags/embed/tags validation interval. Port 11435 remains the existing single-worker and backend verification server. Multi-workflow fleet mode with a real HTTP client requires the explicit distinct endpoint list; single-workflow compatibility does not require a pool.

All three servers must use the same approved Ollama image and BGE-M3 digest. TEST currently uses image `sha256:32931b46719f673c05fdbaa81ccb26da18ea4a1c57590a754874ab28ba269eb2`, model `bge-m3:567m`, digest `sha256:7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab`. The fleet replicas use the existing model directory read-only, 4 GiB / 2 CPU limits per replica, loopback-only published ports, dropped capabilities and no-new-privileges. They are persistent TEST execution services, not disposable test containers. Never delete their shared model storage during scratch cleanup.

Before replacing the shared worker, stop single/fleet gracefully and retain original journals and file locks until in-flight HTTP finishes. Install the reviewed source and unit, verify hashes and systemd configuration, then restart with the existing protected credentials. Do not restart the excluded legacy UNKNOWN worker. `INFERENCE_STARTED` / `INFERENCE_FINISHED` logs contain only task/device/model identifiers, runner port and timing; validate real overlapping task intervals on different runner ports, matching raw results, and unique settled receipts. Multiple RUNNING rows alone are insufficient.

`taskLockS1/Pro/Rack` remain nonnegative integral USDT hint thresholds. New `task_lock_minutes` snapshots are zero and historical nonzero snapshots are ignored on completion. Existing lock reads remain enforced. `scripts/generate-tasklock-recovery.ps1` generates a TEST-only six-device audited CAS recovery from a fresh stopped-worker snapshot; it does not connect to MySQL. Independently review the generated SQL and precision before execution. It never changes task/receipt/wallet/E3 records and does not apply to unknown-origin locks or device 1152.
