# TEST BGE-M3 fleet parallel execution

`uvel-cloud-bge-fleet.service` supplies one independent workflow per currently eligible discovered instance, with six workflow slots by default. Each device still has one workflow and its original durable journal. Discovery and health run independently. Removing an instance stops its new economic requests; adding it again uses the original journal and recovery rules. A stopped or ambiguous instance must not be cleared or replayed to make capacity available.

After an original task is positively confirmed, its workflow can request the next task on the next scheduler turn (up to the existing one-second scheduler cadence), including successful receipt reconciliation. The single worker also continues immediately after a positive completion. `UVEL_CLOUD_POLL_SECONDS` remains the discovery and idle/unsent/error retry interval; it is not a per-task completion cooldown. Empty queues and failed or ambiguous requests retain their original backoff and durable recovery checks. Each new claim still verifies the server's current eligibility, binding, lifecycle and task availability; no task is invented to keep the UI busy.

Stopping before an economic request's durable intent raises `NotSent`. An older `UNKNOWN_NEXT` is locally reclassified only when its exact state contains just the current binding, valid original NEXT key and phase, with no call of any operation registered for that key. The original journal atomically records a `NEXT_PREINTENT_RECOVERY` / `NOT_SENT` local marker and preserves that key as `NEXT_NOT_SENT`; this classification makes no HTTP request. Single recovery and fleet startup reuse this classification before scheduling. Any existing call, different binding, malformed key or extra task field keeps the UNKNOWN isolated. An empty backend active-task query alone never authorizes replay; real UNKNOWN requests and all prior recovery budgets remain unchanged.

The configured bound must cover the sum of eligible, non-excluded instances across all owners in this fleet, not just one owner's six activation slots. `UVEL_CLOUD_FLEET_PARALLELISM` remains bounded to 1–8 and cannot exceed the number of distinct configured runner endpoints. When discovery exceeds the workflow bound, `FLEET_ACTIVE_CAPACITY_EXCEEDED` stops all new `/next-task` requests instead of silently queuing devices. Original claimed work may complete and receipt reconciliation remains available; capacity alone never changes instance presence, generation or UNKNOWN recovery budgets. A later complete discovery within capacity reopens claims. A larger population needs provisioned independent runners and an adequate bounded fleet configuration; populations above eight need a separately reviewed discovery partition or bound change.

The installed Ollama 0.33.3 scheduler forces embedding models to parallel=1. Raising `OLLAMA_NUM_PARALLEL` cannot provide concurrent BGE-M3 execution. The six-workflow fleet therefore leases six separate loopback model servers, `127.0.0.1:11436` through `127.0.0.1:11441`, for the complete tags/embed/tags validation interval. Port 11435 remains the existing single-worker and backend verification server. Multi-workflow fleet mode with a real HTTP client requires the explicit distinct endpoint list; single-workflow compatibility does not require a pool.

All seven servers must use the same approved Ollama image and BGE-M3 digest. TEST currently uses image `sha256:32931b46719f673c05fdbaa81ccb26da18ea4a1c57590a754874ab28ba269eb2`, model `bge-m3:567m`, digest `sha256:7907646426070047a77226ac3e684fbbe8410524f7b4a74d02837e43f2146bab`. The fleet replicas use the existing model directory read-only, 4 GiB / 2 CPU limits per replica, loopback-only published ports, dropped capabilities and no-new-privileges. They are persistent TEST execution services, not disposable test containers. Never delete their shared model storage during scratch cleanup.

Before replacing the shared worker, stop single/fleet gracefully and retain original journals and file locks until in-flight HTTP finishes. Install the reviewed source and unit, verify hashes and systemd configuration, then restart with the existing protected credentials. Do not restart the excluded legacy UNKNOWN worker. `INFERENCE_STARTED` / `INFERENCE_FINISHED` logs contain only task/device/model identifiers, runner port and timing; validate real overlapping task intervals on different runner ports, matching raw results, and unique settled receipts. Multiple RUNNING rows alone are insufficient.

The fixed single executor remains excluded from fleet discovery. Its normal idle loop and idle background health first call the read-only `/eligibility` endpoint. An inactive or paused device sends no new heartbeat or economic request after that check; the normal loop waits its polling interval and can resume after legitimate reactivation with the same executor identity and journal. A positive eligibility response with an unjournaled active task is blocked. Eligibility is never used to clear or replay UNKNOWN requests: existing pending work follows the original receipt/manifest and exact recovery-budget rules. A lifecycle change between eligibility and a later request remains guarded by the backend; a sent uncertain request still stops for reconciliation.

`taskLockS1/Pro/Rack` remain nonnegative integral USDT hint thresholds. New `task_lock_minutes` snapshots are zero and historical nonzero snapshots are ignored on completion. Existing lock reads remain enforced. `scripts/generate-tasklock-recovery.ps1` generates a TEST-only six-device audited CAS recovery from a fresh stopped-worker snapshot; it does not connect to MySQL. Independently review the generated SQL and precision before execution. It never changes task/receipt/wallet/E3 records and does not apply to unknown-origin locks or device 1152.
